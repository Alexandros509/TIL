# PA Lv3 — 리전 선택과 IAM

## 리전을 어디에 둘지

해저광케이블 현황이 1차 기준
동아시아 1차 집결지 = 일본
글로벌 서비스는 일본 리전을 먼저 보는 경우 많음

국제 정세·환율도 봄
우방국 우선 = 미국·일본

최신 기술은 일본·미국에 먼저 나오고 다른 나라는 늦음
리전마다 안 열리는 서비스도 있음
콘솔 들어가기 전 리전 확인 필수

실습은 서울 고정이 과금 사고 방지
서비스 위치 결정은 케이블·정세·기능 출시 시점을 같이 봄

## Root vs IAM

| 구분 | 역할 |
|---|---|
| Root | 본주 / 최대한 안 쓰는 것이 원칙 |
| IAM | 단기간·권한 선택해서 씀 |

AWS 사용 시 이중 로그인 필수

### IAM 부품

| 워딩 | 뜻 |
|---|---|
| IAM 사용자 | Root가 만든 사람 계정 / 그룹에 넣고 액세스 활성화 / 로그인 링크·암호 전달 |
| IAM 그룹 | 같은 권한을 묶은 단위 / 개인마다 FullAccess 안 주고 그룹으로 부여 |
| 정책 Policy | 할 수 있는 일의 목록 |
| 역할 Role | 사람 말고 서비스·서버가 임시로 쓰는 권한 |

IAM은 글로벌
리전이 아니라 계정 단위 설정

권한은 개발자 담당 구역만
FullAccess는 대체로 안 줌
일일이 붙이기 번거로워서 그룹을 만듦

서버 권한은 여러 번 강조해도 부족함
**JD(직무기술서, Job Description)** 범위를 철저히 지킬 것

### 액세스 키

보안 자격 증명의 액세스 키는 기본 사용 안 함
비밀 액세스 키가 털리면 서버 전체가 털림

readonly도 env를 읽을 수 있음
환경 변수에 개인정보·시크릿 있으면 readonly만으로도 유출 가능

## 구성·비용 메모

| 워딩 | 뜻 |
|---|---|
| t3.micro | EC2 작은 인스턴스 / 실습·토이용 |
| Lightsail | EC2보다 단순한 묶음 상품 / 개인·소규모 고정 요금에 가까움 |
| 혁신의숲 / 정부 크레딧 | 개인사업자면 크레딧 경로 추천 |
| AWS Summit 크레딧 | 행사·이벤트로 받는 크레딧 |

리액트 서버·서비스는 빌드 산출물을 압축·다이어트
정적 용량이 S3 저장·전송 비용으로 이어짐

도메인 예: `내도메인.한국`
가입 후 연결해서 사용

## AWS가 안정적이라는 말의 기준

사설 서버와 비교할 때 보통 이 세 가지

- 비용: 전기·회선·UPS를 직접 안 짊어짐
- 24시간 전기: 사설이면 UPS·발전기가 필요
- 회선: 데이터센터 초고속 랜

안정 = 안 내려가는 것만이 아님
비용·전원·네트워크가 한꺼번에 관리되는지에 가까움
