## 보안 그룹

인바운드 = 밖에서 서버로 들어오는 규칙
아웃바운드 = 서버에서 나가는 규칙
유형 `모든 트래픽`은 위험 → 삭제

오늘 연 것
1. SSH / 소스 = 내 IP (가능하면 My IP)
2. HTTP 80 / 소스 `0.0.0.0/0` (Anywhere-IPv4)
3. HTTP / Anywhere-IPv6
4. 모든 TCP + 내 계정 — 넓음 실습 후 줄일 것

인증서·도메인 없음
HTTPS는 나중에
도메인+인증 경로 언급: 한 달 약 4만 원대 상품도 있음
오늘은 HTTP만

IPv4 vs IPv6
표현 가능한 주소 개수 차이
주소가 모자라니 v6를 늘림
자동차 번호 앞자리 2자리 → 3자리와 같은 감각

default 보안 그룹은 삭제 안 됨
새로 만든 그룹만 삭제
default 인바운드는 SSH만 남기고 나머지 삭제
이유: 기본 그룹이 다른 자원에 붙을 수 있어서 입구를 최소로 둠

종료 시 키 페어도 삭제

## 네트워크 주소

| 종류 | 누가 봄 |
|---|---|
| Public IP | 사용자에게 주는 주소 |
| Private IP | VPC 안에서만 |

AWS Public IP는 중지·재시작 때 바뀜
고정하려면 탄력적 IP

탄력적 IP
- 할당 = 주소 예약
- 인스턴스에 연결 = 공개 주소가 그 IP로 고정
- 계정당 기본 4개 / 더 필요하면 한도 상향 요청
- 보통 프론트·백 정도면 2개 안팎

할당만 하고 인스턴스에 안 붙이면 과금
종료 순서
1. 탄력적 IP 릴리스
2. 전송·연결 해제
3. 인스턴스 종료
회색 종료 = 크레딧·과금 확인용으로 남기지 말 것

기본으로 읽는 이름
- `index.html`
- `index.nginx-debian.html`

아래는 안 바뀌는 이유

```bash
sudo cp AWS_selfintro.html /var/www/html/index.nginx-debian.html
sudo cp AWS_selfintro.html /var/www/html/index.html
ls -l /var/www/html
```

## SSR vs CSR

서버사이드 렌더링 SSR
서버가 HTML을 다 그려서 줌
검색 노출에 유리
메타데이터(title description og)를 코드에 넣어야 구글이 읽기 쉬움
수업 예: 갤럭시 S25 검색 노출
단점: 게임·3D처럼 무거운 산출물은 서버 자원을 크게 먹음

클라이언트사이드 렌더링 CSR
원본(JS 번들)을 받고 브라우저가 그림을 그림
초기 HTML이 비면 크롤러가 메타를 못 볼 수 있음
용량·연산이 클라이언트로 이동

노출이 필요하면 SSR 또는 메타가 있는 정적 HTML
인터랙션·그래픽이 크면 CSR 비중을 늘림

리액트 산출물은 빌드 다이어트
용량이 S3·전송·첫 로딩으로 이어짐

## 보충

상태 점검 2종
- 시스템 상태 점검: AWS 쪽 호스트
- 인스턴스 상태 점검: OS 부팅
둘 다 OK여야 Connect·SSH가 안정

SSH 소스
실습 편의로 Anywhere를 열면 키만 있으면 전 세계 접속 시도
가능하면 My IP
카페·핫스팟이면 IP가 바뀌어 SSH가 끊김 → 그때만 소스 수정

`t4g` = ARM Graviton
예전에 적던 `t3` = x86
AMI 아키텍처와 타입이 같아야 시작됨

gp3
범용 SSD
8GB는 OS+Nginx+작은 HTML엔 남음
로그·도커 이미지를 쌓으면 부족해짐

Nginx 안 보일 때
1. 보안 그룹 80 열려 있는지
2. `sudo systemctl status nginx`
3. `/var/www/html/index.html` 존재
4. 브라우저가 HTTPS로 강제 접속 중인지 (오늘은 인증서 없음 → `http://`)

탄력적 IP 한도 4개는 소프트 리밋
안 쓰는 주소는 릴리스
인스턴스 지워도 탄력적 IP는 안 따라 지워짐
