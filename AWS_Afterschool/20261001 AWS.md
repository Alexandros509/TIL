# Compose 기동 · health · EC2 8000 공개

[원본 노트](../raw/AWS_Afterschool/20261001%20AWS.md)

[관련: Docker · FastAPI MSA · EC2](./20260922%20AWS.md)

[관련: PA Lv3 — EC2 · Nginx · 탄력적 IP](./20260915%20AWS.md)

오늘은 MSA·Dockerfile 설계보다 **Compose를 로컬·EC2에서 실제로 올리며 막힌 지점**을 정리한다. 아키텍처·서비스 분리는 [0922](./20260922%20AWS.md)를 본다.

### 어디서 빌드하나

`compose.yaml`(또는 `docker-compose.yml`)이 있는 디렉터리에서 명령을 친다. 상위·다른 폴더에서 치면 파일을 못 찾거나 엉뚱한 프로젝트가 뜬다.

실습 폴더 예: EC2 SSH 후 `~/AWS-261001-Test` (`ubuntu@ip-...` 프롬프트). **Windows PowerShell이 아니라 EC2 셸**이다.

```bash
docker compose up -d --build
```

- `-d`: 백그라운드
- `--build`: 이미지 다시 빌드 후 기동 (필기 오타 `-build` 아님)
- Healthy: healthcheck가 통과한 상태. Compose `ps` / `docker compose ps`에서 확인

설정·코드·Dockerfile을 고쳤으면 **리빌드가 필수**다. 컨테이너만 재시작해서는 이미지 레이어가 안 바뀌는 경우가 많다.

정석으로 내릴 때:

```bash
sudo docker compose down
```

볼륨까지 지울지(`-v`)는 데이터 보존 여부에 따라 따로 결정. (0922·튜터 블로그 맥락)

### /health 가 왜 있나

서버 생사 판단용. 오케스트레이션·Compose healthcheck가 **일정 간격으로** `/health`(또는 설정한 경로)에 요청을 보낸다.

- 응답이 정상이면 Healthy
- 실패가 이어지면 Unhealthy → 재시작 정책·배포 판단에 쓰임

필기 포인트: **엔드포인트를 반드시 두고**, healthcheck가 그 URL을 치게 맞춘다. (앱 루트 `/`만 열어두면 health와 역할이 섞이기 쉽다)

### 로컬에서 브라우저

```text
http://127.0.0.1:8000/docs
```

- FastAPI면 Swagger가 `/docs`
- **`0.0.0.0`은 브라우저 주소가 아니다.** 바인드(어느 인터페이스에 열지) 표기다. 주소창에 넣으면 `ERR_ADDRESS_INVALID`

로컬에서 컨테이너가 `0.0.0.0:8000`에 바인드되어 있어도, PC 브라우저는 `127.0.0.1`(또는 `localhost`)로 접속한다.

### EC2에 올리기 — clone부터

목표: **로컬 Docker만이 아니라 AWS EC2**에서 같은 Compose를 돌린다.

1. EC2에 SSH (`ubuntu@…`)
2. 저장소 clone  
   - `git@github.com:…` 쓰려면 **EC2의 SSH 공개키를 GitHub에 등록**한 뒤  
   - host key fingerprint 질문 → `yes`
3. 프로젝트 디렉터리로 이동 (`compose.yaml` 위치)
4. Docker 엔진이 없으면 Compose도 안 된다

```text
sudo: docker: command not found
```

→ `.env`만 있어도 **실행되지 않는다.** 엔진부터 설치.

Ubuntu는 Docker 공식 문서 **Install using the apt repository**를 따른다:  
[Docker Engine on Ubuntu (apt repository)](https://docs.docker.com/engine/install/ubuntu/#install-using-the-repository)

설치 후 다시:

```bash
sudo docker compose up -d --build
```

(권한에 따라 `sudo` / docker 그룹 가입 여부는 환경마다 다름)

### 8000 포트 — 보안 그룹과 바인드

밖(내 PC 브라우저)에서 열려면 **두 층**이 맞아야 한다.

**1) 보안 그룹**

- EC2 → 보안 그룹 → 인바운드 규칙 추가
- TCP **8000**, 소스: 실습에서는 **내 IP만** (필기: IPv4·IPv6 각각 규칙)
- SSH(22)도 본인 IP만 유지하는 게 수업 흐름과 맞음

**2) 컨테이너/Compose 바인드**

`127.0.0.1:8000`만 열려 있으면 **EC2 안에서만** 접속된다. 밖에서는 보안 그룹을 열어도 막힌다.

- compose의 ports / `BIND_HOST` 등을 **`0.0.0.0`** 으로 (튜터 실습: 로컬 기본 `127.0.0.1`, EC2는 `0.0.0.0`)
- 인스턴스에서 설정을 고친 뒤 반영:

```bash
sudo docker compose up -d --force-recreate
# 또는 리빌드가 필요하면 --build 포함
```

목표 `ps` 표시 예:

```text
0.0.0.0:8000->8000/tcp
```

`127.0.0.1:8000->8000/tcp`이면 아직 호스트 루프백만.

### 브라우저 · 장애 나눔

```text
http://<퍼블릭IP>:8000/docs
```

| 증상 | 먼저 볼 곳 |
|------|------------|
| EC2 안 `curl`은 되고 PC만 실패 | 보안 그룹 TCP 8000 (소스 IP·IPv6) |
| `ps`가 `127.0.0.1:8000` | compose 바인드 → `0.0.0.0` 후 recreate |
| `docker: command not found` | 엔진 미설치 |
| 빌드/파일 못 찾음 | `compose.yaml` 디렉터리인지 |
| Docker 수정했는데 반영 안 됨 | `down` 후 `up -d --build` |

### 한 줄 흐름

```text
compose.yaml 위치
  → (없으면) Docker Engine 설치
  → docker compose up -d --build
  → Healthy(/health)
  → EC2: SG 8000 + 0.0.0.0 바인드
  → http://퍼블릭IP:8000/docs
```

### 확인

- [ ] 오늘 실습 레포명이 `AWS-261001-Test`인지, 공개 포트가 8000만인지 수업 자료와 일치하는가
- [ ] healthcheck가 실제로 `/health`인지, 다른 path인지 compose 파일에서 한 번 더 확인
- [ ] 보안 그룹을 `0.0.0.0/0`으로 열지 않았는지 (필기·튜터: **내 IP만**)
