##### 2. 초기 자바스크립트의 변수 선언: var의 치명적인 결함

var
 1. 호이스팅 문제
 2. 변수의 유효범위 (scope)
	 -  함수 레벨 스코프 (Function-level Scope)
 3. 선언자(var)을 생략하고 변수를 지역변수로 정의 > 전역변수가 된다 => 선언 키워드 생략 허용 (암묵적 전역 변수)

* **동작 원리:** `코드 파싱(번역)` ➔ `메모리/전역 객체 등록` ➔ `실제 코드 실행`

* JS 엔진은 코드를 위에서부터 실행하기 전, 사전 파싱 단계를 거쳐 선언문들을 메모리에 먼저 등록함.

* **호이스팅 (Hoisting):**
* 변수 및 함수 선언이 해당 스코프의 **최상단으로 끌어올려진 것처럼 동작**하는 현상.
* 브라우저 전역 스코프에서 함수 선언문 사용 시 최상위 전역 객체(`window`)에 프로퍼티로 할당됨 (`window.add = ...`).

* **핵심 특징:**
* **함수 정의 위치와 무관하게 호출 가능:** 함수 선언문은 함수 전체가 메모리에 통째로 등록되므로 선언부보다 윗줄에서 호출해도 정상 작동함.

```javascript
console.log(add(1, 2)); // 정상 실행 (3)

function add(a, b) {
  return a + b;
}

```

* **함수 선언문:** 선언 전 호출 가능 (함수 전체 호이스팅)
* **함수 표현식 / `let`·`const`:** 선언 전 호출 시 TDZ(일시적 사각지대)로 인해 `ReferenceError` 발생

---

* **변수(`var`) 호이스팅 (지양)**: 선언과 동시에 `undefined`로 초기화되어 런타임 오류와 코드 흐름 왜곡의 주원인이 되므로 `const`/`let`을 사용합니다.
* **함수(`function`) 호이스팅 (지향)**: 선언과 동시에 함수 객체가 완성된 상태로 등록되므로 구조적인 코드 배치에 유용하게 활용할 수 있습니다.

---

**함수 호이스팅의 핵심 장점 2가지**

1. **가독성 극대화 (탑다운 구조 배치)**
* 파일 상단에 메인 비즈니스 로직을 먼저 두고 세부 헬퍼 함수는 하단에 밀어둘 수 있어 코드 파악이 훨씬 빨라집니다.

2. **상호 재귀 및 선언 순서 딜레마 해소**
* 함수들이 서로를 교차 호출할 때 호출 순서에 얽매이지 않고 안정적인 참조가 가능해집니다.

---

import re
from langchain_core.messages import HumanMessage
from langchain_core.runnables import chain
from langchain_core.output_parsers import StrOutputParser
from lib import get_model

@chain
def protected_message(message: str) -> list[HumanMessage]:
    pattern = re.compile(r"(010)\D*(\d{4})\D*(\d{4})")

    message = pattern.sub(r"\g<1>-****-****", message)

    return [HumanMessage(message)]

model = get_model()
parser = StrOutputParser()

chain = protected_message | model | parser
chain.invoke("나의 전화번호는 010-1000-1000")
~~~
