### 5장 SQL
#### 3.1 서브쿼리 기초
서브쿼리 (부속질의)
-  내부쿼리 결과를 외부쿼리가 이용
1. SELECT(2. 외부쿼리) 문에 SELECT(1. 내부쿼리)가 포함된 질의
2. 스칼라 서브쿼리
	-  SELECT 서브쿼리 FROM
	- 단일값 반환
3.  인라인 뷰 (가상 테이블) 
	-  SELECT ... FROM 서브쿼리
	- 실제 물리적 테이블 X . 조회 결과를 가지고 테이블처럼 사용가능한 임시 테이블
4.  WHERE절 서브쿼리
	-  SELECT ... FROM ... WHERE 서브쿼리
		1) 비상관 서브쿼리 (교재 예시) 
			-  SELECT ... FROM ... WHERE col > (서브쿼리) 
			- 내부가 먼저 실행 - 내부 결과(보통 단일값)를 외부가 조건에 사용 
			- 예: 전체 평균보다 큰 주문
		2) 상관 서브쿼리 SELECT ... FROM t WHERE ... (서브쿼리가 t.컬럼 참조)
		    - 외부 행의 값을 내부가 사용 
		    - 행마다 내부 쿼리가 다시 실행되는 경우가 많음 
		    - 예: 그 고객의 평균보다 큰 주문
5. IN / NOT IN
	-  서브쿼리가 여러 행을 반환할 때는 = 대신 IN을 사용
	-  서브쿼리가 반환한 값 목록 중 하나라도 일치하면 조건을 만족
	- NOT IN은 서브쿼리 결과에 포함되지 않는 행만 가져올 때 사용
6. EXISTS / NOT EXISTS
	- 데이터가 존재하는지 여부만 판단
	-  서브쿼리의 결과가 한 행이라도 존재하면 TRUE를 반환
	-  NOT EXISTS는 서브쿼리 결과가 없을 때 TRUE를 반환

- FROM 앞에는 단일값만 나올 수 있게 해야함.

 | 구분 | IN / NOT IN | EXISTS / NOT EXISTS |
| :--- | :--- | :--- |
| **비교 방식** | 서브쿼리가 반환한 **값 목록 전체**와 비교 | 조건에 일치하는 데이터의 **존재 여부(True/False)**만 확인 |
| **실행 방식** | 서브쿼리 결과를 메모리에 목록으로 적재 후 비교 | 일치하는 행을 1개라도 찾는 즉시 탐색 중단 (Short-Circuit) |
| **NULL 처리 (주의)** | 서브쿼리 결과에 `NULL`이 포함되면 `NOT IN` 결과가 **빈 값(0건)**으로 출력됨 | `NULL` 값의 유무에 영향받지 않고 일치 여부만 정상 판단 |
| **서브쿼리 형태** | 비상관 서브쿼리 주로 사용 (`WHERE id IN (SELECT id ...)`) | 상관 서브쿼리 사용 (`WHERE EXISTS (SELECT 1 ... WHERE o.id = c.id)`) |
| **성능 (일반적 경향)** | 서브쿼리 결과가 **소량**이거나 정적 리스트일 때 유리 | 서브쿼리 대상 테이블이 **대량**이거나 인덱스가 걸려 있을 때 유리 |
