### 5.4 이터레이터와 제너레이터
#### 5.4.1 이터러블과 이터레이터의 동작 방식
##### 5.4.1.1 객체(Iterable)와 이터레이터(Iterator)
 - 이터러블 (Iterable)
    - 반복 가능한 객체
    - \_\_iter\_\_(..) 정의되어 있다면 반복 가능!
    ~~~python
    .__iter
     ~~~
    - \_\_next\_\_(..) 인덱스를 한칸씩 이동하면서 요소를 꺼내오는 기능을 정의
 - 이터레이터(반복자)
    - 반복을 하려면
      - 이터레이터 객체 생성 (`__iter__` 호출(iter...))
      - 순서를 한칸씩 이동하면서 요소 조회(`__next__` 호출 next(...))

#### 5.4.2 yield 키워드와 제너레이터의 지연 평가
 - yield와 제너레이터(Generator)
    * `yield`를 사용하는 함수를 **제너레이터 함수**라고 한다.
    * 제너레이터 함수는 값을 한 번에 모두 생성하지 않고, **필요할 때마다 하나씩 생성**한다.
    * `yield`를 만나면 값을 반환하고 함수의 실행을 **일시 정지**한다.
    * 이후 `next()`가 호출되면 정지했던 위치부터 **실행을 재개**한다.

    > **핵심:** `yield` = 값을 내보내고, 현재 실행 상태를 보존한 채 잠시 멈춤


 - 지연 평가(Lazy Evaluation)
    - 지연 평가 : 데이터를 미리 모두 계산하지 않고, **실제로 필요한 시점에 계산하여 생성하는 방식**
        * 일반적인 리스트 → 필요한 데이터를 미리 모두 생성하여 메모리에 저장
        * 제너레이터 → `next()` 등으로 요청할 때마다 필요한 값을 하나씩 생성

text
일반적인 방식
데이터 전체 생성 → 메모리에 저장 → 사용

제너레이터
값 요청 → 하나 생성 → 사용
       → 다음 값 요청 → 하나 생성 → 사용



> * `yield` → 값을 하나 반환하고 실행을 일시 정지
> * `next()` → 정지한 위치부터 실행 재개
> * 제너레이터 → 값을 필요할 때마다 하나씩 생성하는 객체
> * 지연 평가 → 필요한 시점에 데이터를 계산·생성하는 방식

동기: 순서대로 실행하고 결과도 순서대로 도출

### 6.1 모듈과 패키지
#### 6.1.1 독립 소스 파일 모듈과 디렉터리형 패키지 구조
##### 6.1.1.1 모듈(Module)
 - 모듈 : 파이썬 파일 하나
 - 다른 파일에서 모듈을 불러와서 사용하는 경우 많다
 - 모듈명은 파일 이름
 - `__name__` : 모듈 이름

##### 6.1.1.2 디렉터리형 패키지(Package) 
디렉터리형 패키지
 - 패키지는 모듈을 모아 놓은 디렉토리
 - from 패키지명.하위패키지 import ...
 - 전체 패키지 경로 : 절대 경로 접근 예) chapter.mod1
 - 상대 경로 접근법 (..): 바로 위 패키지
                  (.): 현재 모듈이 있는 패키지

#### 6.1.2. 모듈 로드를 위한 키워드와 표준 라이브러리 활용
##### 6.1.2.1 import, from, as 키워드
import, from, as
 - import : 모듈 불러오기
    마침표(.)를 통해 모듈 안의 정의된 함수 호출 가능
    ~~~python
    import mod1
    mod1.add(10,20)
    ~~~
 - from 모듈명/패키지명 import 모듈에 있는 함수,변수,클래스 등등, 모듈
    ~~~python
    from mod1 import add, minus, VERSION
    add(10,20)
    ~~~
 - from 모듈명 import * -> 모듈의 전체 함수, 변수, 클래스를 불러온다

 - as  : alias - 별칭
     ~~~python
     import calculation as calc
     ~~~


 - 패키지 내에서 사용할 공통적인 함수, 변수, 클래스를 정의
