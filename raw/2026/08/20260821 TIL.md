### 11.1 동기(Sync) vs 비동기(Async)
 - 동기
    작업 하나 제어권 묶임 (Blocking)
 - 비동기 (Coroutine)
    - 작업 새로 생기면 제어권 넘어가고 (Nonblocking), 
    - 결과를 보지 않고 바로 넘겨서 동시라고 보일 수 있지만 동시는 아님. 약간의 딜레이.
    -  비동기 함수 정의
       -  1. 함수 정의 def 앞에 async
       -  2. await을 만나면 제어권 즉시 반환

 - 프로세서와 대기의 관계 : CPU Bound vs I/O Bound
   - CPU Bound (연산 중심 작업)
     - 복잡한 수식 연산 처리
     - 처리 속도가 하드웨어의 물리적 성능에 의해 결정
   - I/O Bound (입출력 중심 작업)
     - 서버에 데이터를 요청, 외부에 요청을 보내고 응답을 기다리는 상태
     - 데이터가 이동하는 지연 시간(Latency)이 전체 시스템 속도를 결정
     - 내부의 프로세서는 별도의 연산 없이 대기


 - 제어권 반환 여부: Blocking vs Non-blocking
    - Blocking (블로킹)
      - 호출된 하위 코드가 작업을 마칠 때까지 제어권을 독점
    - **Non-blocking (논블로킹)**
      - 제어권을 상위 코드가 그대로 유지하거나, 요청 즉시 제어권을 다시 돌려받는 방식
    
 - 이벤트 루프
     - 단일 일꾼이 대기 상태인 작업들을 순찰하며 완료 신호가 들어온 태스크들을 차례대로 배정해 주는 스케줄러
     - 동기식 운영 (머신 앞 부동자세 대기)
     - 비동기식 운영 (진동벨 활용 멀티태스킹)
주방 공간,컴퓨터 작동 개념,상세 설명
1. 조리 도마,Call Stack (콜 스택),일꾼이 지금 당장 손을 움직여 연산하고 처리하는 실제 작업대입니다.
2. 자동 머신,Background (백그라운드),"일꾼의 손을 떠나서 기계(네트워크 서버, 저장장치 등)가 알아서 비동기 작업을 수행하는 격리된 공간입니다."
3. 완성 쟁반,Callback Queue (콜백 큐),"기계 작업이 끝나 진동벨이 울린 결과물들이, 일꾼의 마지막 처리(콜백 함수)를 받기 위해 줄을 서서 대기하는 공간입니다."

### 11.2 코루틴(Coroutine)과 async / await
1. 코루틴(Coroutine)
   - 필요한 경우 제어권을 잠시 양보할 수 있는 함수
   - 차례가 되면 멈췄던 지점부터 이어서 작업을 수행
2. 실행 환경에 따른 가동 방식
   - 주피터 노트북에서는 이벤트 루프가 가동 중 -> await 함수명()
   - 파이썬 파일(py)를 실행할 때는 이벤트 루프를 생성해야 정상 동작 asyncio.run()

### 11.3 비동기 태스크 동시 처리 및 실무 실습

 - asyncio.gather()
   - 1. 무중단 스케줄링 (이벤트 루프의 조율)
        이벤트 루프가 여러 코루틴(작업)을 동시에 관리합니다.

        작업 중 대기 상태(await)가 발생하면 즉시 다른 작업으로 제어권을 전환하여, 쉬는 시간 없이 최대한의 효율을 뽑아냅니다.

   - 2. 에러 통제권 (return_exceptions 옵션)
        동시에 실행되는 여러 작업 중, 일부 작업에서 에러가 발생했을 때의 처리 방식을 결정합니다.

        False (기본값): 하나의 작업이라도 에러가 나면 전체 작업이 즉시 중단됩니다.

        True: 에러가 발생한 작업은 결과

    ~~~python
    import asyncio

    async def work(title,seconds):
        await asyncio.sleep(seconds)
        print(title, "완료")
        return title + "완료"

    async def main():
        results = await asyncio.gather(
            work("작업 A",2),
            work("작업 B",3),
            work("작업 C",1)
            )
        print(results)

    await main()    
    ~~~
    ~~~python

    import asyncio

    async def work():
        await asyncio.sleep(2)
        print("작업 완료")

    # await work()
    asyncio.run(work()) # 이벤트 루프 생성 -> 실행


    ~~~

#### 1. httpx 주요 클래스 (Classes)

| 클래스명 | 주요 역할 | 비고 |
| :--- | :--- | :--- |
| `httpx.Client` | **동기식** HTTP 요청 처리 및 커넥션 풀 관리 | `with` 문과 함께 사용 권장 |
| `httpx.AsyncClient` | **비동기식** HTTP 요청 처리 (코루틴 동작) | `async with` 문 및 `await` 필수 |
| `httpx.Response` | 서버가 반환한 HTTP 응답 데이터 캡슐화 객체 | 상태 코드, 헤더, 본문 등 포함 |
| `httpx.Limits` | 커넥션 풀 설정 제어 (최대 연결 수 등) | 대규모 동시 요청 최적화 시 활용 |

> 🚨 **주의:** `AsyncClient`의 메서드를 호출할 때는 앞에 반드시 **`await`**를 붙여야 합니다.

---

#### 2. 클라이언트 요청 메서드 (Request Methods)

| 메서드명 | HTTP 메서드 | 주요 설명 및 매개변수 |
| :--- | :--- | :--- |
| `.get(url)` | GET | **데이터 조회:** 쿼리 스트링은 `params=dict` 형태로 전달 |
| `.post(url)` | POST | **데이터 생성:** 바디 데이터는 `json=dict` 또는 `data=dict`로 전달 |
| `.put(url)` | PUT | **데이터 수정:** 자원의 전체 수정을 요청할 때 사용 |
| `.delete(url)`| DELETE | **데이터 삭제:** 특정 리소스의 삭제를 요청할 때 사용 |
| `.request(method, url)`| 커스텀 | 임의의 HTTP 메서드(PATCH, HEAD 등)를 문자열로 직접 지정하여 요청 |

---

#### 3. 응답 객체 주요 속성 및 메서드 (Response Objects)

| 속성 / 메서드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `.status_code` | 속성 `int` | HTTP 상태 코드를 반환 (예: 200, 404, 500) |
| `.text` | 속성 `str` | 응답 본문을 텍스트 문자열 형태로 반환 (자동 디코딩 포함) |
| `.content` | 속성 `bytes` | 응답 본문을 인코딩되지 않은 순수 바이너리(바이트) 형태로 반환 |
| `.json()` | 메서드 | JSON 형식의 응답 본문을 파이썬 딕셔너리/리스트로 파싱하여 반환 |
| `.raise_for_status()` | 메서드 | 상태 코드가 4xx(클라이언트 오류), 5xx(서버 오류)일 경우 예외 발생시킴 |

~~~python
# 동기식 호출
import httpx

with httpx.Client() as client:
    response = client.get("https://jsonplaceholder.typicode.com/posts/1")
    print(response.json())

# 비동기식 호출
import httpx
import asyncio

async def main():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://jsonplaceholder.typicode.com/posts/1")
        print(response.json())

asyncio.run(main())
~~~

## 찾아본 내용
 - **`async`** & **`await`**
   - 완벽한 바늘과 실의 관계
   - async : 중간에 멈출 수 있는 함수 (코루틴) 선언
     - **비동기 프로그래밍을 할 수 있도록 지원하는 기본 라이브러리(모듈)**
   - await : async 함수 내부에서만 쓸 수 있는 일시정지 버튼
   - async가 없는 일반 함수에서는 await를 쓸 수 없고, await가 없는 async 함수는 사실상 일반 함수와 똑같이 한 번에 쭉 실행되어 비동기의 의미가 없음

 - 이벤트 루프 생성 / 코루틴 실행이 헷갈림. async def 함수로 루프 생성? 아니면 그 함수를 실행해야 루프 생성? 그럼 코루틴은? 
    - 1단계 (레시피/설계도 정의): async def work(): ...

    단순히 "앞으로 이런 비동기 요리를 만들겠다"는 설계도(레시피)를 작성해 둔 상태입니다. (아무 일도 일어나지 않음)

    - 2단계 (주문서/코루틴 생성): my_order = work()

    함수를 호출하면 요리가 나오는 것이 아니라, 포스기에서 주문서(코루틴 객체)가 툭 출력됩니다. 누군가에게 주지 않으면 종이 쪼가리일 뿐입니다. (코드는 아직 1줄도 실행되지 않음)

    - 3단계 (주방/루프 생성 및 실제 실행): asyncio.run(my_order)

    새로운 주방(이벤트 루프)을 뚝딱 만들어 내고, 방금 뽑은 주문서를 메인 요리사에게 넘기며 "이제 요리 시작해!"라고 지시합니다. (코루틴이 루프 안으로 들어가 드디어 코드가 한 줄씩 실행됨)
