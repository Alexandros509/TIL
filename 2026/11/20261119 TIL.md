## 어제의 복습

1. 질문과 문서 간의 문체나 전문성 격차가 큰 경우, 언어 모델이 먼저 가상의 예상 답변 문서를 생성한 뒤 이를 임베딩하여 검색에 활용하는 Query 변환 기법
   - HyDE (Hypothetical Document Embeddings)
2. 복수의 특화 데이터베이스(문서, SQL, 웹)가 존재할 때, 질문의 성격을 판별하여 적절한 저장소 경로로 검색 요청을 분기시키는 Query 변환 기법
   - Query Routing
3. 2단계(2-Stage) 검색 구조에서 1차 검색기와 2차 리랭커(Cross-Encoder)를 분리하여 사용하는 주된 이유로 가장 적절한 것
   - 모든 대용량 문서에 무거운 모델을 적용할 때 발생하는 속도 저하를 막고, 소수 후보군만 정밀 채점하기 위해서
4. 맥락 압축(Contextual Compression)과 리랭킹(Re-ranking)의 기능적 차이를 가장 적절하게 설명한 것
   - 리랭킹은 문서 단위의 순서를 재배열하고, 맥락 압축은 문서 내부의 불필요한 문장을 잘라낸다
5. 질문에 포함된 단어와 문서 내 단어의 의미는 같으나 표기 형태가 달라 키워드 기반 검색(BM25)이 관련 문서를 찾지 못하는 현상
   - 어휘 불일치

**4장 3강 : Re-ranking (1)**

> 교재 · 4장 3강

어제 비교한 1차 검색과 재순위의 차이를, 오늘은 분류 헤드와 학습 손실까지 풀어 본다.

### 1. Cross-Encoder의 동작 메커니즘 (로지스틱 회귀 구조)

- 입력 결합 (Concatenation): 질문($Q$)과 후보 문서($D$)를 특수 토큰으로 이어 붙여 단일 시퀀스로 구성한다 (`[CLS] Q [SEP] D [SEP]`).
- 교차 어텐션 (Cross-Attention via Self-Attention): 트랜스포머 인코더 내부에서 질문의 모든 토큰과 문서의 모든 토큰이 서로 직접 어텐션 가중치를 계산하여 미세한 문맥적 연관성을 포착한다.
- 풀링 및 분류 헤드 (Classification Head): 인코더 최종 레이어의 첫 번째 `[CLS]` 토큰 히든 벡터($h_{\text{[CLS]}}$)를 추출한 뒤, 가중치 벡터 $W$와 편향 $b$로 선형 변환(Logit) 한다.
- 시그모이드($\sigma$) 함수를 적용해 `0~1` 사이 스칼라 점수를 출력한다.

$$\text{Score}(Q, D) = \sigma(W \cdot h_{\text{[CLS]}} + b)$$

- 학습 및 추론:
  - 학습(Training): 정답 문서(Positive)는 `1`, 오답 문서(Negative)는 `0`으로 라벨링하여 이진 교차 엔트로피(Binary Cross-Entropy, BCE) 손실로 미세조정(Fine-tuning)한다.
  - 추론(Inference): 1차 검색된 후보 문서들을 각각 질문과 쌍(Pair)으로 묶어 통과시킨 뒤, 산출된 `0~1` 점수를 기준으로 내림차순 정렬(Re-ranking)하여 상위 $K$개만 LLM 컨텍스트로 전달한다.

**Cross-Encoder**는 질문과 문서를 한 시퀀스로 묶어, 위 분류 헤드가 관련성 확률을 직접 내는 재순위 모델이다.

### 2. Bi-Encoder vs. Cross-Encoder 비교

**Bi-Encoder**는 질문과 문서를 각각 독립적으로 인코딩한 뒤 벡터를 비교한다.

| 구분                | Bi-Encoder (임베딩 모델)                    | Cross-Encoder (리랭커 모델)                        |
| ------------------- | ------------------------------------------- | -------------------------------------------------- |
| 입력 방식           | 질문과 문서를 각각 독립적으로 인코딩        | 질문과 문서를 [SEP]로 합쳐 동시에 인코딩           |
| 유사도 산출         | 두 임베딩 벡터 간 코사인 유사도 / 내적 계산 | [CLS] 벡터 → Linear + Sigmoid (0~1 확률 직접 예측) |
| 토큰 간 상호작용    | 없음 (인코딩 완료 후 벡터 비교만 수행)      | 모든 토큰 쌍 간 직접적인 Self-Attention 수행       |
| 사전 인덱싱         | 가능 (문서 벡터를 Vector DB에 미리 저장)    | 불가능 (질문이 들어올 때마다 실시간 연산 필요)     |
| 속도 및 정확도      | 매우 빠름 / 상대적으로 정확도 낮음          | 연산량 많고 느림 / 정확도 매우 높음                |
| RAG 파이프라인 역할 | 1차 대규모 후보군 검색 (Retrieval, Top-100) | 1차 후보군 정밀 재정렬 (Re-ranking, Top-5)         |

한 줄 요약: RAG의 Cross-Encoder는 질문과 문서를 하나로 묶어 트랜스포머 인코더로 깊은 토큰 간 상호작용을 계산한 뒤, `[CLS]` 벡터 위에 로지스틱 회귀(Linear + Sigmoid)를 얹어 `0~1` 관련성 확률로 문서를 재정렬(Re-ranking)하는 모델이다.

**이해 잘못한 부분 / 피드백**

정확히 짚은 부분: Cross-Encoder가 트랜스포머 인코더(BERT, RoBERTa 등)의 출력 위에 로지스틱 회귀(Logistic Regression)와 동일한 형태의 분류기(Classification Head: Linear + Sigmoid)를 얹어 `0~1` 사이의 관련성 확률을 산출한다는 핵심 직관은 완전히 정확하다.

추가로 짚고 넘어갈 실무 디테일 (트레이드오프 및 예외):

- 임베딩 사전 계산 불가 (Latency): 질문(Query)과 문서(Document)를 `[CLS] Q [SEP] D [SEP]` 형태로 묶어 동시에 Self-Attention을 태우므로, 문서 벡터를 DB에 미리 인덱싱할 수 없다. 추론 시 후보 문서 $N$개마다 인코더 순전파를 $N$번 수행해야 하므로 1차 검색(Retrieval)에는 쓸 수 없고, 상위 20~100개만 추려 재정렬하는 리랭킹(Re-ranking) 단계에만 사용해야 한다.
- 토큰 길이 제한: 질문과 문서가 하나의 입력 시퀀스로 합쳐지므로 모델의 최대 토큰 한도(예: BERT 계열 512 토큰, BGE-Reranker-v2-m3 등 최신 모델 8,192 토큰)를 함께 나눠 써야 한다. 긴 청크(Chunk) 사용 시 문서 뒷부분이 잘릴 수 있다.
- 학습 손실 함수 확장: 기본은 이진 분류(BCE Loss)이지만, 실제 고성능 리랭커(예: bge-reranker, Cohere Rerank)는 후보 문서들 간의 상대적 순위를 더 정밀하게 학습하기 위해 ListNet / InfoNCE 계열의 Listwise Cross-Entropy Loss를 함께 활용하기도 한다.

**7장 1강 : 평가셋 설계 원칙 적용 (1)**

> 교재 · 7장 1강

표준 평가지 (**골든셋**, Golden Set)의 구성은 다음과 같다.

0. 질문 유형
1. 질문 (Question)
2. 모범 정답 (Ground Truth)
3. 근거 문서 (Context)

### 1. RAG 평가셋 설계 목적 및 지표 연계

- 도메인 리스크 기반 검증 강도 설정:
  - 일반 안내/FAQ: 응답 유창성 및 전반적 관련성 중심의 허용적 임계치 적용
  - 법률·금융·의료 규정: 사실성(Faithfulness) 및 환각 억제에 엄격한 임계치(예: Faithfulness 0.95 이상) 적용
- 파이프라인 단계별 채점 지표 연계 (예: RAGAS, TruLens 프레임워크 기준):
  - 검색(Retrieval) 평가: Context Precision(상위 검색 청크 내 정답 포함 비율), Context Recall(모범 정답 도출에 필요한 근거 청크 회수율) → `Question + Context + Ground Truth`로 측정
  - 생성(Generation) 평가: Faithfulness(생성 답변이 검색된 Context에만 근거하는지 검증), Answer Relevance(답변이 사용자 질문 의도에 부합하는지 검증) → `Question + Context + Generated Answer`로 측정

### 2. 골든셋의 3대 핵심 요소

- 질문 (Question): 실제 유저 페르소나가 입력할 법한 자연어 질의 (구어체, 약어, 오탈자 등 현실적 노이즈 포함)
- 모범 정답 (Ground Truth): 평가의 정답 기준선(Baseline)으로, 주관적 수식어를 배제하고 핵심 팩트와 논리 구조를 명확히 기술한 이상적 답변
- 근거 문서 (Ground Truth Context): 모범 정답을 도출하는 데 필수적인 원본 문서 청크 집합. 검색 실패(원하는 청크를 못 찾음)와 생성 실패(청크는 찾았으나 LLM이 잘못 요약/왜곡함)를 분리 진단하는 핵심 기준이 된다.

### 3. 질의 유형(Query Type) 커버리지 설계

| 질의 유형                                    | 정의 및 특징                                                          | 검증 목표                                                              | 권장 비중 (예시) |
| -------------------------------------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------- |
| 단순 사실 확인 (Single-hop)                  | 단일 문서 청크 내에 명시된 팩트, 수치, 정의를 직접 추출하는 문항      | 기본적인 임베딩·키워드 검색 정확도 및 정확한 정보 추출 능력            | 40~50%           |
| 복합 추론 질문 (Multi-hop)                   | 서로 다른 2개 이상의 청크를 결합해 비교·계산·인과관계를 도출하는 문항 | Top-K 검색 포괄성(Recall) 및 LLM의 다중 문맥 종합 추론 능력            | 30~35%           |
| 문서 외 함정 질문 (Out-of-Domain / Negative) | 제공된 지식베이스에 정답이 없는 질문 또는 전제가 틀린 질문            | 사전 학습 지식을 끌어오는 환각(Hallucination) 억제 및 적절한 거절 능력 | 15~25%           |

### 4. 평가셋 설계서 구조화 및 LLM 자동 검증 워크플로우

- 표 형태 구조화 스키마: `ID | Query_Type | Difficulty | Question | Ground_Truth | Ground_Truth_Context | Expected_Behavior(답변/거절)` 컬럼으로 표준화하여 버전 관리(CSV/JSON/Parquet)를 수행한다.
- LLM 기반 자동 검증 (LLM-as-a-Judge) 단계:
  1. 유형 분류 검증: 작성된 질문이 의도한 `Query_Type`(단순/복합/함정) 조건을 충족하는지 LLM으로 태깅 및 교차 검증한다.
  2. 정답 도출 가능성(Groundedness) 검증: `Ground_Truth`의 모든 문장이 실제로 `Ground_Truth_Context`만으로 논리적 비약 없이 도출되는지 자동 판별하여 불량 문항을 필터링한다.

한 줄 요약: RAG 골든셋은 질문-모범 정답-근거 문서 3요소를 단순 사실·복합 추론·문서 외 함정 유형으로 균형 있게 구성하여, 검색 실패와 생성 환각을 분리 진단하고 정량적으로 개선하기 위한 표준 정답지이다.

**이해 잘못한 부분 / 피드백**

잘 정리된 부분: RAG 평가에서 검색(Retrieval) 단계와 생성(Generation) 단계의 실패 원인을 분리 진단하기 위해 질문(Question) - 모범 정답(Ground Truth) - 근거 문서(Context)의 3요소를 세트로 묶어야 한다는 핵심 원리가 정확히 잡혀 있다.

실무 설계 시 놓치기 쉬운 함정 (Pitfalls):

- 합성 데이터(Synthetic Data) 편향: LLM으로 문서에서 질문을 역생성할 때, 원문 표현을 그대로 베낀 키워드 매칭형 질문만 양산하기 쉽다. 실제 서비스 로그에서 발생하는 동의어·구어체·모호한 표현을 반드시 혼합해야 한다.
- Negative(문서 외 함정 질문) 비율 누락: 실제 운영 환경에서는 지식베이스 밖의 질문이 빈번하게 유입된다. 전체 골든셋 중 최소 15~20% 이상을 문서 외 질문(Unanswerable)으로 배정해야 "모른다"고 답하는 거절(Refusal) 능력을 검증할 수 있다.
- 근거 문서 단위(Chunk ID vs. Raw Text) 불일치: 청킹 전략(Chunk Size, Overlap)을 변경할 때마다 기존 텍스트 기반 Context 매칭이 깨질 수 있으므로, 평가셋에는 원본 문서 ID와 핵심 발췌문(Span)을 함께 기록해 두는 것이 유지보수에 유리하다.

**7장 2강 : 평가셋 구축 (1)**

> 교재 · 7장 2강

튜터 `06_01.ipynb`는 사내 규정 3문서를 넣고, 구조화 출력으로 골든셋 샘플 4개를 만든다. 질문 유형은 단순 사실, 복합 추론, 문서 외 함정이다. 코드는 튜터 GitHub 원본이다.

```python
from typing import List
from pydantic import BaseModel, Field

from langchain.chat_models import init_chat_model
from langchain_core.documents import Document
from langchain_core.prompts import PromptTemplate

"""
표준 정답지(Golden Set)
- 질문 (user_input)
- 모범정답 (reference)
- 근거문서 (retrieved_contexts)
"""

class RagEvalSample(BaseModel):
    user_input: str = Field(description="제공된 근거 문서들을 바탕으로 사용자가 질의할 법한 질문")
    reference: str = Field(description="근거 문서에 기반한 모범정답(Ground Truth)")
    retrieved_contexts: List[str] = Field(
        description="해당 질문과 정답을 도출하는 데 실제로 사용된 1개 이상의 원본 문서 내용"
    )

class RagEvalDataset(BaseModel):
    samples: List[RagEvalSample] = Field(
        description="근거 문서로부터 생성된 평가 샘플 목록"
    )

source_docs: List[Document] = [
    Document(
        page_content="원격 근무 지원 규정: 주 2회 재택근무가 가능하며, 원격 근무 당일은 오전 9시까지 사내 메신저 근태 채널에 출근 등록을 완료해야 합니다.",
        metadata={"source": "근태규정.pdf", "chunk_id": 1}
    ),
    Document(
```

**7장 3강 : RAGAS 검색 지표 측정 (1)**

> 교재 · 7장 3강

6장에서 본 정밀도·재현율 정의는 [11-18 TIL](./20261118%20TIL.md)에 있다. 오늘은 **RAGAS**가 같은 이름을 어떻게 계산하는지를 본문으로 채운다.

### 1. 문맥 정밀도 (Context Precision)

**Context Precision**은 검색된 상위 $K$개의 청크 중 모범 정답(Ground Truth) 도출에 실제로 유용한 청크가 얼마나 높은 순위(Top-rank)에 배치되었는지 평가하는 순위 기반 지표다.

- 계산 원리 (Mean Precision@K):
  - LLM 심사관이 검색된 각 청크($k = 1, \dots, K$)마다 모범 정답 도출에 기여했는지 여부($v_k \in \{0, 1\}$)를 판별한다.
  - 정답 청크가 발견된 위치($k$)까지의 누적 정밀도($\text{Precision@k}$)를 계산해 평균을 낸다.

$$\text{Context Precision@K} = \frac{\sum_{k=1}^{K} (\text{Precision@k} \times v_k)}{\text{상위 } K\text{개 내 실제 관련 청크 총수}}$$

- 실무적 의미: 점수가 낮다면 임베딩 모델의 변별력이 부족하거나, 노이즈 청크가 상위를 차지해 LLM의 컨텍스트 윈도우 낭비 및 답변 품질 저하를 유발하고 있음을 의미한다. 해결책은 Chunk Size 축소, Hybrid Search(BM25 + Dense) 도입, Reranker 적용이다.

### 2. 문맥 재현율 (Context Recall)

**Context Recall**은 모범 정답(Ground Truth)을 구성하는 모든 핵심 사실(Claim)들이 검색된 문맥(Retrieved Contexts) 안에 누락 없이 얼마나 포함되어 있는지 평가하는 지표다.

- 계산 원리 (Sentence/Claim Attribution):
  - LLM 심사관이 모범 정답(Ground Truth)을 개별 문장(또는 원자적 사실 단위)으로 분해한다.
  - 분해된 각 문장이 검색된 청크들의 내용으로부터 추론·귀속(Attributable)될 수 있는지 판별한다.

$$\text{Context Recall} = \frac{\text{검색된 문맥에서 근거를 찾을 수 있는 Ground Truth 문장 수}}{\text{Ground Truth의 전체 문장 수}}$$

- 실무적 의미: 점수가 낮다면 LLM이 아무리 뛰어나도 재료(근거) 자체가 전달되지 않아 환각(Hallucination)이나 "모른다"는 오답을 낼 수밖에 없는 상태다. 해결책은 Top-$K$ 개수 증가, Query Expansion(Multi-Query / HyDE), 청킹 전략 재설계다.

### 3. Context Precision vs. Context Recall 비교

| 구분                  | 문맥 정밀도 (Context Precision)                        | 문맥 재현율 (Context Recall)                                   |
| --------------------- | ------------------------------------------------------ | -------------------------------------------------------------- |
| 핵심 질문             | 가져온 문서들이 쓸모 있고, 핵심 문서가 맨 위에 있는가? | 정답을 만드는 데 필요한 근거를 하나도 안 놓치고 다 가져왔는가? |
| 측정 대상 (분모 기준) | 검색기(Retriever)가 반환한 상위 K개 청크의 순위 품질   | 모범 정답(Ground Truth)을 구성하는 전체 문장(사실) 수          |
| 감점 요인             | 불필요한 노이즈 문서 유입, 핵심 문서의 하위 순위 배치  | 다중 문서 추론(Multi-hop) 시 일부 근거 청크 누락               |
| K값 증가 시 경향      | 노이즈 증가로 하락 경향                                | 근거 포함 확률 증가로 상승 경향                                |
| 주요 개선 기법        | Reranker(Cross-Encoder) 적용, 메타데이터 필터링        | Top-K 확대, Query Rewriting, 동의어/키워드 하이브리드 검색     |

한 줄 요약: RAGAS의 검색 평가는 필요한 근거를 빠짐없이 챙겼는지 보는 Context Recall(누락 방지)과, 그중 진짜 핵심 근거를 최상단에 깔끔하게 배치했는지 보는 Context Precision(순도 및 순위)의 균형을 맞추는 과정이다.

**이해 잘못한 부분 / 피드백**

잘 정리된 부분: RAGAS 검색 평가의 양대 축을 순도 및 상위 배치(Context Precision)와 누락 방지(Context Recall)로 명확히 구분하고, 각각 `0~1` 사이 점수로 환산된다는 핵심 개념을 정확하게 정리했다.

실무 및 수식 관점의 보완 포인트 (Pitfalls):

- Context Precision은 단순 비율이 아니라 순위 가중 평균(Precision@K)이다. 단순히 검색된 5개 중 2개가 정답이라고 `2/5 = 0.4`가 되는 것이 아니다. 정답 문서가 1위, 2위에 몰려 있을 때와 4위, 5위로 밀려났을 때 점수가 크게 달라진다(LLM의 Lost-in-the-Middle 현상 방지 목적).
- Context Recall은 청크 개수가 아니라 모범 정답 문장(Claim) 단위로 계산된다. 검색된 청크 ID를 직접 비교하는 방식(Traditional IR)과 달리, RAGAS는 LLM-as-a-Judge를 통해 모범 정답(Ground Truth)을 문장/사실 단위로 쪼갠 뒤, 각 문장이 검색된 문맥(Retrieved Contexts)에 의해 뒷받침(Attributed)되는지 비율을 계산한다.
- 트레이드오프(Trade-off) 관계: 검색 개수($K$)를 무작정 늘리면 필요한 근거가 포함될 확률이 높아져 Context Recall은 상승하지만, 불필요한 노이즈 청크가 함께 유입되어 Context Precision은 급락한다. 따라서 1차 검색(Bi-Encoder)으로 $K$를 넉넉히 잡아 Recall을 확보한 뒤, Cross-Encoder(Reranker)로 상위 순위를 재정렬해 Precision을 끌어올리는 2단계 파이프라인을 사용한다.
