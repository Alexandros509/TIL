```python
import os
from dotenv import load_dotenv
from langchain_openai import OpenAIEmbeddings
from langchain_postgres.vectorstores import PGVector
from langchain_core.documents import Document

load_dotenv()

embedding_model = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

connection_url = os.getenv("DATABASE_URL")

vector_store = PGVector(
    embeddings=embedding_model,
    collection_name="integrated_university_rules",
    connection=connection_url,
    use_jsonb=True
)

initial_documents = [
    Document(
        page_content="[도서관 규정] 학부생은 최대 5권까지 14일간 대출 가능합니다.",
        metadata={"source": "rules_library.txt", "category": "library", "year": 2026}
    ),
    Document(
        page_content="[장학금 규정] 직전 학기 평점 3.5 이상 시 장학금 대상입니다.",
        metadata={"source": "rules_scholarship.txt", "category": "scholarship", "year": 2026}
    )
]

vector_store.add_documents(initial_documents)
```

**3장 2강 : 벡터 검색 실행·결과 분석 (1)**

> 교재 · 3장 2강

- `similarity_search_with_score`는 문서 본문과 벡터 간 거리 점수를 한 번에 돌려준다
- **코사인 거리**는 코사인 유사도를 거리로 바꾼 값(\(1 -\) 유사도)이다. 0에 가까울수록 비슷하고, 숫자가 커질수록 관련성이 떨어진다
- PGVector 기본 지표는 코사인 거리라서, 1에 가까울수록 비슷한 유사도 스케일과 혼동하지 않아야 한다

| 지표 구분                   | 계산 수식  | 완벽 일치 시 값 | 완전 불일치 시 값 | 수치 해석 방법         |
| --------------------------- | ---------- | --------------- | ----------------- | ---------------------- |
| 코사인 유사도               | cos(θ)     | 1.0             | 0.0 또는 -1.0     | 높을수록 관련성이 높음 |
| 코사인 거리 (PGVector 기본) | 1 - cos(θ) | 0.0             | 1.0 이상          | 낮을수록 관련성이 높음 |

구간 기준(교안·오늘 필기 동일):

- 우수 구간 (0.0 ~ 0.35): 질문의 핵심 의도와 문서의 내용이 직접적으로 부합하는 상태
- 보통 구간 (0.35 ~ 0.60): 주제는 관련되어 있으나 세부 조건이나 키워드가 일부 일치하는 상태
- 주의 구간 (0.60 초과): 의미적 연관성이 거의 없으며 노이즈로 작용할 가능성이 높은 상태

튜터 `03_01`에서 같은 질의로 거리를 확인한 결과다. 주석도 코사인 거리는 0에 가까울수록 유사하다고 적혀 있다.

**3장 3강 : Top-k 설정과 score threshold (1)**

### 1. Top-k

- 질문과 가장 유사한 문서를 몇 개까지 가져올지 정하는 **Top-k** 파라미터
- 수많은 후보 중 상위 \(k\)개만 추려서 LLM 프롬프트에 넣음

트레이드오프

- \(k\)가 너무 크면 → 노이즈 증가, 토큰 낭비, 핵심 문맥 희석
- \(k\)가 너무 작으면 → 필요한 근거 누락 → 환각 위험
- 경험적 기준: 단답형 `k=2~3`, 종합형 `k=4~6`

### 2. Score Threshold

- 검색된 문서가 통과해야 하는 최소 유사도 기준선이 **Score Threshold**다
- 관련 없는 문서가 LLM으로 들어가는 것을 차단
- DB에 답이 없는 질문일 때 특히 유용

### 3. 코사인 거리 기준 해석 (PGVector 등)

코사인 거리 = (1 - 유사도) → 작을수록 더 유사

| 거리 점수   | 구간      | 판단                                    |
| ----------- | --------- | --------------------------------------- |
| 0.00 ~ 0.35 | 우수      | 핵심 의도와 일치 → 문맥으로 주입        |
| 0.35 ~ 0.60 | 보통      | 부분 관련 → Top-k 조건과 함께 선별 사용 |
| 0.60 초과   | 주의/탈락 | 노이즈로 판단 → 제외                    |

한 줄 요약: Top-k는 “몇 개 가져올지”, Score Threshold는 “얼마나 유사한 것만 남길지”를 정하며, 코사인 거리에서는 작을수록 더 좋은 점수다.

> 교재 · 3장 3강

- PGVector는 코사인 거리를 기본 지표로 쓰므로, 설정한 임계값보다 거리 점수가 큰 문서는 탈락시킨다
- 교안 실습의 거리 임계 예시는 0.60이다
- 검색기 설정은 `search_kwargs`에 모은다. 튜터 `03_01` 주석:

```python

    "k": 3,  Top-k, 유사도 기준 상위 3개 추출
    "filter": { .... }, metadata 필터링 조건...
    "score_threshold": ..., -> 필수로 search_type="similiarity_score_threshold" 설정이 필수
}
"""
```

`similarity_search_with_relevance_scores`는 1에 가까울수록 유사한 0~1 점수를 쓴다.
튜터 코드의 `SCORE_THRESHOLD`는 0.7이다. 주석은 data >= 0.7이라고 적었지만, 실제 인자는 1에서 그 값을 뺀 0.3이 들어간다.

```python
# similarity_search_with_relevance_scores(..) : 유사도 임계치를 설정힐 수 있음
SCORE_THRESHOLD = 0.7

# 1에 가까울 수록 유사 0~1
searched_docs2 = vector_store.similarity_search_with_relevance_scores(
    query=query,
    score_threshold=1 - SCORE_THRESHOLD # data >= 0.7
)

for doc, score in searched_docs2:
    print(f"score={score:.4f}, doc={doc}")
```

**3장 4강 : 메타데이터 필터링 검색 (1)**

### 1. 메타데이터 필터링이란?

- 문서에 붙은 속성 정보(이름표)를 기준으로 검색 후보를 미리 좁히는 **메타데이터 필터링** 기술
- 예: 카테고리, 작성 연도, 담당 부서, 버전 등
- 벡터 유사도만 쓸 때 생기는 모호함을 줄임

### 2. 왜 필요한가? (유사도 검색의 한계)

- 벡터 검색은 의미적 유사성만 봄
- “2023년 규정”과 “2024년 규정”처럼 문장 구조가 비슷하면 구버전을 잘못 가져올 위험 있음
- 이런 사실(Fact) 조건은 메타데이터로 명확히 걸러야 함

### 3. Pre-filtering의 장점

- **Pre-filtering**은 벡터 거리를 계산하기 전에 메타데이터 조건을 먼저 적용한다
- 조건에 맞지 않는 문서는 계산 대상에서 즉시 제외
- 결과: 검색 속도 ↑ + 정확도 ↑

### 4. PGVector 필터 문법 (JSONB)

PGVector는 메타데이터를 JSONB로 저장한다.

| 유형      | 문법 예시                                   |
| --------- | ------------------------------------------- |
| 단일 조건 | `filter={"category": "장학"}`               |
| 다중 조건 | `filter={"category": "장학", "year": 2024}` |

여러 조건을 동시에 만족하는 문서만 대상으로 유사도 검색을 수행한다.

한 줄 요약: 메타데이터 필터링은 벡터 검색 전에 사실 조건으로 후보를 미리 줄여, 정확도와 속도를 동시에 높이는 기술임.

**3장 5강 : 검색 문맥 주입 프롬프트 설계 (1)**

### 1. 문맥 주입(Context Injection)이란?

- AI에게 참고 문서를 지침과 함께 명확히 전달하는 **문맥 주입** 기술
- 자체 학습 지식에 의한 왜곡·환각을 차단하는 목적

### 2. 목적과 환각 제어

- 외부 지식 강제: 오래된 내부 지식 대신, 프롬프트에 입력된 최신 문서를 최우선 기준으로 사용하도록 함
- 답변 범위 한정: “제시된 문서 내용 외에는 답변하지 말 것” 제약을 걸어 허위 정보 생성 방지

### 3. RAG 프롬프트 템플릿의 3요소

| 요소     | 역할                                                        |
| -------- | ----------------------------------------------------------- |
| System   | AI 역할, 답변 어조, “참고 문서 외 임의 답변 금지” 규칙 명시 |
| Context  | 검색기로 추출된 복수의 문서 본문이 들어가는 영역            |
| Question | 사용자가 실제로 입력한 자연어 질문                          |

한 줄 요약: 문맥 주입은 검색된 문서와 제약 지침을 함께 넣어 AI가 자체 지식이 아닌 제공된 문맥만으로 답하게 만드는 기술임.

> 교재 · 3장 5강

- 여러 `Document`의 본문을 연결 기호로 묶어 하나의 텍스트 문맥으로 만드는 과정이 문맥 포맷팅이다
- `ChatPromptTemplate`은 시스템 지시와 사용자 입력을 분리해 동적으로 메시지를 조립한다
- 프롬프트가 너무 길어지면 모델이 중간 영역 사실을 놓치는 Lost in the Middle 현상이 있다


시스템 메시지에 참고 문서만 근거로 쓰라는 제약이 들어가고, `{context}`와 `{question}`이 각각 Context·Question 슬롯이다.

**3장 6강 : 검색→생성 체인 통합 (1)**

### 1. LCEL 검색→생성 통합 체인이란?

- 사용자의 단일 입력값을 검색기와 프롬프트 슬롯으로 나누어 보낸 뒤, 모델 답변까지 한 번에 도출하는 연결 기술
- **LCEL**(LangChain Expression Language)로 구현

### 2. 단일 입력의 분기와 병합 구조

- 입력 분기: 하나의 질문 텍스트가 검색기 경로와 질문 보존 경로로 동시에 진입
- 문맥 생성 경로: 질문 → Retriever로 문서 검색 → 포맷팅 함수로 묶어 `{context}`에 전달
- 질문 유지 경로: `RunnablePassthrough`로 질문 텍스트를 수정 없이 그대로 `{question}`에 전달
- 파이프 연산자(`|`): 선행 작업의 결과값을 후행 작업의 입력값으로 넘겨 전체 과정을 하나의 체인으로 연결

한 줄 요약: LCEL 체인은 하나의 질문을 검색 경로와 질문 유지 경로로 분기한 뒤 `|`로 합쳐, 검색부터 답변 생성까지 한 번에 처리하는 파이프라인임.

> 교재 · 3장 6강

- 통합 체인은 검색, 포맷팅, 프롬프트, 모델, 출력 파서를 파이프로 이은 파이프라인이다
- `StrOutputParser`는 모델이 낸 메시지에서 순수 문자열만 추출한다

튜터 `03_01` 체인과 출력이다.

**3장 7강 : 출처 표기·응답 후처리 (1)**

### 1. 출처 표기와 문서 전달 원리

- 답변 생성 마지막까지 본문 + 메타데이터(꼬리표)를 파이프라인 전체에 걸쳐 온전히 전달하는 **출처 표기**
- 모델이 임의 추측하지 않고 “몇 년도, 어떤 문서의 몇 조” 같은 명확한 출처와 함께 답변하도록 함

### 2. 문서 메타데이터 활용

- 메타데이터: 문서 제목, 생성 연도, 카테고리 등 추가 정보
- 검색기(Retriever)가 찾아낸 원본 데이터를 버리지 않고, 체인 마지막 단계에서 답변과 함께 출력

### 3. 검색과 출처 분기 구조

- `RunnablePassthrough`로 텍스트 문맥과 원본 문서 리스트를 분기 처리
- 텍스트로 합쳐진 문맥 → 프롬프트로 들어가 답변 생성
- 원본 문서 리스트 → 그대로 보존되어 출처 표기에 사용

### 4. RAG 응답 후처리

- 체인의 결과물을 사용자가 읽기 쉽도록 가공하는 작업
- 응답 분리: 언어 모델이 작성한 ‘생성 답변’과 시스템이 유지한 ‘출처 리스트’를 나눔
- 시각적 정렬: 출처 리스트를 순서대로 나열하여 텍스트 형태로 깔끔하게 조립

한 줄 요약: 출처 표기는 메타데이터를 체인 끝까지 보존한 뒤, 답변과 출처를 분리·포맷팅하는 후처리로 신뢰도 높은 응답을 만드는 과정임.

**4장 1강 : 키워드 검색 vs 벡터 검색 (1)**

키워드 검색은 글자가 맞는지, 벡터 검색은 의미가 가까운지를 본다. 어제 짧은 로드맵은 [11-16 TIL 4장 1강](./20261116%20TIL.md)을 본다. 오늘 구현과 TF·IDF·토크나이저 상세는 아래 5장 1강에 둔다.

**5장 1강 : BM25 키워드 검색 구현 (1)**

### 1. BM25 알고리즘이란?

- **BM25**는 문서 안에 특정 단어가 얼마나 자주 나오는지(TF)와 전체 문서들 사이에서 그 단어가 얼마나 희귀한지(IDF)를 종합 계산해 순위를 매기는 대표적인 키워드 검색 알고리즘
- 문장의 뉘앙스나 의미를 추론하기보다, 고유명사·전문 용어가 본문에 실제로 존재하는지 빠르고 정확하게 찾는 데 탁월

### 2. 키워드 검색의 원리와 3대 계산 요소

- 단어 빈도 (TF, Term Frequency): 검색 단어가 한 문서 안에 자주 등장할수록 해당 문서의 관련도 점수 상승
- 역문서 빈도 (IDF, Inverse Document Frequency): 여러 문서에 너무 흔하게 나오는 일반 단어는 가중치를 낮추고, 희귀한 핵심 단어에 높은 가중치 부여
- 문서 길이 정규화: 문서가 비정상적으로 길어서 단어가 많이 포함된 경우 점수가 과도하게 높아지지 않도록 전체 길이에 비례해 보정

### 1. TF (Term Frequency, 단어 빈도)

- **TF**는 특정 단어가 한 문서 안에 얼마나 자주 등장하는지 나타내는 값
- 해당 단어가 문서에 많이 나올수록 TF 점수 ↑
- 의미: “이 문서가 그 단어와 얼마나 관련 있는가”를 보는 지표

### 2. IDF (Inverse Document Frequency, 역문서 빈도)

- **IDF**는 특정 단어가 전체 문서들 사이에서 얼마나 희귀한지 나타내는 값
- 많은 문서에 흔하게 나오는 단어(예: “있다”, “그리고”) → IDF 점수 ↓
- 일부 문서에만 나타나는 희귀한 단어(예: 고유명사, 전문 용어) → IDF 점수 ↑
- 의미: “이 단어가 얼마나 중요한 식별 정보인가”를 보는 지표

### 3. TF와 IDF의 관계

- TF만 보면 흔한 단어도 점수가 높아질 수 있음
- IDF로 흔한 단어의 가중치를 낮추고 희귀 단어의 가중치를 높여 보완
- BM25는 이 둘 + 문서 길이 정규화를 합쳐 최종 순위를 결정

한 줄 요약: TF는 문서 안 단어 출현 빈도, IDF는 전체 문서에서 단어의 희귀도를 나타내며, 둘이 합쳐져 키워드 검색 점수를 만든다.

### 3. 토크나이저(Tokenizer)의 역할

- 긴 텍스트 문장을 검색 시스템이 분석할 수 있도록 가장 작은 단위인 토큰(단어) 목록으로 쪼개는 **토크나이저**
- 분절 기준: 띄어쓰기 공백 기준 또는 한국어 형태소 단위로 분절하여 BM25에 단어 목록 전달

한 줄 요약: BM25는 TF·IDF·문서 길이 정규화를 종합해 단어 출현 기반 순위를 매기는 키워드 검색 알고리즘이며, 토크나이저가 문장을 단어 목록으로 쪼개 입력한다.

**5장 3강 : RRF·가중치 튜닝 (1)**

### 1. RRF (Reciprocal Rank Fusion)이란?

- **RRF**(Reciprocal Rank Fusion)는 점수 측정 기준이 완전히 다른 여러 검색기를 순위(등수) 기준으로 공정하고 균형 있게 합쳐주는 알고리즘
- BM25 점수(0~수십)와 벡터 유사도(0~1)는 직접 비교 불가 → 절대 점수 대신 순위의 역수를 이용해 단일 순위표로 통합

### 2. 점수 체계 불일치와 RRF의 필요성

- 점수 체계의 불일치: BM25는 문장 길이·단어 빈도에 따라 점수가 크게 변동, 벡터 유사도는 0~1 범위
- RRF 해결책: 절대 점수를 배제하고 각 검색기에서의 등수를 역수로 변환해 합산

$$
\text{RRF}(d) = \sum_{i} \frac{1}{k + \text{rank}_i(d)}
$$

- 상수 \(k\)의 역할: 일반적으로 \(k=60\)을 적용해 1위와 2위의 점수 차이가 과도하게 벌어지는 것을 방지

### 3. 질의 유형에 따른 가중치 분배 전략

- 키워드 중심 질의: 사규 명칭, 에러 코드, 고유 시스템명 → BM25 가중치 상향 (`weights=[0.8, 0.2]`)
- 의미 중심 질의: 의도·서술형, 단어가 기억 안 날 때 → 벡터 가중치 상향 (`weights=[0.2, 0.8]`)

| 질의 유형          | 추천 가중치 (BM25 : Vector) | 주요 특징                                                  |
| ------------------ | --------------------------- | ---------------------------------------------------------- |
| 고유명사·약어 중심 | 0.8 : 0.2 또는 0.7 : 0.3    | 특정 단어가 본문에 반드시 존재해야 할 때 효과적            |
| 일반적인 균형 검색 | 0.5 : 0.5                   | 단어 일치와 의미 유사도를 균등하게 고려                    |
| 의도·서술형 뉘앙스 | 0.2 : 0.8 또는 0.3 : 0.7    | 단어가 일치하지 않아도 맥락적 동의어를 찾아야 할 때 효과적 |

한 줄 요약: RRF는 점수 체계가 다른 검색기들을 순위의 역수로 공정하게 합치고, 질의 유형에 따라 BM25와 Vector 가중치를 조절하는 하이브리드 검색 기법임.

### 가중치가 적용된 RRF 공식

공식

$$
\text{score}(d) = \sum_{i} w_i \cdot \frac{1}{k + \text{rank}_i(d)}
$$

- `w_i`: 각 검색기 가중치 (예: BM25 0.8, Vector 0.2)
- `k`: 보통 60
- `rank_i(d)`: i번째 검색기에서 문서 d의 순위

### 실제 계산 예시

가정:

- \(k = 60\)
- 가중치: BM25 = 0.7, Vector = 0.3
- 문서 A, B 두 개

| 문서 | BM25 순위 | Vector 순위 |
| ---- | --------- | ----------- |
| A    | 1         | 4           |
| B    | 3         | 1           |

문서 A 계산

공식

$$
\begin{align*}
\text{BM25 기여} &= 0.7 \times \frac{1}{60 + 1} = 0.7 \times \frac{1}{61} \approx 0.011475 \\
\text{Vector 기여} &= 0.3 \times \frac{1}{60 + 4} = 0.3 \times \frac{1}{64} \approx 0.004688 \\
\text{최종 score} &\approx 0.011475 + 0.004688 = 0.016163
\end{align*}
$$

문서 B 계산

공식

$$
\begin{align*}
\text{BM25 기여} &= 0.7 \times \frac{1}{60 + 3} = 0.7 \times \frac{1}{63} \approx 0.011111 \\
\text{Vector 기여} &= 0.3 \times \frac{1}{60 + 1} = 0.3 \times \frac{1}{61} \approx 0.004918 \\
\text{최종 score} &\approx 0.011111 + 0.004918 = 0.016029
\end{align*}
$$

이 경우 문서 A가 약간 더 높은 점수를 받아 최종 1위가 됨.

한 줄 요약: 가중치 RRF는 각 검색기의 \(w_i / (k + \text{rank})\)를 더해 최종 점수를 만들며, 위 예시처럼 순위에 가중치를 곱해 합산한다.
