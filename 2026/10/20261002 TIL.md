**2장 2강 : 특수 타입과 타입 추론 메커니즘**

### 1. 특수 타입 (any, unknown, never)

- 타입을 명시하기 어려운 특수 상황에 쓰는 규격

`any`

- 컴파일 시 타입 체크 X
- 모든 타입이 가능
- 타입 오류 체크 X → 런타임 오류 가능성 ↑
- 지양

~~~typescript
let flexibleValue: any = "정산 완료";
flexibleValue = 10000;
flexibleValue = true;
flexibleValue.calculateTotalScores(); // 컴파일은 통과할 수 있음
~~~

`unknown`

- 모든 타입이 가능
- 로직 상에서 타입을 알 수 있는 코드가 반드시 필요
  - 없으면 → 컴파일 시 오류
- any보다는 타입 안정성이 있다
- **타입 좁히기**(Type Narrowing): 조건문으로 타입을 입증한 블록 안에서만 접근 허용

> 교재 · 2장 2강

| 검증 방식 | 대상 데이터 | 설명 |
| --- | --- | --- |
| `typeof` | 원시 타입 | string, number, boolean 등 판별 |
| `Array.isArray()` | 배열 | 배열 형식인지 검증 |
| 사용자 정의 타입 가드 | 객체·커스텀 | `is` 키워드로 속성 구조 검증 |

| 비교 항목 | any | unknown |
| --- | --- | --- |
| 값의 할당 | 모든 타입 대입 가능 | 모든 타입 대입 가능 |
| 속성·메서드 접근 | 검사 없이 즉시 가능 | 좁히기 전 접근 불가 (컴파일 에러) |
| 안전성 | 낮음 | 높음 (사전 검증 강제) |

- any는 정적 분석을 무력화 → 정체를 모를 때는 unknown → 좁히기

`never`

- 값 반환 X
- 함수의 실행이 정상적으로 종료되지 않음을 의미
- 의도적으로 예외 오류를 발생시키거나 무한 루프를 실행하여 반환값 자체가 존재하지 않는 구조에 지정
- 유니온이 모두 좁혀진 뒤의 남는 가지를 막는 **소진 검사**(exhaustive narrowing)에도 쓰임

> 교재 · 2장 2강

~~~typescript
function triggerSevereError(message: string): never {
    throw new Error(message);
}
function processInfiniteLoop(): never {
    while (true) {
        console.log("프로세스 실행 중");
    }
}
~~~

function aggregateScores(...scores: number[]): number {

### 2. 고차 함수 인자로 전달되는 콜백 함수의 인라인 타입 정의

> 교재 · 3장 2강

**2.1 배열 변환(map) 과정에서의 콜백 타입 지정**

~~~typescript
type square = (score: number) => number;

const scores: number[] = [90, 80, 100, 60];

function convert(scores: number[], converter: square): number[] {
    const newScores = [];
    for (const score of scores) {
        const result = converter(score);
        newScores.push(result);
    }
    return newScores;
}
convert(scores, x => x * x);
~~~

- **인터페이스**: `interface` 키워드를 사용하여 주로 객체의 구조를 정의하기 위해 만들어진 문법. 호출 시그니처로 함수 형태도 표현 가능
- 상속이나 확장성이 뛰어나 리액트(React) 등 웹 프레임워크에서 데이터를 주고받을 때 자주 쓰임

> 교재 · 4장 1강

~~~typescript
interface ProductInterface {
    code: string;
    price: number;
    brand: string;
}
const monitor: ProductInterface = {
    code: "MON-32",
    price: 350000,
    brand: "테크기어"
};
~~~

**1.3 타입 별칭과 인터페이스의 차이점**

| 구분 (기능 및 특징) | 인터페이스 (interface) | 타입 별칭 (type alias) |
| --- | --- | --- |
| 객체(object) 구조 정의 | ✅ 가능 | ✅ 가능 |
| 객체 구조 확장 (extends) | ✅ extends 사용 | ✅ 인터섹션(`&`) 사용 |
| 클래스 구현 (implements) | ✅ 가능 | ✅ 가능 |
| 선언 병합 (Declaration Merging) | ✅ 가능 | ❌ 불가능 |
| 복합 타입 정의 (유니온 / 인터섹션) | ❌ 불가능 | ✅ `\|`, `&`로 가능 |
| 함수(function) 타입 정의 | ✅ 호출 시그니처 | ✅ 함수 타입 표현식 |
| 객체 이외의 다양한 타입 표현 (원시값 등) | ❌ 불가능 | ✅ 가능 |
| typeof 연산자를 활용한 타입 추출 | ❌ 불가능 | ✅ 가능 |

### 2. 속성 제어자: readonly와 선택적 속성(?)

- `readonly`와 물음표(`?`)는 데이터의 수정 가능 여부와 필수 여부를 제어
- 객체 속성의 안전성을 보장하거나 불필요한 에러 없이 유연한 데이터 처리 가능

**2.1 readonly로 데이터 훼손 방지하기**

- 객체 생성 후 특정 속성의 값을 수정할 수 없도록 '읽기 전용'으로 잠그는 키워드
- 계좌번호, 결제 금액, 고유 ID 등 시스템 내에서 변경되지 않아야 할 필수 데이터를 보호

> 교재 · 4장 1강

~~~typescript
interface Account {
    readonly accountId: string;
    owner: string;
    balance: number;
}
const myAccount: Account = {
    accountId: "110-123-456789",
    owner: "김철수",
    balance: 50000
};
myAccount.balance = 55000;
// myAccount.accountId = "220-987-654321"; // 컴파일 에러
~~~

**2.2 선택적 속성(?)으로 유연한 객체 설계하기**

- 속성명 뒤에 물음표(`?`)를 붙여 데이터 입력의 선택 가능성을 지정하는 제어자
- 프로필 자기소개, 선택 옵션 등 값이 없을 수도 있는 상황에서 에러를 방지

> 교재 · 4장 1강

~~~typescript
type Profile = {
    userId: string;
    nickname: string;
    bio?: string;
};
const userWithBio: Profile = {
    userId: "user01",
    nickname: "코딩왕",
    bio: "안녕하세요! 프론트엔드 개발자입니다."
};
const userWithoutBio: Profile = {
    userId: "user02",
    nickname: "새내기"
};
~~~

**4장 2강 : 인덱스 시그니처와 인터페이스 확장**

### 1. 동적 속성을 다루는 인덱스 시그니처

**인덱스 시그니처**(Index Signature)

> 속성의 이름(Key)을 지정하지 않고, Key와 Value의 타입 규격만 정의하여 동적 객체를 다루는 문법

**1.1 사전에 키를 알 수 없는 동적 객체 타입 정의**

- 인덱스 시그니처: 객체에 들어올 속성 이름을 미리 확정할 수 없을 때 `[key: T]: V` 형태로 규격을 지정
- 허용 Key: `string` / `number` / symbol·템플릿 리터럴
- Key 타입의 제약: 인덱스 시그니처 Key에 유니온(`'id' | 'name'`)을 직접 지정할 수 없다. 특정 키만 제한하려면 `Record<K, T>` 또는 맵드 타입(Mapped Type)을 쓴다

string 및 number 키 타입 정의

~~~typescript
interface StudentScore {
    [subjectScore: string]: number; // 속성명은 string, 값은 number
}
const student1: StudentScore = {
    국어: 90,
    영어: 70,
};
console.log(student1);
~~~

symbol 키 타입 정의 (TypeScript 4.4+)

~~~typescript
const idSymbol: unique symbol = Symbol("id");
interface SymbolKeyObject {
    [key: symbol]: string; // 키로 symbol 타입을 허용
}
~~~

템플릿 리터럴 키 타입 정의 (TypeScript 4.4+)

~~~typescript
interface ApiEndpoints {
    [key: `get_${string}`]: string; // 키가 반드시 'get_'으로 시작
}
const apis: ApiEndpoints = {
    get_member: "회원목록...",
    // post_member: "회원가입....",
};
~~~

특정 유니온 키 제한 시 대안 (Record 활용)

~~~typescript
type AllowedKeys = "id" | "name";
const userInfo: Record<AllowedKeys, string> = {
    id: "user01",
    name: "사용자01",
    // email: "이메일"
};
console.log(userInfo);
~~~

### 2. 인터페이스 확장과 선언 병합

인터페이스 확장은 기존 정의된 속성을 바탕으로 새로운 속성을 추가하여 타입을 재사용하는 방법

**2.1 extends 키워드를 활용한 상속 구조**

~~~typescript
// 기본 상품 정보를 정의하는 부모 인터페이스
interface Product {
  id: number;     // 상품 식별 번호
  name: string;   // 상품 이름
  price: number;  // 상품 가격
}

// Product를 상속받아 전자제품 규격을 정의하는 자식 인터페이스
interface Electronics extends Product {
  warrantyMonths: number; // 보증 기간(월) 속성 추가
}

// 확장된 Electronics 인터페이스를 적용한 객체 생성
const laptop: Electronics = {
  id: 1000,
  name: "삼성노트북",
  price: 1000000,
  warrantyMonths: 12,
};
~~~

**2.2 자동 선언 병합 (Declaration Merging)**

- **선언 병합**: 동일한 이름으로 선언된 여러 인터페이스는 TypeScript 컴파일러에 의해 하나로 합침
- 동일한 인터페이스 이름으로 작성된 속성들이 하나의 타입 구조로 병합

~~~typescript
interface User {
    id: number;   // 사용자 식별 번호
    name: string; // 사용자 이름
}
interface User {
    email: string; // 이메일 속성
}
// 병합되어 id, name, email이 모두 필요
~~~
