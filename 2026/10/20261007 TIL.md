**2장 1강 : Next.js 동작 원리 & 프로젝트 구축 (1)**

> 교재 · 2장 1강

**React.js**: UI 라이브러리

왜 생겼나

- HTML DOM 조작이 많아질수록 페이지가 느려지고 UX가 떨어짐
- 페이스북(현 Meta)이 이 문제를 풀려고 만든 UI 라이브러리

빌드 결과물 (CSR)

- `index.html`, CSS, JS
- 거의 빈 HTML + JS 번들 형태

```html
<!-- index.html -->
<div id="root"></div>
<script src="bundle.js"></script>
```

- 브라우저가 JS를 받아 실행한 뒤에야 `#root` 안에 화면이 동적으로 그려짐

**CSR** (Client Side Rendering)

- 브라우저(클라이언트)에서 JS로 화면을 그리는 방식
- 장점
  - 초기 번들을 받은 뒤에는 화면 전환이 빠르다
  - 필기: 인터넷 연결이 없어도 화면이 출력 (이미 받은 HTML·CSS·JS로 화면이 동작하는 경우 — 아래 「확인」. API로 새 데이터를 받을 때는 여전히 네트워크 필요)
- 단점
  - 약간의 초기 로딩 지연 (JS 다운로드·실행)
  - 검색 반영 X (SEO 문제) — 검색 로봇이 빈 HTML을 보게 됨. 가장 큰 단점

React가 항상 빠른가

- 아님. 화면이 자주 바뀌는 동적 앱에 적합
- 거의 안 바뀌는 정적 페이지는 가상 DOM 비교 비용만 더해져 맞지 않을 수 있음

**Next.js**: React.js 기반 프레임워크 (라우팅·렌더링·빌드까지)

**SSR** (Server-Side Rendering)

1. **prerender** (Pre-render): 서버에서 번역하면서 내용이 채워진 HTML을 전송
2. **hydration**: 받은 HTML에 JS를 연결해 클릭 등 동적 특성을 반영

```html
<div id="root">
  <h1>상품 목록</h1>
  <!-- 이미 내용이 있음 -->
</div>
```

- 내용 있는 HTML이 오므로 첫 화면이 바로 보이고 검색에 반영됨
- 요청마다 서버 렌더링 → 약간의 지연·서버 부담 가능
- Next.js는 SSR만 쓰는 게 아님. 페이지마다 **SSG**(빌드 시 미리 생성)·CSR 등을 골라 쓸 수 있음

React vs Next 한눈에

| 항목        | React.js             | Next.js                  |
| ----------- | -------------------- | ------------------------ |
| 정체        | UI 라이브러리        | React 기반 프레임워크    |
| 기본 렌더링 | CSR (브라우저)       | SSR 등 (서버)            |
| 첫 화면     | JS 실행 후 표시      | 내용 있는 HTML 바로 표시 |
| SEO         | 불리                 | 유리                     |
| 화면 전환   | 빠름                 | Hydration 후 빠름        |
| 빌드 도구   | Babel + Webpack (JS) | SWC + Turbopack (Rust)   |

일반 React 경로 — JSX/TSX → **Babel** 트랜스파일러(번역) → JS

모듈·빌드·번들링

- 모듈화된 파일: 상단에 모듈1(컴포넌트), 모듈2, 모듈3 등 여러 개로 분리된 개발 파일
- **빌드**(Build): 여러 모듈을 하나로 모으는 과정
- **번들링**(Bundling): 묶어 주는 작업
- 대표 번들러: `webpack`
- 최종 결과물: 브라우저가 실행할 수 있는 정적 JS·CSS 파일 하나(또는 소수)로 병합

흐름: `.jsx` / `.tsx` 컴포넌트들 → 트랜스파일(JS로 번역) → 번들링(여러 모듈을 하나로) → 배포 가능한 파일

여러 개의 흩어진 모듈을 webpack을 통해 통합된 JS/CSS 파일로 묶어내는 번들링 과정

Next.js 경로 (성능 ↑, Rust로 개발)

- 트랜스파일: **SWC** (Speedy Web Compiler)
- 번들링: **Turbopack**

빌드 도구 비교

| 역할         | 과거 (React 기본) | Next.js                   |
| ------------ | ----------------- | ------------------------- |
| 트랜스파일러 | Babel             | SWC (Speedy Web Compiler) |
| 번들러       | Webpack           | Turbopack                 |
| 개발 언어    | JavaScript        | Rust                      |
| 속도         | 느림              | 빠름                      |

Babel·Webpack은 JS로 만들어져 프로젝트가 커질수록 번역·묶기가 느렸고, Next.js는 Rust로 다시 만든 SWC·Turbopack으로 속도를 높임

일반 React(Babel + webpack)와 Next.js(SWC + Turbopack)를 구분해서 기억

**2장 2강 : Virtual DOM & JSX/TSX 컴포넌트 (1)**

> 교재 · 2장 2강

**선언적 UI** (React): "화면이 어떤 상태여야 하는지" 결과 형태만 정의하면, 리액트가 변경 사항을 적용

- 명령형 UI (기존 JS): 화면의 특정 요소를 직접 찾아가 하나씩 변경

**가상 DOM** (Virtual DOM): 실제 화면(Real DOM)을 수정하기 전, 변경된 부분만 미리 계산해 보는 메모리상의 가벼운 JS 객체

흐름: 상태 변경 → 새 가상 DOM 생성 → 이전과 비교(diffing) → 바뀐 부분만 실제 DOM에 반영

- 메모리 안 객체 비교는 싸고, 느린 실제 DOM 조작은 최소로 모음
- 전부 비우고 다시 그리는 게 아니라, 차이가 난 부분만 골라 한 번에 업데이트

- **Diffing**: 데이터가 바뀌면 새 가상 DOM을 만들고, 이전 가상 DOM과 차이 비교
- **Reconciliation**(재조정): Diffing으로 실제 바뀐 최소한의 부분만 브라우저 화면에 반영

**JSX** (JavaScript XML): HTML과 유사한 작성 방식으로 컴포넌트 화면 구조를 표현

**TSX** (TypeScript XML / TypeScript + JSX): HTML 유사 표기 + TypeScript 타입 검사

Next.js에서는 브라우저가 TSX를 읽지 못하므로 SWC가 `React.createElement` 호출로 변환 (일반 React 수업 경로의 Babel과 구분)

TSX 작성 규칙

1. `<이름></이름>` 짝
2. 단일 태그도 끝맺음 기호 필수 — `<br />` (셀프 클로징). HTML처럼 `/` 생략하면 SyntaxError
3. 단일 루트: 변화 감지(Diffing) 효율·`React.createElement`가 한 객체만 반환 → 컴포넌트는 단일 노드(루트)로 구성
4. 실제 DOM에 노드를 남기지 않고 묶기: `<Fragment>...</Fragment>` 또는 `<>...</>`
   - 불필요한 `<div>` 남발은 DOM 오염·Flex/Grid 자식 관계를 깨뜨릴 수 있음
5. JSX 구간에서 JavaScript 코드 → `{ ... }`
6. 조건식
   - 삼항 조건: `조건 ? 참 : 거짓`
   - And 연산자(단락 회로 평가): `조건 && 출력할_요소` — 앞이 true일 때만 뒤 요소 출력
7. 주석: JSX 태그 사이는 `{/* 여러 줄 */}`이 표준. `{}` 안·여는 태그 속성 영역에서는 // 한 줄(닫는 }가 주석되지 않게 줄바꿈 필요)
8. 속성명 변환: HTML 속성 중 JS 예약어와 충돌하는 이름은 바꿔 씀 — class → `className`, for → `htmlFor`
9. 반환 타입
   - `React.JSX.Element`: JSX 요소만 반환
   - `React.ReactNode`: JSX 요소 + 다른 형태(문자열, 숫자, null 등 — 필기에는 함수·객체 등도 적음, 「확인」)

      <div>

        <br />

        {user.hasCoupon && <p>사용 가능한 10% 할인 쿠폰이 있습니다!</p>}

      </div>
    </Fragment>
  );

## 확인이 필요한 사항

⚠ CSR 「인터넷 연결이 없어도 화면이 출력」 — 초기 HTML/JS 번들은 네트워크로 받아야 함. 필기 HTML 노트: 이미 받은 리소스로 화면이 보이는 경우이며, API로 새 데이터를 받을 때는 네트워크가 필요. 2장 1강 Notion 본문이 비어 교재와 직접 대조 불가 → 추가 확인 필요

⚠ 오탈 이중 기록 — 필기 번역햄서 → 본문 번역하면서 / Defalt Formatter → Default Formatter / JSC 문법구간 → JSX 문법구간

⚠ JSX 주석 — 필기 /\* _/·// 만 적음. 교재(2.2)는 태그 사이 {/_ \*/} 표준. 태그 사이에 그냥 // 를 쓰면 화면에 글자로 출력될 수 있음
