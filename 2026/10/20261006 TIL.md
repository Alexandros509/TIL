**5장 1강 : Union, Intersection과 리터럴 타입**

> 교재 · 5장 1강

**유니온 타입** (`|`): 바 기호 기준 기재된 타입 중 하나를 만족하면 허용

- 숫자·문자열 등 여러 타입이 올 수 있는 변수 정의에 사용

~~~typescript
let userId: string | number;
userId = "user01";
userId = 1000;
console.log("사용자 ID:", userId);
~~~

객체 유니온과 공통 필드

- 서로 다른 객체 타입을 유니온으로 묶으면, 컴파일러는 모든 타입에 공통으로 존재하는 속성만 접근 허용
- 특정 타입 전용 속성에 바로 접근하면 런타임 오류 위험 → 컴파일 단계에서 차단

~~~typescript
interface CardPayment {
    amount: number;
    cardNumber: string;
}

interface BankTransfer {
    amount: number;
    bankCode: string;
}

type PaymentMethod = CardPayment | BankTransfer;

function processPayment(payment: PaymentMethod): void {
    console.log("결제 요청 금액:", payment.amount);
    // console.log(payment.cardNumber); // 공통 아님 → 컴파일 에러

    if ('cardNumber' in payment) {
        console.log("카드 번호: ", payment.cardNumber);
    } else {
        console.log("은행 코드: ", payment.bankCode);
    }
}

const myPayment: CardPayment = {
    amount: 50000,
    cardNumber: "1234-1234-1234-1234"
};
processPayment(myPayment);
~~~

**인터섹션 타입** (`&`): 지정된 모든 타입의 속성을 동시에 만족하도록 합성

- 독립적으로 정의된 타입을 결합해 확장 타입을 만들 때 활용
- 결합된 타입의 속성을 모두 갖춰야 컴파일 통과
- `string & number`처럼 양립 불가한 원시 타입 결합 → `never`

~~~typescript
type UserProfile = {
  name: string;
  email: string;
};

type UserPermissions = {
  adminLevel: number;
};

type SuperAdmin = UserProfile & UserPermissions;

const adminUser: SuperAdmin = {
  name: "사용자01",
  email: "user01@test.org",
  adminLevel: 1
};
console.log(adminUser);
~~~

~~~typescript
interface Product {
  id: number;
  name: string;
  price: number;
}

interface Inventory {
  stock: number;
  location: string;
}

type ManageableProduct = Product & Inventory;

const item: ManageableProduct = {
  id: 101,
  name: "무선 키보드",
  price: 89000,

  location: "A-12"
};
~~~

**서로소 판별 유니온** (Discriminated Union)

- 객체 타입에 공통 리터럴 태그 속성을 부여해 조건문에서 타입을 명확히 구분하는 패턴
- **판별자**(Discriminant): 타입을 구분하는 공통 속성. 서로 중복되지 않는 리터럴 값
- API 요청 상태(로딩·성공·실패)처럼 독립 상황별 데이터를 정리할 때 사용

~~~typescript
type LoadingState = {
    status: "loading";
};

type SuccessState = {
    status: "success";
    data: string[];
};

type ErrorState = {
    status: "error";
    errorMessage: string;
};

type NetworkState = LoadingState | SuccessState | ErrorState;
~~~

`switch`로 상태 분기 — 판별자 태그를 case마다 해당 객체 타입으로 제한

~~~typescript
function renderNetworkState(state: NetworkState) {
    switch (state.status) {
        case "loading":
            console.log("LoadingState");
            break;
        case "success":
            console.log("SuccessState:", state.data);
            break;
        case "error":
            console.log("ErrorState:", state.errorMessage);
            break;
    }
}

const responseSuccess: SuccessState = {
    status: "success",
    data: ["상품 A", "상품 B", "상품 C"]
};
const responseError: ErrorState = {
    status: "error",
    errorMessage: "네트워크 연결 오류"
};
renderNetworkState(responseSuccess);
renderNetworkState(responseError);
~~~

**6장 1강 : 제네릭 함수와 제네릭 인터페이스**

> 교재 · 6장 1강

**제네릭**(Generic): 다양한 타입을 하나의 틀로 다루면서도 타입 안전성을 보장하는 타입 변수 시스템

any의 한계와 제네릭 필요성

- `any` → 컴파일러 타입 검사 비활성화 → 런타임 오류 가능
- 타입별 개별 함수 → 동일 로직 반복 (코드 중복)
- 제네릭: 타입을 미리 고정하지 않고, 호출 시점에 타입을 인자로 받아 결정

~~~typescript
function echoAny(value: any): any {
  // 입력받은 값을 그대로 반환하는 함수
  return value.toUpperCase();
}

function echoGeneric<T>(value: T): T {
  // <T>는 타입 매개변수로, 입력받은 value의 타입을 T로 지정하고 동일한 T 타입을 반환합니다.
  return value;
}

const num = echoGeneric<string>("100");
console.log("typeof num:", typeof num);

const num2 = echoGeneric(100);
console.log("typeof num:", typeof num2);
~~~

제네릭 함수 설계

- 타입 매개변수 식별자: 관례상 `<T>`, 여러 개면 `<T, U, V>`
- 타입 자동 추론: `<number>`처럼 명시하지 않아도 인자 값으로 컴파일러가 추론

~~~typescript
function getFirstElement<T, U>(arr: T[], info: U): T | undefined {
    if (arr.length === 0) {
        return;
    }
    console.log("Info:", info);
    return arr[0];
}

const numbers = [10, 20, 30];
//const firstNumber = getFirstElement<number, string>(numbers, "출력");
const firstNumber = getFirstElement(numbers, "출력");
console.log(firstNumber);
~~~

**6장 2강 : 제네릭 제약 조건과 keyof 연산자**

> 교재 · 6장 2강

**제네릭 제약 조건**: 제네릭 매개변수가 특정 규칙·구조를 반드시 만족하도록 범위 제한

- `<T extends 제한할_타입>` — T가 해당 타입을 만족하도록 강제
- 필기 메모: `<T extends Lengthwise>` → T는 Lengthwise의 하위 타입. 덕타이핑 특징, 상속 관계가 없어도 그 특징이 있으면 하위 타입

~~~typescript
interface Lengthwise {
    length: number;
}

function printLength<T extends Lengthwise>(item: T): number {
    return item.length;
}

console.log(printLength("안녕하세요."));
console.log(printLength([10, 20, 30]));
console.log(printLength(1234)); // number에는 length 없음 → 컴파일 에러 유도
~~~

`keyof`: 객체 타입이 가진 모든 속성 키 이름을 문자열 리터럴 유니온으로 추출

- 존재하지 않는 속성 접근(오타)을 컴파일 시점에 방지

~~~typescript
interface UserProfile {
    id: number;
    name: string;
    email: string;
    age: number;
}

type UserKeys = keyof UserProfile;  // 'id' | 'name' | 'email' | 'age'

const a: UserKeys = 'name';
const b: UserKeys = 'Name'; // 대소문자 불일치 → 컴파일 에러 유도
~~~

제약 조건 + keyof 결합 — 안전한 속성 조회

- `<T, K extends keyof T>` — K는 T의 키 중 하나
- 반환 타입 `T[K]` — 조회한 속성의 실제 타입 추론

~~~typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const product = {
  id: 101,
  title: "무선 키보드",
  price: 45000,
  isAvailable: true
};

const title = getProperty(product, "title");
console.log("title:", title);

// 존재하지 않는 키 → 컴파일 에러 유도
const discount = getProperty(product, "discount");
~~~

**7장 1강 : 클래스 구조와 접근 제한자 및 상속**

> 교재 · 7장 1강

클래스 접근 제어자 (인스턴스 변수, 인스턴스 메서드) — 필기

- `public`: 클래스 내부, 외부 모두 접근 가능 (기본값)
- `protected`: 클래스 내부에서만 접근 가능, 상속을 통하면 하위 클래스 내부에서도 접근 가능
- `private`: 클래스 내부에서만 접근 가능

클래스 / 접근 제한자

- 클래스: 객체를 찍어내는 틀
- 접근 제한자: 내부 데이터를 외부에 얼마나 공개할지 결정하는 안전장치

필드·생성자

- 클래스 필드: 클래스 내부에서 관리되는 변수. TS에서는 타입을 미리 명시
- 생성자: 객체 생성 시 가장 먼저 실행. 필드 값 초기화

~~~typescript
class BankAccount {
    private owner: string;
    private balance: number;

    constructor(owner: string, balance: number) {
        this.owner = owner;
        this.balance = balance;
    }

    getSummary(): string {
        return `소유자: ${this.owner} / 잔액: ${this.balance}`;
    }
}

const myAccount = new BankAccount("김철수", 10000);
console.log(myAccount.getSummary());
console.log(myAccount.owner); // private → 외부 접근 컴파일 에러 유도
~~~

접근 제한자 정리

| 제한자 | 접근 범위 |
| --- | --- |
| public | 클래스 내부, 자식 클래스, 외부 어디서든 (기본값) |
| protected | 클래스 내부와 상속받은 자식 클래스만. 외부 불가 |
| private | 해당 클래스 내부만. 자식·외부 완전 차단 |

~~~typescript
class SecureAccount {
    public owner: string;
    protected accountType: string; // 클래스 내부만 가능 + 상속을 통해서 하위 클래스 내부에서 가능
    private balance: number;

    constructor(owner: string, accountType: string, balance: number) {
        this.owner = owner;
        this.accountType = accountType;
        this.balance = balance;
    }

    public getSecureBalance(): number {
        return this.balance;
    }
}

const myAcc = new SecureAccount("김철수", "보통예금", 10000);
console.log("owner:", myAcc.owner);
// console.log("accountType:", myAcc.accountType); // protected 외부 불가
~~~

~~~typescript
class SubSecureAccount extends SecureAccount {
    constructor(owner: string, accountType: string, balance: number) {
        super(owner, accountType, balance);
    }

    getType(): string {
        return this.accountType;
    }

    getBalance(): number {
        // return this.balance; // private → 자식도 불가
        return this.getSecureBalance();
    }
}

const myAcc2 = new SubSecureAccount("이영희", "정기적금", 50000);
console.log("accountType:", myAcc2.getType());
console.log("balance:", myAcc2.getBalance());
~~~

생성자 단축 속성 선언

- 생성자 매개변수 앞에 접근 제한자를 쓰면, 필드 선언과 `this` 할당을 자동 처리

    }

const myAcc3 = new CompactAccount("김철수", "보통예금", 20000);

클래스 상속과 `super`

- `extends`: 부모 기능을 유지하며 자식 클래스를 확장. 코드 재사용
- `super()`: 자식 생성자에서 부모 생성자 실행
- `super.메서드`: 부모에 정의된 메서드·자원 참조
- **메서드 오버라이딩**: 물려받은 메서드를 자식 목적에 맞게 재정의

~~~typescript
class BaseAccount {
    constructor(
        public owner: string,
        protected balance: number
    ) {}

    public printDetails(): void {
        console.log(`소유자: ${this.owner}, 잔액: ${this.balance}원`);
    }
}

class SavingsAccount extends BaseAccount {
    private interestRate: number;

    constructor(owner: string, balance: number, interestRate: number) {
        super(owner, balance);
        this.interestRate = interestRate;
    }

    public addInterest(): void {
        const interest = this.balance * this.interestRate;
        this.balance += interest;
        console.log(`이자 ${interest}원이 적립되었습니다.`);
    }

    public printDetails(): void {
        super.printDetails();
        console.log(`적용 이자율: ${this.interestRate * 100}%`);
    }
}
~~~

**7장 2강 : 추상 클래스, 인터페이스 구현 및 static**

> 교재 · 7장 2강

추상 — 필기

- 공통적인/일반적인
- 정해지지 않은

추상 클래스 — 필기

- 함수의 기능 수행이 정의되지 않은 클래스
- 클래스 키워드(`class`) 앞에 `abstract` 키워드 추가

인터페이스 — 필기

- 객체 구조를 정의하는 타입
- 메서드는 모두 추상 메서드
- 객체의 설계만을 위한 타입

**추상 클래스**: 직접 인스턴스를 만들 수 없지만, 하위 클래스가 반드시 구현할 공통 표준 구조를 제공

- `abstract`: 클래스·메서드 앞에 작성해 추상 규격 선언
- 인스턴스화 제한: `new`로 직접 생성 불가
- 추상 메서드: 본문(`{}`) 없음. 하위 클래스에서 반드시 오버라이딩 구현

~~~typescript
abstract class ServiceUser {
    showProfile(): void {
        console.log("프로필 출력...");
    }

    abstract getRole(): string;
}

// const user1 = new ServiceUser(); // 추상 클래스 직접 생성 불가

class CustomerUser extends ServiceUser {
    getRole(): string {
        return "ADMIN";
    }
}

const user1 = new CustomerUser();
console.log(user1.getRole());

class CustomerUser2 extends ServiceUser {
    getRole(): string {
        return "MANAGER";
    }
}
~~~

인터페이스 구현(`implements`)과 **다형성**

- 구조적 규격 강제: 인터페이스에 정의된 모든 속성·메서드를 포함하도록 강제
- 다중 구현: 쉼표로 여러 인터페이스를 동시에 구현 가능
- 다형성: 동일 인터페이스를 구현한 서로 다른 클래스 객체를 하나의 인터페이스 타입(배열·매개변수)으로 일괄 제어

~~~typescript
interface PaymentMethod {
    pay(amount: number): boolean;
}

class CreditCardPayment implements PaymentMethod {
    constructor(private cardNumber: string) {}

    pay(amount: number): boolean {
        console.log(`신용카드(${this.cardNumber})로 ${amount}원이 결제 되었습니다.`);
        return true;
    }
}

const card = new CreditCardPayment("1234-1234-1234-1234");
card.pay(30000);
~~~

~~~typescript
interface Notifiable {
    sendReceipt(message: string): void;
}

class MultiPaymentCard implements PaymentMethod, Notifiable {
    sendReceipt(message: string): void {
        console.log(message, " 영수증 전송");
    }
    pay(amount: number): boolean {
        console.log("결제 진행");
        return true;
    }
}
~~~

~~~typescript
class KakaoPayPayment implements PaymentMethod {
    constructor(private accountId: string) {}

    pay(amount: number): boolean {
        console.log(`[3단계 성공] 카카오페이 계정(${this.accountId})에서 ${amount}원이 결제되었습니다.`);
        return true;
    }
}

const kakaoPay: PaymentMethod = new KakaoPayPayment("1111");
const multiPay: PaymentMethod = new MultiPaymentCard();
console.log(kakaoPay.pay(30000));
console.log(multiPay.pay(20000));

if (multiPay instanceof MultiPaymentCard) {
    console.log(multiPay.sendReceipt("메세지"));
}
~~~

배열을 통한 다형성 일괄 처리 (`PaymentMethod[]`)

~~~typescript
const paymentList: PaymentMethod[] = [
    new CreditCardPayment("1234-1234-1234-1234"),
    new KakaoPayPayment("1111"),
    new MultiPaymentCard()
];

console.log("--- 다형성 배열 일괄 실행 ---");
paymentList.forEach((paymentItem) => {
    paymentItem.pay(5000);
});
~~~

**정적 멤버** (`static`)

- 개별 객체(`this`)가 아닌 클래스명으로 직접 접근. 메모리에 단 하나만 존재해 모든 객체가 공유

Getter / Setter

- `private` 속성에 안전하게 접근하고, 값 변경 시 검증 로직 적용
- 괄호 없이 속성명처럼 접근

~~~typescript
class UserCounter {
    private static totalUsersCount: number = 0;

    constructor(public username: string) {
        UserCounter.totalUsersCount++;
    }

    static getTotalUsers(): number {
        return UserCounter.totalUsersCount;
    }
}
~~~

~~~typescript
class ServerConfig {
    private _serverUrl: string;

    constructor(initialUrl: string) {
        this._serverUrl = initialUrl;
    }

    get serverUrl(): string {
        return this._serverUrl;
    }

    set serverUrl(newUrl: string) {
        if (!newUrl.startsWith("https://")) {
            console.log("[2단계 실패] 보안 접속(https://) 주소만 등록할 수 있습니다.");
            return;
        }
        this._serverUrl = newUrl;
        console.log(`[2단계 성공] 서버 주소가 변경되었습니다: ${this._serverUrl}`);
    }
}
~~~

## 확인이 필요한 사항

⚠ 교재와 필기의 내용 차이 — `protected`

필기: 클래스 내부에서만 접근 가능, 상속을 통하면 하위 클래스 내부에서도 접근 가능

교재: 클래스 내부와 상속받은 자식 클래스에서만 접근이 가능하며, 외부에선 접근이 불가능합니다

가능한 해석: 필기 「클래스 내부에서만」은 private과 혼동될 수 있으나, 이어지는 「상속을 통하면 하위…」로 protected를 의도한 메모. 의미는 교재와 대체로 같음

추가 확인 필요

⚠ 추상 클래스 필기 「함수의 기능 수행이 정의되지 않은 클래스」 — 교재·예시(`ServiceUser`)는 일반(구체) 메서드와 추상 메서드를 함께 둘 수 있음

⚠ 인터페이스 메서드는 시그니처만 선언(`abstract` 키워드 없음). 의미상 추상 메서드와 비슷함

⚠ 러프에서 추상/추상클래스/인터페이스 불릿이 7.1 아래에 있었음 → 교재 매핑상 7장 2강으로 배치함
