## 어제의 복습

1. 웹 브라우저의 자바스크립트 실행 순서 중, HTML 파싱이 완료되어 DOM 트리 구축이 끝났음을 알리는 이벤트로, 이미지 등 외부 리소스의 로드 완료 여부와 상관없이 발생하는 것
   - `DOMContentLoaded`

2. 외부 자바스크립트 파일을 `<script>` 태그로 불러올 때 사용하는 속성 중, HTML 파싱을 막지 않고 병렬로 다운로드하지만 실행 시점에는 파싱이 중단되며 여러 파일 간 실행 순서가 보장되지 않는 속성
   - `async`
   - `defer`: `DOMContentLoaded` 이벤트 이후 실행 → DOM 조작 가능

3. 현재 페이지의 방문 이력을 삭제하지 않고 남겨둔 채로 새로운 URL로 페이지를 이동시켜, 사용자가 '뒤로 가기' 버튼으로 이전 페이지에 복귀할 수 있도록 하는 Location 객체의 메서드
   - `location.assign()`

4. 자바스크립트의 전역 실행 컨텍스트(함수나 블록 외부의 가장 바깥 영역)에서, Window 객체와 완전히 동일한 참조 대상이 아닌 것
   - `document`

5. HTML 요소를 구성하는 객체가 제공하는 프로퍼티로, add·remove·toggle·contains 메서드를 통해 클래스 문자열을 직접 파싱하지 않고도 CSS 클래스를 안전하게 추가·삭제·전환할 수 있게 해주는 것
   - `classList`

## 오늘의 학습

### 7. 이벤트 모델 제어 및 비동기 네트워크 통신

#### 브라우저 이벤트 처리 및 전파

**이벤트 (Event)**

- 웹 페이지 내에서 발생하는 모든 사용자의 행동

**이벤트 핸들러 (Event Handler)**

- 이벤트가 발생했을 때 실행되는 함수
- 러프의 「핸들러 등록이 예약 번호표(ID)를 돌려준다」는 타이머 반환으로 읽음. ID 설명은 아래 타이머 절에만 둠

![event_loop](../../images/Chapter%2007/javascript_event_loop.png)

**스레드**

- 스레드: 작업자(일꾼), 작업 단위
- 하나의 스레드는 코드가 실제로 실행되는 독립된 실행 영역인 하나의 Call Stack(호출 스택)을 가짐

**멀티 스레드**

- 여러 작업자가 동시에 일함
- 각각의 스레드가 독립적인 Call Stack(실행 영역/스택)을 여러 개 가지고 동시에 작업을 병렬로 처리

**자바스크립트는 싱글 스레드 (Single Thread)**

#### 타이머 — `setTimeout` / `setInterval`

예약 번호표(타이머 ID)는 `addEventListener` 반환이 아니다. `setTimeout` / `setInterval`이 돌려주는 값이고, 그 ID를 `clearTimeout` / `clearInterval`에 넘기면 예약을 취소한다. (FE_16 §6)

- `setTimeout(이벤트 핸들러, 지연시간)`
  - 지연시간 `1000` → 1초
  - 지정 시간 뒤 한 번 실행
- `setInterval(이벤트 핸들러, 지연시간)`
  - 같은 간격으로 반복 지연 실행

#### 이벤트를 등록하는 방법

1. HTML 요소의 이벤트 속성 (`on` + 이벤트명)
   - 이벤트 1개 등록
   - 다른 이벤트 핸들러를 등록하면 바뀜(덮어쓰기)
   - `onload`를 2개 했는데 왜 하나만 도나
     - 프로퍼티(속성)에 값을 대입하는 방식이라 주소(참조)가 덮어씌워졌기 때문
2. `document.addEventListener(이벤트명, 이벤트 핸들러 함수, 캡처링 여부)`
   - 여러 핸들러를 누적할 수 있는 쪽 (대비는 「교재 보충」표)
   - 세 번째 인자: 이벤트 전파 방향
     - `false`: 버블링 단계에서 전파 (기본값)
     - `true`: 캡처링 단계에서 전파

이벤트는 바깥에서 안으로 내려갔다가(캡처링), 목표 지점에 닿고(타깃), 다시 안에서 바깥으로 올라가며(버블링) 전파된다.

- 1단계 캡처링 (Capturing): 최상위 `window` → 목표 타깃. 바깥 → 안
- 2단계 타깃 (Target): 실제 클릭/발생한 목표 요소 도착, 해당 요소 이벤트 핸들러 실행
- 3단계 버블링 (Bubbling): 목표 타깃 → 최상위 부모. 안 → 바깥

#### 이벤트 객체

이벤트 핸들러의 첫 번째 매개변수.

1. 발생한 이벤트와 관련된 정보
2. 이벤트 통제 메서드
   - `stopPropagation`: 이벤트 전파 차단
   - `stopImmediatePropagation`: 이벤트 전파 차단 + 같은 요소의 다른 핸들러도 즉시 중단
3. `e.currentTarget`: `this`와 동일 대상 참조 / 이벤트가 바인딩된 요소
   - `e.target`: 실제 이벤트가 발생한 요소(타깃)

#### 마우스 이벤트

- `click`
- `dblclick`
- `mousemove`
- `mousedown`: 마우스 클릭(누르는 순간)
- `mouseup`: 마우스 클릭 후 뗄 때

요소 좌측 상단 기준 `offsetX`, `offsetY`

#### 키 이벤트

- `keydown` (러프 `keydodwn` 교정)
- `keypress`: 기능키(Alt, Ctrl, …) 동작 X
- `keyup`: 키를 누르고 뗄 때

- `key`
- `code`
- `keyCode` (러프 `keycode` 교정): 유니코드

#### 기타

- `change`: `select`, `number`, `range`, `<input type="file">`
- `submit`
- `focus`

#### AJAX (Asynchronous JavaScript and XML)

- 페이지 새로고침 없이 데이터로 치환하는 기술
- FE_16 도입도 화면 전체 새로고침 없이 필요한 부분만 바꾸는 흐름이다. 교재가 그 수단으로 두는 것은 fetch API (GET/POST 본문은 오늘 범위 밖)

## 핵심 개념

- 이벤트 = 페이지 안 사용자 행동. 이벤트 핸들러 = 그때 실행되는 함수
- 타이머 ID는 `setTimeout` / `setInterval` 반환값 → `clearTimeout` / `clearInterval`. 핸들러 등록 반환이 아님
- 스레드 = 작업 단위 + Call Stack 하나. 멀티 스레드는 스택이 여러 개·병렬. JS는 싱글 스레드
- 등록: `on*` / 프로퍼티 대입은 1개·덮어쓰기. `addEventListener(type, listener, useCapture)`는 누적. `false` 버블링(기본), `true` 캡처링
- 전파: 캡처링(window→타깃) → 타깃 → 버블링(타깃→부모)
- 이벤트 객체: 정보 + `stopPropagation` / `stopImmediatePropagation`. `currentTarget`(바인딩, `this`) vs `target`(실제 발생)
- 마우스: click·dblclick·mousemove·mousedown·mouseup. 요소 좌상단 `offsetX`/`offsetY`
- 키: keydown·keypress(기능키 X)·keyup. `key` / `code` / `keyCode`
- 기타: `change`(select·number·range·file) · `submit` · `focus`
- AJAX: 새로고침 없이 데이터로 치환

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재에서 가져온 내용이다.

### 이벤트 등록 3방식 (FE_15 §1)

| 방식 | 형태 | 핸들러 수 |
|---|---|---|
| HTML 속성 | 태그 안 `onclick="..."` | 1개. 새로 적으면 이전 무효 |
| DOM 프로퍼티 | `element.onclick = 함수` | 1개. 대입하면 이전 참조가 덮임 |
| `addEventListener` | `target.addEventListener(type, listener, useCapture)` | 같은 요소·같은 type에 여러 개 누적. `type`은 이벤트 이름 문자열, `listener`는 콜백 |

### `useCapture` (FE_15 §1.2)

| 값 | 의미 |
|---|---|
| `false` (기본) | 버블링 단계에서 리스너 실행 |
| `true` | 캡처링 단계에서 리스너 실행 |

### 전파 3단계 (FE_15 §3.1)

| 단계 | 방향 |
|---|---|
| 캡처링 | `window`에서 출발, 상위 → 이벤트 타깃 (하향) |
| 타깃 | 실제 발생 요소에 도달, 그 요소의 리스너 실행 |
| 버블링 | 타깃에서 조상을 거쳐 `window`까지 (상향). `focus`·`blur` 등 일부는 버블링 없음 |

### `stopPropagation` vs `stopImmediatePropagation`

| 메서드 | 하는 일 | 출처 |
|---|---|---|
| `stopPropagation` | 현재 요소 너머 다른 요소로 전파 차단 | 필기 · FE_15 §3.3 |
| `stopImmediatePropagation` | 전파 차단 + 같은 요소의 나머지 핸들러도 즉시 중단 | 필기 (교재 §3.3에는 없음) |

### `currentTarget` vs `target` (FE_15 §1.2 주석 · 필기)

| 프로퍼티 | 가리키는 것 |
|---|---|
| `e.currentTarget` | 리스너가 등록(바인딩)된 요소. 필기: `this`와 동일 |
| `e.target` | 이벤트가 실제로 발생한 요소 |

### 마우스 이벤트 (FE_15 §2.1–2.2)

| 이름 | 시점 |
|---|---|
| `mousedown` | 버튼을 누르는 순간 |
| `mouseup` | 누르고 있던 버튼에서 손을 떼는 순간 |
| `click` | 같은 요소에서 mousedown과 mouseup이 모두 끝났을 때 |
| `dblclick` | 짧은 시간에 두 번 클릭 |
| `mousemove` | 요소 안에서 포인터가 움직이는 동안 계속 |
| `offsetX` / `offsetY` | 이벤트가 발생한 요소의 왼쪽 위 모서리 기준 상대 좌표 |

### 키보드 이벤트 · `key` / `code` / `keyCode` (FE_15 §2.3–2.4)

| 이름 | 설명 |
|---|---|
| `keydown` | 자판을 누르는 순간. 누르고 있으면 연속 발생 |
| `keypress` | 글자가 입력될 때. Alt·Ctrl·Shift·방향키 등 기능키에는 반응 없음. 표준에서 빠지는 추세라 `keydown` 권장 |
| `keyup` | 자판에서 손을 뗄 때 1회 |
| `key` | 눌린 키가 나타내는 문자 (예: `"a"`, `"Enter"`) |
| `code` | 자판의 물리적 위치 (예: `"KeyA"`) |
| `keyCode` | 키의 숫자 값 (교재: 아스키/유니코드 정수) |

### 타이머 (FE_16 §6)

| 함수 | 역할 |
|---|---|
| `setTimeout(콜백, ms)` | 지정 ms 뒤 콜백 1회. 반환값 = 타이머 ID |
| `setInterval(콜백, ms)` | 지정 ms마다 콜백 반복. 반환값 = 타이머 ID |
| `clearTimeout(id)` | 해당 `setTimeout` 예약 취소 |
| `clearInterval(id)` | 해당 `setInterval` 반복 정지 |


### 싱글 스레드 vs 멀티 스레드 (FE_16 §1.1)

| 구분 | 싱글 스레드 | 멀티 스레드 |
|---|---|---|
| 개념 | 코드를 실행하는 주체가 1개 | 주체가 여러 개 |
| 장점 | 자원 충돌이 없고 흐름 제어가 단순 | 여러 작업을 동시에 처리 |
| 단점 | 긴 연산이면 다음 작업이 대기 | 순서 꼬임·자원 충돌 가능 |


### 기타 이벤트 (FE_15 §2.5)

| 이름 | 시점 |
|---|---|
| `change` | `input`·`select` 등에서 값을 바꾼 뒤 포커스를 잃거나 선택을 끝낼 때. 필기 대상: select·number·range·file |
| `submit` | `form` 데이터가 서버로 나가기 직전 |
| `focus` | 요소가 포커스를 얻을 때. 버블링 없음 |

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
|------|------|------|------|
| 타이머 ID | 핸들러 절에 「등록 방법/번호 반환 = 예약 번호표」 | FE_16 §6: `setTimeout`/`setInterval` 반환 ID를 clear에 전달 | 본문 구조를 타이머 절로 옮김 |
| 등록 | HTML `on*`·`onload` 대입 덮어쓰기, `addEventListener` | HTML 속성 / DOM 프로퍼티(둘 다 1개·덮어쓰기) / `addEventListener`(누적) | 필기 경험 유지 · 3방식은 보충 표 |
| `keyCode` | 유니코드 | 아스키/유니코드 정수 | 표기 `keyCode`로 교정 · 값 종류는 확인 |
| `stopImmediatePropagation` | 전파 차단 + 같은 요소 다른 핸들러 중단 | §3.3은 `stopPropagation`·`preventDefault` | 필기 유지 |
| Call Stack | 스레드 1개 = Call Stack 1개 | §1은 스레드=작업 단위. Call Stack 없음 | 필기 유지 |
| AJAX | 새로고침 없이 데이터로 치환 | 도입은 부분 갱신, 수단은 fetch API | 한 줄 정렬만. fetch 본문 제외 |

## 확인이 필요한 사항

⚠ 타이머 ID — 러프는 이벤트 핸들러 아래에 두었음. 편집은 FE_16 §6대로 `setTimeout`/`setInterval` 반환으로 옮김. 수업에서 핸들러 반환이라고 했는지.

⚠ `keyCode` — 필기 「유니코드」 vs 교재 「아스키/유니코드 정수」.

⚠ `stopImmediatePropagation` — 필기에만 있음. 교재 §3.3은 `stopPropagation`과 `preventDefault`.

⚠ Call Stack — 필기. 교재 §1은 스레드 정의·싱글/멀티 표만 있고 호출 스택은 없음.

⚠ `onload` 2개→1개 — 필기는 HTML 이벤트 속성 절에서 프로퍼티 대입 덮어쓰기로 설명. 교재는 HTML 속성과 DOM 프로퍼티를 둘 다 1개 제한으로 구분.

## 필기 누락 가능성

오늘 교재(FE_15 §1–3, FE_16 §1·§6)에 있으나 필기에 없거나 이름만인 항목.

- `removeEventListener` — 익명 함수로 등록하면 삭제 불가, 기명·참조 보관 필요 (FE_15 §1.3)
- `mouseover` / `mouseout` / `scroll` (FE_15 §2.1)
- `screenX`/`clientX`/`pageX` 계열 — 필기는 `offsetX`/`offsetY`만 (FE_15 §2.2)
- `preventDefault` — 링크 이동·폼 제출 같은 기본 동작 취소 (FE_15 §3.3)
- FE_15 §4 `this` 바인딩(`bind`·래퍼)과 리스너에 추가 데이터 넘기기

※ Promise·콜백 지옥·async/await·fetch GET/POST(FE_16 §2–5)는 오늘 본문에서 제외.
