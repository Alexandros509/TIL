**2장 3강 : 컴포넌트 기초, Props 전달 & 구조 분해 할당 (1)**

> 교재 · 2장 3강

**컴포넌트**(Component): 화면을 이루는 독립적이고 재사용 가능한 UI 블록, 리액트에서는 JS 함수 하나로 만듦

- 화면의 특정 영역(버튼, 카드, 헤더 등)을 만드는 함수
- 화면에 그려질 HTML 형태의 코드(JSX)를 반환(return)
- 한 번 만들어 두면 여러 페이지에서 필요할 때마다 가져와 재사용

컴포넌트 정의 3규칙

1. **PascalCase**: 함수 이름 첫 글자는 반드시 대문자 (예: ProductCard, PayButton)
   - 첫 글자가 소문자(productCard)면 리액트가 일반 HTML 태그(`<div>`, `<button>`)로 오인
2. JSX 반환: 함수 내부에서 `return ( ... )`으로 화면에 표시할 HTML 모양의 코드 반환
3. 내보내기(export) 여부 결정
   - 외부 공유용: 다른 파일에서 불러올 컴포넌트는 함수 앞에 `export default`
   - 파일 내부 전용: 그 파일 안에서만 조각으로 쓰는 컴포넌트는 export 없이 일반 함수로 정의

~~~typescript
// [내부 전용 컴포넌트]
// export가 없으므로 이 파일 내부에서만 보조용으로 사용됩니다.
function StockBadge(): React.JSX.Element {
  return <span style={{ color: 'green', fontWeight: 'bold' }}>[재고 있음]</span>;
}

// [외부 공개용 메인 컴포넌트]
// export default가 붙어 있어 다른 파일(page.tsx 등)에서 import하여 가져갈 수 있습니다.
export default function ProductCard(): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      <h2>무선 게이밍 마우스 <StockBadge /></h2>
      <p>가격: 49,000원</p>
    </div>
  );
}
~~~

부모·자식 컴포넌트

- 부모 컴포넌트: 다른 컴포넌트를 자신의 코드 내부에 포함해 불러오는 상위 컴포넌트 (예: `page.tsx`)
- 자식 컴포넌트: 부모 컴포넌트 내부에 배치되어 호출되는 하위 컴포넌트 (예: `ProductCard.tsx`)

**Props**(Properties): 부모 컴포넌트가 자식 컴포넌트의 속성(Attribute) 형태로 넘겨주는 데이터 — 읽기 전용 데이터 주문서

- **단방향 데이터 흐름**: 데이터는 항상 부모 ➔ 자식 한쪽 방향으로만 흐름
- 자식 컴포넌트는 전달받은 Props를 직접 수정할 수 없음 (Read-only)
- 전달 기호
  - 문자열: `title="무선 게이밍 마우스"`처럼 큰따옴표·작은따옴표로 감쌈 (중괄호 생략 가능)
  - 숫자·불리언·변수·객체: 자바스크립트 값·표현식은 중괄호 — `price={49000}`, `isStock={true}`

~~~typescript
// [app/components/ProductCard.tsx - 자식 컴포넌트]
// 자식 컴포넌트가 전달받을 Props 객체의 타입을 지정합니다.
interface ProductCardProps {
  title: string;
  price: number;
  isStock: boolean;
}

// 매개변수로 props 객체 전체를 전달받습니다.
export default function ProductCard(props: ProductCardProps): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      {/* props 객체에 점(.)을 찍어 필요한 데이터에 접근합니다. */}
      <h2>{props.title}</h2>
      <p>가격: {props.price.toLocaleString()}원</p>
      <p>상태: {props.isStock ? '구매 가능' : '품절'}</p>
    </div>
  );
}
~~~


**구조 분해 할당**(Destructuring)

- 점 표기법은 `props.title`, `props.price`처럼 매번 props.을 반복해 붙여야 해서 코드가 길어짐
- 매개변수 위치에서 `{ title, price, isStock }`처럼 객체를 바로 해체해 가져옴 → 코드가 명확 (권장)

~~~typescript
interface ProductCardProps {
  title: string;
  price: number;
  isStock: boolean;
}

// 매개변수 자리에서 곧바로 필요한 속성만 뽑아냅니다. (props. 생략 가능)
export default function ProductCard({ title, price, isStock }: ProductCardProps): React.JSX.Element {
  return (
    <div style={{ border: '1px solid #ccc', padding: '16px', borderRadius: '8px' }}>
      {/* 변수명만 직접 사용하여 코드가 훨씬 간결해집니다. */}
      <h2>{title}</h2>
      <p>가격: {price.toLocaleString()}원</p>
      <p>상태: {isStock ? '구매 가능' : '품절'}</p>
    </div>
  );
}
~~~

`children`: 컴포넌트 여는 태그와 닫는 태그 사이(`<Card>여기에 들어가는 내용</Card>`)에 포함된 요소를 전달받는 리액트의 약속된 특별한 Prop

- 일반 Props: 단일 태그(Self-closing) 형태로 속성을 넘김
- children Props: `<Card><p>내용</p></Card>`처럼 태그 사이에 자식 HTML 태그나 다른 컴포넌트를 넣어 감싸는(Wrapper) 구조
- children에는 글자·HTML 태그·다른 컴포넌트 무엇이든 들어올 수 있음 → TypeScript 타입은 `React.ReactNode`

~~~typescript
// [app/components/Card.tsx]
import React from 'react';

// children 속성의 타입은 React.ReactNode로 지정합니다.
interface CardProps {
  children: React.ReactNode;
}

export default function Card({ children }: CardProps): React.JSX.Element {
  return (
    <div style={{
      border: '1px solid #e1e4e8',
      borderRadius: '12px',
      padding: '20px',
      boxShadow: '0 4px 6px rgba(0,0,0,0.05)',
      backgroundColor: '#ffffff'
    }}>
      {/* 부모가 태그 사이에 넣어준 내용이 이 위치에 렌더링됩니다. */}
      {children}
    </div>
  );
}
~~~

**2장 4강 : 리액트 이벤트 & 'use client' 경계 (1)**

이벤트 타입 (React)

- 입력값 변경: `ChangeEvent<T>`
- 클릭/마우스: `MouseEvent<T>`

> 교재 · 2장 4강

리액트 이벤트는 사용자 동작을 감지했을 때 실행할 함수의 이름(참조)을 전달하는 방식으로 동작

- **함수 참조** `onClick={handleClick}` — 올바른 방식
  - 함수 이름 뒤에 괄호 `()`를 붙이지 않고 함수 객체의 참조값만 전달
  - 사용자가 실제로 클릭하는 시점에 리액트가 함수를 실행
- 즉시 호출 `onClick={handleClick()}` — 잘못된 방식
  - 괄호를 붙이면 컴포넌트가 화면에 그려지는(렌더링) 순간 함수가 즉시 실행
  - 함수 안에 상태를 변경하는 로직이 있으면 무한 리렌더링(Infinite Loop) 에러
- 인자를 넘겨야 할 때는 익명 화살표 함수로 감싸서 전달: `onClick={() => handleClick(productId)}`

이벤트 속성은 HTML과 달리 카멜 케이스(camelCase)

| 카테고리 | 이벤트 속성 | 대상 태그 | 주요 용도 |
| --- | --- | --- | --- |
| 마우스 | onClick | button, div 등 | 요소를 마우스로 클릭했을 때 |
| 마우스 | onMouseEnter | 모든 요소 | 커서가 요소 영역 안으로 들어올 때 |
| 마우스 | onMouseLeave | 모든 요소 | 커서가 요소 영역 밖으로 나갈 때 |
| 입력 / 폼 | onChange | input, select 등 | 입력창 값이 변경될 때마다 실시간 |
| 입력 / 폼 | onSubmit | form | 제출 버튼을 누르거나 Enter를 칠 때 |
| 입력 / 폼 | onFocus | input, textarea | 포커스가 맞춰졌을 때(입력 준비) |
| 입력 / 폼 | onBlur | input, textarea | 포커스가 벗어났을 때(다른 곳 클릭) |
| 키보드 | onKeyDown | input, textarea | 키를 누르는 순간 (Enter 키 감지 등) |
| 키보드 | onKeyUp | input, textarea | 키를 눌렀다 떼는 순간 |

~~~typescript
// [app/components/EventPractice.tsx]
'use client'; // 이벤트를 사용하므로 클라이언트 컴포넌트로 지정합니다.

import React from 'react';

export default function EventPractice(): React.JSX.Element {
  // 마우스 클릭 이벤트 핸들러 (함수 참조용)
  const handleClick = (e: React.MouseEvent<HTMLButtonElement>): void => {
    alert('기본 클릭 이벤트 실행!');
  };

  // 인자를 받는 클릭 핸들러
  const handleItemClick = (itemName: string): void => {
    alert(`${itemName} 상품을 선택했습니다.`);
  };

  // 키보드 입력 이벤트 핸들러
  const handleKeyDown = (e: React.KeyboardEvent<HTMLInputElement>): void => {
    if (e.key === 'Enter') {
      alert(`엔터 키가 입력되었습니다! 입력값: ${e.currentTarget.value}`);
    }
  };

  return (
    <div style={{ border: '1px solid #aaa', padding: '16px', borderRadius: '8px', display: 'flex', flexDirection: 'column', gap: '12px' }}>
      <h3>1단계: 리액트 이벤트 실습</h3>

      {/* 올바른 함수 참조 방식 */}
      <button onClick={handleClick} style={{ padding: '8px', cursor: 'pointer' }}>
        기본 클릭 이벤트 (함수 참조)
      </button>

      {/* 인자 전달용 화살표 함수 감싸기 방식 */}
      <button onClick={() => handleItemClick('게이밍 키보드')} style={{ padding: '8px', cursor: 'pointer' }}>
        인자 전달 클릭 이벤트 (화살표 함수)
      </button>

      {/* 키보드 및 포커스 이벤트 */}
      <input
        type="text"
        placeholder="글자 입력 후 Enter를 누르세요"
        onKeyDown={handleKeyDown}
        onFocus={() => console.log('입력창 포커스 획득')}
        onBlur={() => console.log('입력창 포커스 해제')}
        style={{ padding: '8px', border: '1px solid #ccc', borderRadius: '4px' }}
      />
    </div>
  );
}
~~~

Form 제출과 기본 동작 방지

- HTML `<form>`은 제출(submit) 시 페이지 전체를 새로고침하며 서버로 데이터를 전송하는 기본 성질이 있음
- 리액트 앱은 전체 새로고침이 일어나면 데이터 상태가 초기화 → `e.preventDefault()`로 자동 새로고침 차단

~~~typescript
// [app/components/OrderForm.tsx - Form 제출 및 새로고침 방지]
'use client'; // 이벤트를 다루므로 클라이언트 컴포넌트로 지정합니다.

import React from 'react';

export default function OrderForm(): React.JSX.Element {
  // Form 제출 이벤트 핸들러 함수
  const handleSubmit = (e: React.FormEvent<HTMLFormElement>): void => {
    // 브라우저의 자동 새로고침 기본 동작을 차단합니다.
    e.preventDefault();
    alert('Form 제출 완료! 페이지가 새로고침되지 않고 유지됩니다.');
  };

  return (
    <form onSubmit={handleSubmit} style={{ border: '1px solid #ddd', padding: '16px', borderRadius: '8px' }}>
      <h3>2단계: Form 제출 실습</h3>
      <div style={{ marginBottom: '8px' }}>
        <input
          type="text"
          placeholder="요청사항을 입력하세요"
          style={{ border: '1px solid #ccc', padding: '6px', borderRadius: '4px', width: '100%' }}
        />
      </div>
      <button
        type="submit"
        style={{ backgroundColor: '#22c55e', color: '#fff', border: 'none', padding: '8px 12px', borderRadius: '4px', cursor: 'pointer' }}
      >
        요청사항 전송
      </button>
    </form>
  );
}
~~~

Server/Client 경계와 `'use client'`

- **Server Component**(기본값): Next.js App Router의 모든 컴포넌트는 기본적으로 서버에서 미리 만들어짐 → `onClick` 같은 브라우저 이벤트를 직접 쓰면 서버 에러
- Client Component 전환: 이벤트 핸들러가 있는 파일 최상단에 `'use client'` → 브라우저 상호작용을 처리하는 클라이언트 컴포넌트가 됨
- 선언 규칙
  - 최상단 위치: 파일 첫 줄에 `'use client';` (주석을 제외하고 어떤 코드보다 위)
  - 최소 영역: 페이지 전체(`page.tsx`)보다 이벤트를 처리하는 최소한의 자식 컴포넌트에만 선언하는 것이 성능상 가장 좋음
- `'use client'`를 적어도 100% CSR로만 동작하지 않음
  - 서버에서 첫 HTML 뼈대를 미리 만들고(SSR), 브라우저에서 JS가 연결된 뒤 클릭 같은 기능(CSR)이 동작하는 하이브리드 방식
  - 이 연결 과정이 **하이드레이션**
- 지침 없는 기본 서버 컴포넌트는 완성된 결과물만 전송 → 브라우저 JS 용량 0 Byte 유지

`Array.map()`: 기존 배열의 각 요소를 바탕으로 새로운 배열을 생성하는 자바스크립트 표준 메서드

**Unique Key**: 리액트가 변경된 항목(추가, 수정, 삭제)을 구별하기 위해 각 리스트 요소에 부여하는 고유 식별자

- 재조정(Reconciliation): 변경 사항이 있는 부분만 실제 DOM에 반영하는 리액트의 비교 과정
- `key` 속성을 설정하면 리액트는 전체 리스트를 다시 그리지 않고 변경된 요소만 선별해 업데이트
- index를 key로 쓰면 항목 추가·삭제·순서 변경 시 인덱스 값이 바뀌어 이전·현재 상태를 잘못 비교 → 입력 필드 값 상실 등 UI 상태 오류

| 식별자 종류 | Key 사용 적절성 | 설명 |
| --- | --- | --- |
| 고유 ID (id) | 적절 (key={item.id}) | 데이터의 추가/삭제와 관계없이 변하지 않는 고유 값 |
| 배열 인덱스 (index) | 조건부 사용 (key={index}) | 순서 변경이나 삭제 시 인덱스가 변경되어 상태 오류 가능성 존재 |
| 랜덤 값 (Math.random()) | 부적절 | 렌더링 시마다 새로운 Key가 생성되어 전체 리스트가 재렌더링됨 |

~~~typescript
// [app/components/KeyComparison.tsx]
import React from 'react';

// 사용자 데이터 객체의 구조 타입 정의
interface User {
  id: number;
  name: string;
  role: string;
}

export default function KeyComparison(): React.JSX.Element {
  // 정적 사용자 목록 데이터
  const users: User[] = [
    { id: 101, name: '김철수', role: '개발자' },
    { id: 102, name: '이영희', role: '디자이너' },
    { id: 103, name: '박민수', role: '기획자' },
  ];

  return (
    <div style={{ padding: '16px', border: '1px solid #ccc', borderRadius: '8px', marginBottom: '20px' }}>
      <h3>Key 설정 방식 비교</h3>

      <h4>Index를 Key로 사용 (순서 변경 시 문제 가능성)</h4>
      <ul>
        {users.map((user: User, index: number): React.JSX.Element => (
          // 배열 순서 번호인 index를 key로 지정하는 형태
          <li key={index} style={{ marginBottom: '4px' }}>
            [{index}] {user.name} ({user.role})
          </li>
        ))}
      </ul>

      <h4>고유 ID를 Key로 사용 (권장 방식)</h4>
      <ul>
        {users.map((user: User): React.JSX.Element => (
          // 데이터가 가진 고유값 id를 key로 지정하는 형태
          <li key={user.id} style={{ marginBottom: '4px' }}>
            [ID: {user.id}] {user.name} ({user.role})
          </li>
        ))}
      </ul>
    </div>
  );
}
~~~
