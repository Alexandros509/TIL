## 오늘의 학습
### 5장 SQL

**3.1 서브쿼리 기초**

서브쿼리 (부속질의)

- 내부쿼리 결과를 외부쿼리가 이용
1. SELECT(2. 외부쿼리) 문에 SELECT(1. 내부쿼리)가 포함된 질의
2. 스칼라 서브쿼리
   - SELECT 서브쿼리 FROM
   - 단일값 반환
3. 인라인 뷰 (가상 테이블)
   - SELECT ... FROM 서브쿼리
   - 실제 물리적 테이블 X. 조회 결과를 가지고 테이블처럼 사용 가능한 임시 테이블
4. WHERE절 서브쿼리
   - SELECT ... FROM ... WHERE 서브쿼리
   1) 비상관 서브쿼리 (교재 예시)
      - SELECT ... FROM ... WHERE col > (서브쿼리)
      - 내부가 먼저 실행 — 내부 결과(보통 단일값)를 외부가 조건에 사용
      - 예: 전체 평균보다 큰 주문
   2) 상관 서브쿼리 SELECT ... FROM t WHERE ... (서브쿼리가 t.컬럼 참조)
      - 외부 행의 값을 내부가 사용
      - 행마다 내부 쿼리가 다시 실행되는 경우가 많음
      - 예: 그 고객의 평균보다 큰 주문
5. IN / NOT IN
   - 서브쿼리가 여러 행을 반환할 때는 `=` 대신 IN을 사용
   - 서브쿼리가 반환한 값 목록 중 하나라도 일치하면 조건을 만족
   - NOT IN은 서브쿼리 결과에 포함되지 않는 행만 가져올 때 사용
6. EXISTS / NOT EXISTS
   - 데이터가 존재하는지 여부만 판단
   - 서브쿼리의 결과가 한 행이라도 존재하면 TRUE를 반환
   - NOT EXISTS는 서브쿼리 결과가 없을 때 TRUE를 반환



| 구분 | IN / NOT IN | EXISTS / NOT EXISTS |
| --- | --- | --- |
| 비교 방식 | 서브쿼리가 반환한 **값 목록 전체**와 비교 | 조건에 일치하는 데이터의 **존재 여부(True/False)**만 확인 |
| 실행 방식 | 서브쿼리 결과를 메모리에 목록으로 적재 후 비교 | 일치하는 행을 1개라도 찾는 즉시 탐색 중단 (Short-Circuit) |
| NULL 처리 (주의) | 서브쿼리 결과에 `NULL`이 포함되면 `NOT IN` 결과가 **빈 값(0건)**으로 출력됨 | `NULL` 값의 유무에 영향받지 않고 일치 여부만 정상 판단 |
| 서브쿼리 형태 | 비상관 서브쿼리 주로 사용 (`WHERE id IN (SELECT id ...)`) | 상관 서브쿼리 사용 (`WHERE EXISTS (SELECT 1 ... WHERE o.id = c.id)`) |
| 성능 (일반적 경향) | 서브쿼리 결과가 **소량**이거나 정적 리스트일 때 유리 | 서브쿼리 대상 테이블이 **대량**이거나 인덱스가 걸려 있을 때 유리 |

**3.2 FROM절과 SELECT절 서브쿼리**

서브쿼리는 WHERE에만 있는 게 아님.

- FROM : 집계 결과를 임시 테이블처럼
- SELECT : 행마다 계산한 단일값을 열로 추가

1. 인라인 뷰 (FROM절 서브쿼리)
   - FROM에 둔 서브쿼리. 결과가 테이블처럼 동작
   - DB에 저장되지 않는 임시 테이블
   - 반드시 별칭 (`AS 별칭명`)
   - 여러 열 가능. 외부에서 그 열을 참조
   - HAVING으로 되는 집계 필터도 많음. 집계 결과를 다시 JOIN하거나 추가 계산할 때 인라인 뷰가 더 편함
   - 예: 고객별 총 주문 금액 구한 뒤 100만 이상만

~~~sql
-- 고객별 총 주문 금액을 먼저 계산한 뒤, 100만원 이상인 고객만 조회
SELECT customer_id, total_amount
FROM (
    SELECT customer_id, SUM(amount) AS total_amount
    FROM orders
    GROUP BY customer_id
) AS customer_totals
WHERE total_amount >= 1000000;
~~~

2. 스칼라 서브쿼리 (SELECT절 서브쿼리)
   - SELECT에 둔 서브쿼리. 수학의 스칼라 = 단일값
   - 반드시 한 행, 한 열
   - 행마다 계산값을 새 열로 붙일 때
   - 여러 행이면 PostgreSQL 오류: `more than one row returned by a subquery used as an expression`
   - 단일값 맞추려면 WHERE 또는 집계 (AVG, COUNT, SUM …)
   - 예: 고객 옆에 전체 평균 주문 금액

~~~sql
-- 각 고객의 이름과 함께 전체 평균 주문 금액을 나란히 조회
SELECT
    customer_id,
    name,
    (SELECT AVG(amount) FROM orders) AS avg_order_amount
FROM customers;
~~~

   - SELECT절에서도 상관 가능. 외부 행(`o.customer_id`)을 내부가 참조
   - 예: 각 주문 옆에 그 고객의 총 주문 횟수

~~~sql
-- 각 주문과 함께 해당 고객의 총 주문 횟수를 열로 추가
SELECT
    o.order_id,
    o.customer_id,
    o.amount,
    (
        SELECT COUNT(*)
        FROM orders o2
        WHERE o2.customer_id = o.customer_id
    ) AS total_orders_by_customer
FROM orders o;
~~~

3. 서브쿼리 vs JOIN
   - 결과가 같은 경우가 많음. 가독성·성능·상황에 따라 고름
   - 소규모면 읽기 쉬운 쪽. 대규모면 `EXPLAIN ANALYZE`로 실행 계획 비교

| 비교 항목 | 서브쿼리 | JOIN |
| --- | --- | --- |
| 가독성 | 조건/계산 로직이 분리됨 | 테이블 관계를 한눈에 |
| 반환 구조 | 외부 쿼리 기준 열만 | 여러 테이블 열을 같이 |
| 성능 | 단순 조건 필터에 유리한 편 | 대용량 JOIN에 최적화된 경우 많음 |
| NULL | EXISTS면 비교적 안전 | OUTER JOIN으로 NULL 제어 |
| 상황 | 집계를 조건으로, 존재 여부 | 두 테이블 열을 함께, 관계 표현 |

~~~sql
-- 서브쿼리 방식: 주문이 있는 고객 조회
SELECT customer_id, name
FROM customers
WHERE customer_id IN (SELECT DISTINCT customer_id FROM orders);

-- JOIN 방식: 같은 결과
SELECT DISTINCT c.customer_id, c.name
FROM customers c
JOIN orders o ON c.customer_id = o.customer_id;
~~~

## 핵심 개념

- 서브쿼리: 내부쿼리 결과를 외부쿼리가 이용
- 스칼라: SELECT절, 단일값
- 인라인 뷰: FROM절, 임시 테이블처럼 사용. 물리적 테이블 아님
- WHERE 비상관: 내부 먼저, 보통 단일값을 외부 조건에 사용
- WHERE 상관: 외부 행 값을 내부가 참조. 행마다 다시 실행되는 경우가 많음
- 여러 행이면 `=` 대신 IN. NOT IN은 목록에 없는 행
- EXISTS / NOT EXISTS는 존재 여부만
- NOT IN + 서브쿼리 NULL → 결과 0건. NOT EXISTS는 NULL에 덜 흔들림
- 유동 텍스트: VARCHAR / TEXT (타입 정의는 2026-09-02 TIL)
- UUID 32자, 8-4-4-4-12
- 소프트 삭제: `deleted_at`이 NULL이 아니면 삭제
- ACID: 원자성 All or Nothing, 일관성, 격리성, 지속성

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

- 서브쿼리는 괄호 `()`로 감싼다. 바깥이 외부 쿼리(Outer Query), 안이 내부 쿼리(Inner Query)
- 위치 명칭: WHERE절 서브쿼리 / FROM절 인라인 뷰 / SELECT절 스칼라 서브쿼리. 교재 3장 1강은 WHERE를 먼저 다루고, FROM·SELECT는 다음 강
- WHERE 비상관 예:

~~~sql
-- 평균 주문 금액보다 큰 주문만 조회
SELECT order_id, customer_id, amount
FROM orders
WHERE amount > (
    SELECT AVG(amount)
    FROM orders
);
~~~

- IN / NOT IN 예:

~~~sql
-- 주문을 한 번 이상 한 고객만 조회
SELECT customer_id, name
FROM customers
WHERE customer_id IN (
    SELECT DISTINCT customer_id
    FROM orders
);

-- 한 번도 주문하지 않은 고객 조회
SELECT customer_id, name
FROM customers
WHERE customer_id NOT IN (
    SELECT DISTINCT customer_id
    FROM orders
);
~~~

- NOT IN 서브쿼리에 NULL이 있으면 전체가 빈 결과가 될 수 있어 NOT EXISTS가 더 안전하다고 교재가 적음
- EXISTS 예는 `SELECT 1` + 상관 조건:

~~~sql
-- 주문 이력이 있는 고객만 조회
SELECT customer_id, name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
~~~

- 인라인 뷰는 별칭(`AS 별칭명`)이 필요함. 집계 결과를 다시 필터하거나 JOIN할 때 씀
- 스칼라가 여러 행을 반환하면 PostgreSQL 오류: `more than one row returned by a subquery used as an expression`
- TEXT vs VARCHAR: 길이 제한이 명확할 때만 VARCHAR(n). 대부분 TEXT
- ACID 교재 표: A 모두 성공 또는 모두 실패 / C 제약조건을 깨지 않음 / I 동시 트랜잭션이 서로 간섭하지 않음 / D COMMIT된 것은 장애가 나도 남음

	-  서브쿼리가 반환한 값 목록 중 하나라도 일치하면 조건을 만족
	- NOT IN은 서브쿼리 결과에 포함되지 않는 행만 가져올 때 사용
6. EXISTS / NOT EXISTS
	- 데이터가 존재하는지 여부만 판단
	-  서브쿼리의 결과가 한 행이라도 존재하면 TRUE를 반환
	-  NOT EXISTS는 서브쿼리 결과가 없을 때 TRUE를 반환

- FROM 앞에는 단일값만 나올 수 있게 해야함.

 | 구분 | IN / NOT IN | EXISTS / NOT EXISTS |
| :--- | :--- | :--- |
| **비교 방식** | 서브쿼리가 반환한 **값 목록 전체**와 비교 | 조건에 일치하는 데이터의 **존재 여부(True/False)**만 확인 |
| **실행 방식** | 서브쿼리 결과를 메모리에 목록으로 적재 후 비교 | 일치하는 행을 1개라도 찾는 즉시 탐색 중단 (Short-Circuit) |
| **NULL 처리 (주의)** | 서브쿼리 결과에 `NULL`이 포함되면 `NOT IN` 결과가 **빈 값(0건)**으로 출력됨 | `NULL` 값의 유무에 영향받지 않고 일치 여부만 정상 판단 |
| **서브쿼리 형태** | 비상관 서브쿼리 주로 사용 (`WHERE id IN (SELECT id ...)`) | 상관 서브쿼리 사용 (`WHERE EXISTS (SELECT 1 ... WHERE o.id = c.id)`) |
| **성능 (일반적 경향)** | 서브쿼리 결과가 **소량**이거나 정적 리스트일 때 유리 | 서브쿼리 대상 테이블이 **대량**이거나 인덱스가 걸려 있을 때 유리 |
