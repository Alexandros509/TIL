## 오늘 공부한 내용

### 동시성 제어 기법

1. **비관적 락**
   - `SELECT ... FOR UPDATE`
   - 수정이 완료되면 잠금 해제
   - 성능 저하 가능성
   - 강한 잠금
2. **낙관적 락**
   - 테이블 구성
   - 테이블의 구조가 수정이 되면 증가시킴
3. **원자적 조건부 갱신** (Conditional UPDATE)
   - 조건을 `UPDATE` 한 문장에 넣어서, 별도 읽기/버전 비교 없이 선점 여부를 판정
4. **외부 분산락** (Redis)
   - DB 밖에 락 저장소를 두고, 여러 인스턴스 사이 순서를 조정

### RLS (Row Level Security)

- CRUD
- 회원의 권한을 체크 (DB) (`SELECT`, `INSERT`, `UPDATE`, `DELETE`)

## 핵심 개념

- 비관적 락: `SELECT ... FOR UPDATE`, 수정 완료 시 해제, 강한 잠금·성능 저하 가능
- 낙관적 락: 테이블 구성과 연동해 수정 시 값을 증가시키는 방식(필기)
- 원자적 조건부 갱신: 조건을 `UPDATE` 한 문장에 넣어 선점 여부 판정
- 외부 분산락(Redis): DB 밖 락 저장소로 인스턴스 간 순서 조정
- RLS: DB에서 회원 권한을 체크하며 CRUD에 적용

## 확인이 필요한 사항

⚠ 낙관적 락 필기: 「테이블의 구조가 수정이 되면 증가」
⚠ 일반적 설명과의 차이: 흔히 말하는 낙관적 락은 **행의 version(또는 유사 컬럼)을 올리고 저장 시 비교**하는 방식이다. 필기의 「구조」가 테이블 DDL 변경인지, version 증가를 가리키는 말인지는 확인이 필요하다.

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재(데이터베이스 & AI 활용 · 3장 6~8강)에서 가져온 내용이다.
※ 오늘은 RLS 필기와 직접 맞닿는 정의·주의만 둔다.

### RLS (3장 7강)

- 코드의 `.eq("user_id", user.id)`만으로는 부족하다. 조건을 빼면 다른 사람 데이터도 볼 수 있어, DB가 강제하는 **RLS**가 필요하다.
- RLS를 켜고 `auth.uid() = user_id` 정책을 두면 본인 행만 접근할 수 있다.

~~~~sql
alter table documents enable row level security;

create policy "본인 문서만 조회"
on documents
for select
using (auth.uid() = user_id);
~~~~

- `auth.uid()`: 현재 로그인 사용자 id
- **USING**: 이미 있는 행을 조회·수정·삭제할 때 검사
- **WITH CHECK**: 새로 저장·수정될 데이터의 `user_id`가 본인인지 검사
- SELECT 정책만 있으면 INSERT가 RLS 위반으로 막힐 수 있다. CRUD에도 정책이 필요하다.

### Auth와 user_id (3장 6강, 맞닿는 한 줄)

- 로그인 사용자의 `user.id`를 문서 `user_id`에 넣어야 RLS·필터링의 기준이 된다.

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 (3장 6~8) | 결과 |
| --- | --- | --- | --- |
| 비관적/낙관적 락, 조건부 UPDATE, Redis 분산락 | 필기 있음 | 해당 범위에 없음 | 필기 유지 |
| RLS | CRUD 시 DB에서 회원 권한 체크 | RLS enable, `auth.uid()`, USING/WITH CHECK | 교재 보충 |
| Auth / user_id | 복습·SDK 목적 수준 | user.id ↔ user_id | 맞닿는 한 줄만 보충 |
| 사용자별 CRUD 미니 과제 | 없음 | 3장 8강 | 필기 누락 가능성 |

## 필기 누락 가능성

다음 내용은 교재(3장 6~8강)에는 있으나 오늘 필기에서는 짧게만 다루었거나 없다. 수업에서 다루었다면 필기를 놓쳤을 가능성이 있다.

- RLS `enable` + `auth.uid() = user_id` 정책 SQL, USING/WITH CHECK
- 코드 `.eq`만으로는 부족하고 RLS가 규칙을 강제한다는 점
- Auth 흐름과 `user.id` → `user_id` 연결
- 사용자별 문서 CRUD 미니 앱 통합(3장 8강)

※ 동시성 제어 기법(비관적/낙관적 락, 조건부 UPDATE, Redis 분산락)은 오늘 필기에 있으나 지정 교재 범위(3장 6~8)에는 없다. 다른 장·자료가 있으면 그 출처로 보충하는 편이 맞다.
