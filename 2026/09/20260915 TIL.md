**7.1.2 하이퍼링크, 멀티미디어 및 폼 태그**

하이퍼링크 : 페이지 이동

1. 양식 (Form) 태그
   - **action** : 제출 처리 URL, 서버 URL
   - **method** : 전송 방식
     - **GET** (기본값) : 자원 조회/검색, 전송할 데이터는 URL에 포함 `?이름=값&이름=값` (쿼리 스트링, Query String)
       - 쿼리 스트링 (Query String) : 웹 브라우저 등 클라이언트가 서버로 데이터를 전달할 때 URL 끝에 물음표(`?`)와 함께 붙이는 `키=값` 형태의 문자열
     - **POST** : 서버에 변경을 가하는 요청, 요청 전문의 body에 실려 전송
     - 추후 설명 예정
   - **target** : `_self`, `_parent`, `_top`, `_blank`
   1. **input** : 입력을 위한 태그
      - **type** : 입력 유형
        - **text** (기본값)
        - **password** - 비밀번호
        - **radio** - 여러 개 중 1개 선택, name 값 동일하게 묶어야 함
        - **checkbox** - 여러 개 중 여러 개 선택
        - **submit** - 약식 제출, **reset** - 입력 항목 초기화, **button** - 일반 버튼
        - **email**
        - **number**
        - **color**
        - **range**
        - **date**
        - **time**
        - **datetime**
      - **name**
        1. **전송할 값의 이름**
        2. radio, checkbox의 그룹 명칭
      - **value**
        1. 입력 값
        2. `type="text" | "password" | "number"` : 사용자가 입력 → 값이 할당
      - **required** : 필수 입력 항목
        - min
        - max
        - step
      - **placeholder** : 안내 문구
      - **readonly** : 읽기 전용 (**데이터 전송 O**)
      - **disabled** : 기능 무력화 (**데이터 전송 X**)
   2. **button**
      - **type**
        - **submit** : 양식 제출
        - **reset** : 양식 입력 취소
        - **button** → 일반 버튼
      - `<button>버튼명</button>`
   3. 태그와 입력 요소를 연결
      1. 입력 요소를 태그(주로 label)로 감싼다
      2. `for`(label) · `id`(입력 요소)
   4. textarea : 여러 줄 텍스트 입력
   5. select : 여러 개 중 한 개 또는 여러 개
      - option : 선택 항목
        - selected : 기본값 선택
      - multiple : 여러 개 선택
      - size : 한 번에 보일 개수

2. HTTP 전문 구조 (판서)

**요청 전문** (Request Message, 클라이언트 → 서버)

- **헤더 (`Header`)**: 요청 쪽 정보 (메서드, 브라우저, 데이터 타입)
  - Network **Request headers**
  - 예: `Content-Type: application/x-www-form-urlencoded`
- **바디 (`Body`)**: 전송할 실제 데이터
  - Network **Payload (Form Data)**

**응답 전문** (Response Message, 서버 → 클라이언트)

- **헤더 (`Header`)**: 응답 정보·상태 (상태 코드, 서버 환경, 응답 타입)
  - Network **Response headers**, `Status Code: 200 OK`
- **바디 (`Body`)**: 서버가 돌려준 데이터 (HTML, JSON 등)
  - Network **Response** 탭, 화면에 렌더링된 `회원 가입 처리 완료....`

**7.1.2.5 HTML 태그 레퍼런스**

항목 나열, 메뉴·네비게이션

| --- | --- | --- | --- |
| `<ul>` | Unordered List | 순서 없는 목록, 앞 점(•) | 상단 메뉴, 카테고리 |

**7.1.3 HTML5 시멘틱 태그의 구조화**

시멘틱 태그 : 이름만 봐도 의미, 역할 명확히 알 수 있게 만든 태그

- Semantic : 의미
- `<table>`, `<video>`, ...
- 필요한 이유
  1. 검색엔진 최적화
  2. 웹 접근성
  3. 코드 가독성 향상

레이아웃을 구성하는 태그

1. `<header>` : 상단 공통 영역
2. `<footer>` : 하단 공통 영역
3. `<main>` : 본문
4. `<section>` : 내용 구분
5. `<article>` : 섹션별 내용
6. `<nav>` : 주 메뉴
7. `<aside>` : 좌우 영역

~~~html
성별 <!-- 태그로 입력 요소 감쌈 -->
    <label>
        <input type="radio" name="gender" value="FEMALE"> 여성
    </label>

    <label>
        <input type="radio" name="gender" value="MALE"> 남성 <br>
    </label>

취미 <!-- for id -->
    <input type="checkbox" name="hobby" value="reading" id="hobby_reading">
    <label for="hobby_reading">독서</label>

    <input type="checkbox" name="hobby" value="study" id="hobby_study">
    <label for="hobby_study">공부</label>
~~~

**7.2 CSS를 활용한 웹 스타일링 및 기본 레이아웃**

**7.2.1 CSS 기초와 스타일링 문법**

CSS (Cascading Style Sheets) [14일 Cascading](<20260914 TIL.md#찾아본 내용>)

- 웹 문서에 스타일링 담당

1. 스타일 적용 기본 구조
   - 선택자 (selector) { 속성 : 값 }
   - 스타일 속성 : color, background, width, height, ...
2. 적용 방법
   1. 인라인 스타일
      - 태그의 style 속성에 직접 적용
   2. 내부 스타일 시트
      - `<style> ... </style>` 태그 안에 스타일을 정의
   3. 외부 스타일 시트
      - CSS 파일을 생성하고 연동 (`<link rel="stylesheet" href="./style.css">`)
4. 주석
   - `/* 설명 */`
   - 설명 / 해석 배제
4. 선택자 (selector)
   1. 기본 선택자
      1. 전체 선택자 (`*`)
      2. 태그 선택자 (태그 이름)
      3. 클래스 선택자 (`.클래스명`)
         - 여러 개 요소 선택, 복수 선택 가능, 여러 개 이름 지정(클래스)
      4. 아이디 선택자 (`#아이디명`)
         - 아이디 명은 하나만 지정 가능, 유일한 이름으로 지정(아이디), 1개만을 선택하는 속성
   2. 복합 관계 선택자
      1. 하위 선택자 (조상-자손)
         - 하위 : 자손
         - 정렬 순서 : 조상 ... 자손
      2. 자식 선택자 (부모 > 자식)
         - 부모 : 바로 위 요소
         - 자식 : 바로 아래 요소
      3. 일반 형제 선택자 (형 ~ 동생)
         - 형 : 기준
         - 동생 : 기준 아래에 정의된 요소
      4. 인접 형제 선택자 (형 + 동생)
         - 형 : 기준
         - 동생 : 기준 바로 아래 요소 1개
5. 스타일 적용 우선 순위
   - 범위가 넓을수록 ↓, 좁을수록 ↑
   - 태그 선택자 < 클래스 선택자 < 아이디 선택자 < style 속성
   - 가장 많이 사용 : 태그(공통 스타일), 클래스(세부 스타일)
   - 참고) 우선순위 강제 적용 - `!important` 남용 주의!

## 옵시디언 텍스트 밑줄 및 주석/설명 표기법

### 1. 상시 노출 (커서 호버 불필요)

**단어 바로 위 주석 (루비 태그)**

일본어 후리가나 태그를 활용해 텍스트 바로 위에 작은 폰트로 주석을 띄운다.

~~~html
<ruby><u>밑줄 친 단어</u><rt>상시 표시될 설명</rt></ruby>
~~~

**단어 옆 인라인 주석**

`<small>` 태그나 기호로 본문 옆에 작은 글씨를 둔다.

~~~html
<u>밑줄 친 단어</u> <small>(※ 한 줄 설명 내용)</small>
~~~

**단어 바로 아래 (인라인 블록)**

CSS 인라인 스타일과 `<br>`로 하단에 주석을 고정한다.

~~~html
<span style="display:inline-block; vertical-align:top;">
<u>밑줄 친 단어</u><br>
<span style="font-size: 0.75em; color: gray;">└ 여기에 한 줄 설명</span>
</span>
~~~

**강조 블록 (옵시디언 Callout)**

개념 단위의 긴 메모를 박스로 상시 노출할 때 쓴다.

~~~md
> [!note] <u>밑줄 친 핵심 개념</u>
> 여기에 상시 노출할 핵심 설명을 작성합니다.
~~~

### 2. 숨김 / 호버 / 각주

**기본 각주 (문서 최하단)**

클릭하면 하단으로 가거나, 호버 팝업으로 미리볼 수 있다.

~~~md
이 문장에서 <u>강조할 키워드</u>[^1]에 밑줄을 긋습니다.

[^1]: 여기에 밑줄 친 키워드에 대한 한 줄 설명을 작성합니다.
~~~

**마우스 호버 툴팁**

`<abbr>`의 `title`로 올렸을 때만 보이게 한다.

~~~html
<u><abbr title="여기에 표시할 한 줄 설명을 적습니다">설명할 텍스트</abbr></u>
~~~

**편집 모드 전용 메모 (읽기 뷰 숨김)**

읽기 뷰에서는 숨고, 작성·수정 중에만 보인다.

~~~md
<u>밑줄 친 텍스트</u> %% 여기에만 보이는 한 줄 메모 %%
~~~

## 핵심 개념

- Form: action, method(GET/POST), input type, name/value, label 연결, button, select/textarea
- HTTP 전문: 요청·응답의 Header / Body (판서, DevTools Network)
- HTML 태그 레퍼런스: 리스트, 테이블, 포매팅, details/summary 등
- 시멘틱 태그: header, footer, main, section, article, nav, aside
- CSS: 선택자(기본·복합), 적용 3방식, 우선순위, `!important` 주의

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

### GET / POST (FE 1-2)

- **GET**: 서버 데이터 조회(Read). URL 뒤 쿼리스트링(`?key=value`)으로 전달
- **POST**: 서버 데이터 생성·수정·삭제(Write). HTTP 요청 본문(Body)에 담아 전달
- POST가 주소창에 안 보인다고 해서 안전한 것은 아님. 암호화되지 않은 HTTP에서는 Body도 가로챌 수 있음. 구분은 보안이 아니라 **서버 상태 변경 여부**

### name · value · label (FE 1-2)

- **name**: 서버로 전송되는 데이터 상자의 이름(Key). 없으면 전송 시 유실될 수 있음
- **value**: 상자에 담기는 실제 내용. radio/checkbox/option은 개발자가 value를 직접 지정해야 함
- **label 연결**: (1) `for`와 `id`를 일치시키는 명시적 연결 (2) 입력 요소를 `<label>`로 감싸는 암묵적 연결

### 시멘틱 레이아웃 (FE 1-3)

- **`<main>`**: 문서에서 단 한 번. 핵심 본문
- **`<article>`**: 따로 떼어도 이해되는 독립 콘텐츠(기사, 포스트)
- **`<section>`**: 본문 안 주제별 묶음
- **`<div>`**: 의미 없이 CSS용으로만 묶을 때. 시멘틱과 구분

### CSS 우선순위 (FE 2-1)

- 범위가 좁을수록(구체적일수록) 우선: 태그 < 클래스 < 아이디 < 인라인 `style`
- 가중치가 같으면 **나중에 선언된** 규칙이 덮어씀
- `!important`는 강제 적용 수단이나 남용하면 유지보수가 어려워짐

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
|------|------|------|------|
| 장 번호 | 7장 / 7.1.x / 7.2.1 | FE 1-2, 1-3, 2-1 | 확인 필요(번호 체계 상이, 필기 유지) |
| Form method | GET·POST, 쿼리 스트링·Body | 동일 + 보안 오해 주의 | 교재 보충 |
| input type | datetime 포함 | `datetime-local` (현지 일시) | 확인 필요 |
| required 하위 | min / max / step을 required 아래에 둠 | min·max·step은 number/range 등 type 관련 | 확인 필요 |
| 시멘틱 | header~aside 역할 요약 | 동일 + main 1회·article 독립성 | 교재 보충 |
| CSS 선택자 | 기본·복합·우선순위 | 동일 + 가상 클래스/요소 등 | 필기 범위 유지 |
| HTTP 전문 | 요청/응답 Header·Body 판서 | FE 1-2는 method·쿼리 위주 | 필기(판서) 유지 |

## 확인이 필요한 사항

⚠ 필기 장 번호와 교재 장 번호가 다름. 필기 **7장(7.1.2, 7.1.3, 7.2.1)** ≈ 교재 **FE 1-2 / 1-3 / 2-1**. 제목 번호는 필기 그대로 유지함.

⚠ 필기 `input type="datetime"`. 교재는 **`datetime-local`**(현지 표준 시간대 기준 날짜+시간). 필기 표기 유지, 교재와 차이 확인 필요.

⚠ 필기에서 `required` 아래에 min / max / step을 둠. 교재에서는 해당 속성이 number·range 등 type과 함께 설명됨. 필기 구조 유지, 소속 관계 확인 필요.

⚠ 시멘틱 절 아래의 성별·취미 label 예시는 Form(label 연결) 실습으로 보이며, 필기 위치는 그대로 둠.

⚠ 필기 `submit` : 「약식 제출」. 교재는 양식 제출(`type="submit"`). 오타인지 약식(간단 제출)인지는 확인 필요.

⚠ 필기 시멘틱 예시에 `<table>`, `<video>`가 있음. 교재 레이아웃 예는 `header`/`nav`/`main` 계열. 필기 위치 유지.

## 필기 누락 가능성

다음 내용은 교재에는 있으나
오늘 수업에서 다루었는지는 확실하지 않습니다.

- FE 1-2: `<img>` / `<audio>` / `<video>` 속성(controls, autoplay, muted 등), `type="file"`
- FE 2-1: 가상 클래스(`:hover` 등)·가상 요소(`::before`/`::after`), 폰트·배경 상세 속성

※ 수업에서 다루었다면
필기를 놓쳤을 가능성이 있습니다.
