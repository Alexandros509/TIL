## 오늘 공부한 내용

### API (Application Programming Interface)

- 애플리케이션 개발 명세서 — 프로그램 간 호출 규약 (Interface ≠ UI)

1. **REST API** (Representational State Transfer)
   - 표현적 상태 전이
   - 자원의 **상태**를 JSON 같은 **표현**으로 주고받음
   - 공식: 자원(URI) + 행위(HTTP 메서드)
     - 자원: 명사. `/users/3`
     - 행위: 동사. GET 조회, POST 생성, PUT 전체수정, PATCH 부분수정, DELETE 삭제
     - URI (Uniform Resource Identifier): 고유 자원 식별자
     - URL: URI 중 위치(주소)를 가리키는 것. `https://api.example.com/users/3`
   - https://developers.kakao.com/docs/ko/kakaologin/rest-api

### SDK

API 명세를 구현해 놓은 라이브러리

### 변수 : 타입

- `num: int = 100`
- `title: str = "ABC"`
- `list` / `tuple` / `dict`
- 클래스 → 타입
- 함수: `def 함수명(...) -> 타입(반환타입):`

### `@dataclass`

- 데이터 담는 일반 클래스의 보일러플레이트를 줄이는 표준 라이브러리 데코레이터
- `__init__`, `__repr__`, `__eq__`를 안 써도 자동 생성

### 저장 프로그램 (Stored Program)

1. **함수 (Function)**
   - 매개변수의 반환값
   - `SELECT` 구문 내에서 사용 가능 예) `AVG()`, `SUM()`
   - 단일 트랜잭션: 원자성 O, TCL 사용 불가
2. **프로시저 (Procedure)**
   - 독립 프로그램
   - `CALL 프로시저명(...);`
   - 트랜잭션 제어 가능 (`COMMIT`, `ROLLBACK` 정의 가능)
3. **트리거 (Trigger)**
   - 추후 다룰 예정

### 연산자 `:=`
#### PL/pgSQL `:=`
함수 안 변수 대입 (`v_total_price := 0`)

#### Python 바다코끼리 `:=`
조건/반복에서 대입과 사용을 동시에


| 기호 | 역할 |
| --- | --- |
| `->>` | JSON 키의 알맹이를 text로 추출 |
| `->` | JSON/JSONB 타입 유지하고 꺼냄 |
| `::` | `CAST(값 AS 타입)`과 같음 (단축 형변환) |
| `UUID` / `INT` | 변환 목표 데이터 타입 |
| `product_id` (맨 뒤) | `AS` 생략한 컬럼 별칭 |

- `p_` = Parameter. 함수 호출 때 밖에서 넘긴 인자
- `v_` = Variable. `DECLARE`에서 만든 함수 안 임시 변수

### Builder · `@dataclass` 실습

```python
class Product:
    # 내부 식별자
    _sentinel = object()  # 정적인 클래스 변수

    # 클래스 외부에서 직접 생성은 차단
    def __init__(self, token, name, price, description):
        if token is not Product._sentinel:  # 외부에서 직접 생성한 경우
            raise Exception("직접 생성할 수 없습니다.")

        self.__name = name
        self.__price = price
        self.__description = description

    def name(self):
        return self.__name

    def price(self):
        return self.__price

    def description(self):
        return self.__description

    def __repr__(self):
        return f"Product(name='{self.__name}', price='{self.__price}', description='{self.__description}')"

    # Product 객체를 조립하고 생성하는 클래스
    class Builder:
        def name(self, name):
            self.__name = name
            return self

        def price(self, price):
            self.__price = price
            return self

        def description(self, description):
            self.__description = description
            return self

        # 객체를 생성
        def build(self):
            return Product(Product._sentinel, self.__name, self.__price, self.__description)


product = (
    Product.Builder()
        .name("아이폰")
        .price(10000)
        .description("설명")
        .build()
)

print(product)
print(
    product.name(),
    product.price(),
    product.description(),
)


def list_sum(nums: list[int]):
```

### 주문 트랜잭션 함수 · RPC 호출

```sql
CREATE OR REPLACE FUNCTION create_order_transaction(
    p_order_name TEXT,
    p_order_email TEXT,
    p_order_phone TEXT,
    p_receiver_name TEXT,
    p_receiver_phone TEXT,
    p_zipcode TEXT,
    p_address TEXT,
    p_address_sub TEXT,
    p_delivery_memo TEXT,
    p_user_id UUID,
    p_items JSONB -- [{"product_id": "uuid", "quantity": 1}, ...]
)
RETURNS JSONB
LANGUAGE plpgsql
SECURITY DEFINER

AS $$
DECLARE
  v_order_id UUID;
  v_order_no TEXT; -- 20260911113021300
  v_total_price INT := 0;
  v_item RECORD;
  v_product RECORD;
BEGIN
  -- 상품이 있는지 체크
  IF p_items IS NULL OR jsonb_array_length(p_items) = 0 THEN
    RAISE EXCEPTION '주문할 상품이 없습니다.';
  END IF;

  -- 주문번호 생성
  v_order_no := TO_CHAR(CURRENT_TIMESTAMP, 'YYYYMMDDHH24MISS');

  -- orders 테이블에 기본 정보를 주문서 추가, 상품 총합 0
  INSERT INTO orders (
    order_no, order_name, order_email, order_phone,
    receiver_name, receiver_phone, zipcode, address, address_sub, delivery_memo,
    total_price, user_id
  ) VALUES (
    v_order_no, p_order_name, p_order_email, p_order_phone,
    p_receiver_name, p_receiver_phone, p_zipcode, p_address,
    p_address_sub, p_delivery_memo, 0, p_user_id
  )
  RETURNING id INTO v_order_id;

  -- products 테이블에서 상품을 조회한 후 order_items 테이블에 상품 정보를 추가
  FOR v_item IN
      SELECT (elem->>'product_id')::UUID product_id,
              (elem->>'quantity')::INT quantity
      FROM jsonb_array_elements(p_items) elem
  LOOP
    -- 구매 수량 검증
    IF v_item.quantity <= 0 THEN
      RAISE EXCEPTION '주문 수량은 1개 이상이어야 합니다.';
    END IF;

    -- 실제 상품 조회
    SELECT id, name, price INTO v_product
    FROM products WHERE id = v_item.product_id AND deleted_at IS NULL;

    -- 상품 조회의 결과가 없는 경우
    IF NOT FOUND THEN
      RAISE EXCEPTION '등록되지 않거나 삭제된 상품 입니다. (ID: %)', v_item.product_id;
    END IF;

    -- 주문 상품 등록
    INSERT INTO order_items (
      order_id, product_id, item_name, price, quantity
    ) VALUES (
      v_order_id, v_product.id, v_product.name, v_product.price, v_item.quantity
    );

    -- total_price 누적
    v_total_price := v_total_price + (v_product.price * v_item.quantity);
  END LOOP;

  -- orders 테이블에 상품 총금액(total_price)을 업데이트
  UPDATE orders
  SET total_price = v_total_price
  WHERE id = v_order_id;

  -- 결과 반환
  RETURN jsonb_build_object(
    'success', TRUE,
    'order_id', v_order_id,
    'order_no', v_order_no
  );

EXCEPTION
  -- 트랜잭션 실패
  WHEN OTHERS THEN
    RAISE EXCEPTION '주문처리 실패: %', SQLERRM;
END;
$$;
```

## 핵심 개념

- REST: 자원(URI) + 행위(HTTP 메서드). SDK는 API 명세의 구현 라이브러리
- 저장 프로그램: Function(반환·단일 트랜잭션·TCL 불가) / Procedure(`CALL`·COMMIT/ROLLBACK 가능) / Trigger(추후)
- `p_` / `v_`, JSONB `->>` / `->` / `::`, PL/pgSQL `:=`
- `@dataclass`, Builder로 객체 조립
- `create_order_transaction` + `supabase.rpc(...).execute()` — 실패 시 롤백 검증용 페이로드

## 교재 보충

※ 필기와 맞닿는 정의·주의만. 출처: 「특강」PostgreSQL Function/Procedure 트랜잭션 제어, 「데이터베이스 & AI 활용」4장 4강(RPC·원자성).

### Function vs Procedure (특강)

- **Function**: `RETURNS` 있음. 호출 전체가 하나의 트랜잭션으로 묶여, 에러 시 앞선 INSERT까지 자동 롤백. Supabase RPC는 보통 함수를 `SELECT` 기반으로 호출.
- **Procedure**: `CALL`로 실행. 내부에서 `COMMIT`/`ROLLBACK` 가능 → 대량 배치에서 락을 나눠 풀 때 사용. 단일 값 `RETURN` 없음.

### 주문 함수가 막는 것 (특강 · 필기 코드와 동일 계열)

- orders + order_items를 함수 한 번에 묶어 **유령 주문(일부만 저장)** 을 막는다.
- 단가는 클라이언트가 넘긴 값이 아니라 DB의 `products`를 조회해 넣고, 결제 시점 이름·가격을 `order_items`에 **스냅샷**으로 남긴다.
- `RAISE EXCEPTION` → 파이썬 `except`로 잡히고, DB 쪽은 통째 롤백.

### AI 로그와 RPC (4장 4강, 맞닿는 한 줄)

- 질문 저장과 응답 로그 저장이 따로면 반쪽 데이터가 생긴다. 여러 저장을 묶을 때도 DB 함수(RPC)를 쓰면 자동으로 한 트랜잭션이 된다.

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
| --- | --- | --- | --- |
| REST·SDK·타입·`@dataclass`·Builder | 필기 있음 | 지정 특강/4장 범위와 직접 겹침 적음 | 필기 유지 |
| Function / Procedure / TCL | 구분 필기 | 특강 비교표·자율 커밋 | 교재 보충 |
| `create_order_transaction` · RPC | 코드·실패 페이로드 | 특강 실습과 동일 계열 | 필기 유지 + 스냅샷·롤백 주의 보충 |
| AI 질문·응답 이중 저장 | 없음 | 4장 4강 RPC | 맞닿는 한 줄만 |

## 필기 누락 가능성

지정 교재에는 있으나 오늘 필기에서 짧게만 다루었거나 없다. 수업에서 다루었다면 놓쳤을 수 있다.

- Function이 Supabase RPC에 맞는 이유(PostgREST/`SELECT` 기반 반환)
- 주문 단가 **스냅샷** 이유(원본 가격 변동·클라이언트 위변조)
- 대량 배치용 Procedure + `LOOP` + 중간 `COMMIT`(락 분산)
- 4장: 질문·응답을 한 트랜잭션으로 묶는 `ask_and_log` 류 RPC
