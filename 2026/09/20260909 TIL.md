## 오늘 공부한 내용

### 트랜잭션 4가지 원칙 (ACID)

- **A — Atomicity (원자성)** : All or Nothing
- **C — Consistency (일관성)** : Keep the RULE
- **I — Isolation (격리성)** : Don't interfere — 동시 트랜잭션이 서로 간섭하지 않음
- **D — Durability (지속성)** : 낙장불입 — `COMMIT` → 영구 반영

### TCL 기본 명령

- `BEGIN;` → 트랜잭션 시작
- `COMMIT;` → 트랜잭션 종료 (DB 영구 반영)

### LangChain 프레임워크

'추상화' — 정해지지 않은, 공통적인 층을 감싸 쓰는 프레임워크.

#### 3.1 로드 / 불러오기

~~~~python
from langchain_ollama import ChatOllama
# 지시할 수 있는 프롬프트
from langchain_core.prompts import ChatPromptTemplate
~~~~

#### 3.2 ChatPromptTemplate으로 입력 템플릿 조립

- `system`: 역할, 상황, 제한 조건, 예시 → 시스템 메시지
- `user`: 사용자의 질의 → `HumanMessage(...)`
- `assistant`: AI의 답변 → `AIMessage(...)`

~~~~python
prompt_template = ChatPromptTemplate.from_messages([
    ("system", "당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 교육 전문가입니다. 2문장 이내로 친절하게 설명하세요."),
    ("user", "{user_question}")
])

user_question = "프로그래밍에서 '변수'가 무엇인가요?"
sample_prompt = prompt_template.invoke({
    "user_question": "프로그래밍에서 '변수'가 무엇인가요?"
})

sample_prompt
~~~~

#### 3.3 ChatOllama로 모델 호출

~~~~python
model = ChatOllama(
    model="exaone3.5:7.8b-instruct-q4_K_M",
    # base_url="http://localhost:11434"  # Ollama 서버 주소
)

model
response = model.invoke(sample_prompt)

response
~~~~

#### 3.4 StrOutputParser로 순수 텍스트만 추출

~~~~python
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()

# raw_response 객체에서 순수 텍스트만 추출
text = parser.invoke(response)

text
~~~~

#### 3.5 LCEL 파이프(`|`)로 체인 결합·실행

LangChain Expression Language.

~~~~python
chain = prompt_template | model | parser
res = chain.invoke({
    "user_question": "클래스(Class)에 대해서 알기 쉬운 비유를 통해 설명하세요"
})

res
~~~~

### 실시간 통신 방식 비교

| 구분 | Polling (폴링) | SSE (Server-Sent Events) | WebSocket (웹소켓) |
|------|----------------|--------------------------|--------------------|
| 통신 방향 | 단방향 (`Client → Server`) | 단방향 (`Server → Client`) | 양방향 (`Client ⇄ Server`) |
| 프로토콜 | HTTP / HTTPS | HTTP / HTTPS (텍스트 스트림) | WS / WSS (독립 프로토콜) |
| 연결 방식 | 매 주기마다 연결 수립·종료 | 1회 HTTP 연결 후 유지 (스트리밍) | 핸드셰이크 후 전이중 연결 유지 |
| 동작 원리 | 클라이언트가 주기적으로 데이터 유무 확인 | 서버 이벤트 발생 시 즉시 푸시 | 클라이언트·서버 실시간 상호 송수신 |
| 서버 부하 | 높음 (반복 요청 오버헤드) | 낮음 (단일 HTTP 커넥션 유지) | 중간 (동시다발 세션 유지 비용) |
| 자동 재연결 | 직접 구현 필요 | 브라우저 기본 내장 지원 | 직접 구현 필요 |
| 주요 활용처 | 단순 주기 갱신, 구형 시스템 연동 | LLM 토큰 스트리밍, 실시간 알림/시세 | 실시간 채팅, 멀티플레이 게임, 협업 툴 |

### Event-Driven (이벤트 기반) 개념

- **개념 정의**
  - **Polling, SSE, WebSocket**: 데이터를 주고받는 구체적인 **통신 프로토콜/전송 수단**
  - **Event-Driven**: 특정 상태 변화나 사건(Event)이 일어났을 때 감지하고 비동기적으로 반응·처리하는 **소프트웨어 설계 패러다임**
- **동작 방식의 차이**
  - **Polling (요청 기반)**: 클라이언트가 변화가 있는지 계속 능동적으로 찔러보는 구조 (`"새 데이터 있어?"`)
  - **SSE / WebSocket (이벤트 기반 구현체)**: 서버가 대기하다 이벤트가 발행(Publish)되는 순간 연결된 클라이언트로 즉시 밀어넣는(Push) 구조 (`"이벤트 발생했으니 받아가!"`)

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재(데이터베이스 & AI 활용 · 2장 5강~3장 6강)에서 가져온 내용이다.

### TCL · ROLLBACK (2장 5–6강)

- **TCL (Transaction Control Language)**: 여러 DML을 하나의 단위로 묶고, 확정(`COMMIT`) 또는 취소(`ROLLBACK`)한다.
- 트랜잭션: 더 이상 쪼갤 수 없는 작업 단위. 모두 성공하거나 모두 실패.
- `ROLLBACK`: `BEGIN` 이후 변경을 모두 취소하고 `BEGIN` 이전으로 되돌린다.
- PostgreSQL은 트랜잭션 중 한 명령이라도 오류가 나면 트랜잭션 전체를 실패 상태로 두고, `ROLLBACK` 후에야 다음 작업이 가능하다.
- 트랜잭션 없이 이어 실행하면 앞 INSERT는 이미 저장된 채 뒤 명령만 실패해 **반쪽짜리 데이터**가 남을 수 있다.

### Supabase Database · API · SDK (3장 1–2강)

- Supabase Database = PostgreSQL. 테이블을 만들면 PostgREST가 REST API를 자동 생성한다.
- SDK는 이 REST API를 함수 한 줄로 쉽게 호출하도록 감싼 도구다.
- 예: 테이블 `documents` → `https://<프로젝트>.supabase.co/rest/v1/documents`
- **Publishable key**: 공개용·제한 권한 (클라이언트, **RLS와 한 세트**)
- **service role key**: 관리자·전권 — 서버 전용, 앱/브라우저 노출 금지
- 환경: `uv add supabase python-dotenv`, `.env`에 `SUPABASE_URL` / `SUPABASE_PUBLISHABLE_KEY`, `.gitignore`에 `.env`
- `load_dotenv()` 후 `create_client(url, key)`로 Client 초기화. 연결 확인은 `select` + `response.data` (빈 리스트 `[]`도 정상).

### SDK CRUD · Auth 요약 (3장 3–6강)

- `insert({...}).execute()` — 키 = 컬럼명. 성공 시 `id`, `created_at` 등이 `response.data`에 포함.
- `select` + `eq` / `order` / `limit` 체인. 결과는 리스트(행=딕셔너리).
- `update` / `delete`에는 반드시 `.eq(...)` 조건. 조건 없으면 전체 행이 바뀌거나 삭제될 수 있다. 작업 후 `select`로 검증.
- Auth: `sign_up` / `sign_in_with_password` / `sign_out`. 로그인 사용자 `user.id`를 `user_id`에 넣어 문서와 연결.
