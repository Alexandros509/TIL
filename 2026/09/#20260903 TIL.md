## 오늘의 학습

### 도메인 무결성 제한조건

- 테이블의 속성(열) 값이 그 속성에 정의된 도메인(유효한 값의 범위 및 타입)에 속해야 한다는 규칙

### SQL 명령어 분류

1. DDL (Data Definition Language) 데이터 정의
   - `CREATE` : 정의
     - CREATE 대상
     - 테이블 생성: `CREATE 테이블명(컬럼명1 데이터타입 제약조건`[^1]`제약조건,...)`
   - `ALTER` : 변경
   - `DROP` : 삭제
     - `DROP TABLE 테이블명;`
   - `TRUNCATE`
     - 테이블의 구조 유지, 초기화 (복구가 안 되는 위험한 쿼리)
2. DML (Data Manipulation Language) 데이터 조작
   - `INSERT` : 추가
     - `INSERT INTO 테이블명(컬럼명,...) VALUES(값,...)`
   - `UPDATE` : 수정
   - `DELETE` : 삭제
   - `SELECT` : 조회
3. DCL (Data Control Language) 데이터 제어
   - `GRANT` : 권한 부여
   - `REVOKE` : 권한 회수
4. TCL (Transaction Control Language) 트랜잭션 제어
   - `COMMIT` : 데이터를 DB에 영구반영
   - `ROLLBACK` : COMMIT 전 반영 내용을 돌리기

SQL은 대소문자 구분 없이 실행됨

`---`는 Python의 `#`과 같음

제약조건 여러 개 중첩 가능

### 데이터 원자성 (Atomicity)

- All or Nothing
- 부분 실행 허용 X
- 모두 반영 / 전혀 반영 X

### 데이터 타입 / 기본키

- 데이터 타입 - 자동증감 `INT GENERATED ALWAYS AS IDENTITY`
- 대표할 수 있는 형태의 컬럼으로 2개를 묶어서 조합의 형태로 중복되지 않게
- `PRIMARY KEY(컬럼명,...)` > 여러 컬럼의 조합으로 기본키를 만드는 경우 (복합키)

### 외래키 (Foreign Key)

- 참조 무결성 제약조건이 적용
- `CREATE TABLE 테이블명(컬럼명 자료형 제약조건 REFERENCES 테이블명(컬럼명))`
- 부모 테이블 : 외래키 없음, 원본 데이터 유지
- 자식 테이블 : 외래키 존재, 부모를 참조
- 부모 쪽 테이블에 없는 참조값을 자식 테이블이 사용 X
- 부모 쪽 레코드에 자식 레코드가 있으면 부모 레코드들 삭제 X
- `ON DELETE`
  - `CASCADE` → 부모 레코드가 삭제 → 자식 레코드도 함께
  - `SET NULL` → 부모 레코드 삭제 → 자식 레코드의 참조 컬럼의 값을 NULL로 교체

### 데이터 무결성 제약조건 (Data Integrity Constraint)

1. 도메인 / 자료형
2. 개체 / 기본키
3. 참조 / 외래키

### 관계형 데이터베이스(RDBMS) 정규화

정규화 → 데이터 중복과 이상현상을 개선하기 위해서 테이블의 구조를 단계적으로 개선하는 과정

1. 제 1 정규형 (1NF)
   - 원자값 유지
   - 하나의 컬럼에 하나의 값만
2. 제 2 정규형(2NF)
   - 부분 함수 종속 제거
   - 복합 기본키의 일부가 아닌 전체에 완전 종속되도록 유지
   - 복합키의 **일부**에만 종속되는 녀석을 떼어내라!
3. 제 3 정규형(3NF)
   - 이행적 함수 종속 제거
   - 기본키가 아닌 일반 컬럼끼리 서로 종속되는 관계를 끊고 별도 테이블로 분리
   - 기본키가 아닌 일반 컬럼끼리 **다단계로 의존**하는 녀석을 떼어내라!

- **데이터 중복 및 파편화 방지**
  - 회원 정보를 여러 번 입력해 생기는 저장 공간 낭비와 데이터 흩어짐 차단
- **데이터 불일치(Inconsistency) 예방**
  - 정보(예: 개명) 수정 시 갱신 누락으로 원본을 알 수 없게 되는 오류 방지
- **단일 진실 공급원(SSOT) 구축**
  - 고유 정보는 기준 테이블(`MEMBER`) 한 곳에만 저장해 신뢰성 유지
- **외래키(FK) 최소 참조**
  - 종속 테이블(가입 이력 등)에는 상세 정보 대신 식별 가능한 최소 고유 번호(FK)만 기록
- **실시간 정보 조회(Join)**
  - 외래키를 따라 기준 테이블을 참조하여 필요한 상세 정보를 즉시 결합

~~~sql

	seq SERIAL primary key,
	user_id VARCHAR(50) unique not null,

--- MEMBERS 테이블 삭제
drop table members;

--- INSERT
insert into members( user_id ,password,user_name)
values('user01','1234','사용자01');

--- SELECT 조회
select * from members;

--- 복합키
create table CLUB_MEMBERS (
	user_seq INT,
	club_name VARCHAR(50),
	user_name VARCHAR(45),
	age INT CHECK(age<=25),
	created_at timestamptz default current_timestamp,
	primary key (user_seq, club_name)
);

drop table club_members;

insert into club_members(user_seq,club_name,user_name,age)
values(2,'전자기타','김철수','23');

select * from club_members;

truncate table members;

select * from members;

---drop table club_members;

insert into members (user_id ,user_name ,password)

delete from members where seq=2;

select * from members;

create table CLUB_MEMBERS (
	seq SERIAL primary key,
	user_seq INT references members(seq) on delete cascade,
	club_name VARCHAR(40),
~~~

## 핵심 개념

- 도메인 무결성: 열 값이 정의된 도메인의 범위·타입에 속해야 하는 규칙
- SQL은 DDL / DML / DCL / TCL 네 가지로 분류됨
- 데이터 원자성(Atomicity): All or Nothing
- 복합키: 여러 컬럼의 조합으로 기본키를 구성
- 외래키(FK): 참조 무결성 제약조건이 적용되며 부모/자식 테이블 관계를 형성

- 정규화(1NF~3NF): 데이터 중복과 이상현상을 개선하기 위해 테이블 구조를 단계적으로 개선하는 과정

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

**데이터 타입**

데이터 타입은 테이블의 각 열(Column)에 저장될 수 있는 데이터의 종류를 정의한다.

| 데이터 타입 | 설명 | 예시 |
| --- | --- | --- |
| INT | 정수형 숫자 | 나이: 25, 수량: 100 |
| VARCHAR(n) | 가변 길이 문자열 (최대 n자) | 이름: "홍길동", 이메일: "hong@example.com" |
| DATE | 날짜 (YYYY-MM-DD 형식) | 가입일: 2024-01-01 |
| DECIMAL(p, s) | 소수점이 있는 숫자 (전체 p자리, 소수점 s자리) | 가격: 29900.50 |
| BOOLEAN | 참/거짓 | 활성여부: true / false |
| TEXT | 긴 문자열 | 게시글 내용 |

**스키마(Schema)**

스키마는 데이터베이스의 구조와 제약 조건을 정의한 설계도이다. 어떤 테이블이 있는지, 각 테이블에 어떤 열이 있는지, 각 열의 데이터 타입과 제약 조건은 무엇인지를 명세한다.

**DDL과 DML**

DDL은 그릇을 만드는 것, DML은 그릇에 음식을 담는 것으로 비유한다.

**복합키(Composite Key)**

하나의 열이 아닌 여러 열을 조합하여 PK를 구성하는 경우를 복합키라 한다. 수강 신청 테이블에서 (학생 ID, 강의 ID)를 조합하면 유일한 식별자가 된다.

**자주 쓰는 제약 조건 (교재 표)**

| 제약 조건 | 설명 |
| --- | --- |
| PRIMARY KEY | 기본키. 중복 불가, NULL 불가 |
| NOT NULL | NULL 값 저장 불가 |
| UNIQUE | 중복 값 저장 불가 (NULL은 허용) |
| DEFAULT 값 | 값이 입력되지 않으면 기본값 자동 적용 |
| REFERENCES | 외래키 참조 테이블 지정 |

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
| --- | --- | --- | --- |
| SQL 분류 | DDL, DML, DCL, TCL | 1장 4강은 DDL·DML 중심. DCL·TCL은 있다는 언급 | 확인 필요 |
| CREATE 문법 | `CREATE 테이블명(...)` | `CREATE TABLE 테이블명 (...)` | 확인 필요 |
| 자동증감 | `INT GENERATED ALWAYS AS IDENTITY` | 예시는 `INT PRIMARY KEY` | 확인 필요 |
| 실습 PK | 코드는 `SERIAL primary key` | 교재 예시는 `INT PRIMARY KEY` | 확인 필요 |
| TRUNCATE | 구조 유지·초기화, 복구 안 됨 | 오늘 교재 본문에 없음 | 필기 유지 |
| 원자성 | All or Nothing | 오늘 교재 본문에 없음 | 필기 유지 |
| PK·FK·참조 무결성 | 부모/자식, ON DELETE CASCADE·SET NULL | 동일 취지 | 동일 |
| 1NF·2NF·3NF | 원자값 / 부분 종속 제거 / 이행 종속 제거 | 동일 취지 | 동일 |
| CHECK | 각주·`CLUB_MEMBERS` 코드에 있음 | 1장 4강 제약 표에는 없음 | 필기 유지 |

## 확인이 필요한 사항

⚠ 교재와 필기의 내용 차이

필기:
CREATE 문법에 TABLE 키워드 없이 `CREATE 테이블명(...)`으로 적음. 자동증감은 `INT GENERATED ALWAYS AS IDENTITY`. 실습 코드 PK는 `SERIAL`.

교재:
`CREATE TABLE 테이블명 (...)`. 예시 PK는 `INT PRIMARY KEY`.

가능한 해석:
필기는 문법 뼈대만 적었거나, PostgreSQL에서 SERIAL / IDENTITY를 따로 실습한 메모일 수 있다. 이론 메모와 코드가 한 줄로 맞춰져 있지는 않다.

추가 확인 필요

⚠ `---` 주석 표기. SQL 주석은 보통 `--`이다. 필기 문장과 코드 블록 주석은 원문 그대로 두었다.

⚠ 정규화 설명의 기준 테이블은 `MEMBER`, 실습 테이블명은 `MEMBERS`이다.

## 오늘의 학습
도메인 무결성 제한조건
- 테이블의 속성(열) 값이 그 속성에 정의된 도메인(유효한 값의 범위 및 타입)에 속해야 한다는 규칙

SQL
1. DDL (Data Definition Language) 데이터 정의
	- CREATE : 정의
		- CREATE 대상 
		  테이블 생성
			  - CREATE 테이블명(컬럼명1 데이터타입 제약조건[^1] 제약조건,...)
	- ALTER : 변경
	- DROP : 삭제
		- DROP TABLE 테이블명;
	- TRUNCATE
		- 테이블의 구조 유지, 초기화 (복구가 안 되는 위험한 쿼리)
2.  DML (Data Manipulation Language) 데이터 조작
	- INSERT : 추가
		- INSERT INTO 테이블명(컬럼명,...) VALUES(값,...)
	- UPDATE : 수정
	- DELETE : 삭제
	- SELECT : 조회
3. DCL (Data Control Language) 데이터 제어
	- GRANT : 권한 부여
	- REVOKE : 권한 회수
4. TCL (Transaction Control Language) 트랜잭션 제어

 - 부모 테이블 : 외래키 없음, 원본 데이터 유지

 - 부모 쪽 테이블에 없는 참조값을 자식 테이블이 사용 X

데이터 무결성 제약조건 (Data Integrity Constraint)

**관계형 데이터베이스(RDBMS) 정규화
-> 데이터 중복과 이상현상을 개선하기 위해서 테이블의 구조를 단계적으로 개선하는 과정
1. 제 1 정규형 (1NF)
	- 원자값 유지
	- 하나의 컬럼에 하나의 값만
2. 제 2 정규형(2NF)
	- 부분 함수 종속 제거
	- 복합 기본키의 일부가 아닌 전체에 완전 종속되도록 유지
	- 복합키의 **일부**에만 종속되는 녀석을 떼어내라!
3. 제 3 정규형(3NF)
	- 이행적 함수 종속 제거
	- 기본키가 아닌 일반 컬럼끼리 서로 종속되는 관계를 끊고 별도 테이블로 분리
	- 기본키가 아닌 일반 컬럼끼리 **다단계로 의존**하는 녀석을 떼어내라!
	
- **데이터 중복 및 파편화 방지**
    - 회원 정보를 여러 번 입력해 생기는 저장 공간 낭비와 데이터 흩어짐 차단
- **데이터 불일치(Inconsistency) 예방**
    - 정보(예: 개명) 수정 시 갱신 누락으로 원본을 알 수 없게 되는 오류 방지
- **단일 진실 공급원(SSOT) 구축**
    - 고유 정보는 기준 테이블(`MEMBER`) 한 곳에만 저장해 신뢰성 유지
- **외래키(FK) 최소 참조**
    - 종속 테이블(가입 이력 등)에는 상세 정보 대신 식별 가능한 최소 고유 번호(FK)만 기록
- **실시간 정보 조회(Join)**
    - 외래키를 따라 기준 테이블을 참조하여 필요한 상세 정보를 즉시 결합

~~~SQL
create table MEMBERS(

seq SERIAL primary key,

user_id VARCHAR(50) unique not null,

);
~~~
