### 5. JavaScript 함수의 실행 원리와 객체 지향 문법

#### 5.1 함수의 정의, 실행 과정 및 고급 함수 기법

1. function

~~~javascript
function 함수명(매개변수, ...) {
  // 수행할 코드
  return 반환값;
}
~~~

- 함수명: 함수 객체의 이름표 (변수와 같다!)
- **일급 객체 (First-class Object)**: 변수 할당, 함수 인자 전달, 반환값 사용이라는 세 가지 자유를 완전히 누릴 수 있는 모든 값
- **일급 함수 (First-class Function)**: 함수를 일반 숫자나 문자열처럼 '값'으로 취급하여 인자 전달과 반환이 자유로운 언어적 특성

2. 함수의 실행 평가 과정
   - 실행 가능한 객체로 함수를 번역하는 과정
   - 실행 가능한 객체: EC (Execution Context) 객체
   - EC: 실행 문맥

**클로저**

- 유효범위 체인 (scopes)

### 객체 상속

1. 프로토타입 기반의 객체 간의 상속 (프로토타입 체인)
2. 생성자 함수
   - 객체를 생성하는 함수
   - 네이밍 관례: 첫 글자를 대문자
   - `new` 연산자
     - `const p1 = new Person();`
   - 참고: [MDN Function](https://developer.mozilla.org/ko/docs/Web/JavaScript/Reference/Global_Objects/Function)
3. 생성자 함수가 객체를 생성하는 과정 (`new` ...)

⚠ 교재와 필기의 내용 차이

필기:
1. 생성자 함수의 prototype 객체 상속
2. 생성자 함수의 this를 생성된 객체의 주소로 변경하고 (= 값의 할당)

교재 (FE_12, new 4단계):
1. 빈 객체 생성
2. 프로토타입 링크 연결 (`newObj.__proto__ = 생성자.prototype`)
3. this 바인딩 및 함수 실행
4. 인스턴스 반환

가능한 해석:
필기는 2·3단계(프로토타입 연결 + this 바인딩·할당) 위주로 적었고, 1단계(빈 객체 생성)·4단계(반환)는 생략했을 수 있다. 필기 단계를 임의로 교체하지 않고 아래에 교재 보충으로 둔다.

추가 확인 필요

4. `생성자.prototype.메서드`
   - 객체가 생성되면 공유하는 메서드 (인스턴스 메서드)
5. `생성자.메서드`
   - 객체 생성 없이 공유하는 메서드 (정적 메서드)

### 데이터 프로퍼티 · 접근자 프로퍼티

**데이터 프로퍼티**

- `value`: 값
- `writable`: 변경 가능 여부
- `enumerable`: 열거 가능 여부
  - `for ... in`
  - `Object.keys()` → false이면 객체의 속성이 노출되지 않음
- `configurable`
  - 재정의 가능 여부 (설정을 변경할 수 있는가?)
  - false: 삭제도 불가

**접근자 프로퍼티**

- `get` 함수: 읽기
- `set` 함수: 쓰기
- `enumerable`: 열거 가능 여부
- `configurable`: 재정의 가능
- get, set 함수 → 내부 속성 통제. 은닉은 다른 기법(클로저 — 캡슐화)

### 참고: 즉시 실행 함수 (IIFE)

- 정의 → 즉시 호출
- `(function 함수명(생략)(...) {})();`

~~~javascript
(function(num1, num2) {
  console.log("즉시 실행되나요?", num1, num2);
})(10, 20);
~~~

⚠ 교재와 필기의 내용 차이

필기:
즉시 실행 함수(IIFE) 문법·예시를 「참고」로 적어 두었다.

교재:
오늘 범위 교재(FE_10 / FE_11 / FE_12)에 IIFE 전용 절은 없다. FE_11의 「즉시 실행」은 `call`/`apply`가 함수를 바로 실행한다는 뜻으로 쓰인 표현이다.

가능한 해석:
수업·검색 메모로 남긴 참고일 수 있다. 필기 분량만 유지하고 교재식 확장은 하지 않는다.

추가 확인 필요

### Object.seal · Object.freeze

**`Object.seal(...)`**: 객체 밀봉 → `Object.preventExtensions(...)` 적용 ⇒ 속성 추가 방지

1. 속성 추가 X
2. 속성 삭제 X
3. 속성 변경 가능

**`Object.freeze(...)`**: 객체 동결

1. 속성 추가 X
2. 속성 삭제 X
3. 속성 변경 X

### 직렬화 · JSON · 복사

**직렬화 (serialization)**

- 전송 가능한 형태로 변환 (JSON 문자열)

⚠ 교재와 필기의 내용 차이

필기:
함수, undefined — 변환 불가 → **null로 대체**

교재 (FE_12):
함수(function)나 undefined 타입은 직렬화 대상에서 **제외**된다.

가능한 해석:
배열 요소의 `undefined`가 `null`로 바뀌는 경우와, 객체 프로퍼티에서 키가 빠지는 경우를 묶어 메모했을 수 있다. 표기를 하나로 단정하지 않고 필기·교재를 병기한다.

추가 확인 필요

**JSON 객체**

- 자바스크립트 객체 → JSON 문자열 (직렬화)
  - `stringify(...)`
- JSON 문자열 → 자바스크립트 객체 (역직렬화)
  - `parse(...)`

**복사**

- 주소만 복사: 얕은 복사
- 깊은 복사: 새로운 객체 + 내용도 복사

## 핵심 개념

- 객체 리터럴 `{키:값}`. 키는 변수명 규칙. 값은 원시 / 객체 타입
- 속성 접근 `.` / `[]`, 추가·수정은 대입, 삭제는 `delete`
- 함수는 일급 객체·일급 함수. EC(Execution Context) = 실행 문맥
- 클로저 · 유효범위 체인 (scopes)
- 프로토타입 체인. 생성자(첫 글자 대문자) + `new`. prototype 메서드(인스턴스) vs 생성자 메서드(정적)
- 데이터 프로퍼티: value / writable / enumerable / configurable. 접근자: get / set
- IIFE: 정의 즉시 호출 (필기 참고. 오늘 교재 전용 절 없음)
- `Object.seal`(추가·삭제 X, 변경 O) / `Object.freeze`(추가·삭제·변경 X)
- JSON `stringify` / `parse`. 얕은 복사 vs 깊은 복사

### FE_10 (4장 3강) — 객체 리터럴 · 프로퍼티

- 객체: 이름(Key)과 값(Value)을 한 쌍으로 묶은 복합 데이터 타입. 빈 객체 `{}`
- 프로퍼티: 객체에 포함된 데이터 하나(키–값 쌍)
- `.` : `객체.키`. `[]` : `객체['키']` (문자열 키). 없는 프로퍼티 읽기 → `undefined`
- 추가: 없는 키에 대입. 수정: 있는 키에 대입. 삭제: `delete 객체.키`
- 객체는 참조 타입. 변수에 대입하면 값 복제가 아니라 주소(참조)가 공유된다 (어제의 복습 card 예와 동일 맥락)

### FE_11 (5장 1강) — 함수 · 일급 · 실행 문맥 · 클로저

- 함수 구성: 함수 이름, 매개변수(Parameter), 함수 바디, 반환값(Return), 인수(Argument)
- 일급 객체의 3대 권리: 변수 할당 / 인자로 전달(콜백) / 반환값으로 사용 — 필기 「세 가지 자유」와 동일 방향
- 엔진은 평가 단계(선언·식별자 등록)와 실행 단계를 구분한다. 호출 스택에 쌓이는 실행 정보가 **실행 문맥**
- 클로저: 외부 함수가 끝나 스택에서 제거되어도, 반환된 내부 함수가 외부 지역 변수를 계속 참조하면 그 변수 공간은 유지된다

### FE_12 (5장 2강) — new · 프로퍼티 · 잠금 · JSON · 깊은 복사

- `new` 4단계: ① 빈 객체 생성 → ② 프로토타입 링크 연결 → ③ this 바인딩·생성자 실행 → ④ 인스턴스 반환
- `생성자.prototype`에 올린 메서드는 인스턴스가 공유. 생성자 함수에 직접 붙인 메서드는 정적(객체 생성 없이 호출) 쪽에 가깝다
- `Object.getOwnPropertyDescriptor(객체, "키")`로 value·writable·enumerable·configurable 명세 조회
- 잠금 3단계: `preventExtensions`(추가만 차단) / `seal`(추가·삭제 차단, 값 변경은 가능) / `freeze`(추가·삭제·값 변경 모두 차단)
- `JSON.stringify` = 직렬화, `JSON.parse` = 역직렬화. 함수·undefined는 직렬화에서 제외(교재 표현)
- 중첩 객체에서 단순 대입은 얕은 복사(참조 공유). `JSON.parse(JSON.stringify(obj))`로 참조를 끊은 복사본을 만드는 기법이 교재에 있다 (함수·undefined·순환 참조 등은 한계)

## 확인이 필요한 사항

⚠ `#### 4.1 JavaScript 개발 환경 구성` — 제목은 환경 구성인데 본문은 객체 리터럴이다. 커리큘럼상 객체 리터럴은 4장 3강. 제목 번호를 고칠지, 라벨만 바꿀지 확인.

⚠ `new` 과정 — 필기 2단계 vs 교재 4단계. 수업에서 1·4단계를 말했는지, 필기만 줄였는지 확인.

⚠ 직렬화 — 필기 「함수·undefined → null로 대체」 vs 교재 「제외」. 배열/`null` 치환과 객체 키 생략을 혼동했는지 확인.

⚠ IIFE — 필기에만 있는 참고. 오늘 교재(FE_10~12) 전용 절 없음. 어디서 들었는지 확인.

⚠ `Object.seal` 설명의 「`preventExtensions` 적용」 — 교재는 seal을 추가·삭제 차단(값 변경은 가능)으로 정리하고, preventExtensions는 「추가만 차단」인 별도 단계다. seal ⊃ preventExtensions 느낌의 메모인지 확인.

## 필기 누락 가능성

다음 내용은 오늘 범위 교재에는 있으나, 필기에는 키워드만 있거나 없다. 수업에서 다루었다면 놓쳤을 수 있다.

- `new` 4단계 중 빈 객체 생성·인스턴스 반환
- `Object.getOwnPropertyDescriptor` / `Object.defineProperty`
- `Object.preventExtensions`를 seal·freeze와 구분한 3단계 잠금
- 클로저 코드 예시(외부 변수 은닉)
- JSON으로 깊은 복사하는 구체적 패턴과 한계
