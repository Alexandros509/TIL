## 어제의 복습

1. 생성자 함수 내부에서 `this.area = function() {...}` 형태로 메서드를 정의할 때 발생하는 가장 큰 구조적 문제점
   - 인스턴스를 생성할 때마다 동일한 함수가 메모리에 중복 생성되어 자원이 낭비
2. 객체에 존재하지 않는 프로퍼티나 메서드에 접근했을 때, 자바스크립트 엔진이 내부 링크(`__proto__`)를 따라 상위 객체들을 차례로 검색하는 연결 구조
   - 프로토타입 체인
3. 클래스(class) 구문과 일반 생성자 함수(function)를 비교한 설명으로 옳은 것
   - 클래스는 `new` 없이 호출하면 TypeError가 발생하지만, 생성자 함수는 `new` 없이 호출해도 에러 없이 전역 객체를 오염시킬 수 있다
4. 자식 클래스의 constructor 내부에서 부모 클래스의 속성을 초기화하고 `this`에 정상적으로 접근하기 위해 반드시 먼저 호출해야 하는 구문
   - `super()`
5. 객체 내부에 중첩된 객체가 있을 때, `JSON.stringify`와 `JSON.parse`를 연속으로 적용하여 참조 주소를 공유하지 않는 완전히 독립적인 복사본을 만드는 기법
   - 깊은 복사

#### 5. 화살표 함수 (Arrow Function)

##### 5.1 정의 방법 및 스코프 생략 규칙

- `function` 키워드 생략
- 매개변수 정의부와 코드 실행 영역 (`{}`) 사이에 `=>` 로 표기
- 코드 구현 부분이 한 줄이면 `{}` 생략 가능, `return`도 생략해야 한다
- 변수명도 한 글자면 충분
- 매개변수가 1개면 생략 가능, 없거나 2개 이상이면 불가

~~~javascript
function square(num) {
  return num * num;
}
const square2 = (num) => {
  return num * num;
};

square2(10);
// const square3 = (num) => num * num;
// const square3 = (x) => x * x;
const square3 = x => x * x;
square3(10);

const person = {
  name: "Dude",
  age: 23,
  showInfo() {
    console.log("this", this);
  }
};
person.showInfo();

const person = {
  name: "Dude",
  age: 23,
  showInfo: () => {
    console.log("this", this);
  }
};
person.showInfo();
~~~

##### 5.2 화살표 함수의 제한 사항

- 생성자 함수 사용 불가
- `arguments` 객체 미지원
- `yield` 사용 불가

※ 교재 FE_11 (5장 1강)은 화살표 제한에서 `yield` 사용 불가(제너레이터로 구성 불가)만 언급한다. 제너레이터 본문은 필기에서 별도 정리(아래 「제너레이터」).

##### 5.3 일반 함수 vs 화살표 함수의 this 바인딩 비교

- 일반 함수 vs 화살표 함수의 `this` 바인딩 비교
- 화살표 함수의 `this` : 함수가 정의되는 시점에 이미 결정되어 있는 `this`로 정의됨

~~~javascript
const person = {
  name: "Dude",
  age: 23,
  showInfo() {
    const f = () => { // this는 알 수 없지만, 명확하게 showInfo가 호출되어야 정의되므로 this는 showInfo의 this와 같다.
      console.log("this", this);
    };
    f();
  }
};
person.showInfo();
~~~

#### 6. 자바스크립트 실행 평가 과정과 클로저 (Closure)

※ 필기는 소제목만. 아래 설명은 FE_11 사실로만 채움(본문에만 둠 · 「교재 보충」에 재서술하지 않음).

##### 6.1 엔진의 2단계 제어 프로세스

- 1단계: 평가 단계 (Creation/Evaluation Phase) — 식별자 등록(호이스팅 배경)
- 2단계: 실행 단계 (Execution Phase) — 값 주입·호출

##### 6.2 데이터 정렬과 호출 스택 (Call Stack)의 동작 방식

- 호출 스택 **LIFO**: 호출 시 Push, 종료·`return` 시 Pop 후 아래 함수로 복귀. FIFO와 대비.

##### 6.3 클로저 (Closure)의 생성과 작동 원리

- 외부 함수가 스택에서 제거되어도, 반환된 내부 함수가 외부 지역 변수를 참조하면 그 공간이 유지됨(클로저). 은닉(캡슐화)에 사용.

#### 팩토리 함수 · 고차 함수 (Higher-Order Function)

~~~javascript
// 고차 함수(Higher Order Function): 함수를 반환하는 함수
function add(x) {
  return function(y) {
    return function(z) {
      return x + y + z;
    };
  };
}

// 연속 호출 (Currying)
add(10)(20)(30); // 60

// 첫 번째 값이 10으로 고정된 새로운 함수 생성 -> 팩토리 함수 역할
const add10 = add(10);
~~~

#### Function.prototype · this를 바꿔 함수를 다루는 3형제

`function abc(a, b) {}`

- `abc = new Function(정의..);`
  - 모든 함수 객체는 `Function.prototype`을 상속받는다
  - `Function.prototype`에 정의된 기능 사용 가능

- `Function.prototype.apply()`
- `Function.prototype.bind()`
- `Function.prototype.call()`

| 메서드 | 하는 일 | 인수 형태 | 호출 시점 |
|---|---|---|---|
| `call` | 지금 바로 실행 | 나열 `fn.call(thisArg, a, b)` | 즉시 |
| `apply` | 지금 바로 실행 | 배열 `fn.apply(thisArg, [a, b])` | 즉시 |
| `bind` | 새 함수만 만듦 | 나열 `fn.bind(thisArg, a)` | 나중에 |

##### 7. 명시적 this 바인딩 (call, apply, bind)

**`call()`**

- 지정한 `this` + 개별 인수로 **즉시 호출**
- 다른 객체의 메서드·생성자를 빌려 쓸 때
- `Product.call(this, name, price)`처럼 생성자 체이닝

**`apply()`**

- `call`과 같음. 차이점은 인수를 **배열(또는 유사 배열)** 로 넘김
- `Math.max.apply(null, numbers)`처럼 배열을 가변 인수로 펼칠 때
- 지금은 보통 스프레드 `Math.max(...numbers)`로 대체

**`bind()`**

- 실행하지 않음. `this`(와 앞쪽 인수)가 **고정된 새 함수**를 반환
- 콜백에서 `this`가 끊길 때 (`setTimeout(obj.method.bind(obj))`)
- 일부 인수를 미리 박아 두는 부분 적용(partial application)

한 줄: **지금 실행 = `call`/`apply`, 나중에 쓸 함수 만들기 = `bind`.** `call`은 인수 나열, `apply`는 인수 배열.

#### 제너레이터

`function* ...() { yield }`

**제너레이터 = 멈췄다 다시 이어가는 함수**

`function*`로 선언. 호출하면 바로 실행되지 않고 **이터레이터(Generator 객체)** 를 반환.
`yield`에서 일시 정지. `next()` 호출 시 그 지점부터 재개. 지역 변수 상태 유지.

※ 범위: 교재 5-1은 화살표 `yield` 금지만. 아래는 필기 상세.

~~~javascript
function* gen() {
  yield 1
  yield 2
  return 3
}

const g = gen()
g.next() // { value: 1, done: false }
g.next() // { value: 2, done: false }
g.next() // { value: 3, done: true }
~~~

| 키워드 | 역할 |
|---|---|
| `function*` | 제너레이터 함수 선언 |
| `yield 값` | 값 내보내고 일시 정지 |
| `yield*` | 다른 제너레이터·이터러블에 위임 |
| `next(x)` | 재개. `x`는 직전 `yield`의 결과값이 됨 |
| `return` / 끝 | `{ value, done: true }` |

**일반 함수와의 차이**

- 일반: 한 번에 끝까지 실행, 값 하나 `return`
- 제너레이터: `yield`마다 값 생산, 호출자는 `next()`로 소비
- `for...of`, 스프레드, 구조 분해에 바로 사용 가능 (`iterable`)

**자주 쓰는 패턴**

- 지연 시퀀스 (무한 카운터, 페이지네이션)
- 큰 데이터를 한 번에 만들지 않고 하나씩 생산
- `next(값)`으로 바깥에서 안쪽으로 값 주입

~~~javascript
function* idMaker() {
  let i = 0
  while (true) yield i++
}
const ids = idMaker()
ids.next().value // 0
ids.next().value // 1
~~~

참고: `new`로 생성자처럼 쓰면 TypeError. `async function*`는 비동기 제너레이터 (`for await...of`).

### 배열 (Array)

- 같은 자료형 + 연속된 공간 구성

**배열 객체 (Array Object)**

- 모든 타입의 값을 지정 가능
- 여러 개 관리
  - 데이터 군집 (컬렉션 중 하나)

1. Array 생성자 함수 생성
   - 매개변수 1 → 0 이상의 정수 → 배열 요소의 개수
   - ⚠ 원문의 의미가 모호합니다. 필기: 「매개변수 2 → 문제」 (복수 인수일 때 요소로 채우는 쪽인지, 주의점인지 원문만으로는 단정하지 않음)
2. `Array.prototype` 상속 여부
3. `instanceof` 객체의 상속 관계 체크
   - 프로토타입 체인 관계
4. `[...]` = `new Array(...)` 동일
5. 주요 메서드
   - **추가**
     - `push(...)` : 요소의 끝에 추가
     - `unshift(...)` : 요소의 앞에 추가
     - `splice(...)` : 지정된 위치의 요소를 추가 또는 삭제
   - **삭제**
     - `pop(...)` : 끝 요소를 꺼낸다 (반환, 제거)
     - `shift(...)` : 앞 요소를 꺼낸다 (반환, 제거)
     - `splice(...)` : 중간을 잘라 빼거나 끼워 넣는 메서드
   - **수정 → 새로운 배열 객체 반환**
     - `map(callback 함수)` : callback 함수 정의 내용대로 변경
     - `filter(callback 함수)` : callback 함수 정의 내용대로 필터
   - **조회**
     - `forEach(callback 함수)`
     - `indexOf(...)` : 요소의 위치 번호 (왼쪽→오른쪽)
     - `lastIndexOf(...)` : 요소의 위치 번호 (오른쪽→왼쪽)
   - **`Symbol.iterator`**
     - 객체를 **이터러블(iterable)** 로 만드는 잘 알려진 심볼
     - `for (... of ...)`
     - `obj[Symbol.iterator]()` 가 **이터레이터(iterator)** 를 반환해야 함
     - 이터레이터 = `{ next() }` 객체. `next()` → `{ value, done }`
     - 내장 이터러블: `Array`, `String`, `Map`, `Set`, `TypedArray`, `arguments`, 제너레이터
     - `for...of`, 스프레드 `[...x]`, 구조 분해가 이 메서드를 호출

| | `forEach` | `indexOf` / `lastIndexOf` |
|---|---|---|
| 목적 | 전부 돌며 부수 효과 | 위치 찾기 |
| 반환 | `undefined` | 숫자 인덱스 또는 `-1` |
| 중단 | 불가 | 첫/마지막 발견 시 끝 |

- **반복자(이터레이터)**
  - 값을 **하나씩** 꺼내는 객체
  - 제너레이터(`function*`)는 이터레이터를 자동으로 구현 (`yield` = `next()`에 값 공급)

- `for (const x of iterable)`
  - 이터러블의 **값**을 순회 (`for...in`은 **키**)
  - 내부적으로 `Symbol.iterator()` → 반복 `next()` → `done === true`면 종료
  - `break` / `return` / `throw`로 중단 가능 (`forEach`와 차이)

| | `for...of` | `for...in` | `forEach` |
|---|---|---|---|
| 대상 | 이터러블 **값** | 열거 가능 **키** | 배열 요소 |
| 프로토콜 | `Symbol.iterator` | 열거 속성 | 배열 메서드 |
| 중단 | `break` 가능 | `break` 가능 | 불가 |

## 핵심 개념

- 매개변수 기본값 / `arguments` / Rest(`...params`) / 전개 연산자 / 비구조화 할당
- 함수 선언문(호이스팅 O) vs 표현식(`const`·TDZ, 선언 전 호출 X)
- 일급 객체 3대 속성: 변수 할당 · 매개변수 전달(콜백) · 반환값
- 화살표: `=>`, 생략 규칙, 생성자/`arguments`/`yield` 불가, `this`는 정의 시점(상위 스코프)
- 평가·실행 2단계, 호출 스택(LIFO), 클로저(외부 변수 유지·은닉)
- 고차 함수·커링·팩토리 (`add(10)(20)(30)`, `add10 = add(10)`)
- `call`/`apply`(즉시) vs `bind`(새 함수). 인수 나열 vs 배열
- 제너레이터 `function*` · `yield` · `next()` · iterable
- 공통 객체(네이티브·내장 생성자) / 호스트 객체. Number·`isNaN`·`parseInt`/`parseFloat`. JSON·Math. 원시 래퍼
- Array: 생성·prototype·`instanceof`. push/unshift/splice · pop/shift · map/filter · forEach/indexOf/lastIndexOf · `Symbol.iterator`
- `for...of`(값) vs `for...in`(키) vs `forEach`(중단 불가)

| | `unshift(값)` | 맨 앞 추가 | 예 |

| | `reverse()` | 순서 역순 | 예 |

**Math 주요 메서드**

| 메서드 | 기능 | 예 | 결과 |
|---|---|---|---|
| `Math.abs(x)` | 절댓값 | `Math.abs(-5)` | `5` |

| `Math.ceil(x)` | 올림 | `Math.ceil(4.1)` | `5` |

**JSON**

- `JSON.stringify(value[, replacer[, space]])` : 직렬화. `space`로 들여쓰기 가능
- `JSON.parse(text[, reviver])` : 역직렬화

**원시 래퍼**

- 원시값에 `.`으로 메서드 접근 시 엔진이 임시 래퍼 객체 생성(자동 박싱) → 메서드 실행 → 임시 객체 소멸(언박싱)
- `new String()` / `new Number()` / `new Boolean()` 직접 생성은 객체 타입이 되어 `===`·조건식에서 의도치 않은 결과가 날 수 있어 지양(교재)
