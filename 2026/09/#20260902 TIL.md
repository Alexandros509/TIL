### 5장 SQL & 데이터베이스

### 1.1 SQL, Data 기초

- 데이터 : 처리되지 않은 값(원시 값)
- 정보 : 데이터에 의미 부여
- DBMS(DataBase Management System) : 데이터를 관리하는 소프트웨어
- SQL (Structured Query Language) : 문법적 규칙
- 쿼리 : 데이터베이스에 보내는 질문, 질의
- RDBMS (Relational) : 테이블 간의 관계

DBMS 종류

| DBMS | 라이선스 |
| --- | --- |
| MySQL | 오픈소스 |
| Oracle | 유료 |
| MSSQL | 유료 |
| PostgreSQL | 오픈소스 |

테이블 구조

- 테이블(Table) : 데이터를 저장하기 위한 공간 (행과 열로 구성된 2차원 구조)
- 행 (Row/Record)
- 열 (Column/Field/속성)
- 셀 : 각각의 데이터 (주문 번호, 주문 상품)
- 스키마(Schema) : 테이블 구조와 제약 사항을 정의한 명세서

### 1.2 데이터베이스 구조

데이터 무결성 제약 조건

1. 도메인 무결성 제약 조건 (동일 컬럼 동일한 자료형)
2. 개체 무결성 제약 조건 (기본 키 제약 조건)
3. 참조 무결성 제약 조건

자료형 (Data Type)

1. 숫자형
   - 정수 : `SMALLINT`(2byte), `INT`(4byte), `BIGINT`(8byte)
   - 실수 : `REAL`(4byte), `DOUBLE PRECISION`(8byte), `DECIMAL(p, s)` (p - 전체 자리수, s - 소수점 자리수)
2. 문자형
   - `CHAR(자리수)` : 고정 사이즈 문자
   - `VARCHAR(최대 자리수)` : 최대 자리수만큼의 문자 (최대를 넣지 않으면 문자 크기만큼만 공간 할당)
   - `TEXT` : 여러 줄 텍스트 (길이 제한 X, 가변 문자열)
3. 논리형 `BOOLEAN` : TRUE, FALSE, NULL (1byte)
4. 날짜와 시간
   - `DATE` : 날짜
   - `TIME` : 시간
   - `TIMESTAMP` : 날짜+시간
   - `TIMESTAMPZ` : (Zone) 날짜+시간+시간대 (기본적으로 UTC+0)
5. JSON
   - `JSONB` : 바이너리로 저장된다 → 속도가 빠르다
   - `JSON`
6. 기타
   - `ENUM` : 열거형 - `ENUM('READY', 'ORDER', ...)`
     - 주문상태 예시 : READY, ORDER, IN_CASH, DELIVERY
   - `vector(차원수)` : 나중에 벡터 DB 사용할 때 쓰는 자료형

## 핵심 개념

- 트랜스포머는 인코더(BERT), 인코더-디코더(BART), 디코더(GPT, Gemma) 구조로 나뉜다
- 토크나이저는 토큰을 나누는 기능이며 BPE, 센텐스피스 방식이 있다
- 데이터는 처리되지 않은 원시 값이고, 정보는 데이터에 의미가 부여된 것이다
- RDBMS는 테이블 간의 관계로 구성된다
- 데이터 무결성 제약 조건에는 도메인/개체/참조 무결성이 있다
- 기본키(PK)는 중복을 허용하지 않고 NULL을 가질 수 없다

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

**BPE (Byte Pair Encoding)**
자주 등장하는 글자 쌍을 반복해서 합쳐가며 어휘 사전을 만드는 방식으로, GPT나 Llama, Gemma 같은 최근 LLM들이 기반으로 삼고 있다.

**센텐스피스 (SentencePiece)**
띄어쓰기가 없어도 처리할 수 있는 독립형 전처리 라이브러리로, 공백을 별도 기호로 다루기 때문에 띄어쓰기가 불규칙한 한국어나 띄어쓰기가 없는 중국어·일본어 처리에도 잘 맞는다.

**Gemma**
리소스가 제한된 환경에서도 자연스럽게 문장을 생성하고 대화할 수 있도록 구글이 만든 경량 오픈소스 LLM이다.
