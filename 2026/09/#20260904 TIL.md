### DDL (데이터 정의어)

데이터 삭제 시 복구 불가 (`ROLLBACK` 불가)

1. CREATE
    - `CREATE [TABLE, INDEX, TYPE...]`
2. DROP
    - `DROP [TABLE, INDEX, TYPE]`
3. TRUNCATE
    - `TRUNCATE TABLE 테이블명;`
    - 테이블의 데이터를 비운다 (초기화)
4. ALTER
    - `ALTER TABLE 테이블명 ADD COLUMN 컬럼명 자료형 [제약조건];`
    - `ALTER TABLE 테이블명 RENAME COLUMN 기존컬럼명 TO 변경컬럼명;`
    - `ALTER TABLE 테이블명 DROP COLUMN 컬럼명;`
    - `ALTER TABLE 테이블명 ALTER COLUMN 컬럼명 TYPE 자료형;` (데이터 타입 변경: 구조 변경, 데이터가 없는 경우)
    - `ALTER TABLE 테이블명 ALTER COLUMN 컬럼명 TYPE 자료형 USING (컬럼명::자료형);` (데이터가 존재하고 형변환이 필요한 경우)
    - `ALTER TABLE 테이블명 ALTER COLUMN 컬럼명 SET 제약조건명/DEFAULT`
    - `ALTER TABLE 테이블명 ALTER COLUMN 컬럼명 DROP 제약조건명/DEFAULT`
    - `ALTER TABLE 테이블명 ADD CONSTRAINT 제약조건구분이름 PRIMARY KEY (컬럼명, ...);`
    - `ALTER TABLE 테이블명 ADD CONSTRAINT 제약조건구분이름 UNIQUE (컬럼명);`
    - `ALTER TABLE 테이블명 ADD CONSTRAINT 제약조건구분이름 CHECK (조건식);`
    - `ALTER TABLE 테이블명 ADD CONSTRAINT 제약조건구분이름 FOREIGN KEY (현재 테이블의 컬럼명) REFERENCES 참조 테이블명(컬럼명);`
    - `ALTER TABLE 테이블명 DROP CONSTRAINT 제약조건구분이름;`

### 테이블 관계도 기본 표기

- 1:1 테이블 관계도: `-|----|-`
- 1:N: `-|---o<-` (N은 0개 이상: 없어도 됨)
- 1:N: `-|---|<-` (N은 1개 이상: 필수)
- 1:N: `-|----<-`
- N:M: `-|-<--ㅁ-->-|-`

### DML (데이터 조작어)

1. INSERT (추가)
    - `INSERT INTO 테이블명 (컬럼명, ...) VALUES (값1, ...), (값2, ...);`
    - 모든 컬럼이고 순서대로 추가하는 경우는 컬럼명 생략 가능.
2. UPDATE (수정)
    - `UPDATE 테이블명 SET 컬럼명 = 변경할 값, 컬럼명2 = 변경할 값, ...`
3. DELETE (삭제)
4. SELECT (조회)

## 찾아본 내용

### ERD 까마귀 발 표기법 (Crow's Foot Notation)

관계선 양 끝의 **최소 참여도(0 or 1)** 와 **최대 카디널리티(1 or N)** 기호 조합을 통해 엔티티 간 관계를 표현한다.

### 1. 기본 구성 기호

선 끝 표식 중 **안쪽은 최소값(Min)**, **바깥쪽(엔티티 접촉부)은 최대값(Max)** 의미

| 기호 | 명칭 | 의미 | 설명 |
| --- | --- | --- | --- |
| `\|` | 선 (Dash) | 1 (One) | 정확히 1개 존재 |
| `o` | 원 (Circle) | 0 (Zero) | 존재하지 않을 수 있음 (선택적 / Optional) |
| `<` / `>` | 까마귀 발 (Crow's Foot) | N (Many) | 여러 개 존재 (다수 / Multiple) |

### 2. 관계선 끝 단일 엔티티 기준 표기 (4가지 기본 패턴)

| 표기 | 카디널리티 범위 | 명칭 | 상세 의미 |
| --- | --- | --- | --- |
| `-\|-` | 1 | **1 (Mandatory One)** | 정확히 1개 필수 |
| `-o\|-` | 0 .. 1 | **0 or 1 (Optional One)** | 없거나 최대 1개 (선택적) |
| `-\|<` | 1 .. N | **1 or More (Mandatory Many)** | 최소 1개 이상 다수 (필수) |
| `-o<` | 0 .. N | **0 or More (Optional Many)** | 없거나 여러 개 (선택적) |

### 3. 엔티티 간 관계(Relationship) 전체 패턴

**(1) 1 : 1 관계 (One-to-One)**

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| --- | --- | --- |
| `-\|----\|-` | 1 : 1 (양쪽 필수) | 양쪽 엔티티가 서로 정확히 1개씩 연결 *(예: 대한민국 국민 - 주민등록식별정보)* |
| `-\|----o\|-` | 1 : 0..1 (한쪽 선택) | A는 B가 없을 수 있으나, B는 반드시 A가 존재 *(예: 회원 `-\|` - `o\|-` 프로필상세)* |
| `-o\|----o\|-` | 0..1 : 0..1 (양쪽 선택) | 양쪽 모두 상대방 레코드 없이 단독 존재 가능 *(예: 사원 `-o\|` - `o\|-` 주차구역)* |

**(2) 1 : N 관계 (One-to-Many)**

가장 빈번하게 사용되는 데이터 모델링 패턴

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| --- | --- | --- |
| `-\|----o<-` | 1 : 0..N | 부모 필수(1), 자식 0개 이상 (가장 일반적) *(예: 고객 `-\|` - `o<-` 주문)* (주문 없는 고객 가능) |
| `-\|----\|<-` | 1 : 1..N | 부모 필수(1), 자식 최소 1개 이상 필수 *(예: 주문 `-\|` - `\|<-` 주문상품상세)* (상세 없는 주문 불가) |
| `-o\|----o<-` | 0..1 : 0..N | 부모 0..1개, 자식 0개 이상 *(예: 부서 `-o\|` - `o<-` 사원)* (부서 미배정 사원 허용, FK Nullable) |
| `-o\|----\|<-` | 0..1 : 1..N | 부모 선택적, 자식이 존재할 경우 그룹 형성 |

**(3) N : M 관계 (Many-to-Many)**

논리 모델링 표현 방식 / 물리 모델링 시 매핑(교차) 테이블을 통해 1:N 관계로 변환 필수

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| --- | --- | --- |
| `-o<----o<-` | 0..N : 0..N | 양쪽 모두 비어 있을 수 있는 순수 다대다 *(예: 학생 `-o<` - `o<-` 동아리)* |
| `-\|<----o<-` | 1..N : 0..N | 한쪽 최소 1개 이상 필수, 상대방 0개 이상 *(예: 과목 `-\|<` - `o<-` 수강생)* |
| `-\|<----\|<-` | 1..N : 1..N | 양쪽 모두 최소 1개 이상 필수 연결 |

**(4) 특수 관계**

- **물리적 N:M 해소 (중간 매핑 테이블 활용)**

~~~text
[테이블 A] -|---o< [매핑 테이블] >o---| [테이블 B]
~~~

- **자기 참조 관계 (Recursive / Self-Referencing)**
  동일 테이블 내 계층 구조(조직도, 카테고리 등) 표현

~~~text
[카테고리] -o|---+ (상위 카테고리: 0..1)
             |
             +---o< (하위 카테고리: 0..N)
~~~

### 4. 식별 관계 vs 비식별 관계 (선 형태)

| 선 종류 | 명칭 | 의미 |
| --- | --- | --- |
| **실선 (`───`)** | **식별 관계 (Identifying)** | 부모의 기본키(PK)가 자식의 **기본키(PK) 일부**로 전이 (부모 없이 자식 식별 불가) |
| **점선 (`- - -`)** | **비식별 관계 (Non-Identifying)** | 부모의 기본키(PK)가 자식의 **일반 외래키(FK)** 로만 참조 (자식 독자 PK 보유) |

## 핵심 개념

- PostgreSQL 따옴표: 작은따옴표(`''`)는 문자열 리터럴, 큰따옴표(`""`)는 특수문자·대소문자 혼용·예약어용 구분 식별자
- DDL: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. 실행 후 `ROLLBACK` 불가
- ALTER TABLE: `ADD CONSTRAINT`로 PK, UNIQUE, CHECK, FOREIGN KEY 추가, `DROP CONSTRAINT`로 삭제
- DML: `INSERT`, `UPDATE`, `DELETE`, `SELECT`
- Crow's Foot: 안쪽은 최소값(Min: 0 또는 1), 바깥쪽은 최대값(Max: 1 또는 N). N:M은 물리 모델에서 매핑 테이블로 1:N 해소

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

- DDL (Data Definition Language): 데이터베이스 구조(테이블, 스키마 등)를 정의·변경·삭제 (CREATE, ALTER, DROP 등)
- DML (Data Manipulation Language): 테이블 내 데이터를 조회·삽입·수정·삭제 (SELECT, INSERT, UPDATE, DELETE)
- CREATE TABLE 기본 문법:

~~~sql
CREATE TABLE 테이블명 (
열이름1 데이터타입 제약조건,
열이름2 데이터타입 제약조건,
...
);
~~~

- PRIMARY KEY: 중복 불가, NULL 불가
- NOT NULL: NULL 값 저장 불가
- UNIQUE: 중복 값 저장 불가 (NULL은 허용)
- DEFAULT: 값이 입력되지 않으면 기본값 적용
- REFERENCES: 외래키 참조 테이블 지정
- `DROP TABLE 테이블명;`: 테이블과 내부 데이터 영구 삭제
- PostgreSQL `\d 테이블명`: 열 구조, 데이터 타입, 제약 조건 확인
- INSERT 여러 행:

~~~sql
INSERT INTO 테이블명 (열1, 열2, 열3)
VALUES
(값1, 값2, 값3),
(값4, 값5, 값6);
~~~

- 1:1: 한 레코드가 다른 테이블의 한 레코드와 대응 (예: 회원 : 회원 상세정보)
- 1:N: 한 레코드가 다른 테이블의 여러 레코드와 연결 (예: 회원 : 주문)
- N:M: 양쪽이 여러 개와 연결. 중간 테이블(Junction Table)로 두 개의 1:N으로 분리 (예: 학생 : 강의)

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
| --- | --- | --- | --- |
| DDL 범위 | CREATE, DROP, TRUNCATE, ALTER 상세 | CREATE, DROP 중심 | 필기 유지 |
| N:M 표기 | `-│-<--ㅁ-->-│-` 및 매핑 테이블 | Junction Table로 1:N 분리 | 동일 (표기만 다름) |
| 테이블 구조 확인 | 미언급 | PostgreSQL `\d 테이블명` | 교재 보충 |
| INSERT | 컬럼 지정, 생략 가능, 여러 행 VALUES | 열 지정 권장, 여러 행 한 번에 입력 | 동일 |

# ERD 까마귀 발 표기법 (Crow's Foot Notation) 정리

관계선 양 끝의 **최소 참여도(0 or 1)** 와 **최대 카디널리티(1 or N)** 기호 조합을 통해 엔티티 간 관계 표현

---

## 1. 기본 구성 기호

선 끝 표식 중 **안쪽은 최소값(Min)**, **바깥쪽(엔티티 접촉부)은 최대값(Max)** 의미

| 기호 | 명칭 | 의미 | 설명 |
| :---: | :--- | :--- | :--- |
| `\|` | 선 (Dash) | 1 (One) | 정확히 1개 존재 |
| `o` | 원 (Circle) | 0 (Zero) | 존재하지 않을 수 있음 (선택적 / Optional) |
| `<` / `>` | 까마귀 발 (Crow's Foot) | N (Many) | 여러 개 존재 (다수 / Multiple) |

---

## 2. 관계선 끝 단일 엔티티 기준 표기 (4가지 기본 패턴)

| 표기 | 카디널리티 범위 | 명칭 | 상세 의미 |
| :---: | :---: | :--- | :--- |
| `-\|-` | 1 | **1 (Mandatory One)** | 정확히 1개 필수 |
| `-o\|-` | 0 .. 1 | **0 or 1 (Optional One)** | 없거나 최대 1개 (선택적) |
| `-\|<` | 1 .. N | **1 or More (Mandatory Many)** | 최소 1개 이상 다수 (필수) |
| `-o<` | 0 .. N | **0 or More (Optional Many)** | 없거나 여러 개 (선택적) |

---

## 3. 엔티티 간 관계(Relationship) 전체 패턴

### (1) 1 : 1 관계 (One-to-One)

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| :--- | :--- | :--- |
| `-\|----\|-` | 1 : 1 (양쪽 필수) | 양쪽 엔티티가 서로 정확히 1개씩 연결<br>*(예: 대한민국 국민 - 주민등록식별정보)* |
| `-\|----o\|-` | 1 : 0..1 (한쪽 선택) | A는 B가 없을 수 있으나, B는 반드시 A가 존재<br>*(예: 회원 `-\|` - `o\|-` 프로필상세)* |
| `-o\|----o\|-` | 0..1 : 0..1 (양쪽 선택) | 양쪽 모두 상대방 레코드 없이 단독 존재 가능<br>*(예: 사원 `-o\|` - `o\|-` 주차구역)* |

---

### (2) 1 : N 관계 (One-to-Many)

가장 빈번하게 사용되는 데이터 모델링 패턴

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| :--- | :--- | :--- |
| `-\|----o<-` | 1 : 0..N | 부모 필수(1), 자식 0개 이상 (가장 일반적)<br>*(예: 고객 `-\|` - `o<-` 주문)* (주문 없는 고객 가능) |
| `-\|----\|<-` | 1 : 1..N | 부모 필수(1), 자식 최소 1개 이상 필수<br>*(예: 주문 `-\|` - `\|<-` 주문상품상세)* (상세 없는 주문 불가) |
| `-o\|----o<-` | 0..1 : 0..N | 부모 0..1개, 자식 0개 이상<br>*(예: 부서 `-o\|` - `o<-` 사원)* (부서 미배정 사원 허용, FK Nullable) |
| `-o\|----\|<-` | 0..1 : 1..N | 부모 선택적, 자식이 존재할 경우 그룹 형성 |

---

### (3) N : M 관계 (Many-to-Many)

*논리 모델링 표현 방식 / 물리 모델링 시 매핑(교차) 테이블을 통해 1:N 관계로 변환 필수*

| 관계 표기 | 관계 형태 | 설명 및 예시 |
| :--- | :--- | :--- |
| `-o<----o<-` | 0..N : 0..N | 양쪽 모두 비어있을 수 있는 순수 다대다<br>*(예: 학생 `-o<` - `o<-` 동아리)* |
| `-\|<----o<-` | 1..N : 0..N | 한쪽 최소 1개 이상 필수, 상대방 0개 이상<br>*(예: 과목 `-\|<` - `o<-` 수강생)* |
| `-\|<----\|<-` | 1..N : 1..N | 양쪽 모두 최소 1개 이상 필수 연결 |

---

### (4) 특수 관계

* **물리적 N:M 해소 (중간 매핑 테이블 활용)**
  ```text
  [테이블 A] -|---o< [매핑 테이블] >o---| [테이블 B]
  ```

* **자기 참조 관계 (Recursive / Self-Referencing)**  
  동일 테이블 내 계층 구조(조직도, 카테고리 등) 표현
  ```text
  [카테고리] -o|---+ (상위 카테고리: 0..1)
             |
             +---o< (하위 카테고리: 0..N)
  ```

---

## 4. 식별 관계 vs 비식별 관계 (선 형태)

|       선 종류       | 명칭                           | 의미                                                   |
| :--------------: | :--------------------------- | :--------------------------------------------------- |
|  **실선 (`───`)**  | **식별 관계 (Identifying)**      | 부모의 기본키(PK)가 자식의 **기본키(PK) 일부**로 전이 (부모 없이 자식 식별 불가) |
| **점선 (`- - -`)** | **비식별 관계 (Non-Identifying)** | 부모의 기본키(PK)가 자식의 **일반 외래키(FK)** 로만 참조 (자식 독자 PK 보유)  |
