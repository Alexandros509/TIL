## 오늘의 학습

### 5장 SQL

**2.1 데이터 조회하기**

DML 중 1가지 SELECT (조회)

~~~sql
SELECT 컬럼1, 컬럼2, ... FROM 테이블명, ... [WHERE 조건식] ;
~~~

`*` : 모든 열

~~~sql
SELECT * FROM 테이블명;
~~~

1. 불필요한 데이터 → 성능 저하
2. 테이블 구조 변경 시 예상 외 열 포함 (개인정보 등)
3. 코드 가독성 떨어짐

SELECT [ALL | DISTINCT]

- ALL : 기본값 (중복 포함한 전체)
- DISTINCT : 중복 없이 조회

WHERE 조건식

- 조회의 범위를 좁힌다
  1. 비교 연산자 `()`, `<`, `>=`, `=`
     > ⚠ 원문의 의미가 모호합니다. (`()`가 `>`인지 괄호 우선순위인지 불명확)
  2. 논리 연산자 AND, OR, NOT
  3. IN : 포함 여부
     - NOT IN (...) : 미포함 시 TRUE
  4. BETWEEN A AND B : A에서 B 사이
  5. IS NULL : 값이 빈 상태인지 체크
     - IS NOT NULL : 값이 있는 상태인지 체크
     - **NULL은 값이 없는 상태이므로 비교, 산술 등의 연산이 불가**

값이 있을 때만 연산 처리 → `NULL + 100 = NULL`

CASE WHEN : 조건에 따른 다른 값을 부여하는 경우

> 필드를 명시하는 위치에 적용 (FROM 절 앞쪽)

~~~sql
SELECT CASE WHEN 조건식1 THEN 결과1
			WHEN 조건식2 THEN 결과2
			ELSE 결과 -- 모든 조건이 거짓일 때 값
		END AS 새로운 컬럼명
FROM 테이블명
~~~

AS : 별칭 / 생략 가능

- 컬럼명 뒤에 → 다른 컬럼명으로 변경
- 테이블명 뒤에

키워드 검색

- LIKE : 해당 문자열을 포함하는 값 (앞뒤 `%` 활용)
- `%` 와일드카드
  - `LIKE "키워드"` : 키워드에 정확히 매칭
  - `LIKE "키워드%"` : 키워드로 시작하는 매칭
  - `LIKE "%키워드"` : 키워드로 끝나는 매칭
  - `LIKE "%키워드%"` : 키워드가 포함된 매칭

ORDER BY 컬럼명 [ ASC | DESC ] [, 컬럼명 ... ]

- ASC : 오름차순 | 기본값
- DESC : 내림차순
- `ORDER BY 컬럼명 1, 컬럼명 2` → 1차 정렬 이후 동일한 정렬 순서로 2차 정렬
  - `ORDER BY product_name ASC, list_price DESC`
  - 상품명으로 오름차순 정렬 → 같은 정렬 순서 → 가격을 가지고 내림차순
  - **PostgreSQL / Oracle :** `NULL`을 가장 큰 값으로 취급, `NULLS LAST`로 수동 제어

LIMIT 조회할 행 수 [OFFSET 시작인덱스번호]

- ORDER BY 다음으로, 제일 뒤에
- 조회할 행의 최대 개수
- 페이징할 때
  - `LIMIT 10 OFFSET 0;`
  - `LIMIT 10 OFFSET 10;`
  - `LIMIT 10 OFFSET 20;`

**2.2 데이터 집계와 분석**

통계 (집계)

1. 집계 함수
   1. `COUNT (컬럼명)` : 레코드 개수
      - 컬럼이 NULL이 아닌 개수
      - `*` : 전체 컬럼에 대한 레코드 개수
   2. `SUM (컬럼명)` : 합계
   3. `AVG (컬럼명)` : 평균
   4. `MIN (컬럼명)` : 최솟값
   5. `MAX (컬럼명)` : 최댓값
2. GROUP BY
   - `SELECT .. FROM .. WHERE .. GROUP BY 컬럼명 1 [, 컬럼명 2, ...]`
   1. 특정 컬럼 기준으로 그룹을 만든다 (컬럼의 동일 값 기준)
   2. 집계 함수와 함께 쓰이는 경우가 많다
   3. 레코드 개수는 그룹핑된 결과 개수만큼 조회
   4. 조회 컬럼은 반드시 GROUP BY에 명시된 컬럼만 사용 가능
   5. 집계 함수를 포함한 조건은 절대 WHERE 절에서 사용 불가
      - `GROUP BY` → `HAVING` 집계 함수 조건
3. HAVING
   - GROUP BY 이후

**2.3 테이블 결합**

RDBMS 관계형 데이터베이스 관리 체계

Relation 테이블 간의 관계

1. 집합 - 중복 X - 행 방향 합치기
   1. 합집합 : UNION - 합친 후 중복 제거
      - UNION ALL : 중복 허용, 더 빠름
   2. 교집합 : 공통적인 것 INTERSECT
   3. 차집합 : EXCEPT
2. JOIN - 열 방향 합치기

두 테이블에서 공통적인 값을 기준으로 테이블을 하나처럼 조회되도록 결합해주는 것

INNER JOIN

- 동등 조인, 내부 조인 (**교집합**)
- INNER 키워드는 생략 가능

OUTER JOIN

- 외부 조인 - OUTER 생략 가능
  1. LEFT [OUTER] JOIN
     - 주 테이블 반드시 모두 출력 | 보조 테이블 있는 것만 출력
     - 매장 목록을 조회하는데 주문이 있다면 주문이 출력
       → 주문이 있던 없던 무조건 출력 + 주문이 있다면 추가
  2. RIGHT [OUTER] JOIN
     - 보조 테이블 있는 것만 출력 | 주 테이블 모두 출력
  3. FULL [OUTER] JOIN
     - 전부 출력

### 의문

### 탐색 방향

실제 데이터가 비어 있는 NULL 상태가 아니라, 문자열로 들어갔을 가능성을 확인.

### 후보

1. DB상의 실제 `IS NULL` 상태
2. 텍스트로 입력된 문자열 `'null'` 또는 `'NULL'`

### 비교 및 검토

~~~sql
-- 문자열 'null' 또는 'NULL' 조회
SELECT * FROM orders
WHERE LOWER(shipped_date) = 'null';
~~~

### 결론

글자 그대로 NULL이 들어가 있었음.

### SQL 순서

구문 순서

- SELECT - FROM - WHERE - GROUP BY - HAVING - ORDER BY

실행 순서

- FROM - WHERE - GROUP BY - HAVING - SELECT - ORDER BY

## 핵심 개념

- SELECT로 열을 고르고 FROM으로 테이블을 지정한다. `*`는 모든 열
- DISTINCT는 중복 없이 조회, ALL은 기본값(중복 포함)
- WHERE로 조회 범위를 좁힌다. NULL은 비교·산술 연산 불가 (`NULL + 100 = NULL`)
- CASE WHEN은 조건에 따라 다른 값을 부여한다. AS는 별칭이고 생략 가능
- LIKE와 `%` 와일드카드로 문자열 패턴을 찾는다
- ORDER BY는 ASC(기본) / DESC. 여러 컬럼이면 1차 후 2차 정렬
- LIMIT / OFFSET은 ORDER BY 다음, 제일 뒤. 페이징에 사용
- 집계 함수: COUNT, SUM, AVG, MIN, MAX
- GROUP BY로 동일 값 기준 그룹. 조회 컬럼은 GROUP BY에 있는 것만. 집계 조건은 HAVING
- UNION은 행 방향(중복 제거), UNION ALL은 중복 허용
- JOIN은 열 방향. INNER는 교집합, LEFT/RIGHT/FULL은 OUTER

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

- COUNT(*)는 NULL 여부와 관계없이 모든 행 수, COUNT(열명)은 해당 열에서 NULL이 아닌 행 수
- SELECT에 집계 함수가 아닌 열이 있으면 그 열은 GROUP BY에 명시해야 한다
- WHERE는 GROUP BY 전 개별 행 필터, HAVING은 GROUP BY 후 집계 결과 필터
- UNION은 열 수와 데이터 타입이 일치해야 한다. 결과 열 이름은 첫 번째 SELECT를 따른다
- JOIN은 ON으로 연결 기준을 지정한다. INNER는 양쪽 일치 행만, LEFT는 왼쪽 전체, RIGHT는 오른쪽 전체, FULL은 양쪽 모두
- ON에 AND로 여러 컬럼 조건을 같이 쓸 수 있다

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
| --- | --- | --- | --- |
| SELECT * 단점 | 성능, 예상 외 열, 가독성 | 동일 취지 | 동일 |
| COUNT(*) / COUNT(열) | `*`는 전체 레코드, 컬럼은 NULL 아닌 개수 | COUNT(*)는 NULL 포함 전체 행, COUNT(열)은 NULL 제외 | 동일 |
| WHERE vs HAVING | 집계 조건은 WHERE 불가, HAVING | WHERE는 그룹 전, HAVING은 그룹 후 | 동일 |
| UNION / JOIN 방향 | 집합은 행, JOIN은 열 | 동일 | 동일 |
| EXCEPT 표기 | 원문 EXECEPT | EXCEPT | 맞춤법 수정 |
| LIMIT / OFFSET | 원문 OFFEST | OFFSET | 맞춤법 수정 |

## 확인이 필요한 사항

⚠ 비교 연산자 원문이 `()`, `<`, `>=`, `=`이다. `>` 누락인지 괄호 우선순위인지는 원문만으로는 확정하지 않았다.

⚠ LIKE 예시가 큰따옴표 `"키워드"`이다. 교재 예시는 작은따옴표가 많다. 필기 표기는 유지.

	- UNION ALL : 중복 허용, 더 빠름
2. 교집합 : 공통적인 것 INTERSECT
3. 차집합 : EXECEPT

2.JOIN - 열 방향 합치기
: 두 테이블에서 공통적인 값을 기준으로  테이블을 하나처럼 조회되도록 결합해주는 것

INNER JOIN
-  동등 조인, 내부 조인 ( **교집합** )
-  INNER 키워드는 생략 가능

OUTER JOIN
 -  외부 조인 - OUTER 생략 가능
	1. LEFT [OUTER] JOIN
	- 주 테이블 반드시 모두 출력 | 보조 테이블 있는 것만 출력
	- 매장 목록 조회를 조회하는데 주문이 있다면 주문이 출력
		 -> 주문이 있던 없던 무조건 출력 + 주문이 있다면 추가 
	2. RIGHT [OUTER] JOIN 
	-  보조 테이블 있는 것만 출력 | 주 테이블 모두 출력
	3. FULL [OUTER] JOIN
	-  전부 출력
	  
	  
## 찾아본 내용
1. orders의 shipped_date 열에 분명 NULL이 있는데 WHERE IS NULL 으로 안 나옴
	~~~SQL
	   -- 문자열 'null' 또는 'NULL' 조회
		SELECT * FROM orders
		
		WHERE LOWER(shipped_date) = 'null';
	~~~
	글자 그대로 NULL이 들어가 있었음.
