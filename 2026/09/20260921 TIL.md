### var와 호이스팅

`var` 결함 3가지

1. 호이스팅
2. 함수 레벨 스코프 (Function-level Scope)
3. 선언 키워드 생략 → 암묵적 전역

호이스팅 (5–8)

- 동작: `코드 파싱` → `메모리/전역 객체 등록` → `실제 실행`
- 선언이 스코프 **최상단으로 끌어올려진 것처럼** 동작
- 전역 함수 선언문 → `window` 프로퍼티로 할당 (`window.add = ...`)
- **함수 선언문**: 전체 호이스팅 → 선언 전 호출 OK
- **함수 표현식 / `let`·`const`**: 선언 전 호출 → TDZ → `ReferenceError`
- **`var` 호이스팅(지양)**: 선언과 함께 `undefined` 초기화 → 흐름 왜곡
- **함수 호이스팅(지향)**: 객체가 완성된 상태로 등록 → 탑다운 배치·상호 재귀에 유리

~~~javascript
console.log(add(1, 2)); // 정상 실행 (3)

function add(a, b) {
  return a + b;
}
~~~

인터프리터·연산자 메모

- EC(Execution Context) ≈ 파이썬 PyFrameObject. Global EC → `window` 속성
- `+` 오버로드: 숫자 합 / 문자열 결합

### let · const

- `let` : 재할당 가능
- `const` : 상수(재할당 불가)
- block level scope / 호이스팅 사전 차단 / 중복 정의 해결
- 기본은 `const`, 변경 필요할 때만 `let`

### 타입과 typeof

| 타입 | 메모 |
|------|------|
| Number | 정수·실수 구분 없음 |

### RunnableLambda

- RunnableLambda 인터페이스 구현체
  - 동기: `invoke` / `stream` / `batch`
  - 비동기: `ainvoke` / `astream` / `abatch`
- RunnableLambda → Runnable로 래핑
  - 앞 체인이 Runnable이면 뒤 함수도 자동 Runnable
- `@chain` → Runnable로 래핑

~~~python
from langchain_core.messages import HumanMessage

model.invoke([("user", "안녕")])
# RunnableLambda
from langchain_core.runnables import RunnableLambda, chain

@chain
def func_a(message: str) -> str:
    return f"func_a:{message}"

def func_b(message: str) -> str:
    return f"func_b:{message}"

#func_a_runnable = RunnableLambda(func_a)
# func_b_runnable = RunnableLambda(func_b)
chain = func_a_runnable | func_b_runnable

chain.invoke("안녕하세요!")
import re
from langchain_core.messages import HumanMessage
from langchain_core.runnables import chain
from langchain_core.output_parsers import StrOutputParser
from lib import get_model

@chain
def protected_message(message: str) -> list[HumanMessage]:
    pattern = re.compile(r"(010)\D*(\d{4})\D*(\d{4})")

    message = pattern.sub(r"\g<1>-****-****", message)

    return [HumanMessage(message)]

model = get_model()
parser = StrOutputParser()

chain = protected_message | model | parser
chain.invoke("나의 전화번호는 010-1000-1000")
~~~

## 핵심 개념

- Node.js: 브라우저 밖 V8 runtime. `node` / `npm` / `npx` / NVM
- Jupyter JS: 필기 `tslab` + NVM v24 + `kernel.json` 8.3 축약 경로
- `var`: 호이스팅·함수 스코프·암묵적 전역
- 호이스팅: 선언 끌어올림. 함수 선언문 전체 / `var`는 `undefined`
- `let`·`const`: 블록 스코프, 기본 `const`
- 타입 + `typeof null` → `"object"` (설계 오류)
- 템플릿 리터럴: 백틱 + `${}` / tagged template
- RunnableLambda / `@chain`: 함수 → Runnable. sync·async API

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해
교재에서 가져온 내용이다.

### FE 4-1 — Node / NPM / NPX / NVM·Jupyter

- Node.js: 브라우저 밖 JS Runtime
- NPM: 패키지 매니저 / NPX: 일회성 실행
- 교재 실습 커널은 `ijavascript` + **Node.js v20 이하** (`nvm install 20` / `nvm use 20`)
- Jupyter: `uv tool install --with jupyter jupyter-core` → `npm init -y` → `npm install --save-dev ijavascript` → `npx ijsinstall`
- npm 전역: `--global` / `-g`

### FE 4-2 — var / let·const / typeof

- `var` 호이스팅: 선언 전 조회 → `undefined`
- `var` 함수 스코프: `if`/`for` 끝나도 외부 노출
- `let`·`const`: 블록 스코프. 선언 전 → `ReferenceError`
- `typeof null` → `"object"`: 초기 스펙 오류, 하위 호환 유지

### LLM 2-2 — 명확한 지시의 4대 핵심

- Task(임무): 핵심 동작, 명확한 동사
- Context(맥락): 배경·목적·사용 환경
- Constraints(제약): 독자·분량·문체·금지 등
- Format(출력 형식): 마크다운/리스트/표 등

### LLM 4-4 — RunnableLambda

- RunnableLambda: 일반 함수 → LCEL 파이프라인 실행 가능
- 라우팅 예: `{"intent": classifier_chain, "question": ...} | RunnableLambda(route_by_intent)`
- 필기 `@chain` / sync·async API / `protected_message`는 4-4 본문 정의와 별도 필기 메모
