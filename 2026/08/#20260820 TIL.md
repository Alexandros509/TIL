### 9.1 내장 함수

#### 9.1.3 데이터 가공 및 필터링 함수
- `map(function, iterable)` : 일괄 변환
  - iterable의 모든 요소에 동일한 함수 일괄 적용
  - 반환값 : Iterator 반복자. 실제 값 사용 시 `list()`나 `tuple()` 등으로 감싸주어야 함
- `filter(function, iterable)`: 조건별 추출
  - 데이터 목록의 설정 조건문이 True인 요소만 추출
  - 반환값 : Iterator 반복자. 실제 값 사용 시 `list()`나 `tuple()` 등으로 감싸주어야 함 
- 리스트 컴프리헨션으로 대체 가능

~~~python
nums = [*range(1,11)]
nums2 = [x**2 for x in nums]
print(nums2)

nums3 = [x for x in nums if x%2 == 1]
print(nums3)
~~~

- `zip(*iterables, strict=False)` : 다중 데이터 결합
  - 2개 이상의 iterable 
  - Iterator 반환
  - 각 iterable의 동일 인덱스 요소를 모아서 튜플로 묶어 반환 
~~~python

emails = ["cheolsoo@univ.ac.kr", "younghee@gmail.com"]

for name, email in zip(names, emails):
    print(f"이름: {name} | 이메일: {email}")

# [출력 결과]
# 이름: 김철수 | 이메일: cheolsoo@univ.ac.kr
# 이름: 이영희 | 이메일: younghee@gmail.com
~~~

- `sorted(iterable, *, key=None, reverse=False)` : 원본 데이터 새 기준 정렬
  - 정렬 가능한 iterable
  - 새로운 List 반환
  - key : 정렬 기준을 지정하는 함수 (선택)
  - reverse: 오름차순(False) / 내림차순(True)  
~~~python
# 1. 정렬 가능한 iterable (튜플 형태의 과일 이름과 가격)
fruits = [("banana", 3000), ("apple", 1000), ("cherry", 2000)]

# 2. reverse: 오름차순(False) / 내림차순(True) 적용 및 List 반환 확인
# key: 정렬 기준을 지정하는 함수 (여기서는 가격인 1번째 요소, 즉 x[1]을 기준으로 지정)
sorted_fruits = sorted(fruits, key=lambda x: x[1], reverse=True)

print(type(sorted_fruits))  # 결과: <class 'list'> (리스트 반환 확인)
print(sorted_fruits)        
# 결과: [('banana', 3000), ('cherry', 2000), ('apple', 1000)]
# (가격이 비싼 순서인 내림차순으로 정렬됨)
~~~

- `max()`, `min()` : 최대, 최소값
~~~python
numbers = [3, 1, 4, 1, 5, 9]

print(max(numbers))  # 결과: 9 (가장 큰 요소)
~~~

~~~python
    "age": 20,
}

print("json_string:\n", json_string, "type:", type(json_string))

# [출력 결과]
# json_string: {
#     "name": "김철수",
#     "age": 20
# } type: <class 'str'>

# JSON 문자열 -> 파이썬 객체
nums_string = "[1,2,3,4,5]"
user_string = '{"name":"오철수","age":22}'

nums = json.loads(nums_string)
user2 = json.loads(user_string)

print("nums:", nums, "type:", type(nums))
print("user2:", user2, "type:", type(user2))

# [출력 결과]
# nums: [1, 2, 3, 4, 5] type: <class 'list'>
# user2: {'name': '오철수', 'age': 22} type: <class 'dict'>
~~~

### 10.1 파일 입출력과 구조화된 데이터 변환

#### 10.1.1 파일 입출력과 텍스트 파일 다루기
- 파일 입출력 (I/O)
  - 입력 (Input) : 파일에 있는 데이터를 읽기 (`read()`)
  - 출력 (Output) : 데이터를 파일로 작성 (`write()`)

1. **`with open()`의 자원 자동 해제**
- `with` 구문 : 첫 라인에서 `__enter__()` 실행, 마지막 라인 실행 후 `__exit__()` 실행.
~~~python
file = open("test.txt", "w", encoding="UTF-8")
# 파일에 무언가를 쓰는 작업 수행...
file.close()  # 반드시 수동으로 닫아주어야 함!

# "w" (쓰기/덮어쓰기), "a" (추가/append)
# 파일에서 작성하는 위치(파일 포인터)가 가장 앞으로 이동해서 내용을 대체
with open("test.txt", "w", encoding="utf-8") as file:
    pass
    # 들여쓰기가 끝나면 자동으로 file.close()가 실행됨!

# 내부 동작 원리 확인용 클래스
class MyResources:
    def __enter__(self):
        print("__enter__ 호출")
        return self
    
    # with 구문 종료 시 / 예외 발생 시 호출
    def __exit__(self, exc_type, exc_val, exc_tb):
        print("__exit__ 호출")
        
with MyResources() as o:
    print(o)

# "a" (append), \n : 줄바꿈
with open("test.txt", "a", encoding="UTF-8") as fp:
    fp.write("Bye\n")   
~~~

2. **텍스트 파일 읽기 함수 및 메모리 효율성 비교**

| 방식 | 읽는 단위 | 반환 타입 | 메모리 사용량 | 특징 및 장점 |
| :--- | :--- | :--- | :--- | :--- |
| **`for line in fp:`** | **한 줄씩 순차적으로** | 문자열 (`str`) | **매우 낮음 (최소한의 메모리)** | 파일을 통째로 올리지 않고 한 줄씩 처리하여 대용량 파일에 최적화된 **표준 권장 방식**입니다. |
| **`.readlines()`** | **전체 내용을 줄 단위로** | 리스트 (`list`) | **높음** | 모든 줄을 파이썬 리스트로 한 번에 변환하므로 작은 파일에 적합합니다. |
| **`.read()`** | **전체 내용 통째로** | 문자열 (`str`) | **매우 높음** | 파일 전체를 하나의 거대한 문자열로 가져오므로 파일 크기가 크면 메모리 부담이 큽니다. |

~~~python
with open("test.txt", "r", encoding="UTF-8") as fp:
    text = fp.read()
    print(text)

with open("test.txt", "r", encoding="UTF-8") as fp:
    while(text := fp.readline()): # 한 줄씩 읽어서 메모리에 적재 (메모리 소비 적음)
        print(text.strip())

with open("test.txt", "r", encoding="UTF-8") as fp:
    lines = fp.readlines() # 전체를 메모리에 올림
    print(lines)

# 이터레이터(Iterator) 성질을 활용해 한 줄씩 직접 순회(Iteration)하는 방식 (고효율)
with open("test.txt", "r", encoding="UTF-8") as fp:
    for line in fp:
        print(line.strip())
~~~

- **`:=` 왈러스 연산자 (Walrus Operator)**
  - 반복/조건문 안에서 어떤 값을 계산해서 변수에 넣는 동시에, 그 값을 조건식에서 바로 써먹고 싶을 때 사용합니다.
~~~python
# 왈러스 연산자를 쓰지 않을 때
n = len([1, 2, 3, 4, 5])
if n > 3:
    print(f"길이가 {n}입니다.")

    print(f"길이가 {n}입니다.")
~~~

#### 10.1.2 구조화된 데이터 포맷(CSV/JSON)과 구조 변환
1. **CSV 형식 (Comma Separated Value)**
  - 데이터를 쉼표로 구분하여 표 형태의 구조를 표현
  - 용량 작음, 데이터베이스와 연동 쉬움

~~~python
import csv
# newline="" 행 사이에 불필요한 빈 줄(공백 행)이 자동으로 삽입되는 것을 방지
with open("members.csv", "w", encoding="UTF-8", newline="") as fp:
    writer = csv.writer(fp)
    writer.writerow(["이름", "나이", "전화번호"])
    writer.writerow(["김철수", 20, "010-1000-1000"])

with open("members.csv", "r", encoding="UTF-8") as fp:
    reader = csv.reader(fp)
    members = list(reader)
    print(members)
~~~

### 11.1 동기(Sync) vs 비동기(Async)의 이해

#### 11.1.1 동기와 비동기
여러 작업을 진행할 때 '시간적 순서를 어떻게 맞출 것인가'에 대한 규칙.

1. **동기 (Synchronous)**
  - 순차적, 직관적
  - CPU Bound (연산 중심 작업)
  - **Blocking**: 호출된 하위 코드가 작업을 마칠 때까지 제어권을 독점하는 현상. 상위 코드는 실행을 중단하고 대기.
  - 비유: 카운터에서 주문 후 길막하며 대기. 요청 후 결과가 올 때까지 직진하며 대기.
  - 필요성: 논리적인 흐름과 무결성이 중요할 때 (예: 입금 후 잔액 조회).

2. **비동기 (Asynchronous)**
  - 독립적, 효율적 병렬 처리
  - I/O Bound (입출력 중심 작업)
  - **Non-blocking**: 하위 코드에 작업을 요청하더라도 상위 코드가 제어권을 계속 유지하거나 즉시 돌려받는 방식. 하위 작업 완료를 기다리지 않고 다음 코드를 실행.
  - 비유: 카운터에서 주문하고 앉아서 진동벨 대기. 요청 던져두고 내 할 일 하다가 결과 오면 처리.
  - 필요성: 컴퓨터가 멍하니 대기하는 시간(Idle)을 없애고 자원을 극한으로 효율화하기 위해.

~~~python
# 비동기 함수
import asyncio
import time

async def async_work(title, seconds):
    await asyncio.sleep(seconds)
    print(title, "완료!")

# 비동기 함수는 비동기 내에서만 실행 가능하다.
async def main():
    await asyncio.gather(
        async_work("A작업", 2),
        async_work("B작업", 3),
        async_work("C작업", 1)
    )

start = time.perf_counter()
await main()        
end = time.perf_counter()
print("걸린 시간:", end - start)

# [출력 결과]
# C작업 완료!
# A작업 완료!
# B작업 완료!
# 걸린 시간: 3.015118799987249
~~~

## 문제 상황 / 시행착오

9.1 심화 1 : 내장 함수를 활용한 대기자 명부 및 매칭 시스템 구성
> zip() 함수와 enumerate() 함수를 사용해 데이터 결합 후 반복문 출력 시 언패킹 오류 발생

### 의문
`enumerate(zip(v_name, v_email))` 형태로 데이터를 묶은 뒤 `for` 반복문을 돌릴 때, 튜플이 묶여 나오거나 패킹을 풀지 못하는 문제가 발생함. 변수에 언패킹(Unpacking)을 하려면 어떻게 조건과 범위를 지정해야 하는가?

### 탐색 방향
반복문에서 리스트 및 `zip` 객체를 사용할 때 반환되는 데이터의 튜플 계층 구조를 뜯어보고 다양한 변수 할당 시도 진행.

### 후보 및 비교 검토
1. **변수를 단순히 3개 지정 (에러)**
   ~~~python
   for idx, v_name, v_email in enumerate(zip1, start=1):
       print(f"{idx}번 당첨자: {v_name} | 이메일: {v_email}")
   ~~~
   - **결과:** `ValueError: not enough values to unpack (expected 3, got 2)`
   - **원인:** `enumerate(zip1, start=1)`가 반환하는 데이터의 구조는 `(숫자, (이름, 이메일))` 형태의 **이중 묶음(튜플 안에 또 튜플)** 구조임. 파이썬은 이를 2개의 덩어리(인덱스 번호, 내부 튜플)로 제공하는데, 좌변의 변수를 `idx, v_name, v_email`로 3개나 지정하여 불일치 에러 발생.

2. **zip() 객체를 반복문에 직접 재사용 (데이터 유실)**
   ~~~python
   zip_1 = zip(v_name, v_email)
   for idx, zip_1 in enumerate(zip_1, start=1):
       # 여러 번 출력 테스트를 진행할 때 다르게 나오거나 깨짐
   ~~~
   - **원인:** `zip()`이나 `enumerate()`가 반환하는 객체는 일회용 소모성 이터레이터(Iterator)임. 순회가 한 번 끝나고 나면 객체가 비어버림.

3. **반복문 문법 중첩 시도 (에러)**
   ~~~python
   for i, name, email in enumerate(zip1, start=1) in zip(v_name, v_email):
   ~~~
   - **결과:** `TypeError: 'bool' object is not iterable` 치명적인 문법 에러 유발.

### 판단 및 해결 과정
데이터가 겹겹이 포장(Packing)된 구조를 정확히 파악해야 함.
바깥쪽 숫자는 단일 변수(`num`)가 받고, 안쪽의 튜플은 `(name, email)`처럼 **괄호 `( )`로 감싸서 지정하는 이중 괄호 언패킹(Nested Unpacking)**을 선언부에 적용함.

~~~python
v_name = ["이민서", "박준형"]
v_email = ["minseo@ssu.ac.kr", "junhyung@daum.net"]

# enumerate와 zip을 결합하고, 이중 괄호를 통해 안쪽 튜플까지 한 번에 언패킹
for num, (name, email) in enumerate(zip(v_name, v_email), start=1):
    print(f"{num}번 당첨자: {name} | 이메일: {email}")
~~~

### 11.1 동기(Sync) vs 비동기(Async)의 이해
#### 11.1.1 동기와 비동기
 - 여러 작업을 진행할 때 '시간적 순서를 어떻게 맞출 것인가'에 대한 규칙
   1. 동기(Synchronous)
      - 순차적, 직관적
      - CPU Bound (연산 중심 작업)
      - Blocking
        - 호출된 하위 코드가 작업을 마칠 때까지 제어권을 독점하는 현상
        - 상위 코드는 하위 작업이 끝날 때까지 실행을 중단하고 대기
          - ex) 카운터에서 주문 후 길막하며 대기
          - 요청 후 결과가 올 때까지 직진하며 대기
      - **필요성**:  논리적인 흐름과 무결성 like 입금 후 잔액 조회 not 조회 후 입금
   
   2. 비동기(Asynchronous)
      - 독립적, 효율적 병렬 처리
      - I/O Bound (입출력 중심 작업)
      - Non-blocking
        - 하위 코드에 작업을 요청하더라도 제어권을 상위 코드가 그대로 유지하거나, 요청 즉시 제어권을 다시 돌려받는 방식
        - 상위 코드는 하위 작업의 완료를 기다리지 않고 다음 코드를 계속 실행
          - ex) 카운터에서 주문하고 앉아서 진동벨 대기
          - 요청 던져주고 내 할 일 하다가 결과 오면 처리
      - **필요성** : 컴퓨터가 멍하니 대기하는 시간(Idle)을 없애고 자원을 극한으로 효율화하기 위해

~~~python
# 비동기 함수
import asyncio
import time

async def async_work(title, seconds):
    await asyncio.sleep(seconds)
    print(title,"완료!")

# 비동기 함수는 비동기 내에서만 실행 가능하다.
async def main():
    await asyncio.gather(
        async_work("A작업",2),
        async_work("B작업",3),
        async_work("C작업",1)
    )
start = time.perf_counter()
await main()        
end = time.perf_counter()
print("걸린 시간:",end-start)
~~~

## 1. 개요 및 학습 목표
* **목표:** 당첨자 이름 리스트와 이메일 리스트를 `zip()`으로 묶고, `enumerate(start=1)`를 활용해 1번부터 시작하는 번호를 부여한 뒤 지정된 포맷(`n번 당첨자: 이름 | 이메일: 주소`)으로 출력하기.
* **핵심 학습 포인트:** 
  * `zip()` 객체(이터레이터)의 소모성 특성 이해
  * `enumerate(zip(...))` 구조에서 발생하는 **이중 묶음(Packing)** 형태 파악
  * `for`문의 자동 언패킹 및 **이중 괄호 언패킹(Nested Unpacking)** 기법 습득

### ❌ 시행착오 1: `ValueError: not enough values to unpack` 에러 발생
* **시도했던 코드:**
  ~~~python

      print(f"{idx}번 당첨자: {v_name} | 이메일: {v_email}")
~~~

* **원인 분석:**
* `enumerate(zip1, start=1)`가 반환하는 데이터의 구조는 `(숫자, (이름, 이메일))` 형태의 **이중 묶음(튜플 안에 또 튜플)** 구조입니다.
* 파이썬은 이를 2개의 덩어리(인덱스 번호, 내부 튜플)로 제공하는데, 좌변의 변수를 `idx, v_name, v_email`로 3개나 지정하여 언패킹 개수 불일치 에러가 발생했습니다.



---

### ❌ 시행착오 2: `zip()` 객체의 일회용 소모성(Iterator) 문제로 인한 데이터 유실

* **시도했던 코드:**
~~~python
zip_1 = zip(v_name, v_email)
for idx, zip_1 in enumerate(zip_1, start=1):
    # 여러 번 출력 테스트를 진행할 때 데이터가 정상 출력되지 않고 깨짐

~~~


* **원인 분석:**
* `zip()` 함수나 `enumerate()`가 반환하는 객체는 메모리를 아끼기 위해 요소를 한 번에 리스트로 만들지 않고 하나씩 꺼내주는 이터레이터(Iterator)입니다.
* 순회가 한 번 끝나고 나면 객체가 소모되어 비어버리기 때문에, 반복문을 재실행하거나 상태를 착각하면 데이터가 출력되지 않는 문제가 발생합니다. (안전하게 `list()` 등으로 변환하거나 매번 새로 정의해야 함)

* **시도했던 코드:**

~~~python
for i, name, email in enumerate(zip1, start=1) in zip(v_name, v_email):

~~~

* **원인 분석:**
* 파이썬 문법에 맞지 않는 잘못된 비교/순회식 결합으로 인해 `TypeError: 'bool' object is not iterable` 등의 치명적인 문법 에러를 유발했습니다.

## 3. 최종 정답 코드 및 해설

데이터가 겹겹이 포장(Packing)된 구조를 정확히 파악하고, `for`문의 변수 선언부에서 괄호를 활용한 이중 언패킹(Nested Unpacking)을 적용하여 문제를 해결했습니다.

~~~python
v_name = ["이민서", "박준형"]
v_email = ["minseo@ssu.ac.kr", "junhyung@daum.net"]

# enumerate와 zip을 결합하고, 이중 괄호를 통해 안쪽 튜플까지 한 번에 언패킹
for num, (name, email) in enumerate(zip(v_name, v_email), start=1):
    print(f"{num}번 당첨자: {name} | 이메일: {email}")

~~~

### 핵심 요약

1. **포장 구조 파악:** `enumerate(zip(...))`를 사용하면 `(숫자, (이름, 이메일))` 구조의 데이터가 만들어집니다.
2. **이중 언패킹:** 바깥쪽 숫자는 `idx`가 받고, 안쪽의 튜플은 **`(name, email)`처럼 괄호 `( )`로 감싸서** 지정하면 파이썬이 연쇄적으로 껍질을 까서(언패킹해서) 각 변수에 쏙쏙 집어넣어 줍니다.
3. **변수 이름은 자유:** 인덱스를 받는 `idx`나 `i` 같은 이름은 파이썬 예약어가 아니므로 기능상 무엇을 써도 무방하지만, 가독성을 위해 의미가 통하는 관습적인 이름을 사용하는 것이 좋습니다.
