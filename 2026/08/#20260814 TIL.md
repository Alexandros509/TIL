### 5.4 이터레이터와 제너레이터

#### 5.4.1 이터러블과 이터레이터의 동작 방식

##### 5.4.1.1 객체(Iterable)와 이터레이터(Iterator)
- **이터러블 (Iterable)**
  - 반복 가능한 객체
  - `__iter__(..)`가 정의되어 있다면 반복 가능!
  ~~~python
  .__iter
  ~~~
  - `__next__(..)`: 인덱스를 한 칸씩 이동하면서 요소를 꺼내오는 기능을 정의

- **이터레이터(반복자)**
  - 반복을 하려면
    - 이터레이터 객체 생성 (`__iter__` 호출)
    - 순서를 한 칸씩 이동하면서 요소 조회 (`__next__` 호출)

#### 5.4.2 yield 키워드와 제너레이터의 지연 평가

- **yield와 제너레이터(Generator)**
  - `yield`를 사용하는 함수를 **제너레이터 함수**라고 한다.
  - 제너레이터 함수는 값을 한 번에 모두 생성하지 않고, **필요할 때마다 하나씩 생성**한다.
  - `yield`를 만나면 값을 반환하고 함수의 실행을 **일시 정지**한다.
  - 이후 `next()`가 호출되면 정지했던 위치부터 **실행을 재개**한다.

> **핵심:** `yield` = 값을 내보내고, 현재 실행 상태를 보존한 채 잠시 멈춤

- **지연 평가(Lazy Evaluation)**
  - 데이터를 미리 모두 계산하지 않고, **실제로 필요한 시점에 계산하여 생성하는 방식**
  - 일반적인 리스트 → 필요한 데이터를 미리 모두 생성하여 메모리에 저장
  - 제너레이터 → `next()` 등으로 요청할 때마다 필요한 값을 하나씩 생성

~~~text
일반적인 방식
데이터 전체 생성 → 메모리에 저장 → 사용

제너레이터
값 요청 → 하나 생성 → 사용
       → 다음 값 요청 → 하나 생성 → 사용
~~~

> - `yield` → 값을 하나 반환하고 실행을 일시 정지
> - `next()` → 정지한 위치부터 실행 재개
> - 제너레이터 → 값을 필요할 때마다 하나씩 생성하는 객체
> - 지연 평가 → 필요한 시점에 데이터를 계산·생성하는 방식

동기 vs 비동기
- 동기: 순서대로 실행하고 결과도 순서대로 도출
~~~text
----A---------B--------C
 시작 종료  시작 종료
~~~
- 비동기: 순서대로 작업을 시작하지만 결과는 먼저 처리된 순서대로 나온다.

#### 5.4.3 제너레이터 표현식과 리스트 컴프리헨션 비교

##### 5.4.3.1 제너레이터 표현식
- 참고 : 리스트 컴프리헨션 -> 생성 결과가 처음부터 메모리에 적재
- 리스트 대신 튜플로 리스트 컴프리헨션과 동일하게 사용하면 된다 -> 메모리 소비가 적다
- 대용량 데이터 처리에 적합하다.
- 리스트 컴프리헨션은 `[]`, 제너레이터는 `()`를 사용한다.

### 6.1 모듈과 패키지

#### 6.1.1 독립 소스 파일 모듈과 디렉터리형 패키지 구조

##### 6.1.1.1 모듈(Module)
- 모듈 : 파이썬 파일 하나
- 다른 파일에서 모듈을 불러와서 사용하는 경우가 많다.
- 모듈명은 파일 이름이다.
- `__name__` : 모듈 이름

##### 6.1.1.2 디렉터리형 패키지(Package) 
- 패키지는 모듈을 모아 놓은 디렉터리
- `from 패키지명.하위패키지 import ...`
- 전체 패키지 경로 : 절대 경로 접근 (예: `chapter.mod1`)
- 상대 경로 접근법 : 
  - `..`: 바로 위 패키지
  - `.`: 현재 모듈이 있는 패키지

#### 6.1.2. 모듈 로드를 위한 키워드와 표준 라이브러리 활용

##### 6.1.2.1 import, from, as 키워드
- **import** : 모듈 불러오기
  - 마침표(`.`)를 통해 모듈 안에 정의된 함수 호출 가능
  ~~~python
  import mod1
  mod1.add(10,20)
  ~~~
- **from** : 모듈명/패키지명에서 특정한 함수, 변수, 클래스 등을 가져온다.
  ~~~python
  from mod1 import add, minus, VERSION
  add(10,20)
  ~~~
  - `from 모듈명 import *` -> 모듈의 전체 함수, 변수, 클래스를 불러온다.
- **as** : alias (별칭)
  ~~~python
  import calculation as calc
  ~~~

~~~python
if __name__=='__main__': # 터미널에서 파이썬 파일을 실행할 때로 한정
~~~

- **`__init__.py`** : 3.3 버전 이전까지 필수
  - 현재 디렉터리가 패키지임을 알려주는 파일 (넣어주면 좋다)
  - 하위 모듈, 하위 패키지에서 공통적으로 처리해야 하는 코드를 작성, 모듈을 불러올 때 최초 한번만 실행
  - 패키지 내에서 사용할 공통적인 함수, 변수, 클래스를 정의 
  - `from 패키지 import *` 사용 시 `__all__=[....]`에 정의된 모듈만 임포트된다.

#### 1. 패키지 내부 모듈 Import 시 경로 인식 오류

##### 의문
`game` 폴더 안에 `__init__.py`, `lol.py`, `wow.py`가 있고 각각 `LOL`, `WOW` 함수가 존재한다.
`from 모듈명/패키지명 import 함수/변수` 구조를 배웠는데, 왜 `from lol import LOL`은 오류가 나고 `from game import *`를 했을 때는 정상적으로 동작했을까?

##### 원인 분석
- **`from lol import LOL`이 실패한 이유**
  파이썬은 기본적으로 `sys.path` 경로에서 최상위 모듈을 찾는다. `lol.py`는 단독 최상위 모듈이 아니라 `game` 패키지 안의 서브 모듈이므로, 그냥 `lol`이라는 이름의 모듈은 찾을 수 없다. (`game.lol`이 정확한 경로이다)
- **`from game import *`가 동작한 이유**
  `game/__init__.py` 파일 내부에 `__all__ = ["lol"]`이 정의되어 있었기 때문이다. 패키지를 불러오면서 `__init__.py`가 실행되고, `__all__`에 명시된 모듈 이름들만 현재 네임스페이스로 가져오게 되어 `lol.LOL()` 형태로 접근이 가능해진 것이다.

##### 판단 및 결론
- 패키지 안의 서브 모듈은 반드시 패키지 경로를 명시하여 가져와야 한다. (예: `from game.lol import LOL`)
- **`__init__.py` 작성 주의사항:** `__init__.py` 내부에서 `from game import *`와 같이 자기 자신을 다시 참조하는 코드는 순환 참조 문제를 일으킬 수 있으므로 지양해야 한다. 대신 `from .lol import LOL`처럼 상대 경로를 사용하여 명시적으로 가져오거나, 필요한 것만 노출하는 것이 안전하다.

#### 2. VS Code Jupyter Notebook 라인 번호 및 Breakpoint 해제 방법

##### 의문
VS Code Jupyter Notebook REPL 환경에서 코드를 작성하다가 갑자기 코드 칸 앞에 넘버링(숫자)이 붙고, 옆에 점 칸(`click to add a breakpoint`)이 생겼다. 이것의 정체는 무엇이고 어떻게 켜고 끄는가?

##### 해결 과정
1. **코드 앞 숫자 (라인 번호)**
   - **정체:** 실수로 단축키가 눌려 활성화된 셀 내부의 코드 줄 번호.
   - **끄는 방법:** 셀 왼쪽 여백을 클릭하여 선택한 뒤 `Shift + L`을 누르면 전체 셀의 라인 번호가 토글되어 사라진다. (현재 셀만 끄려면 `L` 입력)
2. **점 칸과 안내 문구 (Breakpoint Gutter)**
   - **정체:** 디버깅 시 코드 실행을 특정 줄에서 멈추게 하는 '중단점 영역'이다.
   - **끄는 방법:** VS Code 설정(`Ctrl + ,`)을 열어 `glyphMargin`을 검색한 뒤, `Editor: Glyph Margin` 항목의 체크를 해제(`"editor.glyphMargin": false`)하면 영역과 안내 문구가 완전히 사라진다.

#### 3. 모듈 함수 호출과 객체 메서드 호출의 차이점

##### 의문
`import`로 불러온 모듈 내부 함수를 마침표(`.`)를 붙여서 호출하는 방식(`math.sqrt(16)`)이 클래스의 메서드를 호출하는 것과 겉보기에 아주 비슷해 보인다. 둘은 같은 원리인가?

##### 비교 및 검토
파이썬에서는 모듈, 함수, 클래스의 인스턴스 모두가 '객체'이기 때문에 접근하는 문법(`이름.함수()`)이 동일해 보인다.
- **모듈.함수():** 모듈이라는 상자에서 단순한 '일반 함수' 객체를 꺼내 쓰는 것이다. (첫 번째 인자가 필요 없음)
- **객체.메서드():** 특정 객체에 이미 묶여 있는 '바인딩된 메서드(Bound Method)'를 꺼내 쓰는 것이다.

##### 판단 및 깨달음
클래스의 메서드가 객체에 의존적이라는 의미가 바로 바인딩된 메서드라는 뜻이다. 메서드를 호출할 때 파이썬 내부적으로 `객체.메서드()`를 `클래스.메서드(객체, ...)` 형태로 변환하여 실행해 주기 때문에, 호출한 객체 자신(`self`)이 자동으로 넘어가게 된다.

#### 4. 객체 생성(`p = Person()`)과 기타 키워드의 오해

##### 의문
아직 클래스를 배우지 않아 헷갈리는데, 클래스 안의 `def`도 함수 정의가 맞는가?
그리고 `p = Person()`의 구조가 함수를 변수에 담는 일급 함수(원문 오기: 일차함수, 클로징)나, 이름을 덧붙이는 `as` 키워드랑 비슷한 원리로 이해하면 되는가?

##### 탐색 방향
- 클래스 내부의 `def` 역시 기능적으로 함수 정의(메서드)가 맞다.
- 이미 있는 모듈이나 함수에 별명을 붙이는 `as`(`import math as m`) 및 함수를 일급 객체로 다뤄 변수에 치환하는 개념(`f = greet`)과 비교.

##### 결론
`p = Person()`은 일급 함수나 `as` 키워드와는 전혀 다른 개념이다.
- **`as`:** 이미 존재하는 것에 다른 이름표(별칭)를 붙이는 단순한 행위.
- **`p = Person()`:** 클래스(`Person`)를 호출하여 완전히 **새로운 객체를 하나 생성**해 내고, 그 만들어진 결괏값을 변수 `p`에 담는 행위이다. 
현 단계에서는 괄호 `()`가 붙으면 무언가를 '실행'하거나 새롭게 '생성'하는 동작이라고 이해하고 넘어가면 충분하다.

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재에서 가져온 내용이다.

### 순회 종료 처리와 예외
이터레이터 객체에서 `next()`를 통해 모든 원소를 꺼낸 뒤 더 이상 꺼낼 데이터가 존재하지 않으면 파이썬은 내부적으로 `StopIteration` 예외를 발생시켜 순회가 안전하게 완료되었음을 알린다.

### 코루틴(Coroutine)의 개념
제너레이터가 `yield`를 사용하여 함수 실행을 일시 정지하고 원하는 시점에 다시 깨우는 이 동작 방식은 파이썬의 동시성 프로그래밍인 '코루틴'의 기반이 된다. 코루틴은 서로 제어권을 주고받으며 협력하듯 실행 흐름을 이어간다.

### 제너레이터 표현식의 메모리 최적화
리스트 컴프리헨션은 데이터 개수가 늘어날수록 메모리 용량이 비례하여 증가하지만, 제너레이터 표현식은 요청이 올 때 하나씩 연산을 수행하므로 데이터 개수에 상관없이 항상 고정된 수백 바이트 수준의 작은 메모리만 유지한다.

### 패키지 내 상대 경로 실행 주의점
상대 경로 접근 방식은 전체 시스템이 하나의 '패키지' 형태로 묶여 구동될 때만 정상 작동한다. 터미널에서 스크립트를 단독으로 실행하면 경로를 찾지 못해 오류가 발생하므로, 반드시 `-m` 옵션을 사용하여 가동해야 한다. (`uv run python -m 패키지명.모듈명`)

### 주요 파이썬 표준 라이브러리
- **sys**: 파이썬 인터프리터 제어 및 시스템 경로(`sys.path`) 등을 조회할 때 사용한다.
- **random**: 무작위 난수를 생성하거나 리스트 내 데이터 요소에서 임의의 번호를 추출할 때(`random.randint`) 사용한다.
- **datetime**: 시스템 현재 시간을 수집하고 원하는 포맷(`strftime`)의 문자열 형식으로 변환하여 출력할 때 사용한다.

### 5.4 이터레이터와 제너레이터
#### 5.4.1 이터러블과 이터레이터의 동작 방식
##### 5.4.1.1 객체(Iterable)와 이터레이터(Iterator)
 - 이터러블 (Iterable)
    - 반복 가능한 객체
    - \_\_iter\_\_(..) 정의되어 있다면 반복 가능!
    ~~~python
    .__iter
     ~~~
    - \_\_next\_\_(..) 인덱스를 한칸씩 이동하면서 요소를 꺼내오는 기능을 정의
 - 이터레이터(반복자)
    - 반복을 하려면
      - 이터레이터 객체 생성 (`__iter__` 호출(iter...))
      - 순서를 한칸씩 이동하면서 요소 조회(`__next__` 호출 next(...))

#### 5.4.2 yield 키워드와 제너레이터의 지연 평가
 - yield와 제너레이터(Generator)
    * `yield`를 사용하는 함수를 **제너레이터 함수**라고 한다.
    * 제너레이터 함수는 값을 한 번에 모두 생성하지 않고, **필요할 때마다 하나씩 생성**한다.
    * `yield`를 만나면 값을 반환하고 함수의 실행을 **일시 정지**한다.
    * 이후 `next()`가 호출되면 정지했던 위치부터 **실행을 재개**한다.

    > **핵심:** `yield` = 값을 내보내고, 현재 실행 상태를 보존한 채 잠시 멈춤


 - 지연 평가(Lazy Evaluation)
    - 지연 평가 : 데이터를 미리 모두 계산하지 않고, **실제로 필요한 시점에 계산하여 생성하는 방식**
        * 일반적인 리스트 → 필요한 데이터를 미리 모두 생성하여 메모리에 저장
        * 제너레이터 → `next()` 등으로 요청할 때마다 필요한 값을 하나씩 생성

text
일반적인 방식
데이터 전체 생성 → 메모리에 저장 → 사용

제너레이터
값 요청 → 하나 생성 → 사용
       → 다음 값 요청 → 하나 생성 → 사용



> * `yield` → 값을 하나 반환하고 실행을 일시 정지
> * `next()` → 정지한 위치부터 실행 재개
> * 제너레이터 → 값을 필요할 때마다 하나씩 생성하는 객체
> * 지연 평가 → 필요한 시점에 데이터를 계산·생성하는 방식



동기 vs 비동기
동기: 순서대로 실행하고 결과도 순서대로 도출
----A---------B--------C
 시작 종료  시작 종료

비동기: 순서대로 작업을 시작하지만 결과는 먼저 처리된 순서대로 나온다
