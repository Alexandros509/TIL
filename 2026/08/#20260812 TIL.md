### 🥉 [하] 가이드라인 집중형 : 전설 장비 필터링 함수

**1. 문제**
장비 리스트(딕셔너리를 담은 리스트)를 순회하며 등급이 "전설"이고 레벨이 최소 레벨(min_level) 이상인 장비의 개수와 총 가격을 반환하는 함수를 작성하라.

**2. 내 답**
~~~python
def filter_legendary(equip_list, min_level):
    vip_count = 0
    total_price = 0
    for i in equipments:
        if ["grade"] == "전설" and ["level"] >= min_level:
            vip_count += 1
            total_price += ["price"]
    
    print(f"조건 만족 장비: {vip_count}개")
    print(f"총 가치: {total_price} 골드")
~~~

**3. 오류 및 원인**
*   **딕셔너리 값 접근 방식 오류:** `["grade"]`는 값이 아니라 문자열이 들어간 새로운 리스트일 뿐이다. 리스트를 순회하며 꺼낸 딕셔너리가 변수 `i`에 담겨있으므로, `i["grade"]` 형태로 접근해야 한다.
*   **매개변수 미사용:** 함수에 `equip_list`라는 매개변수(투입구)를 만들어 놓고, 정작 반복문에서는 외부의 전역 변수인 `equipments` 원본을 직접 가져다 썼다. 이렇게 되면 함수가 범용성을 잃게 된다.

**4. 해설**
*   **문법(Grammar):** 딕셔너리의 값을 꺼낼 때는 `변수명["키"]` 형태를 사용하는 것이 파이썬의 필수 문법이다.
*   함수 내부에서는 항상 매개변수로 넘겨받은 변수(`equip_list`)를 사용해야 재사용 가능한 함수가 된다. 가독성을 위해 반복문의 변수명은 `i`보다는 `item`이 직관적이다.

**5. 정답 코드**
~~~python
def filter_legendary(equip_list, min_level):
    vip_count = 0
    total_price = 0
    
    for item in equip_list: # 매개변수 사용 및 변수명 변경
        if item["grade"] == "전설" and item["level"] >= min_level: # item["키"] 문법 적용
            vip_count += 1
            total_price += item["price"] 
    
    print(f"조건 만족 장비: {vip_count}개")
    print(f"총 가치: {total_price} 골드")
~~~

### 🥈 [중] 독립 설계형 : 무한 루프 장비 강화 시뮬레이터

**1. 문제**
무한 루프와 `input()`을 활용하여, 1을 누르면 70% 확률로 강화가 성공하고 2를 누르면 루프가 종료되며 최종 결과를 출력하는 시뮬레이터를 구축하라.

**2. 내 답**
~~~python
import random

enhance_level = 0
try_count = 0

while True:
    simul = input()
    if int(simul) == 1 :
        try_count += 1
        succ = random.randint(1,10)
        if int(succ) >=1 and int(succ) <=7:
            enhance_level += 1
            print(enhance_level)
        else:
            continue
    if int(simul) == 2:
        print("강화를 종료합니다.")
        break
~~~

**3. 오류 및 원인**
*   **출력 요구사항 누락:** 강화 실패 시의 안내 메시지와, 반복문 종료 후 최종 결과(총 시도 횟수, 최종 강화 수치)를 출력하는 코드가 빠졌다.
*   **불필요한 형 변환:** `random.randint()`는 원래 정수(int)를 반환하므로 `int(succ)`로 한 번 더 감쌀 필요가 없다.
*   **비효율적인 구조:** `1`이 아니면 `2`인 배타적 조건이므로 `if-if`가 아닌 `if-elif`를 써야 연산 낭비가 없다.

**4. 해설**
*   **연쇄 비교 연산:** 파이썬은 타 언어와 달리 `1 <= succ <= 7` 처럼 수학의 부등호 방식을 그대로 사용할 수 있다.
*   `input()`은 문자열을 반환하므로, 숫자 계산이 필요 없다면 굳이 `int()`로 바꾸지 않고 문자열 `"1"`과 바로 비교하는 것이 간편하다.

**5. 정답 코드**
~~~python
import random

enhance_level = 0
try_count = 0

while True:
    simul = input("1: 강화 시도, 2: 종료 ➡️ ") # 안내 문구 추가
    
    if simul == "1":  
        try_count += 1
        succ = random.randint(1, 10)
        
        if 1 <= succ <= 7:  # 파이썬 특유의 직관적인 연쇄 비교
            enhance_level += 1
            print(f"강화 성공! 현재 레벨: {enhance_level}")
        else:
            print("강화 실패!") # 실패 메시지 추가
            continue 
            
    elif simul == "2": # if 대신 elif 사용
        print("강화를 종료합니다.")
        break
        
# 루프 밖에서 최종 결과 출력 (\n을 사용해 한 줄 띄우기)
print(f"\n[최종 결과] 총 시도: {try_count}회 / 최종 강화 수치: {enhance_level}")
~~~

### 🥇 [상] 실무 요구형 : 레거시 코드 리팩토링

**1. 문제**
for문과 append()로 길게 작성된 '이름 중복 제거 리스트'와 '가격에 따른 태그 리스트(고가/저가)' 코드를 단 한 줄의 리스트 컴프리헨션과 집합 자료구조를 활용해 압축하라.

**2. 내 답**
~~~python
# 1. 이름 중복 제거 
name_list = [ name_list.append(item["name"] for item in items )]
unique_names = list(set(name_list))   

# 2. 가격 태그 생성
price_tags = [ price_tags.append("고가") if item["price"] >= 50000 else price_tags.append("저가") for item in items ]
~~~

**3. 오류 및 원인**
*   **리스트 컴프리헨션 내부 `.append()` 사용:** 리스트 컴프리헨션 문법 자체가 리스트에 요소를 자동으로 추가해 주는 역할을 한다. 여기에 `.append()`를 쓰면 행동(메서드) 자체가 실행되어 버려, 결과값으로 데이터 대신 `None`이 리스트에 들어간다.

**4. 해설 (가장 중요한 핵심)**
*   **"리스트 컴프리헨션 안에서는 `.append()`를 쓰지 않는다! 파이썬이 알아서 넣어주니까 '넣을 값'만 적어주자."**
*   `[참일_때_값 if 조건 else 거짓일_때_값 for 변수 in 범위]` 공식에서 '값' 자리에는 `"고가"`나 `"저가"`라는 데이터(문자열)만 툭 던져주면 된다.

**5. 정답 코드**
~~~python
items = [
    {"name": "철검", "price": 3000},
    {"name": "강철검", "price": 60000},
    {"name": "철검", "price": 3000},
    {"name": "미스릴검", "price": 120000}
]

# 1. 이름 중복 제거 (단 한 줄로 압축)
unique_names = list(set([item["name"] for item in items]))

# 2. 가격 태그 생성 (if-else 리스트 컴프리헨션)
price_tags = ["고가" if item["price"] >= 50000 else "저가" for item in items]
~~~

### 5.1.1.3 위치 인수와 키워드 인수
- **위치 인수(Positional Arguments)**
  - 순차적 매핑: 매개변수의 순서대로 인수를 차례대로 주입
- **키워드 인수(Keyword Arguments)**
  - `매개변수명=값` 형태
  - 순서 중요 X

~~~python
def introduce_self(name, age):
    print(f"이름: {name}, 나이: {age}")

# 1. 위치 인수를 사용한 호출: 정의된 순서대로 정확히 주입해야 함
introduce_self("홍길동", 30)  # 정상 작동
introduce_self(30, "홍길동")  # 오작동 발생 (이름 공간에 수치 30이 식별됨)

# 2. 키워드 인수를 사용한 호출: 매개변수 이름을 특정하므로 순서가 상관없음
introduce_self(age=25, name="이영희")  # 순서를 뒤바꿔도 안전하게 매핑되어 정상 작동
~~~

### 5.1.2 매개변수의 확장과 결과값 반환 제어

### 5.1.2.1 기본값 매개변수
- **기본값 매개변수(Default Parameter)**
  - 매개변수에 값을 할당하지 않아도 기본적으로 가질 수 있는 값 설정
  - 기본값이 있는 매개변수는 오른쪽 끝부터 차례대로 정의

### 5.1.2.2 가변 인수와 키워드 가변 인수
- 가변 인수(*args)
  - 여러 위치 인수들을 하나의 튜플로 묶어 전달받음
  - 가변적 위치 인수, 매개변수 개수 상관없이 지정 가능
  - 키워드 매개변수로 사용 불가
~~~python
def add(*nums):
    print(nums, type(nums))
add(10, 20)
add(10, 20, 30, 40)
add(20, 30, 50, 80, 90)
~~~

- 키워드 가변 인수(**kwargs)
  - 입력된 키워드 인수들을 딕셔너리 구조로 변환하여 처리
~~~python
def print_user_info(**info):
    print(info)
print_user_info(name="철수", age=20)
~~~

### 5.1.2.3 return 문의 역할과 복수 데이터 반환
- **return**
  - 함수 내부의 값을 함수 호출부로 반환
  - 반환값을 호출부에 전달하고 함수를 즉시 종료
~~~python
def calc(num1, num2):
    return num1+num2, num1*num2, num1-num2, num1/num2
    
calc(9, 2) 
> (11, 18, 7, 4.5) # 튜플이라 하나

a, b, c, d = calc(10, 2)
print(a, b, c, d)
> 12 20 8 5.0
~~~
- **복수 데이터 반환**
  - 쉼표로 구분한 여러 값을 동시에 반환할 수 있음
  - 이 값들은 하나의 **튜플(Tuple)**로 묶여 반환됨
  - 반환된 튜플은 여러 변수에 나누어 받을 수 있음

### 5.1.5 메모리

**프로그램 메모리 구조 (Memory Layout)**

메모리가 고주소(High address)에서 저주소(Low address) 방향으로 할당되는 전체 구조입니다.

| 메모리 영역 | 저장 데이터 | 특징 및 할당 시점 |
| :--- | :--- | :--- |
| **스택(stack)** | 지역변수, 매개변수 (고주소↓) | **compile time**에 크기 결정 |
| **(free memory)** | - | 스택과 힙 사이의 여유 공간 |
| **힙(heap)** | 동적할당 데이터 | **run time**에 크기 결정 |
| **BSS** | 초기화되지 않은 전역변수, 정적변수 | **file size에 영향** |
| **DATA(GAVR)**| 초기화된 전역변수, 정적변수 | **file size에 영향** |
| **CODE(TEXT)**| 함수, 제어문, 상수 등 코드 (저주소↑) | **file size에 영향** |

**파이썬 함수 실행 흐름**

파이썬에서 함수가 작동할 때 Heap 메모리와 Call Stack 간의 상호작용 과정입니다.

1. **[1. 정의 시점]** `def my_func(): ...`
   - **Heap 메모리**에 `PyCodeObject`(코드 객체) 생성. (내부: `bytecode`, `consts`, `names`)
2. **[2. 호출 시점]** `my_func()`
   - **Call Stack**에 `PyFrameObject`(실행 프레임) **PUSH**.
   - 힙의 코드 객체와 연결되며, `Local Variables`, `Local Namespace`, `Previous Frame` 정보를 포함함.
3. **[3. 종료 시점]** `return`
   - **Call Stack**에서 프레임 **POP**. (지역 변수 메모리 해제)

- **정적 메모리**
  - 한 번 기록되면 제거 X
  - 코드 영역
  - 전역 변수
- **동적 메모리**
  - 실행 중 생성과 소멸 반복
  - 힙(Heap) 영역
  - 객체 전용
  - `PyFunctionObject` ⊃ `PyCodeObject` (함수의 매개변수 정의, 수행코드 정의)

함수 정의 시 힙 영역에 함수 객체가 만들어지고, 호출할 때마다 그 함수 객체를 참조해서 실행함.

- **스택 영역(Call Stack)**
  - 함수 실행 영역 메모리 (임시 영역)
  - `PyFrameObject`
  - 함수가 수행 완료하면 메모리에서 제거
  - 지역 변수(함수가 실행될 때만 유효)

흐름: Heap Memory -> Call Stack

- **변수의 종류**
  - 전역 변수: 함수 외부에 정의된 변수
  - 지역 변수: 함수 내부에 정의된 변수 (매개변수도 지역 변수)

~~~python
def add(num1, num2):
    num3 = 30
    result = num1 + num2 + num3 # 지역변수
    return result

result = add(10, 20) 
result # 전역변수
~~~

- **자료구조 비교**

| 특징 | 스택 (stack) | 큐 (queue) |
| :--- | :--- | :--- |
| **원리** | 후입선출 (LIFO) | 선입선출 (FIFO) |
| **명령어** | push, pop, top(peek) | enqueue, dequeue, front, rear |

- **함수 생애주기**
  1. 함수 정의 → 함수 객체 생성
  2. 함수 호출 → 해당 함수의 Stack Frame 생성 → Call Stack에 Push
  3. 함수 실행 종료 → Stack Frame 제거(Pop)
  - 함수 객체 자체는 호출할 때마다 새로 생성되지 않음.
- **인터프리터 기반**
  - 소스코드 -> 한 줄 한 줄 해석(실행 중) -> 결과
- **프레임 객체 정보**
  - `f_locals`
  - `f_globals`

## 찾아본 내용

### 의문 1: for문의 범위가 딕셔너리이므로 키/값을 가져오는 것이다?
- **진실:** 다루고 있는 데이터 구조가 '딕셔너리를 담고 있는 리스트'임.
- **동작 원리:** 리스트를 for문으로 돌리면 요소가 하나씩 빠져나옴. 즉, 키나 값이 분리되어 나오는 것이 아니라 딕셔너리 데이터 전체가 통째로 빠져나와 변수에 담기는 것.

### 의문 2: 함수 정의 시 선언한 변수는 '매개변수'일 뿐인데 어떻게 반복문의 '범위'가 되는가?
- **진실:** 매개변수는 데이터를 받기 위해 뚫어놓은 '빈 상자(투입구)'에 불과함.
- **동작 원리:** 함수가 호출(실행)되는 순간 실제 리스트 데이터(인수)가 매개변수로 전달되며, 이때 비로소 반복문이 순회할 수 있는 '범위'로 작동하게 됨.

### 의문 3: 매개변수(min_level 등)의 자료형(int, str 등)은 언제, 어떻게 결정되는가? 이것도 동적 타이핑인가?
- **원리:** 파이썬은 동적 타이핑 언어. 함수를 정의할 때 자료형을 미리 강제하지 않음.

- **프레임 객체 직접 확인하기**
  파이썬은 `sys` 모듈의 `_getframe()` 함수를 통해 실행 중인 프레임 객체에 직접 접근할 수 있습니다.
~~~python
import sys

def outer_func():
    x = 10
    
    def inner_func():
        y = 20
        # 1. 현재 실행 중인 프레임 객체 가져오기
        frame = sys._getframe()

        parent_frame = frame.f_back
        print(f"부모 함수의 지역 변수: {parent_frame.f_locals}")

    inner_func()

outer_func()
~~~

  - `f_back`: 현재 프레임을 호출한 이전 프레임(부모 함수/호출자)을 가리키는 포인터

## 해결 과정

### 1. 가변 매개변수(`*args`)의 올바른 사용
- **실수:** 함수 정의 시 `*total`로 받은 가변 매개변수를 내부에서도 `len(*total)`처럼 `*`를 붙여서 호출함.
- **원인:** 함수 정의부의 `*`는 여러 인자를 튜플(Tuple)로 묶어주는 역할을 함. 내부에서 다시 `*`를 쓰면 튜플이 Unpacking(풀림)되어 여러 개의 인자가 나열된 꼴이 되므로 `TypeError`가 발생함.
- **해결:** 함수 내부에서는 `*`를 제외하고 튜플 이름 그대로 사용해야 함.
  - ❌ `sum(*total)` -> ⭕ `sum(total)`

### 2. 매개변 이름 덮어쓰기(Shadowing) 방지
- **실수:** `total = sum(total)`과 같이 매개변수명(`total`)과 동일한 이름의 변수에 계산 결과를 재할당함.
- **원인:** 튜플 타입이었던 `total`이 계산 결과인 정수(int)로 덮어씌워짐. 이후 `len(total)`을 호출할 때 정수는 길이를 구할 수 없으므로 에러가 발생함.
- **해결:** 기존 매개변수와 겹치지 않는 완전히 새로운 변수명을 생성하여 할당해야 함.
  - ❌ `total = sum(total)` -> ⭕ `totals = sum(total)`

### 3. 반환값(Return) 타입의 일관성 유지
- **실수:** 예외 상황(`if len == 0`)에서는 단순 print 후 값을 반환하지 않거나 `return 0`을 한 반면, 정상 작동 시에는 `return totals, average` (값 2개)를 반환함.
- **개선:** 함수의 반환 형태는 조건문 분기와 상관없이 항상 일관되게 유지하는 것이 좋은 설계임. 예외 상황에서도 반환 형태를 맞춰주면, 함수를 호출하는 쪽에서 항상 2개의 값을 예상하고 안전하게 처리할 수 있음.
  - 💡 **Tip:** `return 0` 대신 `return 0, 0`으로 수정하여 리턴값의 형태(튜플)와 개수를 맞추기.

~~~python
# 수정된 정상 코드
def get_total_and_average(*total):
    if len(total) == 0:
        return 0, 0 # 반환 타입 일관성 유지
    else:
        totals = sum(total) # 변수명 덮어쓰기 방지
        average = totals / len(total)
    return totals, average

print(get_total_and_average(90, 85, 95))   
print(get_total_and_average(70, 80, 90, 100, 65))
~~~

  결정 시점: 함수가 실행되어 실제 데이터가 투입되는 찰나에, 들어온 데이터의 형태를 보고 파이썬이 눈치껏(자동으로) 자료형을 결정함.
