### 3.1 시퀀스 자료구조
- **자료구조**: 데이터 군집 -> Collection(콜렉션)
- 주로 하는 일 (**CRUD**): Create, Read, Update, Delete

#### 3.1.1 순차 자료구조: 리스트와 튜플
- 순서가 있는 데이터 군집

**1. 인덱스 연산자 (`[]`)**
- 데이터의 위치를 계산하며 **0번**부터 시작합니다.

**2. 리스트 (List)**
- **특징**: 변경 가능(Mutable), `[1, 2, ...]` 형태
- **Create (추가)**
  - `append(요소)`: 리스트 끝에 요소 추가
  - `insert(추가위치, 요소)`: 특정 위치에 요소 추가
  - `extend(콜렉션)`: 원본 리스트 끝에 리스트/튜플의 요소 여러 개를 한 번에 추가
  - `[기존 리스트] + [값1, 값2, ...]`: 끝에 여러 개를 추가한 새로운 리스트 생성
- **Read (조회)**
  - 인덱스 번호로 접근: 예) `fruits1[1]`
  - `index(요소)`: 특정 요소의 위치(인덱스) 번호 반환
- **Update (수정)**
  - 인덱스 번호로 접근하여 다른 값을 대입: 예) `fruits1[1] = '오렌지'`
- **Delete (삭제)**
  - `remove(요소)`: 첫 번째로 발견한 특정 요소 제거
  - `clear()`: 리스트의 모든 요소 제거
- **기타 조작**
  - `sort()`: 오름차순 정렬 / `sort(reverse=True)`: 내림차순 정렬
  - `reverse()`: 요소 순서 반전
  - `count()`: 특정 요소의 등장 횟수 반환

~~~python
fruits = ['Apple', 'Orange', 'Banana']
fruits1 = fruits[1]
fruits1
> 'Orange'

fruits1 = "오렌지"
fruits
> ['Apple', '오렌지', 'Banana']

fruits.append("Melon")
fruits_copy = fruits
fruits_copy
> ['Apple', '오렌지', 'Banana', 'Melon']

fruits_copy[1] = 'Orange' 
> ['Apple', 'Orange', 'Banana', 'Melon']

fruits.extend(["Cherry", "Water Melon"])
fruits
> ['Apple', 'Orange', 'Banana', 'Cherry', 'Water Melon']

fruits = ['Apple']
fruits + ['Orange', 'Banana']
> ['Apple', 'Orange', 'Banana']

fruits_extend = ["Apple"]
print("추가 전(extend):", id(fruits_extend))

fruits_extend.extend(["Orange", "Banana"])
print("추가 후(extend):", id(fruits_extend))
> 추가 전(extend): 1632446564032
추가 후(extend): 1632446564032
~~~

**3. 튜플 (Tuple)**
- **특징**: 변경 불가(Immutable), 읽기 전용, `(1, 2, ...)` 형태
- 값이 하나인 튜플을 선언할 때는 반드시 콤마(`,`)를 함께 추가해야 함: `(값1,)`
- 소괄호 `()`를 생략하고 콤마로만 값을 나열해도 튜플로 정의됨
- **조회 메서드**
  - 인덱스 연산 `[]`: 요소 접근
  - `count(요소)`: 특정 요소의 등장 횟수
  - `index(요소)`: 특정 요소의 위치 번호

~~~python
fruits = ('Apple', 'Orange')
fruits
> ('Apple', 'Orange')

fruits[0] 
> 'Apple'
fruits[0] = '사과' 
> TypeError 변경 불가

fruits2 = fruits + ('Banana', 'Melon')
fruits2 
> ('Apple', 'Orange', 'Banana', 'Melon')

id(fruits), id(fruits2) 
> (1632447236288, 1632447565792)

fruits = 'Apple', 'Orange', 'Banana'
fruits, type(fruits) 
> (('Apple', 'Orange', 'Banana'), tuple)

a, b, _ = ('Apple', 'Orange', 'Banana') # _ : 이 자리는 안 쓰겠다는 관례
a, b 
> ('Apple', 'Orange')

num1 = 10
num2 = 20

# num1, num2 값을 서로 바꾸시오.
tmp = num2
num2 = num1
num1 = tmp
num1, num2
> (20, 10)

num1 = 10
num2 = 20

num1, num2 = (num2, num1)
num1, num2
> (20, 10)
~~~

#### 3.1.2 인덱싱과 슬라이싱
- 시퀀스 자료구조는 데이터를 순차적으로 정렬하여 저장하므로 각 데이터에 고유 위치 번호가 부여됨.
- **인덱싱 (Indexing): 요소 찾기**
  - `0`부터 시작
  - 음수 인덱스(`-1`, `-2`, ...): 우측(맨 뒤)부터 역순으로 조회
- **슬라이싱 (Slicing): 특정 구간 추출**
  - 결과는 항상 새로운 리스트나 튜플로 반환됨
  - `[시작:]`: 시작점 인덱스부터 끝까지 추출
  - `[:종료]`: 처음부터 종료 인덱스 직전까지 추출 (종료 인덱스 미포함, 예: `[:3]`은 0, 1, 2번 추출)
  - `[시작 이상:종료 미만]`: 특정 구간 추출
  - `[시작:종료:증감단위]`: 증감폭으로 지정한 간격마다 데이터 추출

~~~python
numbers = [0, 1, 2, 3, 4, 5]
print(numbers[1:4])   # 출력: [1, 2, 3] (1번 이상 4번 미만)
print(numbers[::2])   # 출력: [0, 2, 4] (2칸 간격으로 추출)
print(numbers[::-1])  # 출력: [5, 4, 3, 2, 1, 0] (역순 정렬)
~~~

#### 3.1.3 시퀀스 자료구조 연산
- `+` 연산: 두 시퀀스를 결합하여 새로운 리스트/튜플 생성
- `* 숫자` 연산: 지정한 숫자만큼 요소를 반복하여 새로 생성
- `in` 연산자: 특정 요소가 포함되어 있는지 확인 (`True`/`False` 반환)
- `not in` 연산자: 특정 요소가 포함되어 있지 않은지 확인
- `len()` 함수: 요소의 전체 갯수(크기) 반환

#### 명시적 형변환
- `list()`: 튜플, 집합 등을 리스트형으로 변환 (새로운 리스트 생성)
- `tuple()`: 리스트, 집합 등을 튜플형으로 변환 (새로운 튜플 생성)

#### 문자열
- 여러 개의 문자가 열을 지어 있는 형태이며, 순서가 있는 시퀀스 자료구조.
- 인덱스 연산자 `[]`로 내부 문자에 접근 가능.

#### 3.1.4 패킹과 언패킹
- **패킹 (Packing)**: 여러 개의 값을 하나의 변수에 묶어서 할당
- **언패킹 (Unpacking)**: 시퀀스 자료구조의 요소들을 여러 독립 변수에 순차적으로 나누어 대입

### 3.2 매핑 및 집합 자료구조

#### 3.2.1 사전 자료구조 (Dictionary)
- 키(Key)와 값(Value)의 쌍으로 이루어진 매핑 자료구조: `{"key": 값, "key": 값, ...}`
- **Key**: 데이터를 찾을 키워드. 중복 불가. (리스트는 Key로 사용 불가)
- **Value**: Key를 통해 찾는 실제 값. 중복 가능.
- 이미 존재하는 Key에 새로운 값을 대입하면 기존 값이 덮어씌워짐.

#### 3.2.2 딕셔너리 고급 제어
- **Create (추가)**
  - 없는 Key 이름으로 값을 대입하면 새로운 항목이 추가됨
- **Read (조회)**
  - `['키 이름']`: 인덱싱처럼 조회. Key가 없으면 `KeyError` 발생
  - `keys()`: 딕셔너리의 모든 Key를 담은 View 반환 (읽기 전용)
  - `values()`: 딕셔너리의 모든 Value를 담은 View 반환 (읽기 전용)
  - `items()`: `(Key, Value)` 쌍 목록을 튜플로 묶어 담은 View 반환
  - `get('key')`: Key가 없어도 Error 없이 `None`을 안전하게 반환. `get('key', 'Default')` 형태로 디폴트값을 직접 지정할 수 있음
- **Update (수정)**
  - 이미 있는 Key에 값을 대입하면 수정됨
  - `update({key: value, key: value, ...})`: 여러 항목을 한 번에 갱신
- **Delete (삭제)**
  - `del items['키']`: 특정 키-값 쌍 삭제
  - `clear()`: 딕셔너리 전체 비우기

- **딕셔너리 변환**
  - `dict(...)`: 키·값 쌍으로 이루어진 다른 자료형(예: 튜플 리스트)을 딕셔너리로 변환

#### 3.2.3 집합 자료구조 (Set)
- 중복 허용 X, 순서 상관 X
- `{1, 2, 3, ...}` 형태를 가짐

##### 집합 연산 기호 및 메서드
- **합집합**: `a | b` 또는 `a.union(b)`
- **교집합**: `a & b` 또는 `a.intersection(b)`
- **차집합**: `a - b` 또는 `a.difference(b)`
- **대칭차집합**: `a ^ b` 또는 `a.symmetric_difference(b)`

##### 형변환 및 요소 조작
- **형변환**: `set(리스트/튜플)`
- **요소 조작 메서드**
  - `add(요소)`: 요소 하나 추가
  - `update(집합/리스트)`: 여러 요소를 한 번에 추가
  - `remove(요소)`: 특정 요소 삭제 (요소가 존재하지 않으면 `KeyError` 발생)
  - `discard(요소)`: 특정 요소 삭제 (요소가 존재하지 않아도 Error 미발생)
  - `clear()`: 전체 비우기

## 찾아본 내용

- **`*` (애스터리스크, asterisk)**
  - `*변수명` (가변 길이 언패킹, Extended Iterable Unpacking)
  - 할당하고 남은 모든 요소를 묶어 리스트(List)로 반환하는 기능.
  - 위치에 상관없이 단 한 번만 사용할 수 있으며, 남은 값이 없으면 빈 리스트 `[]`를 반환함.
  ~~~python
  a, *rest = (1, 2, 3)          # a = 1, rest = [2, 3]
  a, *rest, c = (1, 2, 3, 4)    # a = 1, rest = [2, 3], c = 4
  ~~~

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재에서 가져온 내용이다.

- **리스트와 튜플의 메모리 아키텍처**
  - 리스트는 요소를 변경할 때 객체의 고유 주소를 유지한 채 유연하게 크기를 조정합니다. 따라서 빈번한 데이터 갱신이 일어나는 동적 데이터 관리에 최적화되어 있습니다.
  - 튜플은 고정된 데이터 구조를 가지기 때문에 리스트에 비해 메모리 소모가 적고 접근 속도가 빠릅니다. (불변성)
- **음수 인덱싱 (Negative Indexing)**
  - 맨 마지막 요소를 `-1`로 식별하여 역방향으로 위치를 지정하는 파이썬 고유의 규칙입니다. 데이터 전체 길이를 계산하지 않고 마지막 요소를 쉽게 가져올 수 있습니다.
- **해시 테이블 (Hash Table)**
  - 딕셔너리와 집합은 내부적으로 해시 함수를 사용하여 키를 고유한 메모리 주소로 실시간 변환합니다. 데이터를 처음부터 훑어보지 않고 원하는 요소를 초고속으로 조회할 수 있는 근간이 됩니다.
- **데이터 정제 시 `set()` 변환 주의사항**
  - 리스트를 `set`으로 변환하면 중복은 필터링 되지만 **순서가 보장되지 않는(Unordered)** 특성이 적용되어 인덱싱이나 슬라이싱이 차단됩니다.
  - 중복을 제거한 뒤 다시 순서대로 가공하려면 `list()` 함수를 사용해 다시 리스트로 돌려놓아야 합니다.

## 문제 상황 / 시행착오

- 딕셔너리에서 `get` 메서드 동작 테스트 시, `mobile = user.get('mobilde', 1)` 와 `user.get('mobilde', '1')` 코드의 차이점이 무엇인지에 대한 의문.
- 특히 `get` 메서드의 디폴트 값으로 숫자 `1`과 문자열 `'1'`을 다르게 주는 이유(차이)가 왜 필요한지 궁금함. (일부러 오타 키워드인 `mobilde`를 넣어 기본값 반환을 유도함)

## 해결 과정

- **기본값 자료형의 차이**: `1`은 숫자형(int)을, `'1'`은 문자열형(str)을 기본값으로 반환함.
- **구분이 필요한 이유**: 반환된 값을 이후 코드에서 수학 계산에 쓸지, 텍스트 결합에 쓸지에 따라 알맞은 자료 형태를 맞춰줘야 함.
- **주의점**: 연산 목적과 맞지 않는 자료형을 기본값으로 설정하면, 이후 작업(예: 문자열 + 숫자)에서 타입 에러(`TypeError`)가 발생할 수 있음을 확인.
