### 1. 클래스 변수 (정적 변수)와 인스턴스 변수

| 구분 | 클래스 변수 (Class Variable) | 인스턴스 변수 (Instance Variable) |
| :--- | :--- | :--- |
| **선언 위치** | 클래스 내부, 메서드 외부에 선언 | 메서드 내부 (주로 `__init__`)에 `self.변수명`으로 선언 |
| **메모리 할당** | 클래스가 메모리에 로드될 때 1번만 생성 (클래스 네임스페이스) | 객체(인스턴스)가 생성될 때마다 개별적으로 생성 (인스턴스 네임스페이스) |
| **공유 여부** | 모든 인스턴스(객체)가 같은 변수를 **공유함** | 각 인스턴스마다 **독립적인 값**을 가짐 (공유 안 됨) |
| **호출/접근 방법** | `클래스명.변수명` (권장)<br>`인스턴스명.변수명` (조회만 할 때) | `self.변수명` (클래스 내부)<br>`인스턴스명.변수명` (클래스 외부) |
| **값 수정 방법** | 반드시 `클래스명.변수명 = 값` 형태로 수정해야 함 | `인스턴스명.변수명 = 값` 형태로 수정 |
| **수정 시 영향** | 클래스 변수 수정 시, 이를 공유하는 **모든 객체에 영향을 미침** | 해당 인스턴스의 변수만 수정되며, **다른 객체나 클래스 변수에 영향 없음** |
| **주요 활용 목적** | 모든 객체가 공통으로 가져야 하는 설정값, 카운터(생성 횟수) 등 | 객체마다 달라야 하는 고유한 상태 (캐릭터 이름, HP 등) 저장 |

- **⚠️ 변수 가리기(Shadowing) 주의**: `인스턴스명.클래스변수명 = 10`과 같이 수정하려고 하면, 공유되는 클래스 변수 값이 바뀌는 것이 아니라 해당 객체의 개인 공간(인스턴스 영역)에 동일한 이름의 인스턴스 변수가 새로 생성된다.

### 2. @classmethod, @staticmethod
객체를 생성하지 않아도 접근할 수 있는 메서드를 정의할 때 사용한다.

| 구분 | @classmethod (클래스 메서드) | @staticmethod (정적 메서드) |
| :--- | :--- | :--- |
| **첫 번째 매개변수** | `cls` (클래스 자기 자신) | **없음** (일반 함수와 동일) |
| **클래스 상태 접근** | **가능** (클래스 변수 조회 및 수정 가능) | **불가능** (클래스 상태에 영향받지 않음) |
| **인스턴스 상태 접근** | **불가능** (인스턴스 변수 접근 불가) | **불가능** (인스턴스 변수 접근 불가) |
| **주요 활용 목적** | 클래스 변수 제어, 대체 생성자 (팩토리 패턴 등) | 클래스/객체 상태와 무관한 순수 유틸리티/계산 기능 |
| **호출 방법** | `클래스명.메서드명()` | `클래스명.메서드명()` |

- **상태 접근의 의미**: `cls`를 받으면 클래스 변수를, `self`를 받으면 인스턴스 변수를 읽고 수정할 수 있다는 뜻이다. 두 메서드 모두 `self`를 받지 않으므로 개별 객체(인스턴스)의 상태는 건드릴 수 없다.

### 7.1 예외 처리

#### 7.1.1 구문 오류와 런타임 예외 비교

- **구문 오류 (Syntax Error)**
  - 파이썬 문법 사용상의 문제 (오타, 들여쓰기 실수, 괄호 누락 등)
  - 인터프리터가 해석 단계에서 식별하여 실행을 거부함 (실행 X)
  - 문법 규칙 위반으로 해석이 불가한 상태
- **런타임 예외 (Exception)**
  - 문법상에는 문제가 없음
  - 실행 과정 중에서 발생하는 문제 (논리적 오류)
  - 실행 전에는 알 수 없으며 실행 중에만 식별됨
  - 예시: 숫자를 0으로 나눔, 리스트 범위 밖 인덱스 접근

**파이썬 대표 예외**

0. **Traceback**
   - 예외 처리 추적 및 부가 설명 리포트
   - `traceback.print_exc()`: 에러 스택을 콘솔에 출력
   - `traceback.format_exc()`: 에러 스택을 문자열로 반환
   - `traceback.print_stack()`: 에러 없이 현재 호출 흐름을 확인
1. **IndexError**
   - 리스트나 튜플에서 존재하지 않는 번호(인덱스)로 데이터를 요청할 때 발생
2. **ValueError**
   - 자료형 값의 변환이 불가능하거나 처리할 수 없을 때 발생
3. **TypeError**
   - 서로 다른 데이터 타입끼리 연산하거나 호출할 수 없는 대상을 호출할 때 발생
4. **ZeroDivisionError**
   - 숫자를 0으로 나누려 할 때 발생

#### 7.1.2 try-except 제어 구조와 예외 관리 방식

- **try, except, else, finally 블록**

~~~python
try:
    # 예외가 발생할 가능성이 있는 핵심 로직

except:
    # 예외가 발생하면 유입되는 구간
    # 예외에 대한 대안 처리, 로깅 처리 수행

else:
    # 예외가 발생하지 않고 성공적으로 수행되었을 때만 유입되는 구간

finally:
    # 예외가 발생하든 정상 처리되든 항상 유입되는 보장된 구간
    # 자원 정리(메모리 해제, 파일 닫기) 등의 공통적인 처리
~~~

- 모든 예외 클래스는 `Exception`의 자식 클래스이다.
- 특정 예외를 명확히 지정하지 못하는 경우, `Exception`으로 포괄적인 처리가 가능하다.

#### 7.1.3 다중 예외 처리 및 raise를 활용한 예외 제어

- **다중 예외 처리 (try-except-else-finally)**

~~~python
try:
    num = int(input("입력하세요: "))
    result = 10 / num
    print(result)

# 1. 개별 처리
except ZeroDivisionError:
    print("0이 아닌 정수를 입력하세요.")
except ValueError:
    print("정수를 입력하세요.")    

# 2. 튜플로 묶어서 처리
except (ZeroDivisionError, ValueError):
    print("0이 아닌 정수만 입력.")

# 3. 에러 메시지를 변수(e)로 받아서 출력
except ZeroDivisionError as e: 
    print(e)    

# 4. Exception을 활용한 순차 처리
except ZeroDivisionError:
    print("0이 아닌 정수만 입력.")
except Exception as e: # Exception은 가장 하단쪽 except로 정의해야 함
    print(e)   
~~~

- **raise (의도적 예외 발생)**
  - 기획 의도나 비즈니스 규칙에 맞지 않을 때 개발자가 직접 예외를 발생시킴
  - 사용법: `raise 예외이름("메시지")`
  - raise를 만나면 코드 실행 흐름이 즉시 중단됨

~~~python
# 예시: 나이가 음수일 때
raise ValueError("나이는 음수가 될 수 없음.")

# 비교 1: 함수 내부에 로직이 고정된 방식 (유연성 부족)
def login(user_id, user_pass):
    if not (user_id == "user01"):
        print("ID X")
        print("ID를 확인하는 회원 ID 찾기 페이지로 이동")
        return
    
    if not (user_pass == "1234"):
        print("password X")
        return

    print("Login")

# 비교 2: raise를 사용하여 판단을 외부로 위임하는 방식
def login(user_id, user_pass):
    # 에러 상황만 알리고 대처는 함수를 호출한 바깥쪽 코드에게 맡기기
    if user_id != "user01":
        raise ValueError("ID X") # 예외 발생, 코드 실행 흐름 중단
    
    if user_pass != "1234":
        raise ValueError("password X")

    print("Login")
~~~

- **사용자 정의 예외**
  - `Exception`은 모든 예외의 부모 클래스이다.
  - `Exception`이나 그 자식 클래스를 상속받아 직접 클래스를 만들면, 그 클래스도 예외 클래스로 동작한다.

### 7.2 디버깅 기초

#### 7.2.1 에러 트레이스백(Traceback)과 해석 방법
- **디버깅(Debugging)**: 오류가 발생한 지점과 원인을 찾아내어 해결하는 과정.
- **트레이스백(Traceback)**: 프로그램 멈춤 직전까지 호출된 함수들의 경로를 역순으로 추적하여 보여주는 에러 리포트. 맨 아래 줄의 상세 원인을 확인한 후, 위로 올라가며 소스 파일과 줄 번호를 확인해 근본 원인을 진단한다.

#### 7.2.2 VS Code 디버거 설치 및 흐름 제어
- 주피터 노트북 파일(.ipynb)에서 셀 단위 디버깅을 하려면 VS Code 확장에서 'Python Debugger'를 설치해야 한다.
- 코드 라인 번호 왼쪽 여백을 클릭하여 빨간색 **중단점(Breakpoint)**을 설정할 수 있다.
- **Variables 패널**: 중단점 정지 시 메모리에 로드된 전역/지역 변수의 데이터 상태를 확인하는 패널.
- **흐름 제어 명령어**:
  - `Step Over`: 현재 줄을 실행하고 다음 줄로 이동 (함수 내부로 안 들어감)
  - `Step Into`: 함수 호출 시 해당 함수 내부 첫 줄로 진입
  - `Step Out`: 진입한 함수 내부의 남은 코드를 다 실행하고 호출했던 곳으로 빠져나옴
  - `Continue`: 다음 중단점을 만날 때까지 멈추지 않고 실행

#### 7.2.3 트레이스백 분석 및 디버깅
- 트레이스백에 나타난 파일 링크를 클릭하여 오류 지점으로 바로 이동할 수 있다.
- 코드 셀 옆 드롭다운에서 **'Debug Cell'**을 선택하면 디버거가 실행되며, `Step Over`로 한 줄씩 실행하며 `Variables` 창에서 변수의 증감(예: `total += i`) 과정을 검증할 수 있다.

### 9.1 내장 함수

#### 9.1.1 데이터 타입과 조건을 확인하는 유효성 검증 함수
- `isinstance()`: 지정한 객체가 특정 데이터 타입과 일치하는지 판별 (자료형 검증)
- 다중 조건 판단 함수
  - `all(iterable)`: 데이터 목록의 모든 요소가 `True`로 인식될 때 `True`를 반환. (예외: 빈 리스트 `[]`는 거짓인 원소가 없으므로 `True` 반환)
  - `any(iterable)`: 데이터 목록 중 요소 하나라도 `True`로 인식되면 `True`를 반환. (예외: 빈 리스트 `[]`는 참인 원소가 없으므로 `False` 반환)

#### 9.1.2 수치 계산과 데이터 요약을 위한 통계 함수

- `sum(iterable)`: 숫자로만 구성된 요소들의 누적 합계 반환
- `round()`: 지정한 자리까지 반올림
- (참고) `math` 모듈: `math.ceil()`은 올림, `math.floor()`는 내림
- **statistics 모듈 표준 라이브러리**
  - `mean(iterable)`: 평균값
  - `median(iterable)`: 극단적인 이상치(Outlier) 배제를 위한 중앙값

### try-except 구문에서 에러 발생 위치와 예외 처리 범위

`try-except` 구문에서 가장 중요한 규칙은 **"`except`라는 안전 그물은 오직 `try` 블록 안에서 발생한 에러만 잡아낸다"**는 것이다.

#### 1. 문제 상황: 에러가 `except` 영역을 지난 후(`else`)에 터진 경우

~~~python
today_menu = ["안동찜닭", "함박스테이크", "못 먹은 마늘보쌈"]
try:
    menu_index = int(input("인덱스 번호 입력: ")) 
    # 사용자가 '10'을 입력하면 숫자로 변환 성공이므로 에러 없이 try를 통과함!
except ValueError:
    print("숫자를 입력해주세요.")
except IndexError:
    print("범위를 벗어났습니다.")
else:
    print(today_menu[menu_index]) 
    # 💥 try를 무사히 통과한 후 else에서 실행되다가 리스트 범위를 벗어나 IndexError 발생! 
    # try 구역 밖이므로 except가 잡아주지 못하고 프로그램이 뻗어버림.
~~~

#### 2. 해결 과정: 에러 발생 지점을 `try` 내부로 이동

~~~python
today_menu = ["안동찜닭", "함박스테이크", "못 먹은 마늘보쌈"]
try:
    menu_index = int(input("인덱스 번호 입력: "))
    today_menu[menu_index]  # 💡 에러 감지 센서 역할 (인덱스가 벗어나면 여기서 IndexError 발생)
except ValueError:
    print("숫자를 입력해주세요.")
except IndexError:
    print("범위를 벗어났습니다.") # try 안에서 터졌으므로 except가 즉시 낚아채어 안전하게 처리!
else:
    print(today_menu[menu_index]) # 에러가 없었을 때만 실행됨
finally:
    print("끝")
~~~

`try` 블록 안에 `today_menu[menu_index]`를 추가하여, 인덱스 범위를 벗어난 경우 **`try` 블록 안에서 미리 에러가 터지도록 유도**했다. 그 결과 아래에 대기 중이던 `except IndexError`가 정상적으로 에러를 잡고 프로그램을 안전하게 이어가게 되었다.

#### 3. 핵심 요약 (try-except-else-finally 흐름)
- **`try`**: 에러가 발생할 수 있는 코드를 검사하는 구역. (에러가 터질 위험이 있는 코드는 반드시 여기에 넣어야 보호받음)
- **`except`**: 오직 `try` 안에서 터진 에러만 수습하는 구역.
- **`else`**: `try`에서 에러가 단 하나도 나지 않고 무사히 통과했을 때만 실행되는 구역. (안전 그물이 없으므로 여기서 에러가 나면 프로그램이 멈춤)
- **`finally`**: 에러 발생 여부와 상관없이 맨 마지막에 무조건 실행되는 구역.

> **💡 팁:** 허공에 `today_menu[menu_index]`를 두기보다는, 아예 `else`에 있던 `print(today_menu[menu_index])` 코드를 `try` 안으로 올려버리면 `else`를 생략할 수 있어 코드가 더 직관적이고 깔끔해진다.

- 덧셈이나 곱셈 등 숫자 계산을 하려면 `int()`나 `float()`을 사용하여 명시적인 형 변환(Type Casting)을 해야 한다.

### 2. `len()`의 입력과 반환 자료형
| 구분 | 자료형 (Type) | 설명 및 예시 |
| :--- | :--- | :--- |
| **입력 (Input)** | 길이를 측정할 수 있는 **시퀀스(Sequence) 및 컬렉션(Collection)** | `str` (문자열), `list` (리스트), `tuple` (튜플), `dict` (딕셔너리), `set` (세트) 등 |
| **반환 (Output)** | **`int` (정수형)** | 측정된 요소의 개수를 항상 정수로 반환 |

- **주의사항**
  - 정수(`int`), 실수(`float`), 불리언(`bool`) 등 단일 값을 가지는 자료형은 내부 요소의 개수를 셀 수 없으므로 `len()` 함수에 넣으면 `TypeError`가 발생한다.
  - 딕셔너리(`dict`)의 경우, 요소의 총 개수는 '키(Key)'의 개수(즉, Key-Value 쌍의 개수)를 기준으로 센다.

### 3. 캡슐화와 Getter/Setter의 의미
- 관련된 데이터를 클래스에 묶음 + 민감한 데이터는 숨김(`__`)
- **Getter(뷰어)와 Setter(필터)**로 안전한 출입구만 열어두는 것이 정보 은닉과 캡슐화의 핵심이다.

### 4. 사용자 정의 예외 (Custom Exception)
내장 에러(`ValueError`, `TypeError` 등) 외에, 로직에 맞춰 직관적인 이름의 에러를 직접 정의하여 사용할 수 있다.

1. **예외 정의하기 (상속)**
   파이썬의 최상위 에러 클래스인 `Exception`을 상속받아 나만의 에러 클래스를 만든다.
   ~~~python
   class MyCustomError(Exception):
       def __init__(self, message="내가 만든 커스텀 에러입니다."):
           super().__init__(message)
   ~~~

2. **예외 발생시키기 (raise)**
   조건문 등을 통해 특정 상황이 되면 `raise` 키워드를 사용하여 강제로 에러를 던진다.
   ~~~python
   def check_value(value):
       if value < 0:
           raise MyCustomError("음수는 허용되지 않습니다!") # 에러 발생
   ~~~

3. **예외 처리하기 (except 지정)**
   `try-except` 구문에서 내가 만든 에러 이름을 직접 지정하여 낚아채듯 처리한다.
   ~~~python
   try:
       check_value(-10)
   except MyCustomError as e:  # 내가 만든 에러 지정
       print(f"에러 잡음: {e}") 
       # 출력: 에러 잡음: 음수는 허용되지 않습니다!
   ~~~

### 5. 빈 리스트 `[]`를 `all()`에 넣으면 왜 `True`가 나오는가?

#### 의문
`False`로 취급되는 빈 데이터(예: `[]`)가 있는데, 왜 `all([])`에 넣으면 결과가 `True`가 나오는가?

#### 탐색 방향 및 후보
`all()`과 `any()` 내부 동작 구조와 논리적 관점 차이 확인.

#### 판단 및 결론
논리적 관점에서 이를 **공허한 참(Vacuous Truth)**이라고 부른다.
- `all([])`의 판별 목적은 "거짓인 원소가 하나라도 있는가?" 이다. 빈 리스트에는 원소가 아예 존재하지 않아 거짓인 원소도 발견되지 않으므로, 무사히 통과되어 **True**가 나온다.
- 반면 `any([])`의 판별 목적은 "참인 원소가 하나라도 있는가?" 이다. 참인 원소 역시 발견할 수 없으므로 조건을 만족하지 못해 **False**가 나온다.
- **깨달음**: 참인 원소도 없고 거짓인 원소도 없기 때문에 각 함수의 판별 목적에 따라 `all`은 `True`가, `any`는 `False`가 나오는 것이다.


### 6. `""`와 `''`가 똑같이 문자열을 만든다면 언제 어떻게 구분해서 쓸까?
특히 `f"{person['name']}"`처럼 f-string 조건문 안에서는 왜 두 개를 섞어서 쓰는 걸까?

#### 탐색 방향 (내 사고)
둘 다 똑같은 문자열을 만드는 거라면 기능 차이는 아닐 테고... 문자열 안에 또 따옴표를 넣을 때 에러가 나는 걸 피하려고 상황에 맞춰 번갈아 쓰는 게 아닐까?

#### 결론 (답변)
예상대로 **'따옴표 충돌(SyntaxError) 방지'**가 주된 목적이다.
파이썬 입장에서는 두 따옴표 기능이 100% 같지만, 똑같은 따옴표를 겹쳐 쓰면 파이썬이 문자열의 시작과 끝을 헷갈려 하기 때문에 섞어서 쓴다.

- **f-string 딕셔너리 호출:** 바깥을 `""`로 썼다면 안쪽 키값은 `''`로 쓴다. 
  (잘못된 예: `f"{person["name"]}"` -> 에러 발생)
  (올바른 예: `f"{person['name']}"`)
- **문장 안의 기호:** 문장에 `It's`처럼 `'`가 들어가면 바깥을 `""`로 감싸서 쓴다. 
  (예: `print("It's mine")`)

#### 클래스 변수와 인스턴스 변수 비교

| 구분 | 클래스 변수 (Class Variable) | 인스턴스 변수 (Instance Variable) |
| :--- | :--- | :--- |
| **선언 위치** | 클래스 내부, 메서드 외부에 선언 | 메서드 내부 (주로 `__init__`)에 `self.변수명`으로 선언 |
| **메모리 할당** | 클래스가 메모리에 로드될 때 1번만 생성 (클래스 네임스페이스) | 객체(인스턴스)가 생성될 때마다 개별적으로 생성 (인스턴스 네임스페이스) |
| **공유 여부** | 모든 인스턴스(객체)가 같은 변수를 **공유함** | 각 인스턴스마다 **독립적인 값**을 가짐 (공유 안 됨) |
| **호출/접근 방법** | `클래스명.변수명` (권장)<br>`인스턴스명.변수명` (조회만 할 때) | `self.변수명` (클래스 내부)<br>`인스턴스명.변수명` (클래스 외부) |
| **값 수정 방법** | 반드시 `클래스명.변수명 = 값` 형태로 수정해야 함 | `인스턴스명.변수명 = 값` 형태로 수정 |
| **수정 시 영향** | 클래스 변수 수정 시, 이를 공유하는 **모든 객체에 영향을 미침** | 해당 인스턴스의 변수만 수정되며, **다른 객체나 클래스 변수에 영향 없음** |
| **주요 활용 목적** | 모든 객체가 공통으로 가져야 하는 설정값, 카운터(생성 횟수) 등 | 객체마다 달라야 하는 고유한 상태 (캐릭터 이름, HP 등) 저장 |

* ⚠️ **변수 가리기(Shadowing) 주의**: `인스턴스명.클래스변수명 = 10`과 같이 수정하려고 하면, 공유되는 클래스 변수 값이 바뀌는 것이 아니라 해당 객체의 개인 공간(인스턴스 영역)에 동일한 이름의 인스턴스 변수가 새로 생성된다.
  
#### 2. @classmethod, @staticmethod
 - 객체를 생성하지 않아도 접근할 수 있는 메서드를 정의할 때
 # @classmethod와 @staticmethod 비교

| 구분 | @classmethod (클래스 메서드) | @staticmethod (정적 메서드) |
| :--- | :--- | :--- |
| **첫 번째 매개변수** | `cls` (클래스 자기 자신) | **없음** (일반 함수와 동일) |
| **클래스 상태 접근** | **가능** (클래스 변수 조회 및 수정 가능) | **불가능** (클래스 상태에 영향받지 않음) |
| **인스턴스 상태 접근** | **불가능** (인스턴스 변수 접근 불가) | **불가능** (인스턴스 변수 접근 불가) |
| **주요 활용 목적** | 클래스 변수 제어, 대체 생성자 (팩토리 패턴 등) | 클래스/객체 상태와 무관한 순수 유틸리티/계산 기능 |
| **호출 방법** | `클래스명.메서드명()` | `클래스명.메서드명()` |

* **상태 접근의 의미**: `cls`를 받으면 클래스 변수를, `self`를 받으면 인스턴스 변수를 읽고 수정할 수 있다는 뜻이다. 두 메서드 모두 `self`를 받지 않으므로 개별 객체(인스턴스)의 상태는 건드릴 수 없다.

#### 7.1.2 try-except 제어 구조와 예외 관리 방식
예외 처리 구문
 - `try`, `except`, `else`, `finally` 블록
~~~python
try:
    # 예외가 발생할 가능성이 있는 코드

except:
    # 예외가 발생하면 유입되는 구간, 예외에 대한 대안 처리
    # 대안 로직, 로깅 처리

else:
    # 예외가 발생하지 않아야 유입되는 구간

finally:
    # 예외가 발생하든 정상 처리되든 항상 유입되는 구간, 공통적인 처리
    # 자원 정리(메모리 해제)
~~~
 - 모든 예외 클래스는 Exception의 자식 클래스
 - 특정 예외를 특정하지 못 하는 경우 Exception으로 처리가 가능!

#### 7.1.3 다중 예외 처리 및 raise를 활용한 예외 제어

except ZeroDivisionError:

except Exception as e:# Exception은 가장 하단쪽 except로 정의

### 오답 노트
##### try-except 구문에서 에러 발생 위치와 예외 처리 범위

`try-except` 구문에서 가장 중요한 규칙은 **"`except`라는 안전 그물은 오직 `try` 블록 안에서 발생한 에러만 잡아낸다"**는 것이다.

##### 1. 문제 상황: 에러가 `except` 영역을 지난 후(`else`)에 터진 경우
~~~python
today_menu = ["안동찜닭", "함박스테이크", "못 먹은 마늘보쌈"]
try:
    menu_index = int(input("인덱스 번호 입력: ")) 
    # 사용자가 '10'을 입력하면 숫자로 변환 성공이므로 에러 없이 try를 통과함!
except ValueError:
    print("숫자를 입력해주세요.")
except IndexError:
    print("범위를 벗어났습니다.")
else:
    print(today_menu[menu_index]) 
    # 💥 try를 무사히 통과한 후 else에서 실행되다가 리스트 범위를 벗어나 IndexError 발생! 
    # try 구역 밖이므로 except가 잡아주지 못하고 프로그램이 뻗어버림.
~~~

##### 2. 해결 과정: 에러 발생 지점을 `try` 내부로 이동
~~~python
today_menu = ["안동찜닭", "함박스테이크", "못 먹은 마늘보쌈"]
try:
    menu_index = int(input("인덱스 번호 입력: "))
    today_menu[menu_index]  # 💡 에러 감지 센서 역할 (인덱스가 벗어나면 여기서 IndexError 발생)
except ValueError:
    print("숫자를 입력해주세요.")
except IndexError:
    print("범위를 벗어났습니다.") # try 안에서 터졌으므로 except가 즉시 낚아채어 안전하게 처리!
else:
    print(today_menu[menu_index]) # 에러가 없었을 때만 실행됨
finally:
    print("끝")
~~~
`try` 블록 안에 `today_menu[menu_index]`를 추가하여, 인덱스 범위를 벗어난 경우 **`try` 블록 안에서 미리 에러가 터지도록 유도**했다. 그 결과 아래에 대기 중이던 `except IndexError`가 정상적으로 에러를 잡고 프로그램을 안전하게 이어가게 되었다.

##### 3. 핵심 요약 (try-except-else-finally 흐름)
* **`try`**: 에러가 발생할 수 있는 코드를 검사하는 구역. **(에러가 터질 위험이 있는 코드는 반드시 여기에 넣어야 보호받음)**
* **`except`**: 오직 `try` 안에서 터진 에러만 수습하는 구역.
* **`else`**: `try`에서 에러가 단 하나도 나지 않고 무사히 통과했을 때만 실행되는 구역. (안전 그물이 없으므로 여기서 에러가 나면 프로그램이 멈춤)
* **`finally`**: 에러 발생 여부와 상관없이 맨 마지막에 무조건 실행되는 구역.

> **💡 실무 팁:** 허공에 `today_menu[menu_index]`를 두기보다는, 아예 `else`에 있던 `print(today_menu[menu_index])` 코드를 `try` 안으로 올려버리면 `else`를 생략할 수 있어 코드가 더 직관적이고 깔끔해진다.

4. 예외처리 except가 지정이 가능한가? index, value, zerodivision, type 같은 거 말고 이 오류 뜨면 함수 네이밍 처럼 error지정  
    - 파이썬 사용자 정의 예외 (Custom Exception)

        내장 에러(`ValueError`, `TypeError` 등) 외에, 로직에 맞춰 직관적인 이름의 에러를 직접 정의하여 사용할 수 있다.

        **1. 예외 정의하기 (상속)**
        파이썬의 최상위 에러 클래스인 `Exception`을 상속받아 나만의 에러 클래스를 만든다.
        ~~~
        class MyCustomError(Exception):
            def __init__(self, message="내가 만든 커스텀 에러입니다."):
                super().__init__(message)
        ~~~

        **2. 예외 발생시키기 (raise)**
        조건문 등을 통해 특정 상황이 되면 `raise` 키워드를 사용하여 강제로 에러를 던진다.
        ~~~
        def check_value(value):
            if value < 0:
                raise MyCustomError("음수는 허용되지 않습니다!") # 에러 발생
        ~~~

        **3. 예외 처리하기 (except 지정)**
        `try-except` 구문에서 내가 만든 에러 이름을 직접 지정하여 낚아채듯 처리한다.
        ~~~
        try:
            check_value(-10)
        except MyCustomError as e:  # 내가 만든 에러 지정
            print(f"에러 잡음: {e}") 
            # 출력: 에러 잡음: 음수는 허용되지 않습니다!
        ~~~

        **💡 핵심 요약**
        * **정의:** `class 내에러(Exception):`
        * **발생:** `raise 내에러()`
        * **처리:** `except 내에러:`
