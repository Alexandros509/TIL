### 5.2 변수 스코프와 람다 함수

#### 5.2.1 변수의 유효 범위와 LEGB 스코프 구조

- **변수 스코프(Scope)**: 변수를 접근할 수 있는 범위

##### 5.2.1.1 전역 변수와 지역 변수

- **전역 변수(Global)**: 함수 외부에 정의된 변수, 코드 전역에서 접근 가능
- **지역 변수(Local)**: 함수 내부에 정의된 변수, 함수가 실행될 때만 유효한 변수

- 접근 우선순위

  2. Enclosing - 외부 함수 변수
  3. Global - 전역 변수
  4. Builtin - 내장 함수

##### 5.2.1.3 global 키워드

- 함수 내부에서 전역 변수를 사용하고 수정하기 위해 선언

#### 일급 함수 (First-class Function)

- **함수의 데이터화 (또는 객체화)**
  - 함수와 변수를 동일하게 취급 
  - 함수의 매개변수로 함수를 사용할 수 있다. - 콜백 함수
  - 함수의 반환값으로 함수를 사용할 수 있다. - 팩토리 함수 

     
      # [Python] 일급 함수, 중첩 함수, 그리고 클로저(Closure)
      
      오늘은 파이썬의 함수가 작동하는 고급 개념인 일급 함수, 중첩 함수, 클로저에 대해 학습했다. 아래의 코드는 이 세 가지 개념이 모두 결합된 핵심 예제이다.
      
      ## 📝 예제 코드
      
      ~~~python
      def outer(num1):
          def inner(num2):
              return num1 + num2
          return inner
          
      a = outer(10) # 항상 10을 더해주는 '클로저' 생성
      result = a(20) # 10(기억된 값) + 20(새로운 인자) = 30
      ~~~
      
      ### 🧠 핵심 개념 분석 요약
      
      | 개념 | 핵심 의미 | 코드 적용 과정 | 주요 특징 및 활용 |
      | --- | --- | --- | --- |
      | **중첩 함수 (Nested Function)** | 함수 내부에 또 다른 함수를 정의하는 구조 | `outer` 함수 내부에 `inner` 함수가 정의되어 있음 | 외부에서 내부 함수로의 직접 접근을 막고(캡슐화), 내부 함수는 외부 함수의 지역 변수(`num1`)를 사용할 수 있음 |
      | **일급 함수 (First-class Function)** | 프로그래밍 언어에서 함수를 일반 변수나 데이터(객체)처럼 취급하는 특성 | `outer` 함수가 실행 결과가 아닌 `inner` 함수 자체를 반환하고, 이를 변수 `a`에 할당함 | 함수를 변수에 저장하거나 다른 함수의 인자로 전달 가능하며, 반환값으로도 사용할 수 있음 |
      | **클로저 (Closure)** | 함수가 자신이 생성될 때의 환경(외부 변수 등)을 기억하는 상태 | `outer(10)` 실행이 끝나도 반환된 `inner` 함수(변수 `a`)가 `num1=10`을 계속 기억(포획)함 | 전역 변수를 쓰지 않고도 데이터를 은닉하고 상태를 안전하게 유지할 수 있으며, 팩토리 함수 생성에 유용함 |
      
      # 함수 호출과 콜 스택, 클로저
      
      ## 1. 핵심 예제
      
      ~~~python
      def outer(num1):
          def inner(num2):
              return num1 + num2
          return inner
      
      a = outer(10)
      a(20)
      ~~~
      
      ---
      
      ## 2. 전체 실행 흐름
      
      ### ① `a = outer(10)`
      
      `outer()`가 호출되면서 `outer`의 실행 프레임이 **콜 스택(Call Stack)**에 올라간다.
      
      ~~~text
      Call Stack
      ┌──────────────────┐
      │ outer frame      │
      │ num1 = 10        │
      └──────────────────┘
      ~~~
      
      `num1`에 `10`이 들어간다.
      
      ---
      
      ### ② `inner()` 정의
      
      `outer()` 내부에서 `inner()` 함수가 만들어진다.
      
      ~~~python
      def inner(num2):
          return num1 + num2
      ~~~
      
      `inner()`는 자신의 매개변수 `num2`뿐 아니라 바깥 함수 `outer()`의 `num1`도 사용한다.
      
      즉:
      
      ~~~text
      inner
       ├─ num2 → 자신의 매개변수
       └─ num1 → 바깥 outer의 변수
      ~~~
      
      ---
      
      ### ③ `return inner`
      
      ~~~python
      return inner
      ~~~
      
      여기서는 `inner()`를 **실행하지 않는다.**
      `inner`라는 **함수 자체를 반환**한다.
      
      따라서:
      
      ~~~python
      a = outer(10)
      ~~~
      
      이후 `a`는 단순한 숫자가 아니라 `inner` 함수를 가리킨다.
      
      ~~~text
      a
      ↓
      inner 함수
      ↓
      num1 = 10을 사용할 수 있는 환경
      ~~~
      
      이것이 **일급 함수**와 연결되는 부분이다.
      
      > 일급 함수: 함수를 값처럼 취급하여 변수에 저장하거나 다른 함수의 인수/반환값으로 사용할 수 있다.
      
      ---
      
      ## 3. `outer()`가 끝났는데 `num1 = 10`은 어떻게 되는가?
      
      `outer()`의 실행이 끝나면 `outer`의 **호출 프레임 자체가 콜 스택에서 제거**된다.
      
      ~~~text
      outer() 실행 중
      
      ┌──────────────┐
      │ outer frame  │
      │ num1 = 10    │
      └──────────────┘
      ~~~
      
      실행 종료:
      
      ~~~text
      Call Stack
      └─ outer frame 제거
      ~~~
      
      `outer()`의 실행이 끝나면 outer의 실행 프레임은 콜 스택에서 제거된다.
      
      하지만 `inner()`는 `outer()`의 변수인 `num1`을 참조하고 있다. 따라서 `inner()`가 이후에도 `num1`에 접근할 수 있도록 `num1`과 관련된 외부 변수 환경은 유지된다.
      
      즉,
      
      - ❌ outer의 실행 프레임 전체가 계속 유지되는 것
      - ⭕ outer의 실행은 종료되고 프레임은 제거되지만, inner가 필요로 하는 외부 변수 환경은 유지되는 것
      
      이처럼 **내부 함수가 자신이 만들어진 바깥 환경의 값을 기억하고 사용하는 현상**을 클로저(Closure)라고 한다.
      
      중요:
      
      > 클로저를 "outer의 실행 프레임이 콜 스택에 계속 남아 있는 것"이라고 이해하면 안 된다.
      
      ---
      
      ## 4. `a(20)` 실행
      
      이제:
      
      ~~~python
      a(20)
      ~~~
      
      을 실행한다.
      
      `a`가 `inner` 함수를 가리키고 있으므로 사실상:
      
      ~~~python
      inner(20)
      ~~~
      
      을 실행하는 것과 같다.
      
      새로운 `inner` 실행 프레임이 콜 스택에 올라간다.
      
      ~~~text
      Call Stack
      
      ┌──────────────────┐
      │ inner frame      │
      │ num2 = 20        │
      └──────────────────┘
      ~~~
      
      `inner()`는 다음을 계산한다.
      
      ~~~python
      return num1 + num2
      ~~~
      
      - `num1` → 클로저가 기억하고 있는 `10`
      - `num2` → 이번 호출에서 전달받은 `20`
      
      따라서:
      
      ~~~text
      10 + 20
      → 30
      ~~~
      
      결과를 반환하면 `inner` 프레임도 콜 스택에서 제거된다.
      
      ---
      
      ## 5. `return inner` vs `return inner()`
      
      이 차이가 매우 중요하다.
      
      ### `return inner`
      
      ~~~python
      return inner
      ~~~
      
      → `inner` **함수 자체를 반환**
      
      ~~~python
      a = outer(10)
      ~~~
      
      결과:
      
      ~~~text
      a → inner 함수
      ~~~
      
      따라서:
      
      ~~~python
      a(20)   # 30
      a(50)   # 60
      ~~~
      
      처럼 나중에 여러 번 호출할 수 있다.
      
      ---
      
      ### `return inner()`
      
      ~~~python
      return inner()
      ~~~
      
      → `inner`를 **즉시 실행한 결과를 반환**
      
      그런데 원래 예제의 `inner()`는 `num2`가 필요하다.
      
      ~~~python
      def inner(num2):
      ~~~
      
      따라서:
      
      ~~~python
      return inner()
      ~~~
      
      처럼 인수를 전달하지 않으면 `TypeError`가 발생한다.
      
      예를 들어:
      
      ~~~python
      return inner(20)
      ~~~
      
      이라면:
      
      ~~~text
      outer(10)
      → num1 = 10
      → inner(20) 즉시 실행
      → num2 = 20
      → 10 + 20
      → 30 반환
      → a = 30
      ~~~
      
      이 경우 `a`는 함수가 아니라 **30이라는 결과값**이다.
      
      ~~~python
      a(20)  # 불가능
      ~~~
      
      ---
      
      ## 6. 콜 스택(Call Stack)
      
      콜 스택은 **현재 실행 중인 함수 호출의 프레임이 쌓이는 구조**라고 이해하면 된다.
      
      예:
      
      ~~~python
      def outer():
          inner()
      
      def inner():
          print("hello")
      
      outer()
      ~~~
      
      실행 중:
      
      ~~~text
      ┌──────────────┐
      │ inner frame  │ ← 현재 실행
      ├──────────────┤
      │ outer frame  │
      └──────────────┘
      ~~~
      
      `inner()`가 끝나면:
      
      ~~~text
      ┌──────────────┐
      │ outer frame  │ ← 다시 실행
      └──────────────┘
      ~~~
      
      `outer()`까지 끝나면 스택에서 모두 제거된다.
      
      즉:
      
      > **함수가 호출되면 프레임이 쌓이고, 함수가 종료되면 해당 프레임이 제거된다.**
      
      ---
      
      ## 7. Frame과 `PyFrameObject`
      
      여기서 한 단계 더 깊게 들어가면 **Frame(실행 프레임)**이라는 개념이 있다.
      프레임은 함수가 실행될 때 필요한 실행 상태를 담는 개념이다.
      
      예를 들어 함수의:
      - 지역 변수
      - 매개변수
      - 실행 위치
      - 코드 객체와 관련된 실행 정보
      
      등을 관리한다.
      
      CPython 구현 관점에서는 프레임과 관련하여 **`PyFrameObject`**라는 내부 객체가 존재한다.
      
      ~~~text
      Python 코드
          ↓
      함수 호출
          ↓
      실행 프레임(Frame)
          ↓
      CPython 내부 구현
          ↓
      PyFrameObject 등으로 실행 상태 관리
      ~~~
      
      주의할 점:
      
      > `PyFrameObject`는 Python 문법에서 직접 사용하는 개념이 아니라 **CPython의 내부 구현을 이해하기 위한 개념**이다.
      
      따라서 일반적인 Python 학습에서는:
      
      ~~~text
      함수 호출
      → 프레임 생성
      → 콜 스택에 쌓임
      → 함수 종료
      → 프레임 제거
      ~~~
      
      정도로 이해해도 충분하다.
      
      ---
      
      ## 8. 클로저와 Frame의 관계
      
      여기서 가장 중요한 주의점:
      
      ~~~text
      ❌ outer의 frame이 콜 스택에 계속 남아 있어서 inner가 num1을 기억한다.
      
      ⭕ outer 실행이 끝난 뒤에도 inner가 필요한 외부 변수(num1)에 접근할 수 있도록 해당 값/환경이 유지된다.
      ~~~
      
      즉 **콜 스택의 프레임 수명**과 **클로저가 유지하는 외부 변수의 환경**은 구분해야 한다.
      CPython 내부에서는 클로저의 자유 변수와 관련하여 `cell` 등의 메커니즘이 사용되며, 이것은 단순히 "outer frame 전체가 계속 살아 있다"는 의미가 아니다.
      
      ---
      
      ## 9. 핵심 개념 연결
      
      ~~~text
      일급 함수
        ↓
      함수를 값처럼 취급 가능
        ↓
      inner 함수를 return 가능
        ↓
      중첩 함수
        ↓
      inner가 바깥 outer의 num1을 참조
        ↓
      outer 실행 종료 후에도 필요한 환경 유지
        ↓
      클로저
        ↓
      a가 num1 = 10을 기억하는 inner 함수를 보유
        ↓
      a(20)
        ↓
      inner frame 생성
        ↓
      num2 = 20
        ↓
      num1(10) + num2(20)
        ↓
      30
      ~~~
      
      ---
      
      ## 10. 한 줄 요약
      
      > **`outer(10)`은 `num1 = 10`을 사용하는 `inner` 함수를 만들어 반환하고, `inner`는 바깥 변수 `num1`을 기억하는 클로저가 된다. 이후 `a(20)`으로 `inner`를 호출하면 새로운 실행 프레임에서 `num2 = 20`을 받아 기억하고 있던 `num1 = 10`과 계산한다.**
      
      ### 개념별 한 줄 정리
      
      - **일급 함수**: 함수를 값처럼 다룰 수 있음.
      - **중첩 함수**: 함수 내부에 정의된 함수.
      - **콜 스택**: 현재 실행 중인 함수 호출 프레임이 쌓이는 구조.
      - **Frame**: 함수 실행에 필요한 상태를 담는 실행 단위.
      - **클로저**: 내부 함수가 자신이 만들어진 바깥 환경의 값을 기억하고 사용하는 것.
      - **`PyFrameObject`**: CPython 내부에서 프레임을 다루는 구현 관련 객체.
      - **`return inner`**: 함수 자체를 반환.
      - **`return inner()`**: 함수를 즉시 실행하고 그 결과를 반환.
      

#### 5.2.2 한 줄 형태의 익명 함수: 람다(lambda)와 내장 함수 연동

##### 5.2.2.1 익명 함수: 람다(lambda)

- 간단하게 일회용으로 사용하는 경우 한 줄의 식으로 간단하게 함수 정의
- 일회용으로 사용되므로 매개변수 이름도 최대한 간결하게 (한자)
- `def`와 `return` 구문 없이 표현식만으로 결과를 반환하며, 연산 즉시 종료되므로 가독성을 높이고 메모리를 절약할 수 있다.

~~~python
lambda 매개변수1, 매개변수2, ... : 반환할_표현식(수식)
~~~

##### 5.2.2.2 내장 가공 함수 map(), filter() 연동

- `map()` : 변환 작업
  - 연속된 데이터(시퀀스)의 요소를 하나씩 함수에 통과시켜 새로운 데이터 군으로 일괄 변환(매핑)한다.
- `filter()` : 특정 조건에서 데이터를 선별
  - 제시한 수식 조건의 결과가 참(True)인 데이터만 선별하여 필터링한다.

#### 5.2.3 스코프 은닉 검증 및 한 줄 데이터 가공 구현

##### 5.2.3.1 전역 변수와 지역 변수의 이름 충돌과 은닉 법칙

- 동일한 이름의 전역 변수와 지역 변수가 충돌할 때, 파이썬은 안쪽인 지역(Local) 스코프를 우선 식별하여 전역 변수가 일시적으로 가려지는 **변수 은닉(Variable Shadowing)** 현상이 발생한다.
- 함수가 종료되면 지역 스코프는 소멸하므로, 전역 공간의 데이터는 오염되지 않고 안전하게 유지된다.

##### 5.2.3.2 lambda와 map(), filter()를 활용한 데이터 일괄 가공

- `map()`으로 모든 요소를 일괄 가공한 뒤, `filter()`를 통해 특정 기준을 만족하는 알맹이 데이터만 정제해 내는 파이프라인을 단 한 줄로 구축할 수 있다.

~~~python
fruits = ['사과', '오렌지', '망고']
list(map(lambda x: f"**{x}**", fruits))
     
numbers = [*range(1, 11)] # 1-10
list(filter(lambda x: x % 2 == 1, numbers))
~~~

### 5.3 클로저와 데코레이터

#### 5.3.1 일급 객체와 클로저의 동작 방식

##### 5.3.1.1 파이썬 함수의 일급 객체 특성과 고차 함수

- **일급 객체 (First-class Object):** 파이썬의 함수는 숫자나 문자열처럼 변수에 대입하거나, 인수로 전달하거나, 반환값으로 사용할 수 있는 특성을 가진다.
- **고차 함수 (Higher-order Function):** 일급 객체의 특성을 활용하여 '다른 함수를 인수로 받거나', '결과로 함수를 반환하는' 구조를 말하며, 클로저와 데코레이터의 뼈대가 된다.

##### 5.3.1.2 외부 함수의 변수를 기억하는 클로저(Closure)

- 내부 함수가 외부 함수의 실행이 종료된 후에도 외부 함수의 지역 변수(환경)를 기억하고 유지하는 캡슐화 구조이다.
- 이를 통해 전역 변수를 남용하지 않고도 데이터를 은닉하고 상태를 안전하게 보존할 수 있다.

#### 5.3.2 데코레이터(Decorator)의 동작 원리와 @ 문법

- 디자인 패턴 중 한 가지
- 원본 함수 소스코드 일절 수정 X
- 호출 전후 부가기능 추가 확장

##### 5.3.2.1 데코레이터의 동작 방식

- 원본 함수를 인수로 받아 내부에서 부가 기능이 결합된 새로운 `wrapper` 함수를 생성하고 반환하는 고차 함수 기반으로 동작한다.
- 사용자가 함수를 호출하면 원본 함수 대신 데코레이터가 포장한 `wrapper` 함수가 대리 실행된다.

##### 5.3.2.2 @ 문법 활용한 데코레이터 선언

- 데코레이터 위치, 키워드 인수 다 되야함 -> `(*args, **kwargs)`
- 함수 정의부 상단에 `@데코레이터이름` 기호를 붙여 원본 함수와 직관적으로 연결한다. 복잡한 중첩 코드를 피하고 유지보수성을 극대화한다.

#### 5.3.3 실행 성능 측정 및 자동 로깅 데코레이터 구현

##### 5.3.3.1 함수의 실행 성능 수치를 측정하는 @timer 데코레이터 구현

- 파이썬 내장 라이브러리인 `time` 모듈을 활용하여, 타겟 함수 실행 전후의 시점을 기록하고 소요 시간을 연산한다.
- `*args, **kwargs` 가변 인자를 주입하여 매개변수 구조가 각기 다른 어떤 함수라도 유연하게 성능 측정이 가능하도록 설계한다.

##### 5.3.3.2 자동 로깅(Logging) 기능 구현

- 핵심 함수가 동작하기 전과 후에 어떤 데이터가 넘어왔는지(주입된 인수 데이터), 그리고 원래 함수의 이름(`__name__`)은 무엇인지 자동으로 추적하고 콘솔에 기록을 남기는 시스템을 구현할 수 있다.

### 클로저의 내부 동작 원리 (비유와 콜스택 관점)

#### 의문
🤔 "함수 호출, 콜스택, `PyFrameObject`, 클로저 관점에서 보자면... 바깥쪽 프레임(outer)이 제거될 때 내부 프레임(inner)도 같이 삭제되려는데, inner가 아직 `num1`을 사용 중이라서 마치 윈도우에서 **'다른 프로그램이 사용 중이어서 파일을 삭제할 수 없습니다'**라고 에러가 뜨며 파일이 남아있는 그런 느낌인가?"

#### 해설 및 동작 원리
✨ 이 비유는 파이썬의 메모리 관리 방식인 **참조 카운트(Reference Counting)**의 핵심을 정확히 찌르는 훌륭한 비유이다. 디테일한 동작 과정을 도식화하면 다음과 같다.

**📂 "폴더는 지워지지만, 파일은 들고 튄다" (메모리 구조 다이어그램)**

~~~text
[ 1단계: 함수 호출 ]
콜스택 (Call Stack)에 outer(10)을 위한 [ PyFrameObject (임시 작업 폴더) ] 생성
 └── 파이썬은 inner가 나중에 num1을 쓸 것을 알고, num1을 
     'Cell 객체'라는 특수 금고에 담아 보관함.

[ 2단계: 함수 종료 및 클로저 반환 ]
return inner 실행 
 └── outer 함수의 [ PyFrameObject (임시 폴더) ]는 콜스택에서 삭제(Pop)됨! 🗑️

[ 3단계: 가비지 컬렉터의 동작 (파일 삭제 시도 에러) ]
가비지 컬렉터(청소부): "폴더가 지워졌으니 num1(Cell 금고)도 버릴까?"
 └── 🚨 거부 발생! 바깥으로 반환된 a(inner 함수)가 
     "나 아직 이 데이터 잡고 있어!(참조 카운트 > 0)" 라며 끈을 놓지 않음.
 └── 윈도우 파일 삭제 에러처럼, 프레임(폴더)은 지워졌지만 
     알맹이인 num1(파일)은 메모리에 끈질기게 생존. 이것이 바로 클로저!
~~~

#### 결론
📌 바깥쪽 함수(`outer`)의 실행 공간인 `PyFrameObject` 자체는 완전히 삭제되어 날아가지만, 내부 함수(`inner`)가 필요로 하는 변수(`num1`)는 **Cell 객체** 형태로 참조 카운트가 유지되어 메모리에 살아남는다.

#### 📝 1. 변수의 유효 범위 (Global vs Local Scope)

- **핵심 목표:** 전역 변수와 함수 내부의 지역 변수가 독립적으로 동작함을 확인

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def item_shop:                  # 에러 1: 함수 정의 시 괄호() 누락
#     game_money = 300
#     print(f"{game_money}")      # 고민: 틀린 건 아니지만 단순 변수 출력엔 불필요한 f-string

# [✅ 완성된 정답 코드]
game_money = 7000                 # 함수 밖의 전역 변수

def item_shop():                  # 매개변수가 없어도 괄호 필수
    game_money = 300              # 함수 안의 지역 변수 (전역 변수와 이름만 같을 뿐 남남)

item_shop()                       # 출력: 300 (지역 변수값)
~~~

#### 📝 2. 클로저(Closure)와 `nonlocal` 제어

- **핵심 목표:** 내부 함수에서 바깥 함수의 지역 변수를 유지하고 수정하기

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def message_store(message):     # 에러 1: 외부 함수는 초기화용이므로 인자가 필요 없음
#     storage = " "
#     def add_message(message):
#         nonlocal storage        # 이건 아주 잘함! (외부 지역 변수 수정 허락)
#         storage += message      # 에러 2: 줄바꿈이나 공백 처리가 안 되어 문장이 다닥다닥 붙음
#         return storage
#     return add_message

# [✅ 완성된 정답 코드]
def message_store():              # 팩토리 역할이므로 빈 괄호로 시작
    storage = ""
    
    def add_message(message):
        nonlocal storage          # "내 안에 있는 게 아니라 바깥의 storage를 쓸 거야!" 선언
        storage += message + "\n" # 띄어쓰기 대신 확실한 줄바꿈(\n)으로 누적 더하기
        return storage
        
    return add_message

# my_storage = message_store("") 처럼 쓸 필요 없음
my_storage = message_store() 
print(my_storage("새로운 알림이 도착했습니다."))
print(my_storage("출석 체크가 완료되었습니다.")) 
~~~

#### 📝 3. 데코레이터(Decorator)와 가변 인수(`*args, **kwargs`)

- **핵심 목표:** 타겟 함수 실행 전후로 로그를 찍고, 들어온 인자값 확인하기

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def auto_tracker():               # 에러 1: 매개변수 누락 (@ 쓰면 무조건 타겟 함수를 1번째로 받음)
#     def wrapper(*args,**kwargs):
#         __name__                  # 에러 2: "누구의" 이름인지(org_func) 명시 안 함
#         print(*args,**kwargs)     # 에러 3: print 안에서 포장(**kwargs)을 뜯으면 옵션으로 착각해 에러 남
#         result += org_func(...)   # 에러 4: 값을 누적하는 게 아니므로 단순 할당(=)이어야 함

# [✅ 완성된 정답 코드]
def auto_tracker(org_func):                     # 원본 함수 객체를 받아줄 자리 필수
    def wrapper(*args, **kwargs):
        print(f"[{org_func.__name__}] 실행 시작") # 함수 이름 추출
        
        print("args:", args)                    # 언패킹(*) 없이 상자째로 던져야 출력됨
        print("kwargs:", kwargs)
        
        result = org_func(*args, **kwargs)      # 원본 함수 실행 시엔 포장 뜯어서(*) 전달
        
        print(f"[{org_func.__name__}] 종료.")
        return result
        
    return wrapper

@auto_tracker
def add_numbers(a, b):
    return a + b

add_numbers(999, 123)
~~~

        | --- | --- | --- | --- |
        | **중첩 함수 (Nested Function)** | 함수 내부에 또 다른 함수를 정의하는 구조 | `outer` 함수 내부에 `inner` 함수가 정의되어 있음 | 외부에서 내부 함수로의 직접 접근을 막고(캡슐화), 내부 함수는 외부 함수의 지역 변수(`num1`)를 사용할 수 있음 |
        | **일급 함수 (First-class Function)** | 프로그래밍 언어에서 함수를 일반 변수나 데이터(객체)처럼 취급하는 특성 | `outer` 함수가 실행 결과가 아닌 `inner` 함수 자체를 반환하고, 이를 변수 `a`에 할당함 | 함수를 변수에 저장하거나 다른 함수의 인자로 전달 가능하며, 반환값으로도 사용할 수 있음 |
        | **클로저 (Closure)** | 함수가 자신이 생성될 때의 환경(외부 변수 등)을 기억하는 상태 | `outer(10)` 실행이 끝나도 반환된 `inner` 함수(변수 `a`)가 `num1=10`을 계속 기억(포획)함 | 전역 변수를 쓰지 않고도 데이터를 은닉하고 상태를 안전하게 유지할 수 있으며, 팩토리 함수 생성에 유용함 |
        
        # 함수 호출과 콜 스택, 클로저
        
        ## 1. 핵심 예제
        
        ```python
        def outer(num1):
            def inner(num2):
                return num1 + num2
        
            return inner
        
        a = outer(10)
        a(20)
        ```
        
        ---
        
        ## 2. 전체 실행 흐름
        
        ### ① `a = outer(10)`
        
        `outer()`가 호출되면서 `outer`의 실행 프레임이 **콜 스택(Call Stack)**에 올라간다.
        
        ```text
        Call Stack
        ┌──────────────────┐
        │ outer frame      │
        │ num1 = 10        │
        └──────────────────┘
        ```
        
        `num1`에 `10`이 들어간다.
        
        ---
        
        ### ② `inner()` 정의
        
        `outer()` 내부에서 `inner()` 함수가 만들어진다.
        
        ```python
        def inner(num2):
            return num1 + num2
        ```
        
        `inner()`는 자신의 매개변수 `num2`뿐 아니라 바깥 함수 `outer()`의 `num1`도 사용한다.
        
        즉:
        
        ```text
        inner
         ├─ num2 → 자신의 매개변수
         └─ num1 → 바깥 outer의 변수
        ```
        
        ---
        
        ### ③ `return inner`
        
        ```python
        return inner
        ```
        
        여기서는 `inner()`를 **실행하지 않는다.**
        
        `inner`라는 **함수 자체를 반환**한다.
        
        따라서:
        
        ```python
        a = outer(10)
        ```
        
        이후 `a`는 단순한 숫자가 아니라 `inner` 함수를 가리킨다.
        
        ```text
        a
        ↓
        inner 함수
        ↓
        num1 = 10을 사용할 수 있는 환경
        ```
        
        이것이 **일급 함수**와 연결되는 부분이다.
        
        > 일급 함수: 함수를 값처럼 취급하여 변수에 저장하거나 다른 함수의 인수/반환값으로 사용할 수 있다.
        
        ---
        
        ## 3. `outer()`가 끝났는데 `num1 = 10`은 어떻게 되는가?
        
        `outer()`의 실행이 끝나면 `outer`의 **호출 프레임 자체가 콜 스택에서 제거**된다.
        
        ```text
        outer() 실행 중
        
        ┌──────────────┐
        │ outer frame  │
        │ num1 = 10    │
        └──────────────┘
        ```
        
        실행 종료:
        
        ```text
        Call Stack
        └─ outer frame 제거
        ```
        `outer()`의 실행이 끝나면 outer의 실행 프레임은 콜 스택에서 제거된다.
        
        하지만 `inner()`는 `outer()`의 변수인 `num1`을 참조하고 있다. 따라서 `inner()`가 이후에도 `num1`에 접근할 수 있도록 `num1`과 관련된 외부 변수 환경은 유지된다.
        
        즉,
        
        ❌ outer의 실행 프레임 전체가 계속 유지되는 것
        
        ⭕ outer의 실행은 종료되고 프레임은 제거되지만,
           inner가 필요로 하는 외부 변수 환경은 유지되는 것
        
        
        이처럼 **내부 함수가 자신이 만들어진 바깥 환경의 값을 기억하고 사용하는 현상**을 클로저(Closure)라고 한다.
        
        중요:
        
        > 클로저를 "outer의 실행 프레임이 콜 스택에 계속 남아 있는 것"이라고 이해하면 안 된다.
        
        ---
        
        ## 4. `a(20)` 실행
        
        이제:
        
        ```python
        a(20)
        ```
        
        을 실행한다.
        
        `a`가 `inner` 함수를 가리키고 있으므로 사실상:
        
        ```python
        inner(20)
        ```
        
        을 실행하는 것과 같다.
        
        새로운 `inner` 실행 프레임이 콜 스택에 올라간다.
        
        ```text
        Call Stack
        
        ┌──────────────────┐
        │ inner frame      │
        │ num2 = 20        │
        └──────────────────┘
        ```
        
        `inner()`는 다음을 계산한다.
        
        ```python
        return num1 + num2
        ```
        
        - `num1` → 클로저가 기억하고 있는 `10`
        - `num2` → 이번 호출에서 전달받은 `20`
        
        따라서:
        
        ```text
        10 + 20
        → 30
        ```
        
        결과를 반환하면 `inner` 프레임도 콜 스택에서 제거된다.
        
        ---
        
        # 5. `return inner` vs `return inner()`
        
        이 차이가 매우 중요하다.
        
        ### `return inner`
        
        ```python
        return inner
        ```
        
        → `inner` **함수 자체를 반환**
        
        ```python
        a = outer(10)
        ```
        
        결과:
        
        ```text
        a → inner 함수
        ```
        
        따라서:
        
        ```python
        a(20)   # 30
        a(50)   # 60
        ```
        
        처럼 나중에 여러 번 호출할 수 있다.
        
        ---
        
        ### `return inner()`
        
        ```python
        return inner()
        ```
        
        → `inner`를 **즉시 실행한 결과를 반환**
        
        그런데 원래 예제의 `inner()`는 `num2`가 필요하다.
        
        ```python
        def inner(num2):
        ```
        
        따라서:
        
        ```python
        return inner()
        ```
        
        처럼 인수를 전달하지 않으면 `TypeError`가 발생한다.
        
        예를 들어:
        
        ```python
        return inner(20)
        ```
        
        이라면:
        
        ```text
        outer(10)
        → num1 = 10
        → inner(20) 즉시 실행
        → num2 = 20
        → 10 + 20
        → 30 반환
        → a = 30
        ```
        
        이 경우 `a`는 함수가 아니라 **30이라는 결과값**이다.
        
        ```python
        a(20)  # 불가능
        ```
        
        ---
        
        # 6. 콜 스택(Call Stack)
        
        콜 스택은 **현재 실행 중인 함수 호출의 프레임이 쌓이는 구조**라고 이해하면 된다.
        
        예:
        
        ```python
        def outer():
            inner()
        
        def inner():
            print("hello")
        
        outer()
        ```
        
        실행 중:
        
        ```text
        ┌──────────────┐
        │ inner frame  │ ← 현재 실행
        ├──────────────┤
        │ outer frame  │
        └──────────────┘
        ```
        
        `inner()`가 끝나면:
        
        ```text
        ┌──────────────┐
        │ outer frame  │ ← 다시 실행
        └──────────────┘
        ```
        
        `outer()`까지 끝나면 스택에서 모두 제거된다.
        
        즉:
        
        > **함수가 호출되면 프레임이 쌓이고, 함수가 종료되면 해당 프레임이 제거된다.**
        
        ---
        
        # 7. Frame과 `PyFrameObject`
        
        여기서 한 단계 더 깊게 들어가면 **Frame(실행 프레임)**이라는 개념이 있다.
        
        프레임은 함수가 실행될 때 필요한 실행 상태를 담는 개념이다.
        
        예를 들어 함수의:
        
        - 지역 변수
        - 매개변수
        - 실행 위치
        - 코드 객체와 관련된 실행 정보
        
        등을 관리한다.
        
        CPython 구현 관점에서는 프레임과 관련하여 **`PyFrameObject`**라는 내부 객체가 존재한다.
        
        ```text
        Python 코드
            ↓
        함수 호출
            ↓
        실행 프레임(Frame)
            ↓
        CPython 내부 구현
            ↓
        PyFrameObject 등으로 실행 상태 관리
        ```
        
        주의할 점:
        
        > `PyFrameObject`는 Python 문법에서 직접 사용하는 개념이 아니라 **CPython의 내부 구현을 이해하기 위한 개념**이다.
        
        따라서 일반적인 Python 학습에서는:
        
        ```text
        함수 호출
        → 프레임 생성
        → 콜 스택에 쌓임
        → 함수 종료
        → 프레임 제거
        ```
        
        정도로 이해해도 충분하다.
        
        ---
        
        # 8. 클로저와 Frame의 관계
        
        여기서 가장 중요한 주의점:
        
        ```text
        ❌ outer의 frame이 콜 스택에 계속 남아 있어서
           inner가 num1을 기억한다.
        
        ⭕ outer 실행이 끝난 뒤에도 inner가 필요한
           외부 변수(num1)에 접근할 수 있도록
           해당 값/환경이 유지된다.
        ```
        
        즉 **콜 스택의 프레임 수명**과 **클로저가 유지하는 외부 변수의 환경**은 구분해야 한다.
        
        CPython 내부에서는 클로저의 자유 변수와 관련하여 `cell` 등의 메커니즘이 사용되며, 이것은 단순히 "outer frame 전체가 계속 살아 있다"는 의미가 아니다.
        
        ---
        
        # 9. 핵심 개념 연결
        
        ```text
        일급 함수
          ↓
        함수를 값처럼 취급 가능
          ↓
        inner 함수를 return 가능
          ↓
        중첩 함수
          ↓
        inner가 바깥 outer의 num1을 참조
          ↓
        outer 실행 종료 후에도 필요한 환경 유지
          ↓
        클로저
          ↓
        a가 num1 = 10을 기억하는 inner 함수를 보유
          ↓
        a(20)
          ↓
        inner frame 생성
          ↓
        num2 = 20
          ↓
        num1(10) + num2(20)
          ↓
        30
        ```
        
        ---
        
        # 10. 한 줄 요약
        
        > **`outer(10)`은 `num1 = 10`을 사용하는 `inner` 함수를 만들어 반환하고, `inner`는 바깥 변수 `num1`을 기억하는 클로저가 된다. 이후 `a(20)`으로 `inner`를 호출하면 새로운 실행 프레임에서 `num2 = 20`을 받아 기억하고 있던 `num1 = 10`과 계산한다.**
        
        ### 개념별 한 줄 정리
        
        - **일급 함수**: 함수를 값처럼 다룰 수 있음.
        - **중첩 함수**: 함수 내부에 정의된 함수.
        - **콜 스택**: 현재 실행 중인 함수 호출 프레임이 쌓이는 구조.
        - **Frame**: 함수 실행에 필요한 상태를 담는 실행 단위.
        - **클로저**: 내부 함수가 자신이 만들어진 바깥 환경의 값을 기억하고 사용하는 것.
        - **`PyFrameObject`**: CPython 내부에서 프레임을 다루는 구현 관련 객체.
        - **`return inner`**: 함수 자체를 반환.
        - **`return inner()`**: 함수를 즉시 실행하고 그 결과를 반환.

#### 📝 1. 변수의 유효 범위 (Global vs Local Scope)
- **핵심 목표:** 전역 변수와 함수 내부의 지역 변수가 독립적으로 동작함을 확인

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def item_shop:                  # 에러 1: 함수 정의 시 괄호() 누락
#     game_money = 300
#     print(f"{game_money}")      # 고민: 틀린 건 아니지만 단순 변수 출력엔 불필요한 f-string

# [✅ 완성된 정답 코드]
game_money = 7000                 # 함수 밖의 전역 변수

def item_shop():                  # 매개변수가 없어도 괄호 필수
    game_money = 300              # 함수 안의 지역 변수 (전역 변수와 이름만 같을 뿐 남남)
    print(game_money)             # 변수 값만 깔끔하게 출력

item_shop()                       # 출력: 300 (지역 변수값)
print(game_money)                 # 출력: 7000 (전역 변수는 함수 내부의 영향을 받지 않음!)
~~~

#### 📝 2. 클로저(Closure)와 `nonlocal` 제어
- **핵심 목표:** 내부 함수에서 바깥 함수의 지역 변수를 유지하고 수정하기

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def message_store(message):     # 에러 1: 외부 함수는 초기화용이므로 인자가 필요 없음
#     storage = " "
#     def add_message(message):
#         nonlocal storage        # 이건 아주 잘함! (외부 지역 변수 수정 허락)
#         storage += message      # 에러 2: 줄바꿈이나 공백 처리가 안 되어 문장이 다닥다닥 붙음
#         return storage
#     return add_message

# [✅ 완성된 정답 코드]
def message_store():              # 팩토리 역할이므로 빈 괄호로 시작
    storage = ""
    
    def add_message(message):
        nonlocal storage          # "내 안에 있는 게 아니라 바깥의 storage를 쓸 거야!" 선언
        storage += message + "\n" # 띄어쓰기 대신 확실한 줄바꿈(\n)으로 누적 더하기
        return storage
        
    return add_message

# my_storage = message_store("") 처럼 쓸 필요 없음
my_storage = message_store() 
print(my_storage("새로운 알림이 도착했습니다."))
print(my_storage("출석 체크가 완료되었습니다.")) 
~~~

#### 📝 3. 데코레이터(Decorator)와 가변 인수(`*args, **kwargs`)
- **핵심 목표:** 타겟 함수 실행 전후로 로그를 찍고, 들어온 인자값 확인하기

~~~python
# [❌ 나의 초기 실수 코드 및 고민]
# def auto_tracker():               # 에러 1: 매개변수 누락 (@ 쓰면 무조건 타겟 함수를 1번째로 받음)
#     def wrapper(*args,**kwargs):
#         __name__                  # 에러 2: "누구의" 이름인지(org_func) 명시 안 함
#         print(*args,**kwargs)     # 에러 3: print 안에서 포장(**kwargs)을 뜯으면 옵션으로 착각해 에러 남
#         result += org_func(...)   # 에러 4: 값을 누적하는 게 아니므로 단순 할당(=)이어야 함

# [✅ 완성된 정답 코드]
def auto_tracker(org_func):                     # 원본 함수 객체를 받아줄 자리 필수
    def wrapper(*args, **kwargs):
        print(f"[{org_func.__name__}] 실행 시작") # 함수 이름 추출
        
        print("args:", args)                    # 언패킹(*) 없이 상자째로 던져야 출력됨
        print("kwargs:", kwargs)
        
        result = org_func(*args, **kwargs)      # 원본 함수 실행 시엔 포장 뜯어서(*) 전달
        
        print(f"[{org_func.__name__}] 종료.")
        return result
        
    return wrapper

@auto_tracker
def add_numbers(a, b):
    return a + b

add_numbers(999, 123)
~~~

### 찾아본 내용                
 - #### 💡 클로저의 내부 동작 원리 (비유와 콜스택 관점)

**🤔 나의 질문과 비유:** 
> "함수 호출, 콜스택, `PyFrameObject`, 클로저 관점에서 보자면... 바깥쪽 프레임(outer)이 제거될 때 내부 프레임(inner)도 같이 삭제되려는데, inner가 아직 `num1`을 사용 중이라서 마치 윈도우에서 **'다른 프로그램이 사용 중이어서 파일을 삭제할 수 없습니다'**라고 에러가 뜨며 파일이 남아있는 그런 느낌인가?"
        
**✨ 해설 및 동작 원리:**
이 비유는 파이썬의 메모리 관리 방식인 **참조 카운트(Reference Counting)**의 핵심을 정확히 찌르는 훌륭한 비유이다. 디테일한 동작 과정을 도식화하면 다음과 같다.

##### 📂 "폴더는 지워지지만, 파일은 들고 튄다" (메모리 구조 다이어그램)

~~~text
[ 1단계: 함수 호출 ]
콜스택 (Call Stack)에 outer(10)을 위한 [ PyFrameObject (임시 작업 폴더) ] 생성
 └── 파이썬은 inner가 나중에 num1을 쓸 것을 알고, num1을 
     'Cell 객체'라는 특수 금고에 담아 보관함.

[ 2단계: 함수 종료 및 클로저 반환 ]
return inner 실행 
 └── outer 함수의 [ PyFrameObject (임시 폴더) ]는 콜스택에서 삭제(Pop)됨! 🗑️

[ 3단계: 가비지 컬렉터의 동작 (파일 삭제 시도 에러) ]
가비지 컬렉터(청소부): "폴더가 지워졌으니 num1(Cell 금고)도 버릴까?"
 └── 🚨 거부 발생! 바깥으로 반환된 a(inner 함수)가 
     "나 아직 이 데이터 잡고 있어!(참조 카운트 > 0)" 라며 끈을 놓지 않음.
 └── 윈도우 파일 삭제 에러처럼, 프레임(폴더)은 지워졌지만 
     알맹이인 num1(파일)은 메모리에 끈질기게 생존. 이것이 바로 클로저!
~~~

**📌 최종 결론:**
바깥쪽 함수(`outer`)의 실행 공간인 `PyFrameObject` 자체는 완전히 삭제되어 날아가지만, 내부 함수(`inner`)가 필요로 하는 변수(`num1`)는 **Cell 객체** 형태로 참조 카운트가 유지되어 메모리에 살아남는다.
