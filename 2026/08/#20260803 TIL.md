## 오늘 공부한 내용

### Dos 명령어

- `cls` : 화면 지우기
- `cd` : 디렉토리 변경
- `type` : 파일 내용 확인
- `dir` : 파일/디렉토리 목록 확인
- `dir /w` : 가로로 넓게 보기

### 경로 개념

- `cd .` : 현재 폴더
- `cd ..` : 상위 폴더

### Git 환경 설정 (`git config`)

#### 설정 범위 및 우선순위

- `--global` : 현재 사용자 전역 (모든 경로)
- `--system` : 모든 사용자 전역
- `--local` : 현재 저장소
- **적용 우선순위** : local > global > system

#### 사용자 및 에디터 설정

- `git config --global user.name`
- `git config --global user.email`
- `git config --global core.editor "code" --wait`
- `git config --list` : 전체 설정 확인

### HASH 생성 및 SSH 키 등록

1. **SSH 키 생성**
   - `ssh-keygen -t ed25519 -c email`
2. **키 값 확인**
   - `.ssh` 디렉토리로 이동 (`cd .ssh`)
   - `dir` 명령어로 파일 목록 확인
   - `type id` 입력 후 Tab 키를 눌러 자동 완성하여 파일 내용 확인
3. **GitHub 등록**
   - 확인한 Key 값을 복사
   - GitHub > Settings > SSH and GPG keys 메뉴로 이동
   - Add SSH key를 통해 키 값 등록

### 버전 관리 시스템의 차이

- **CVS, SVN** : 파일의 변경 사항을 기록하고 이를 계산하여 복구하는 방식
- **Git** : 파일 상태를 그대로 기록하는 방식 (Snapshot)
  - `working directory` : 버전 관리의 영향을 받는 경로

### Git 작업 단계

**1. Git 초기화**

- `git init`
- (참고: cmd에서 폴더 생성은 `make directory`, 줄여서 `mkdir` 사용)

**2. 스테이징 단계**

- 변경된 파일을 장바구니에 담는 단계
- `git add filename`
- `git add .` (변경 사항 모두 추가)

**3. 커밋(Commit) 단계**

- 버전이 실제로 기록되는 단계
- `git commit -m "메세지"`

**4. 기록 확인**

- 기록을 확인하고 hashID를 이용해 과거 시점으로 이동 및 복구 가능
- `git log` : 전체 기록 확인
- `git log --oneline` : 한 줄로 요약해서 보기
- `git log --graph` : 시각적 흐름으로 보기
- `git log --branches` : 브랜치 기록 보기
- `git log --decorate` : 참조 이름 표시
- `git log --all` : 모든 기록 보기
- `git log -n갯수` : 지정한 갯수만큼 보기

**5. 시점 변경**

- `git checkout commitID` : 해당 커밋 시점으로 이동
- `git checkout -` : 직전 시점으로 이동

### 기타 Git 명령어

- `git hash-object memeber.md`
- `git diff --staged` : 장바구니(스테이징) 내용과 기존에 저장된 버전의 차이 보기
- `git status` : 현재 상태 확인

## 교재 보충

※ 아래 내용은 사용자의 필기를 보완하기 위해 교재에서 가져온 내용이다.

### Git의 3영역 모델 (Three-Area Model)

Git은 파일을 3개의 공간에서 관리한다.

1. **Working Directory (작업 디렉터리)** : 실제 편집 중인 파일들이 있는 공간.
2. **Staging Area / Index (스테이징 영역)** : 다음 커밋에 포함할 변경 사항을 모아두는 임시 공간.
3. **Repository (저장소)** : 커밋이 영구 저장되는 공간 (`.git` 폴더).

### 스냅샷(Snapshot) 기반 커밋 원리

Git은 파일의 차이(diff)가 아닌 커밋 시점의 모든 파일 상태를 하나의 사진처럼 찍어두는 방식(스냅샷)으로 저장한다. 변경이 없는 파일은 이전 스냅샷을 재사용한다.

### HEAD와 SHA 해시

- **HEAD** : 현재 작업 중인 커밋 또는 브랜치를 가리키는 포인터.
- **SHA 해시** : 각 커밋에 부여되는 40자리 고유 ID. 내용을 기반으로 생성되므로 조금만 바뀌어도 해시가 변경된다.

## 필기 ↔ 교재 비교

| 항목 | 필기 | 교재 | 결과 |
| --- | --- | --- | --- |
| 작업 공간 | working directory | Working Directory, Staging Area, Repository (3영역) | 교재 보충 |
| SSH 키 생성 옵션 | `-c email` | `-C "your_email@example.com"` | 확인 필요 |
| 로그 갯수 제한 | `-n갯수` | `-n 5` | 동일 |

## 확인이 필요한 사항

⚠ **SSH 키 생성 명령어 옵션 차이**
필기에는 `ssh-keygen -t ed25519 -c email` (소문자 c)로 작성되어 있으나, 교재에는 `-C` (대문자 C) 옵션을 사용하도록 안내되어 있습니다.

⚠ **명령어 오탈자 가능성**
필기의 `git hash-object memeber.md`에서 파일명이 `member.md`의 오탈자일 가능성이 있습니다. (원문 코드는 그대로 유지했습니다.)

## 필기 누락 가능성

다음 내용은 교재에는 있으나 오늘 수업에서 다루었는지는 확실하지 않습니다.

- **원격 저장소 복제** : `git clone`의 개념과 `git init`과의 차이점
- **무시할 파일 지정** : `.gitignore` 작성 규칙 (예: `__pycache__/`, `.env` 등 제외)
- **인증 방식 비교** : SSH 키 방식 외의 Personal Access Token(PAT) 인증 방식

※ 수업에서 다루었다면 필기를 놓쳤을 가능성이 있습니다.
