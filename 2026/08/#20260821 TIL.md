### 1. Python 비동기 프로그래밍

#### 11.1 동기(Sync) vs 비동기(Async)
- **동기**
  - 작업 하나 제어권 묶임 (Blocking)
- **비동기 (Coroutine)**
  - 작업 새로 생기면 제어권 넘어가고 (Nonblocking),
  - 결과를 보지 않고 바로 넘겨서 동시라고 보일 수 있지만 동시는 아님. 약간의 딜레이.
  - 비동기 함수 정의
    1. 함수 정의 `def` 앞에 `async`
    2. `await`을 만나면 제어권 즉시 반환

- **프로세서와 대기의 관계 : CPU Bound vs I/O Bound**
  - CPU Bound (연산 중심 작업)
    - 복잡한 수식 연산 처리
    - 처리 속도가 하드웨어의 물리적 성능에 의해 결정
  - I/O Bound (입출력 중심 작업)
    - 서버에 데이터를 요청, 외부에 요청을 보내고 응답을 기다리는 상태
    - 데이터가 이동하는 지연 시간(Latency)이 전체 시스템 속도를 결정
    - 내부의 프로세서는 별도의 연산 없이 대기

- **제어권 반환 여부: Blocking vs Non-blocking**
  - Blocking (블로킹)
    - 호출된 하위 코드가 작업을 마칠 때까지 제어권을 독점
  - Non-blocking (논블로킹)
    - 제어권을 상위 코드가 그대로 유지하거나, 요청 즉시 제어권을 다시 돌려받는 방식

- **이벤트 루프**
  - 단일 일꾼이 대기 상태인 작업들을 순찰하며 완료 신호가 들어온 태스크들을 차례대로 배정해 주는 스케줄러
  - 동기식 운영 (머신 앞 부동자세 대기)
  - 비동기식 운영 (진동벨 활용 멀티태스킹)

| 주방 공간 | 컴퓨터 작동 개념 | 상세 설명 |
| :--- | :--- | :--- |
| 1. 조리 도마 | Call Stack (콜 스택) | 일꾼이 지금 당장 손을 움직여 연산하고 처리하는 실제 작업대입니다. |
| 2. 자동 머신 | Background (백그라운드) | 일꾼의 손을 떠나서 기계(네트워크 서버, 저장장치 등)가 알아서 비동기 작업을 수행하는 격리된 공간입니다. |
| 3. 완성 쟁반 | Callback Queue (콜백 큐) | 기계 작업이 끝나 진동벨이 울린 결과물들이, 일꾼의 마지막 처리(콜백 함수)를 받기 위해 줄을 서서 대기하는 공간입니다. |

#### 11.2 코루틴(Coroutine)과 async / await
1. **코루틴(Coroutine)**
   - 필요한 경우 제어권을 잠시 양보할 수 있는 함수
   - 차례가 되면 멈췄던 지점부터 이어서 작업을 수행
2. **실행 환경에 따른 가동 방식**
   - 주피터 노트북에서는 이벤트 루프가 가동 중 → `await 함수명()`
   - 파이썬 파일(.py)를 실행할 때는 이벤트 루프를 생성해야 정상 동작 → `asyncio.run()`

~~~python
asyncio.run(...)
~~~

#### 11.3 비동기 태스크 동시 처리 및 실무 실습
- **`asyncio.gather()`**
  - 1. 무중단 스케줄링 (이벤트 루프의 조율)
    - 이벤트 루프가 여러 코루틴(작업)을 동시에 관리합니다.
    - 작업 중 대기 상태(`await`)가 발생하면 즉시 다른 작업으로 제어권을 전환하여, 쉬는 시간 없이 최대한의 효율을 뽑아냅니다.
  - 2. 에러 통제권 (`return_exceptions` 옵션)
    - 동시에 실행되는 여러 작업 중, 일부 작업에서 에러가 발생했을 때의 처리 방식을 결정합니다.
    - False (기본값): 하나의 작업이라도 에러가 나면 전체 작업이 즉시 중단됩니다.
    - True: 에러가 발생한 작업은 결과 대신 예외 객체로 수집하고 나머지는 정상적으로 완료합니다.

~~~python
import asyncio

async def work(title,seconds):
    await asyncio.sleep(seconds)
    print(title, "완료")
    return title + "완료"

async def main():
    results = await asyncio.gather(
        work("작업 A",2),
        work("작업 B",3),
        work("작업 C",1)
        )
    print(results)

await main()    
~~~

~~~python
import asyncio

async def work():
    await asyncio.sleep(2)
    print("작업 완료")

# await work()
asyncio.run(work()) # 이벤트 루프 생성 -> 실행
~~~

- **httpx**
  - 웹사이트의 HTML 문서를 가져오거나(크롤링), 다른 서버의 API와 데이터를 주고받을 때 사용하는 HTTP 클라이언트 라이브러리
  - requests (동기)와 사용법이 거의 99% 동일할 정도로 직관적
  - 동기 + 비동기 모두 지원

**1. httpx 주요 클래스 (Classes)**

| 클래스명 | 주요 역할 | 비고 |
| :--- | :--- | :--- |
| `httpx.Client` | **동기식** HTTP 요청 처리 및 커넥션 풀 관리 | `with` 문과 함께 사용 권장 |
| `httpx.AsyncClient` | **비동기식** HTTP 요청 처리 (코루틴 동작) | `async with` 문 및 `await` 필수 |
| `httpx.Response` | 서버가 반환한 HTTP 응답 데이터 캡슐화 객체 | 상태 코드, 헤더, 본문 등 포함 |
| `httpx.Limits` | 커넥션 풀 설정 제어 (최대 연결 수 등) | 대규모 동시 요청 최적화 시 활용 |

> 🚨 **주의:** `AsyncClient`의 메서드를 호출할 때는 앞에 반드시 **`await`**를 붙여야 합니다.

**2. 클라이언트 요청 메서드 (Request Methods)**

| 메서드명 | HTTP 메서드 | 주요 설명 및 매개변수 |
| :--- | :--- | :--- |
| `.get(url)` | GET | **데이터 조회:** 쿼리 스트링은 `params=dict` 형태로 전달 |
| `.post(url)` | POST | **데이터 생성:** 바디 데이터는 `json=dict` 또는 `data=dict`로 전달 |
| `.put(url)` | PUT | **데이터 수정:** 자원의 전체 수정을 요청할 때 사용 |
| `.delete(url)`| DELETE | **데이터 삭제:** 특정 리소스의 삭제를 요청할 때 사용 |
| `.request(method, url)`| 커스텀 | 임의의 HTTP 메서드(PATCH, HEAD 등)를 문자열로 직접 지정하여 요청 |

**3. 응답 객체 주요 속성 및 메서드 (Response Objects)**

| 속성 / 메서드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `.status_code` | 속성 `int` | HTTP 상태 코드를 반환 (예: 200, 404, 500) |
| `.text` | 속성 `str` | 응답 본문을 텍스트 문자열 형태로 반환 (자동 디코딩 포함) |
| `.content` | 속성 `bytes` | 응답 본문을 인코딩되지 않은 순수 바이너리(바이트) 형태로 반환 |
| `.json()` | 메서드 | JSON 형식의 응답 본문을 파이썬 딕셔너리/리스트로 파싱하여 반환 |
| `.raise_for_status()` | 메서드 | 상태 코드가 4xx(클라이언트 오류), 5xx(서버 오류)일 경우 예외 발생시킴 |

~~~python
# 동기식 호출
import httpx

with httpx.Client() as client:
    response = client.get("https://jsonplaceholder.typicode.com/posts/1")
    print(response.json())

# 비동기식 호출
import httpx
import asyncio

async def main():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://jsonplaceholder.typicode.com/posts/1")
        print(response.json())

asyncio.run(main())

import asyncio
import httpx

async def get_post(num):
    async with httpx.AsyncClient() as client:
        url = f"https://jsonplaceholder.typicode.com/posts/{num}"

        res = await client.get(url)
        result = res.json()
        # print(result)

        return result['id'], result['title']
    
# 1번부터 10번까지의 게시물 데이터를 동시에(비동기 병렬) 가져와 출력하는 함수    
# 리스트 컴프리헨션 -> 리스트 언패킹(*)
async def main():
    get_posts = [get_post(i) for i in range(1,11)]
    results = await asyncio.gather(*get_posts)
    print(results)
    
# 1번 게시물 데이터를 순차적으로 10번 반복해서 가져와 출력하는 함수
~~~

### 2. AI Literacy

#### 1장 AI 기본 개념

##### 1.1 AI, ML, DL, 생성형 AI, LLM
AI는 가장 넓은 개념이고, 그 안에 머신러닝(ML), 딥러닝(DL), 생성형 AI 등이 포함되는 계층적 구조로 이해했다.
- **AI (Artificial Intelligence):** 컴퓨터가 사람처럼 학습하고 판단할 수 있도록 만드는 인공지능 기술 전체
- **ML (Machine Learning):** 데이터를 통해 규칙과 패턴을 학습하는 방법
- **DL (Deep Learning):** 인공신경망을 사용하는 머신러닝의 한 분야
- **Generative AI:** 학습한 데이터를 바탕으로 새로운 텍스트, 이미지, 음악, 코드 등을 생성
- **LLM (Large Language Model):** 대규모 텍스트 데이터를 학습하고 다음 토큰을 예측하여 문장을 생성

##### 1.2 생성형 AI의 동작 원리
LLM은 텍스트를 그대로 이해하는 것이 아니라 토큰(Token) 단위로 처리한다.
- **토큰:** AI가 읽고 쓰는 최소 단위
  - 영어는 단어와 토큰이 비교적 비슷하게 나뉘는 경우가 많음
  - 한국어는 형태소나 더 작은 단위로 나뉘어 토큰 수가 많아질 수 있음
  - 한글 프롬프트는 같은 내용이라도 영어보다 토큰 소모량이 많을 수 있음

텍스트는 임베딩(Embedding) 을 통해 실수로 이루어진 벡터로 변환된다.
- **임베딩:** 텍스트를 벡터로 변환
  - 벡터 사이의 거리를 이용해 유사도를 비교할 수 있음
  - 유클리디안 거리
  - 코사인 유사도
    - 1: 매우 유사
    - 0: 유사하지 않음
    - -1: 반대 방향

생성형 AI는 입력된 문맥을 바탕으로 다음에 올 토큰을 확률적으로 예측하여 문장을 만든다.
- **Temperature, Top-k, Top-p**
  - Temperature: 다음 토큰을 선택할 때의 무작위성을 조절
  - Top-k: 확률이 높은 상위 k개의 후보 중 선택
  - Top-p: 누적 확률이 지정된 값에 도달할 때까지의 후보를 대상으로 선택

**SIFT**
AI가 제공한 정보를 그대로 믿지 않고 검증하기 위한 방법으로 SIFT를 배웠다.
- S — Stop: 멈추고 감정을 다스리기
- I — Investigation: 출처 확인
- F — Find: 교차 검증
- T — Trace: 원본 맥락 확인

#### 2장 AI 활용과 리스크

##### 2.1 LLM의 한계와 리스크
- **환각 현상**
  - LLM은 완성된 정답을 데이터베이스에서 검색하는 방식이 아니라, 주어진 문맥을 바탕으로 다음 토큰을 확률적으로 생성한다.
  - 따라서 사실 여부를 스스로 검증하지 못하고 실제로 존재하지 않는 정보도 그럴듯하게 생성할 수 있다.
- **지식 컷오프**
  - 모델의 학습이 끝난 시점 이후의 최신 정보는 모델이 기본적으로 알지 못할 수 있다.
  - 외부 지식 소스나 검색을 이용해 최신 정보를 보완할 수 있지만, 검색 결과 자체의 출처 신뢰성도 확인해야 한다.
- **데이터 편향성**
  - AI는 학습 데이터에 포함된 인간 사회의 편견과 고정관념까지 학습할 수 있다.
    - 성별 편향
    - 인종 및 문화적 편향
    - 직업에 대한 고정관념
    - 기존 사회의 구조적 불평등 재생산
  - 따라서 AI 결과에 특정 성별, 인종, 문화에 대한 편향이 포함되어 있지 않은지 확인할 필요가 있다.
- **AI 디바이드**
  - AI 활용 능력의 차이와 AI에 내재된 편향이 결합하면서 기존의 사회적·경제적 격차가 더 커지고 고착화될 수 있다.
- **자동화 편향과 과신**
  - AI의 결과가 논리적이고 전문적으로 보인다는 이유만으로 인간의 판단보다 AI의 판단을 우선시하는 문제가 발생할 수 있다.
    - Automation Bias: AI나 자동화 시스템의 판단을 인간의 경험이나 다른 정보보다 우선하여 믿는 인지적 편향
    - Overreliance: AI의 능력을 과도하게 신뢰하고 결과를 무비판적으로 받아들이는 것
    - Deskilling: AI에 지나치게 의존하면서 인간의 전문적인 기술이나 추론 능력이 퇴화하는 현상
  - 따라서 AI 결과를 그대로 복사해서 사용하는 것이 아니라 검증 과정이 필요하다.
- **Human-in-the-loop**
  - AI를 완벽한 정답을 주는 시스템으로 보기보다 초안을 만들어 주는 파트너로 보고, 인간이 결과를 검토하고 수정하며 최종 승인하는 구조가 필요하다.
  - 중요한 의사결정에서는 수치와 출처를 확인하고 필요하다면 여러 AI 모델의 결과를 비교해야 한다.

##### 2.2 프롬프트 엔지니어링
프롬프트 엔지니어링은 원하는 결과를 얻기 위해 AI에게 입력하는 지시문의 구조와 내용을 설계하는 것이다. 단순히 질문을 던지는 것보다 무엇을, 어떤 관점에서, 어떤 형식으로 원하는지 명확하게 전달하는 것이 중요하다.

**R-T-C-C-F 5대 요소**
프롬프트를 구조화할 때 다음 다섯 가지 요소를 사용할 수 있다.
- **Role (역할):** AI에게 특정 직업이나 경력 등의 역할을 부여하여 원하는 관점과 답변 방향을 유도한다.
- **Task (목적):** AI가 수행해야 할 핵심 작업을 명확한 행동 동사로 지정한다.
- **Context (맥락):** AI가 작업을 수행하는 데 필요한 배경지식과 상황을 제공한다.
- **Constraint (조건):** 분량, 필수 키워드, 금지 사항, 문체 등의 제약을 지정한다.
- **Format (형식):** 결과물을 어떤 형태로 받을 것인지 지정한다. (Markdown 표, Bullet Point, CSV, 이메일, 코드 등)
- 5대 요소를 구조화하면 모호한 요청보다 원하는 결과물의 방향을 명확하게 전달할 수 있다.

##### 2.3 프롬프트 최적화와 피드백
처음부터 완벽한 프롬프트 하나를 만드는 것만이 아니라, `지시 → 결과물 확인 → 피드백 → 수정` 과정을 반복하면서 결과물을 개선할 수 있다.
- **Chain of Prompting:** 하나의 프롬프트에 너무 많은 목적을 넣기보다 복잡한 작업을 여러 단계로 나누어 순차적으로 지시하는 방식이다.
- **Follow-up:** 첫 번째 결과물이 원하는 수준과 다르면 후속 질문으로 수정할 수 있다.
  - 톤앤매너 수정
  - 특정 부분을 따로 상세하게 요청
  - 비판적인 관점에서 문제점 검토
  - 결과물의 일부를 다시 작성

### async & await
- 완벽한 바늘과 실의 관계
- **async:** 중간에 멈출 수 있는 함수인 코루틴을 선언. 비동기 프로그래밍을 할 수 있도록 지원하는 기본 라이브러리(모듈).
- **await:** async 함수 내부에서 사용할 수 있는 일시정지 버튼(지점).
- async가 없는 일반 함수에서는 await를 사용할 수 없음.
- await가 없는 async 함수는 비동기적인 대기 지점이 없어 비동기의 의미가 약해짐. (사실상 일반 함수와 똑같이 한 번에 쭉 실행됨)

### 이벤트 루프와 코루틴 실행이 헷갈렸던 부분
처음에는 async def 함수가 이벤트 루프를 만드는 것인지, 함수를 실행해야 루프가 만들어지는 것인지 헷갈렸다.

#### 1. 함수 정의
~~~python
async def work():
    ...
~~~
비동기 작업의 설계도를 정의한 상태. (단순히 레시피를 작성해 둔 상태이며 아무 일도 일어나지 않음)

#### 2. 코루틴 객체 생성
~~~python
my_order = work()
~~~
함수를 호출하면 바로 함수 내부 코드가 실행되는 것이 아니라 코루틴 객체가 생성된다. (주문서가 출력된 상태이며 코드는 1줄도 실행되지 않음)

#### 3. 이벤트 루프에서 실행
~~~python
asyncio.run(my_order)
~~~
`asyncio.run()`이 이벤트 루프를 생성하고 코루틴을 실행한다. (새로운 주방을 만들고 메인 요리사에게 지시하여 코드가 실행됨)

## 질문 및 깨달음

### 데코레이터(Decorator) 작성 시 반환값(return) 보존의 중요성

- **의문**
  - 데코레이터의 `wrapper` 함수 안에서 원래 함수를 그냥 실행만 하는 것(`sth()`)과, 결과를 변수에 담아 반환하는 것(`return sth()`)의 구체적인 차이는 무엇일까?

- **깨달음 (과정과 결과의 차이)**
  - **피드백 전 (단순 실행):** 원래 함수가 값을 반환하더라도 `wrapper`가 이를 삼켜버려 최종적으로 `None`이 반환됨.
  - **피드백 후 (값 반환):** `result = sth()`로 결과를 담고 `return result`를 해주어야, 원래 함수의 본질(반환값)이 훼손되지 않고 바깥으로 투명하게 전달됨.

- **만약 반환하지 않으면 어떻게 될까? (오류 원인)**
  - 구문 에러가 바로 나지는 않지만, 실무에서 치명적인 **논리 오류(버그)**를 유발함.
  - 예: 연산이 필요한 함수에 불량 데코레이터를 씌우면 결과값이 `None`이 됨. 이후 이 값을 다른 연산에 사용하려 할 때 `TypeError: unsupported operand type(s) for *: 'NoneType' and 'int'` 에러가 발생하여 프로그램이 터짐.

- **결론 (데코레이터의 황금률)**
  - 데코레이터(포장지)는 '투명한 전달자'여야 한다. `wrapper` 내부에서는 반드시 **`return 원래함수()`** 구조를 지켜야 원래 함수의 반환값이 무사히 도착할 수 있다.

### 11.1 동기(Sync) vs 비동기(Async)
 - 동기
    작업 하나 제어권 묶임 (Blocking)
 - 비동기 (Coroutine)
    - 작업 새로 생기면 제어권 넘어가고 (Nonblocking), 
    - 결과를 보지 않고 바로 넘겨서 동시라고 보일 수 있지만 동시는 아님. 약간의 딜레이.
    -  비동기 함수 정의
       -  1. 함수 정의 def 앞에 async
       -  2. await을 만나면 제어권 즉시 반환

 - 프로세서와 대기의 관계 : CPU Bound vs I/O Bound
   - CPU Bound (연산 중심 작업)
     - 복잡한 수식 연산 처리
     - 처리 속도가 하드웨어의 물리적 성능에 의해 결정
   - I/O Bound (입출력 중심 작업)
     - 서버에 데이터를 요청, 외부에 요청을 보내고 응답을 기다리는 상태
     - 데이터가 이동하는 지연 시간(Latency)이 전체 시스템 속도를 결정
     - 내부의 프로세서는 별도의 연산 없이 대기


 - 제어권 반환 여부: Blocking vs Non-blocking
    - Blocking (블로킹)
      - 호출된 하위 코드가 작업을 마칠 때까지 제어권을 독점
    - **Non-blocking (논블로킹)**
      - 제어권을 상위 코드가 그대로 유지하거나, 요청 즉시 제어권을 다시 돌려받는 방식
    
 - 이벤트 루프
     - 단일 일꾼이 대기 상태인 작업들을 순찰하며 완료 신호가 들어온 태스크들을 차례대로 배정해 주는 스케줄러
     - 동기식 운영 (머신 앞 부동자세 대기)
     - 비동기식 운영 (진동벨 활용 멀티태스킹)
주방 공간,컴퓨터 작동 개념,상세 설명
1. 조리 도마,Call Stack (콜 스택),일꾼이 지금 당장 손을 움직여 연산하고 처리하는 실제 작업대입니다.
2. 자동 머신,Background (백그라운드),"일꾼의 손을 떠나서 기계(네트워크 서버, 저장장치 등)가 알아서 비동기 작업을 수행하는 격리된 공간입니다."
3. 완성 쟁반,Callback Queue (콜백 큐),"기계 작업이 끝나 진동벨이 울린 결과물들이, 일꾼의 마지막 처리(콜백 함수)를 받기 위해 줄을 서서 대기하는 공간입니다."

### 11.3 비동기 태스크 동시 처리 및 실무 실습

 - asyncio.gather()
   - 1. 무중단 스케줄링 (이벤트 루프의 조율)
        이벤트 루프가 여러 코루틴(작업)을 동시에 관리합니다.

        작업 중 대기 상태(await)가 발생하면 즉시 다른 작업으로 제어권을 전환하여, 쉬는 시간 없이 최대한의 효율을 뽑아냅니다.

   - 2. 에러 통제권 (return_exceptions 옵션)
        동시에 실행되는 여러 작업 중, 일부 작업에서 에러가 발생했을 때의 처리 방식을 결정합니다.

        False (기본값): 하나의 작업이라도 에러가 나면 전체 작업이 즉시 중단됩니다.

        True: 에러가 발생한 작업은 결과

    ~~~python
    import asyncio

    async def work(title,seconds):
        await asyncio.sleep(seconds)
        print(title, "완료")
        return title + "완료"

    async def main():
        results = await asyncio.gather(
            work("작업 A",2),
            work("작업 B",3),
            work("작업 C",1)
            )
        print(results)

    await main()    
    ~~~

    ~~~python
        print("작업 완료")

    # await work()
    asyncio.run(work()) # 이벤트 루프 생성 -> 실행
    ~~~

#### 1. httpx 주요 클래스 (Classes)

| 클래스명 | 주요 역할 | 비고 |
| :--- | :--- | :--- |
| `httpx.Client` | **동기식** HTTP 요청 처리 및 커넥션 풀 관리 | `with` 문과 함께 사용 권장 |
| `httpx.AsyncClient` | **비동기식** HTTP 요청 처리 (코루틴 동작) | `async with` 문 및 `await` 필수 |
| `httpx.Response` | 서버가 반환한 HTTP 응답 데이터 캡슐화 객체 | 상태 코드, 헤더, 본문 등 포함 |
| `httpx.Limits` | 커넥션 풀 설정 제어 (최대 연결 수 등) | 대규모 동시 요청 최적화 시 활용 |

> 🚨 **주의:** `AsyncClient`의 메서드를 호출할 때는 앞에 반드시 **`await`**를 붙여야 합니다.

---

#### 2. 클라이언트 요청 메서드 (Request Methods)

| 메서드명 | HTTP 메서드 | 주요 설명 및 매개변수 |
| :--- | :--- | :--- |
| `.get(url)` | GET | **데이터 조회:** 쿼리 스트링은 `params=dict` 형태로 전달 |
| `.post(url)` | POST | **데이터 생성:** 바디 데이터는 `json=dict` 또는 `data=dict`로 전달 |
| `.put(url)` | PUT | **데이터 수정:** 자원의 전체 수정을 요청할 때 사용 |
| `.delete(url)`| DELETE | **데이터 삭제:** 특정 리소스의 삭제를 요청할 때 사용 |
| `.request(method, url)`| 커스텀 | 임의의 HTTP 메서드(PATCH, HEAD 등)를 문자열로 직접 지정하여 요청 |

---

#### 3. 응답 객체 주요 속성 및 메서드 (Response Objects)

| 속성 / 메서드 | 타입 | 설명 |
| :--- | :--- | :--- |
| `.status_code` | 속성 `int` | HTTP 상태 코드를 반환 (예: 200, 404, 500) |
| `.text` | 속성 `str` | 응답 본문을 텍스트 문자열 형태로 반환 (자동 디코딩 포함) |
| `.content` | 속성 `bytes` | 응답 본문을 인코딩되지 않은 순수 바이너리(바이트) 형태로 반환 |
| `.json()` | 메서드 | JSON 형식의 응답 본문을 파이썬 딕셔너리/리스트로 파싱하여 반환 |
| `.raise_for_status()` | 메서드 | 상태 코드가 4xx(클라이언트 오류), 5xx(서버 오류)일 경우 예외 발생시킴 |

~~~python
# 동기식 호출
import httpx

with httpx.Client() as client:
    response = client.get("https://jsonplaceholder.typicode.com/posts/1")
    print(response.json())

# 비동기식 호출
import httpx
import asyncio

async def main():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://jsonplaceholder.typicode.com/posts/1")
        print(response.json())

asyncio.run(main())
~~~

## 찾아본 내용
 - **`async`** & **`await`**
   - 완벽한 바늘과 실의 관계
   - async : 중간에 멈출 수 있는 함수 (코루틴) 선언
     - **비동기 프로그래밍을 할 수 있도록 지원하는 기본 라이브러리(모듈)**
   - await : async 함수 내부에서만 쓸 수 있는 일시정지 버튼
   - async가 없는 일반 함수에서는 await를 쓸 수 없고, await가 없는 async 함수는 사실상 일반 함수와 똑같이 한 번에 쭉 실행되어 비동기의 의미가 없음

 - 이벤트 루프 생성 / 코루틴 실행이 헷갈림. async def 함수로 루프 생성? 아니면 그 함수를 실행해야 루프 생성? 그럼 코루틴은? 
    - 1단계 (레시피/설계도 정의): async def work(): ...

    단순히 "앞으로 이런 비동기 요리를 만들겠다"는 설계도(레시피)를 작성해 둔 상태입니다. (아무 일도 일어나지 않음)

    - 2단계 (주문서/코루틴 생성): my_order = work()

    함수를 호출하면 요리가 나오는 것이 아니라, 포스기에서 주문서(코루틴 객체)가 툭 출력됩니다. 누군가에게 주지 않으면 종이 쪼가리일 뿐입니다. (코드는 아직 1줄도 실행되지 않음)

    - 3단계 (주방/루프 생성 및 실제 실행): asyncio.run(my_order)

    새로운 주방(이벤트 루프)을 뚝딱 만들어 내고, 방금 뽑은 주문서를 메인 요리사에게 넘기며 "이제 요리 시작해!"라고 지시합니다. (코루틴이 루프 안으로 들어가 드디어 코드가 한 줄씩 실행됨)
