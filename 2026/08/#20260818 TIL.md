### 8.1 클래스

#### 8.1.1 객체지향과 클래스, 인스턴스의 관계

- **객체 (Object)**
  - 정의: 속성(변수) + 행위(함수/메서드)
  - 객체지향 프로그래밍: 객체 간의 상호작용의 개념으로 프로그램하는 방식

- **클래스 (Class)**
  - 객체를 만들기 위한 설계도

~~~python
class Bus:
    # 속성 정의 - 첫 번째 매개변수 대부분 self
    def __init__(self):
        self.count = 0 # 승객 수, 초기화: 변수가 되었을 때 최초로 값을 대입
        self.passengers = []
        
    def ride(self, passenger): # 탑승
        self.count += 1 # 승객 수 증가
        self.passengers.append(passenger)
        print("탑승")

    def off(self, passenger): # 하차
        if self.count > 1:
            self.count -= 1 # 승객 수 차감
            self.passengers.remove(passenger)
        print("하차")

    def show_count(self):
        print("승객 수:", self.count)

    def print_self(self):
        print(id(self))

    def __str__(self):
        return f"승객수: {self.count}, 승객: {self.passengers}"


class Passenger:
    # self.name, self.age -> 객체가 생성이 되면 만들어지는 인스턴스 변수
    # (..., name, age) -> 객체를 생성하기 위해서 매개변수로 정의된 지역변수
    def __init__(self, name, age):
        self.name = name
        self.age = age
        
    def __str__(self):
        return f"이름: {self.name}, 나이: {self.age}"
        
    def __repr__(self): # 이 부분을 추가
        # return f"REPL"
        return f"{self.name}({self.age}세)"      


bus1 = Bus() # 객체, 클래스 -> 객체(인스턴스 - 실체)
# 마침표(.) 연산자를 통해서 객체의 (인스턴스)변수, 메서드에 접근 가능
print("탑승객 수:", bus1.count)
bus1.ride()
# > 탑승객 수: 0
# > 탑승

bus2 = Bus()
bus1 is bus2
# > False

bus1 = Bus()
print("bus1주소:", id(bus1))
bus1.print_self()    
# > bus1주소: 2358635520288
# > 2358635520288

bus = Bus()
p1 = Passenger()
p2 = Passenger()

bus.ride(p1)
bus.ride(p2)

bus.show_count()   
# > 탑승
# > 탑승
# > 승객 수: 2  

p1 = Passenger("김철수", 20)
print(p1) # __str__ 호출
print(repr(p1)) # __repr__ 호출
# > 이름: 김철수, 나이: 20
# > 김철수(20세)
~~~

- **`__init__`**
  - 객체가 생성이 되면 가장 먼저 호출되는 메서드
  - 객체가 생성된 직후에 해야 할 처음 작업(초기화 작업)
  - 주로 하는 작업은 인스턴스 변수에 최초로 값을 할당(초기화)
  - self 다음 매개변수는 객체를 생성할 때 외부에서 초기화값을 지정할 수 있다.

- **`self`**
  - 클래스 내부에서 메서드의 첫 번째 매개변수로 정의
  - 객체가 생성이 되면 객체의 자원을 접근하기 위한 참조 변수
  - 클래스 내부에서만 사용 가능

- **속성**: 객체마다 정의된 (인스턴스)변수
- **메서드**: 객체가 가지고 있는 함수

- **`__str__`**: print로 객체의 참조변수를 출력하면 자동으로 호출되는 메서드
  - 보통은 객체 내에 있는 인스턴스 변수의 내용을 출력하는 경우가 많다.
- **`__repr__`**: print를 하면 자동으로 호출(`__str__`과 유사), str이 우선순위가 높다.
  - 로깅 목적 (기록을 위한 목적, 디버깅용): `클래스명(매개변수=값, ...)` -> `eval()` 문자열을 실행했을 때 객체가 만들어지는 형태로 보통 정의
  - `repr(객체 참조변수)`

### 8.2 상속과 캡슐화

#### 8.2.1 상속과 메서드 오버라이딩

- **상속 (Inheritance)**
  - 클래스 기반의 상속 (상속에 대한 정의 -> 객체 생성(상속 관계 성립))
  ~~~python
  class 자식클래스(부모클래스):
      ...
  ~~~
  - 부모클래스: 일반적인 정의들, 상위 개념, 공통된 속성/기능
  - 자식클래스: 구체적인 정의들, 하위 개념, 세부 정의/기능
  - `super`: 부모 클래스를 가리키는 **참조 변수/프록시(대리) 개체**
    - 참고) `self`: 자식 개체(현재 개체)의 참조 변수
    - `super()`: 부모 쪽 객체 생성
    - `super()`를 사용할 때는 부모의 `__init__`에 필요한 **추가 인자**만 넘기면 됨. `self`는 자동으로 들어감.

- **메서드 오버라이딩 (Overriding)**
  - 메서드 재정의
  - 부모 쪽 클래스와 동일한 이름으로 정의하여 기능을 수정, 재정의
  - 자식 쪽 클래스에 정의된 동일한 이름의 함수가 호출 우선순위를 가짐
  - 자식 쪽에서 부모 쪽의 동일한 이름의 메서드를 호출해야 하는 경우는 self로 접근하지 않음
    - `super().부모메서드(...)`

~~~python
class Animal:
    def __init__(self, kind):
        self.kind = kind # 동물 종류
        
    def move(self):
        print("동물이 움직인다.")

class Dog(Animal):
    def __init__(self):
        super().__init__("강아지") # 부모 쪽 인스턴스 변수인 kind에 초기화
        
    def move(self):
        super().move() # 부모 쪽 객체의 move()를 호출
        print(self.kind + " 걸음으로 움직인다.")

class Cat(Animal):
    def __init__(self):
        super().__init__("고양이")
        
    def move(self):
        print("고양이 걸음으로 움직인다.")

dog = Dog()
dog.move()

cat = Cat()
cat.move()

print(cat.kind, dog.kind)
~~~

- **`isinstance`**: 객체의 출처 (클래스 자료형) 확인하는 함수 -> `isinstance(참조 변수, 클래스/자료형)`

~~~python
class Human:
    def move(self):
        print("두발 직립보행")

human = Human()

print("Human은 Animal 클래스로부터 생성되었나?", isinstance(human, Animal))
print("Human은 Human 클래스로부터 생성되었나?", isinstance(human, Human))
print("Dog은 Animal 클래스로부터 생성되었나?", isinstance(Dog, Animal))

# > Human은 Animal 클래스로부터 생성되었나? False
# > Human은 Human 클래스로부터 생성되었나? True
# > Dog은 Animal 클래스로부터 생성되었나? False

s = 'ABC'
# s.lower()
# 문자열인지 체크
isinstance(s, str)
# > True
~~~

- **다중 상속**: 여러 부모클래스를 상속 관계로 정의 가능
  - 다중 상속 시 같은 메서드가 있을 때 호출 우선순위 (MRO)
  - 자식 클래스의 메서드 -> 상속 관계에서 왼쪽에 있는 클래스 -> ...

### 의문 1: 리스트 안에서 `__str__` 호출 문제

- **문제 상황**
  `def __str__(self): return f"승객수: {self.count}, 승객: {self.passengers}"`
  여기서 `self.passengers`는 리스트입니다.
- **분석 및 검토**
  파이썬이 리스트를 문자열로 만들 때는 리스트 안의 각 요소에 대해 `__repr__`를 호출합니다. 그런데 `Passenger` 클래스에는 `__repr__`가 없고 `__str__`만 정의되어 있습니다.

  | 상황 | 호출되는 메서드 | 설명 |
  |---|---|---|
  | `print(passenger)` 또는 `str(p1)` | `__str__` | 직접 출력할 때 |
  | `print([p1, p2])` | 리스트가 각 요소의 `__repr__`를 사용 | 컨테이너 안에서는 무조건 `__repr__` |
  | `repr(p1)` | `__repr__` | 개발자용 표현 |

  즉, 이런 코드가 실행될 때:
  ~~~python
  return f"승객수: {self.count}, 승객: {self.passengers}"
  ~~~
  `self.passengers`는 리스트이기 때문에, 파이썬은 리스트를 문자열로 만들면서 내부적으로 대략 이런 일을 합니다:
  ~~~python
  "[" + ", ".join(repr(item) for item in self.passengers) + "]"
  ~~~
  여기서 `repr(item)`이 호출되기 때문에, `Passenger`에 `__str__`가 있어도 무시되고 `__repr__`를 찾습니다. `__repr__`가 없으면 기본값인 `<__main__.Passenger object at 0x...>`가 나옵니다.

- **결론 및 요약**
  - `__str__`: 사람이 읽기 좋은 표현 (친숙한 출력)
  - `__repr__`: 객체를 명확하게 나타내는 표현 (디버깅/재생성 가능)
  리스트나 딕셔너리 같은 컨테이너는 “내용물을 정확하게 보여줘야 한다”는 목적 때문에 항상 `__repr__`를 사용하도록 정해져 있습니다. 
  `__str__`이 우선순위가 높은 건 그 객체 자체를 출력할 때뿐입니다. 리스트 안에 들어가면 우선순위와 상관없이 `__repr__`가 강제 사용됩니다. 그래서 `__repr__`를 정의해야 리스트 안에서도 예쁘게 출력됩니다.

### 의문 2: `isinstance(Dog, Animal)`은 왜 False인가?

- **의문**
  `isinstance(Dog, Animal)`의 결과가 왜 `False`인가?
- **비교 및 검토**
  여기서 `Dog`는 인스턴스가 아니라 클래스 자체입니다. `isinstance()`는 객체가 어떤 클래스의 인스턴스인지를 검사하는 함수입니다.

  | 검사 대상 | 결과 | 이유 |
  |---|---|---|
  | `isinstance(dog, Animal)` | `True` | `dog`는 `Dog()`로 만든 **인스턴스** |
  | `isinstance(Dog, Animal)` | `False`| `Dog`는 **클래스**이지 인스턴스가 아님 |

### 의문 3: 메서드 내부에서 변수에 `self.`를 반드시 붙이는 이유

- **의문**
  클래스의 메서드 내부에서 변수를 업데이트할 때, 왜 굳이 귀찮게 `self.`를 붙여서(`self.count += 1`) 사용해야 할까?

- **분석 및 검토**
  `self`는 영어 단어 뜻 그대로 "나 자신(현재 작동 중인 특정 객체)"을 의미하며, 마침표(`.`)는 "~의"라는 소유의 의미를 가집니다. 즉, `self.count`는 "나 자신의 count"라는 뜻을 가진 일종의 개인 소유물 이름표입니다.
  
  `self.`를 붙이는 가장 큰 이유는 **변수의 수명과 저장 위치**가 완전히 달라지기 때문입니다.

  | 구분 | `self.`가 없을 때 (`count += 1`) | `self.`가 있을 때 (`self.count += 1`) |
  |:---|:---|:---|
  | **역할** | 함수 내부용 지역 변수 (일회용 메모장) | 객체의 인스턴스 변수 (공식 장부) |
  | **수명** | 함수 실행이 끝나면 파이썬이 까맣게 잊어버림 | 객체가 살아있는 한 영구적으로 보존됨 |
  | **특징** | 함수를 다시 호출하면 처음부터 다시 계산해야 함 | 다음 동작에서도 이전의 누적된 데이터를 계속 이어서 쓸 수 있음 |

- **결론**
  메서드 내부에서 잠깐 쓰고 버릴 값이 아니라, 객체가 지속적으로 상태를 기억하고 유지해야 하는 데이터(예: 누적 탑승객 수)라면 반드시 `self.`를 붙여서 객체 고유의 장부에 기록해야 합니다.

### 6.2 uv를 활용한 의존성 관리 보충
- **PyPI (Python Package Index)**: 전 세계 파이썬 개발자들이 제작한 수십만 개의 오픈소스 패키지가 모여있는 공식 중앙 저장소 플랫폼입니다.
- **선언적 의존성 관리**: 수동 다운로드 방식 대신 프로젝트 명세 파일에 필요한 외장 패키지를 선언해 두면 `uv`가 알아서 탐색 및 주입을 전담하는 방식입니다. 터미널에서 `uv add 패키지명`을 실행하면 최적의 버전을 다운로드하고 명세 파일과 동기화합니다.
- **pyproject.toml과 uv.lock**: 
  - `pyproject.toml`: 프로젝트 명세서. 패키지가 추가되면 파일 내부의 `dependencies` 필드에 명칭과 최소 버전 요건이 기입됩니다.
  - `uv.lock`: 보안 잠금 파일. 내 컴퓨터에 설치된 패키지의 고유 해시와 정확한 버전 번호가 기록되어 버전 충돌을 차단합니다.
- **uv sync**: 깃(Git) 등에서 코드를 새로 내려받았을 때, `uv.lock` 스냅샷과 현재 가상환경을 비교하여 누락된 패키지를 고속 복원하는 명령어입니다.

### 8.2 캡슐화와 Getter/Setter 보충
- **이름 변형 규칙 (Name Mangling)**: 변수 이름 앞에 언더바 두 개(`__`)를 붙이면, 파이썬이 내부적으로 `_클래스명__변수명` 형태로 이름을 변형합니다. 외부에서 원래 이름으로 접근하는 것을 차단하여 실수로 인한 변경을 방지합니다. (완벽한 보안 차단 기능은 아닙니다.)
- **Getter / Setter**: 
  - `Getter`: 은닉된 객체의 데이터(비공개 속성)를 외부에서 안전하게 읽어올 수 있도록 만들어 둔 접근 통로(함수)입니다.
  - `Setter`: 데이터를 무작정 수정하지 못하게, 값의 유효성 조건을 꼼꼼히 검증한 뒤에만 수정을 허용하는 안전장치(함수)입니다.

### 8.2 상속과 캡슐화
#### 8.2.1 상속과 메서드 오버라이딩
 - `상속 (Inheritance)`
    - 클래스 기반의 상속( 상속에 대한 정의 -> 객체 생성(상속 관계 성랍))
    ~~~python
    class 자식클래스(부모클래스):
        ···
    ~~~
    - super : 부모 클래스를 가리키는 **참조 변수/프록시(대리) 개체**
        - 참고) self: 자식 개체(현재 개체)의 참조 변수
        - `super()`:부모쪽 객체 생성
        - `super()`를 사용할 때는 부모의 `__init__`에 필요한 **추가 인자**만 넘기면 됩니다. `self`는 자동으로 들어갑니다.
    - 부모클래스 : 일반적인 정의들, 상위 개념, 공통된 속성/기능
    - 자식클래스 : 구체적인 정의들, 하위 개념, 세부 정의/기능
 - 메서드 오버라이딩 (Overriding)
    - 메서드 재정의
    - 부모쪽 클래스와 동일한 이름으로 정의하여 기능을 수정, 재정의
    - 자식쪽 클래스에 정의된 동일한 이름의 함수가 호출 우선순위를 가진다
    - 자식쪽에서 부모쪽 동일한 이름의 메서드를 호출해야하는 경우는 self로 접근 X
        - super().부모메서드(..)

    ~~~python
    class Animal:
        def __init__(self,kind):
            self.kind= kind #동물 종류
        def move(self):
            print("동물이 움직인다.")

    class Dog(Animal):
        def __init__(self):
            super().__init__("강아지") # 부모쪽 인스턴스 변수인 kind에 초기화
        def move(self):
            super().move() # 부모쪽 객체의 move()를 호출
            print(self.kind+" 걸음으로 움직인다.")
    class Cat(Animal):
        def __init__(self):
            super().__init__("고양이")
        def move(self):
            print("고양이 걸음으로 움직인다.")

    dog=Dog()
    dog.move()

    cat=Cat()
    cat.move()

    print(cat.kind,dog.kind)

    ~~~

### 찾아본 내용
 - def __str__(self):
    return f"승객수: {self.count}, 승객: {self.passengers}"
여기서 self.passengers는 리스트입니다.
파이썬이 리스트를 문자열로 만들 때는 리스트 안의 각 요소에 대해 __repr__를 호출합니다.
그런데 Passenger 클래스에는 __repr__가 없고 __str__만 정의되어 있습니다.

__str__ → print()나 str()을 쓸 때 사용
__repr__ → 리스트, 딕셔너리 등에 들어있을 때, 또는 개발자가 객체를 볼 때 사용

그래서 리스트 안에서는 __str__가 무시되고, 기본값인
<__main__.Passenger object at 0x...>가 나온 것입니다. 

__str__가 “우선순위가 높다”는 말은 그 객체를 직접 print() 하거나 str() 할 때만 해당됩니다.
리스트 안에 들어 있을 때는 규칙이 다릅니다.
| 상황                              | 호출되는 메서드                          | 설명                          |
|-----------------------------------|------------------------------------------|-------------------------------|
| `print(passenger)` 또는 `str(p1)` | `__str__`                                | 직접 출력할 때                |
| `print([p1, p2])`                 | 리스트가 각 요소의 `__repr__`를 사용     | 컨테이너 안에서는 무조건 `__repr__` |
| `repr(p1)`                        | `__repr__`                               | 개발자용 표현                 |

즉, 이런 코드가 실행될 때:
~~~python
return f"승객수: {self.count}, 승객: {self.passengers}"
~~~
self.passengers는 리스트이기 때문에,
파이썬은 리스트를 문자열로 만들면서 내부적으로 대략 이런 일을 합니다:
~~~python
"[" + ", ".join(repr(item) for item in self.passengers) + "]"
~~~
여기서 repr(item)이 호출되기 때문에,
Passenger에 __str__가 있어도 무시되고 __repr__를 찾습니다.
__repr__가 없으면 기본값인 <__main__.Passenger object at 0x...>가 나옵니다.
왜 이렇게 설계했을까?

__str__ : 사람이 읽기 좋은 표현 (친숙한 출력)
__repr__ : 객체를  unambiguously 나타내는 표현 (디버깅/재생성 가능)

리스트나 딕셔너리 같은 컨테이너는 “내용물을 정확하게 보여줘야 한다”는 목적 때문에
항상 __repr__를 사용하도록 정해져 있습니다.
요약

str이 우선순위가 높은 건 그 객체 자체를 출력할 때뿐입니다.
리스트 안에 들어가면 우선순위와 상관없이 __repr__가 강제 사용됩니다.

그래서 __str__만 정의해도 리스트에서는 이름/나이가 안 나오고,
__repr__를 정의해야 리스트 안에서도 예쁘게 출력됩니다.

 - isinstance dog animal 왜 false?
    여기서 Dog는 인스턴스가 아니라 클래스 자체입니다.
    isinstance()는 객체가 어떤 클래스의 인스턴스인지를 검사하는 함수입니다.
